## 기존 계산과 새 도구의 경계

기존 함수를 저장 자료로 직접 호출한 제주 표본(평가 시각 `2026-09-20T16:30:00Z`, TAF 질의 시각 `2026-09-20T17:00:00Z`):

- `summarizeAirport`: VFR, 관측 16:00Z, 표시 시정 ≥10km, RVR 표시 `2000+`.
- `buildDestination`: TAF 유효기간 안이며 base/BECMG/TEMPO 기간표를 반환.
- 기존 REST가 호출하는 순수 함수의 표본이다. HTTP API를 새로 기동하거나 호출한 결과는 아니다.

새 도구는 표시 문자열을 사실값으로 재사용하지 않는다. 특히 RVR의 `2000+`는 미보고 표시이므로 관측값으로 내보내지 않는다. 국내 KMA의 `header.raw_text`도 serializer가 재구성한 TAC일 수 있어 존재 여부만으로 원문이라고 판정하지 않는다.

현재 `flight-category.js`는 공항 기본 미니마 기반 3단계 정책이다. 기존 계산을 유지하고 그 기준을 밝히며, 원본에 별도의 MVFR 범주가 있으면 표시용 fold를 적용하지 않고 구분해 보존한다. 새로운 4단계 계산기를 이번 작업에 추가하지 않는다.

## 추가 승인: KIM 단일 예보 시각·연직단면

사용자가 RADAR/SATELLITE 키로 KIM 한 시각을 받아 단면 생성을 확인하도록 추가 승인했다. 기존 설정·키 라우팅은 바꾸지 않고 `api.radar_satellite_auth_key`를 이 진단에만 명시했다. 기존 요청 관측/사용량 기록을 유지하되 재시도 상한은 1로 낮췄다. 결과·사용량 기록은 별도 `DATA_PATH=artifacts/ai-copilot/1a/kim-single-time`에 저장했으며 운영/활성 뷰에 배포하지 않았다.

- 고정 run: `2026092206`, hf=9, 유효시각 **2026-09-22 15:00 UTC / 9월 23일 00:00 KST**. 다른 run/예보 시각은 조회하지 않았다.
- 사전 제한: 5개 압력면(1000/925/850/700/500hPa) × u/v/T/hgt, 최대 20개 격자. 착빙·습도·KTG 수집 제외.
- 실제: **18회 시도, 17개 격자 성공(7,754,293 byte), 500hPa/v 30초 timeout**. 재시도·나머지 두 변수 조회 없이 중단했다. `summary.json`은 이 실패를 그대로 보존한다.
- 완료된 4개 압력면으로 기존 `loadRouteCrossSection` 실행: **47개 경로 표본 × 4개 층**, 모든 표본의 기온·고도·u/v finite, 예보 후보 1시각, 착빙 unavailable 확인. 김포–제주 직선 243.42NM은 진단용이며 실제 생성 항로가 아니다.
- 결과: `cross-section.json`, `cross-section-verification.json`, `cross-section.html`, `cross-section.svg`. HTML/SVG는 실제 backend 결과를 표시한 별도 진단 그림이다. 제품 단면 UI 캡처·전체 압력면·실제 항로 검증 완료로 세지 않는다.
- 부분 수집도 기존 사용 가능한 층을 보존해 계산할 수 있음을 확인했다. 1B의 실제 경로 fixture 준비는 여전히 별도 작업이다.
