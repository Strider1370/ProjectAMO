# 실제 인증·OpenAI·브라우저 연속 통합 검증

기준일: 2026-09-24 KST. 브라우저 API fixture 검증과 구분되는 유료 인수 기록이다. 데스크톱 Chromium을 사용하며 실제 사용자 DB/로그인 정보를 복사하지 않는다.

## 실행 경계

```bash
node frontend/scripts/copilot-live-eval.mjs --live
```

- `--live`가 없으면 유료 호출 전에 실패한다. API 키는 기존 서버 환경에서 읽으며 출력하지 않는다.
- ignored `artifacts/ai-copilot/live-browser-*` 아래에 새 DB를 만들고 임의 비밀번호를 가진 합성 pilot 계정을 생성한다. 비밀번호·로그인 cookie·확인 토큰은 평가 JSON에 기록하지 않는다.
- 공개 로컬 METAR/TAF/SIGMET/AIRMET/공항경보의 `latest.json`만 복사한다. 모델 격자는 복사/수집하지 않는다. 따라서 NWP 없는 경계 흐름이지 실제 KIM 단면 인수가 아니다.
- 별도 빈 loopback 포트에 실제 `backend/server.js`와 Vite를 실행한다. `AUTO_ADMIN_LOGIN`을 끄고 로그인 폼→bcrypt 인증→세션 cookie→앱 AI 라우터→OpenAI Responses→UI를 그대로 통과한다. Playwright route interception/가짜 provider/인증 우회는 없다.
- 시험 프로세스만 `gpt-6-luna`, `high`, 출력 상한 3200을 사용한다. 수집기·운영 알림을 끄며 기본 `.env`와 3001/5173 개발 서버는 바꾸지 않는다. 종료 시 자신이 시작한 서버/브라우저만 정리한다.
- 합성 저장 경로와 시험 알람은 새 DB에만 쓴다. 등록 직전 0건, 확인 후 1건, 해제 확인 후 0건과 원본 보존을 SQL로 확인한다. 계정/API/화면이 실제로 이어지는지를 검사하지 실제 푸시 전달을 시험하지는 않는다.

## 1차 실제 흐름: 7턴 통과

근거 디렉터리: `artifacts/ai-copilot/live-browser-MLg8KL/`, 실행 요약 `live-browser-run.log`.

1. 비로그인 챗봇에서 로그인 버튼→실제 계정 폼 인증.
2. 김포 공항 질문→공항 자료 도구→실제 Luna 답변이 말풍선에 표시됨.
3. 개인 저장 경로 검색→선택한 ID의 저장 입력 조회.
4. 카드의 준비→확인 클릭→편집기로 저장 입력 불러오기. 기상/알람 자동 실행 없음.
5. 미래 UTC ETD/ETA의 알람 등록 변경안→카드에 표시된 시각과 원 입력 일치→실제 확인 POST→감시 행 1개.
6. 감시 ID 해제 변경안→실제 확인 POST→감시 0개, 원본 유지.
7. 새 IFR 경로 생성→브리핑→FL310/330 비교→같은 보관 결과 열기. API와 화면의 결과 ID 일치.

실제 모델 질문은 7회, 전부 completed. 합산 입력 **83,912**, 출력 **5,071**토큰(추론 포함), 보고된 캐시 입력 0, 질문 대기 합계 **103.8초**. [Luna 표준 단가](https://developers.openai.com/api/docs/models/gpt-6-luna) 기준 추정 **$0.01093**, 실제 청구액은 아니다. 가장 긴 새 경로 질문은 37.0초였다.

저장 입력→확인 API의 동작 성공과 기상 설명 품질은 별도다. 첫 공항 답변의 `BR`을 ‘안개’로 번역한 오류를 발견했다. 프로젝트 `frontend/src/shared/weather/visual-mapper.js`의 기존 매핑과 일치하도록 모델 지침에 BR=박무, FG=안개, HZ=연무 구분을 추가했다. 범용 기상 코드 전체의 검증 완료를 뜻하지 않는다.

고도 비교 캡처 `stored-comparison.png`를 직접 확인했다. 기존 브리핑 UI에 같은 결과·기준 시각·고도별 자료 없음과 제한이 표시된다. 실제 격자를 넣었을 때의 고도별 수치 검증은 남는다.

## TAF 이전 영구 변화 보완

- `model-context.js`에 이미 종료된 BECMG 및 시작한 FM의 인덱스/적용 시각을 시간순으로 표시하는 `completedPermanentChanges`를 추가했다. 기상 값을 새로 합성하지 않으며 원본 `base`와 변화군은 유지한다. 임시/확률 변화나 시각 불명·역전 항목을 완료된 영구 변화로 취급하지 않는다.
- 프롬프트는 전이의 이전 상태를 설명할 때 이 순서를 적용하도록 명시한다. 이전 상태를 확인할 수 없다면 목표 상태와 불확실성만 설명하도록 한다.
- 이전 실패와 동일 frozen 자료·UTC 00:03 질문을 high/3200으로 다시 실행했다. `route-create-luna-prior-state-utc.jsonl`: completed, 입력 **12,715**·출력 **2,680**토큰, **36.3초**, 표준 비용 추정 **$0.00261**.
- 답변에서 제주 바람을 앞선 BECMG의 **170°/5kt → 050°/7kt** 전이로 설명했고, 23:00~01:00 UTC 구간과 요청 구간의 겹침을 보존했다. 최초 기본 예보 110°로 되돌리는 오류는 이 표본에서는 재현되지 않았다. 한 번의 성공을 전체 시간 해석 정확도 보장으로 사용하지 않는다.
- OpenAI Docs의 [Luna 설정 문서](https://developers.openai.com/api/docs/models/gpt-6-luna) 및 GPT-6 공통 prompting 지침을 확인해 모델을 유지하고 좁은 지침 변경 후 실제 표본으로 검증했다. 기본 추론 설정 선택은 여전히 별도다.

## 2차 실패 조사: 보관 결과와 편집기 경로의 구분

- `live-browser-4okvs9/`, `live-browser-final-run.log`: 실제 모델 8회 모두 completed이지만 마지막 화면 시각 assertion 실패. 전체 인수는 실패로 보존한다.
- 처음에는 저장 ETA가 자동 계산값으로 변경됐다고 추정했으나 코드와 독립 브라우저 검증으로 정정했다. `MapView.getAppliedCopilotContext()`는 읽기 전용 보관 결과가 열려 있으면 **화면에 보이는 보관 결과의 입력**을 반환한다. 뒤에 보존된 편집기 입력을 반환하는 것이 아니다. 실패 당시에는 새 경로의 고도 비교 결과가 열려 있었으므로 그 경로의 거리/TAS ETA가 전달된 것이 맞다.
- `copilot-personal`에 자동 계산값과 의도적으로 다른 수동 ETA를 넣은 회귀를 추가했다. 저장 경로 불러오기 직후 → 다른 보관 결과 열기 → 닫기의 세 상태에서 실제 `/api/ai/contexts` 요청과 채팅 참조를 대조한다. 중간에는 보관 결과 ETA, 전후에는 동일한 저장 ETA·전체 입력이며 기상 조회/저장 변경도 없다.
- 네 화면/엔진 **4 pass**, retries=0, 기존 개발 서버 재사용. `saved-eta-regression.log`. 제품 ETA 상태를 변경하는 수정은 하지 않았다. 최초 테스트 작성 중 빈 질문의 전송 버튼을 활성으로 기대한 대기 조건 오류는 응답 말풍선 수 검사로 수정했다.
- 유료 연속 테스트도 보관 결과의 ETA가 저장 ETA와 다름을 검사하고, 보관 결과를 명시적으로 닫은 후 저장 ETA와 geometry를 검증하도록 바로잡았다. 기대 시각을 자동값으로 완화하거나 ETA 검사를 제거하지 않았다.

## 남은 인수

- 실제 보관 KIM 단면·다중 시각/경로 동등성, 운영 publication 갱신과 브라우저 갱신, 모바일 실물 키보드 및 운영 계정/예산/보관 정책은 남아 있다. 공항 상세/기상 레이어 action은 [후속 구현·검증](2026-09-24-ui-actions.md)에서 진행한다.
- 이 8턴 평가 당시 개발 서버는 이전 프로세스 그대로였다. 후속 화면 action 검증 뒤 [일반 로컬 서버 적용](2026-09-24-ui-actions.md)을 완료했다. 운영 배포는 수행하지 않았다.
