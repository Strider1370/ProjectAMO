# 화면·대화 맥락 충돌 확인 (4A)

## 구현 결정

- 공항·경로의 이전 질문 기준과 전송 시점 화면 입력을 비교한다. 경로 이름만이 아니라 전체 적용 입력의 SHA-256 revision을 사용하므로 geometry, 고도, ETD/ETA, 경유점 시간, NWP 선택 변경도 감지한다. 참조 TTL 갱신으로 ID만 달라진 경우는 다른 경로로 보지 않는다.
- 충돌 시 모델에게 선택을 맡기지 않고 전송 전에 사용자에게 현재 기준 / 이전 기준 / 연결 없이를 제시한다. 취소하면 질문 초안·기존 경로를 유지한다. 선택 전에는 경로 등록·유료 모델 요청을 하지 않는다.
- 이전 기준은 마지막 요청의 브라우저 입력 snapshot을 복제·보존하고 필요 시 재등록한다. 기존 경로 조건을 유지한다는 뜻이며 최신 기상 자료를 재조회하지 않는다는 뜻은 아니다. 보관 결과 동일 보기와 구분한다.
- 다른 기준을 선택하면 새 서버 conversation ID를 만든다. 이전 슬롯·브리핑 참조·대화 문장을 모델에 넘기지 않는 경계다. 화면의 대화 내역과 기존 결과 카드는 유지하며 각 질문에 기준 및 새 대화 여부를 표시한다. 이전 대화의 대명사/생략 조건은 새 대화로 자동 이전되지 않는다.
- ‘현재 화면 연결’ 해제도 이전의 연결된 경로가 서버에 남아 조용히 사용되지 않도록 같은 새 대화 경계를 적용한다. 다시 연결해도 이 규칙을 따른다. 첫 질문에는 불필요한 선택을 요구하지 않는다.
- 현재 기준 확인 버튼을 누를 때 화면을 다시 대조한다. 선택 중 다시 바뀌었으면 최신 선택지를 표시하고 다시 확인할 때까지 보내지 않는다. 이전 기준을 선택하면 화면 변경과 무관하게 이전 snapshot을 사용한다.
- 진행 중인 요청의 재시도는 원래 request ID/메시지/시간대/맥락을 그대로 보낸다. 계정 변경·새 대화 시 보존한 snapshot과 선택 상태를 초기화한다.

## 검증 범위

단위 검증은 snapshot 불변성, 전체 조건 변경, 삭제/해제/공항 변경, TTL ID 변화 무시 및 기관 경로 오류를 다룬다. 브라우저 검증은 기존 화면으로 만든 김포–김해 경로에서 김포–제주 보관 결과 보기로 바꿔 세 가지 선택의 request/context/conversation ID를 대조한다. 기상 응답과 인증은 fixture이며 실제 공급자 정확도 검증을 대신하지 않는다.

### 실행 기록

- 순수 맥락/등록/창 모델 단위 검증 **5/5 pass**. 서버 conversation 저장소에도 같은 owner의 새 대화가 이전 문장/슬롯/참조를 물려받지 않는 회귀를 추가했다. AI backend subset은 **83/83 pass** (`context-choice-ai-tests-verified.log`).
- `npm run check`: backend **1,348 pass / 1 skip**, frontend **1,703 pass**, shared14/launcher7/nginx4 및 build 성공. 기존 큰 chunk 경고만 남음 (`context-choice-full-check.log`).
- 최초 맥락 선택 3가지 × 4개 뷰포트/엔진은 **12/12 pass**. 이후 iPad 캡처에서 선택 버튼이 입력창 아래로 밀리는 사용성 문제를 발견해 선택 중 대화 내역/입력창을 잠시 접고 질문 기준을 먼저 보여주도록 수정했다. 선택 취소 시 초점 복원을 다음 렌더에 맞췄다. 동작은 앞선 실행과 합산하지 않고 새로 검증한다.
- 데스크톱과 모바일 캡처를 직접 확인했다. 좁은 기본 플로팅 창에서는 선택 영역 자체를 스크롤할 수 있고, 모바일 전체 시트에서는 선택 4개가 보인다. 기존 대화는 선택 종료 뒤 다시 표시한다.

- 최종 `copilot-chat|copilot-route` 브라우저 회귀 **48/48 pass**, retries=0. desktop / iPad Chromium / mobile / iPad WebKit. 세 선택·취소·접기·화면 재변경 후 재확인·연결 해제의 새 conversation 경계와 기존 등록/고도 표/보관 결과 보기 회귀를 포함한다. console 기록 48개에 `pageerror` 없음. `context-choice-browser-verified.log`.
- 현재 로컬 서버 재사용 실행이며 `CONTRACT_DATA_PATH`를 실제 서버의 `backend/data`로 명시했다. 새 managed 서버의 전체 계약 실행이나 실제 공급자 설명 정확도 검증을 대신하지 않는다. 앱 `/api/ai/status`는 enabled/ready 모두 true다. KIM 수집 설정·MCP 별도 프로세스·공급자 설정은 변경하지 않았다.

## 남은 전체 범위

이 변경은 4A의 맥락 충돌 작업이다. 4A 다중 실경로·시간 일치, 4B 실제 모델 비교 설명/비용, 4C 자연어 입력 채움·초안 덮어쓰기 확인과 실자료 단면 브라우저 대조, 5A/5B 서버 경로 생성, 6A/6B 개인 기능, 7 통합 인수는 미완료다. 모델 기본값·API 키·수집 설정·운영 배포는 변경하지 않는다.
