# 1B / 2: 브리핑·상세와 실제 Codex MCP 검증

검증일: 2026-09-23 KST. 목표: **같은 WSL의 Codex CLI에서 ProjectAMO 도구로 질문하고 답을 받을 수 있는 상태**. 주 담당이 직접 구현·검증했다. 앱 자체 채팅창이나 전체 제품 완료를 의미하지 않는다.

## 구현 결과

- `briefing-service.js`로 기존 REST 검증·자료 취합·`composeBriefing` 호출을 추출했다. `/api/route-briefing`의 JSON 형식과 400/500 의미는 유지한다. 기상 비교 계산을 새로 쓰지 않았다.
- 기존 저장 김포–제주 경로에서 개인 저장 ID·이름을 제외한 검증 fixture를 만들었다. geometry 38좌표, routeModel v1, Y711 8구간, SID/STAR/IAP, 안정적인 마커 ID를 보존했다. 현재 navdata의 같은 구간 ID/FIX와 대조하는 테스트를 둔다.
- 요청은 공항과 시간창 또는 서버에 등록된 고정 fixture ID/내부 context 참조만 받는다. 임의 경로·파일·고도 변경을 모델에게 허용하지 않는다. 브라우저 context 등록은 아직 4A 작업이다.
- 결과는 세션 소유 범위·실제 시계 TTL·항목/바이트 한도를 가진 메모리 저장소에 보관한다. 상세는 보관 결과를 읽으며 자료를 다시 조회하지 않는다. 결과 해시·원래 기준 시각·source 식별자가 유지된다.
- 공식 SDK 1.30.0의 Streamable HTTP로 공항·브리핑·상세 세 도구를 연결했다. 별도 loopback entry이며 앱 서버·수집·DB를 띄우지 않는다. 모델 추론은 Codex의 기존 ChatGPT 로그인 인증을 사용했다.
- Origin/Host 검사, 본문/출력/페이지 상한, 세션·호출 빈도 제한, worker의 실행·대기 시간 제한을 둔다. 계산 1개 + 대기 3개로 모델의 병렬 조회를 처리한다.
- Codex 전역 설정은 변경하지 않았다. 실행별 `-c mcp_servers.projectamo.url=...`로만 연결했다. 공개 서버·nginx·OAuth·배포도 변경하지 않았다.

## 실제 CLI 인수

설치된 `codex-cli 0.155.1`의 `exec --json`으로 검증했다. 별도 빈 작업 디렉터리, `--ignore-user-config`, `--ignore-rules`, `--ephemeral`, read-only sandbox, shell/multi-agent 기능 비활성화, web search 비활성화 상태다. 모델은 CLI 기본값이며 별도 모델 override를 하지 않았다. 테스트용 CLI는 구현을 위임받은 서브에이전트가 아니라 **MCP 클라이언트**다.

| 질문 / 확인 | 실제 결과 |
| --- | --- |
| 김포·제주 2026-09-20 17:00~17:32:28.400 UTC 기상 | `get_airport_weather` 성공. 16:00 METAR, 11:00 발행 TAF, 전체 요청 구간 coverage 확인 |
| 준비된 김포–제주 경로 브리핑 | `get_route_briefing` 성공. 31,000 ft·325.62 NM·고정 시각과 partial 상태 표시 |
| 방금 결과의 경고와 출처 | `get_briefing_detail` 2회 성공. 동일 briefingRef·resultHash·effectiveNow 확인 |
| 서울 공항 조회 | 실제 도구가 `AMBIGUOUS_AIRPORT`, Codex가 인천/김포 선택 필요를 설명 |
| 제주 9월 25일 예보 | 실제 도구가 `TAF_OUTSIDE_WINDOW`, coverage none. Codex가 미래 날씨를 추정하지 않음 |
| 준비된 경로를 FL200으로 변경 | 고정 fixture가 31,000 ft라는 이유로 미지원 설명. 허용되지 않은 고도 인자를 생성하지 않음 |

정상 질문 최종 실행은 **도구 4회, 재시도 0회**. 결과의 METAR 관측 시각·바람·시정·QNH를 원본과 자동 대조했고, 보관 결과의 snapshot 해시들을 저장 파일의 SHA-256과 대조했다. 셸·웹 호출 이벤트가 없음을 검사했다. 한국어 최종 설명도 읽어 관측/예보 시각과 누락 상태를 대조했다.

첫 실행에서는 동시 요청에 `BUSY` 1회, 모델의 상세 `limit:100`에 입력 오류 1회가 발생했다. bounded queue를 추가하고 상세의 1~20개 제한을 도구 설명에도 명시한 뒤 정상 시나리오를 재실행했다. `structuredContent`와 text에 같은 전체 JSON을 중복 전송하던 부분은 짧은 text 안내 + 구조화 결과로 바꾸고 실제 Codex에서 값이 전달되는지 확인했다.

## 시간·자료의 제한

- fixture 기준: **2026-09-20T16:30:00.000Z**, 비행 시간 **17:00:00~17:32:28.400Z**. KST로는 **9월 21일 02:00~02:32:28.400**이다. 원래 저장 경로는 9월 10일 자료이며 duration을 유지해 시간을 조정한 사실을 provenance에 기록했다.
- 공항은 KMA 저장 snapshot, navdata publication은 **2026-06-25**. 자료 수집 상태가 unknown이면 빈 경보 목록을 ‘경보 없음’으로 설명하지 않는다.
- 이 고정 경로 결과에 **NWP 단면·AIP 검증·상시 공역**은 미제공이다. mutable root에서 새 격자를 읽어 과거 결과와 혼합하지 않았다. 원본 계산의 `crossSectionAvailable` 기본값에 기대지 않고 `available:false`를 명시했다. 기존 별도 KIM 직선 진단은 이 경로의 모델 기상으로 사용하지 않는다.
- 위험기상 snapshot의 존재만으로 전체 수집 범위가 완전함을 입증할 수 없어 `SOURCE_COVERAGE_UNVERIFIED`를 반환한다. 결과는 ‘부분 제공’이며 안전·고도 추천을 하지 않는다.
- 기존 hazard 계산기는 발효 종료와 출발 시각이 같은 AIRMET을 `matched`로 반환한다. 계산을 변경하지 않고 양쪽 시각을 보존했고 Codex도 이 경계를 설명했다. TAF의 반열린 시간창 규칙과 같은 규칙이라고 주장하지 않는다.
- 일반 실행에서 매번 과거 자료가 확보되는 것은 아니다. fixture의 기상 파일은 로컬 저장 자료이며, 현재 검증의 hash manifest를 별도 기록했다. 재실행 때 자료가 바뀌면 새 출처/자료 상태를 확인해야 한다.

## 토큰 실측

아래는 Codex가 보고한 **한 실행의 여러 모델 응답에 걸친 누적 사용량**이다. cache는 입력에 포함된 부분집합이며 더해서 계산하지 않는다.

| 실행 | 입력 토큰 | 그중 cached 입력 | 출력 토큰 |
| --- | ---: | ---: | ---: |
| 첫 정상 시나리오: 중복 결과·재시도 포함 | 146,724 | 117,760 | 1,153 |
| 보완 후 같은 정상 질문: 4회 도구 호출 | 80,202 | 57,216 | 981 |
| 별도 예외 질문: 2회 도구 호출 | 49,449 | 37,248 | 459 |

이는 **앱 자체 챗봇의 질문당 토큰/비용이 아니다**. Codex의 기본 지시문·도구 정의·이전 도구 결과를 포함한 반복 입력이 들어간다. 비캐시 입력 차액만으로 실제 구독 청구액도 계산할 수 없다. 표는 재현한 실행의 관측치이고 반복 평균이나 일반 절감률을 보장하지 않는다. 공급자 API 단가에 따른 비용과 첫/10번째 대화 사용량은 3A/3B에서 별도 측정한다. 현재도 결과·근거를 매번 전부 다시 전달하면 입력이 커지므로 자체 runner에서는 관련 digest·참조만 유지해야 한다.

| 명령 / 증거 | 결과 |
| --- | --- |
| `node --test backend/test/ai-*.test.js` | **37 pass / 0 fail** (기존 1A 25개 + 1B/MCP 12개) |
| `npm run test:backend` | **1,302 pass / 1 skip / 0 fail**, 전체 1,303개 |
| `npm run build` | 성공, 기존 bundle 크기 경고 |
| 실제 SDK 클라이언트 | initialize/list/call, strict 인자·없는 도구, Host/Origin·16KiB·요청/세션 상한, 세션 만료·타 세션 참조 차단 |
| worker | 병렬 요청 순차 처리·대기 한도, 시작/계산 deadline·취소·종료 |
| 저장 결과 | 실시간 TTL·소유권·복제·항목/바이트 한도, 페이지 cursor·너무 큰 항목·동일 hash/시각 |
| REST 회귀 | 기존 route-briefing integration 포함 전체 backend 통과; 원래 composer와 공유 서비스 결과 일치 |
| `git diff --check` | 통과 |

backend skip 1개는 기존 실측 radar QCD HDF5 fixture 부재다. UI 코드를 변경하지 않아 새 브라우저 계약 검증은 수행하지 않았다. 1A의 frontend 1,695 pass 기록과 구분한다.

`npm audit --prefix backend`는 moderate 6 / high 2를 보고했다. 8개 항목의 해당 설치 경로/버전이 변경 전 lockfile에도 존재함을 확인했다. 이번 SDK 자체의 advisory는 없었고 관련 없는 자동 dependency 업데이트는 하지 않았다. 일반 운영 공개 전 기존 취약점 정리는 별도 필요하다.
