## 발견과 보완

1. 최초 반복 `luna-final-high-1/2.jsonl`: 모두 응답은 완료했지만, 브리핑 digest에 계획고도의 격자 수치가 없어 착빙/난류를 미제공으로 설명했다. `get_route_briefing`에 기존 `executeAltitudeComparison`의 해당 고도 한 행을 추가했다. 같은 captured 자료·프로파일만 사용하고 격자/좌표를 프롬프트로 보내지 않는다. 보관 포인터 삭제 후 고도 비교와 같은 행인지 회귀로 대조한다.
2. KIM run ID `2026091006`의 UTC 초기화 시각과 사용자 KST를 모델이 직접 해석하던 부분을 `modelContext`의 명시적 `initializedAtDisplay`로 보완했다. 원래 run ID/UTC payload는 보존한다. 날짜 오류·UTC/KST 단위 회귀를 추가했다.
3. 다음 반복 `high-3/4`: 수치/초기화 시각은 개선됐지만 실제 긴 `enroute` 상세에서 `DETAIL_ITEM_TOO_LARGE`가 발생했다. 전체 절차 기하를 한 항목으로 반환하던 것을 요약·항로 구간·절차 구간별 페이지로 분리했다. 좌표는 제외하고 모든 구간/다음 cursor를 유지했다. Node9개 및 실제 MCP의34항목/2페이지 조회가 통과했다.
4. high-2/4에서 한국어 문장에 `覆盖`가 섞였다. [GPT-6 공통 작성 지침](https://developers.openai.com/api/docs/guides/latest-model#prompting-best-practices)을 참고해 coverage를 ‘자료 범위’로 표현하도록 좁게 명시했다. 모델 변경·후처리로 사실 삭제·추가 유료 자동 재시도는 하지 않았다.
5. high-5/6의 5턴은 값·날짜·자료 누락을 맞게 설명했지만 **조회 기준20:46을 자료 수집시각으로 잘못 호칭**했다. high-6의2턴에는 끝에 불필요한 `}`도 남았다. 이를 단순 completed 성공으로 숨기지 않는다. 기준/계산시각과 개별 source.fetchedAt을 구분하고 answer 문자열에 구조 기호를 붙이지 않도록 지침을 보완했다. 해당 흐름의 후속 1~5턴 반복 결과는 아래에 추가한다.
