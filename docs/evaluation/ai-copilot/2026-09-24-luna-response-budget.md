# Luna의 답변 호출 확보와 경로 TAF 범위 정리

2026-09-24 KST. 기본 모델/추론 설정을 변경하지 않았다. 모든 유료 표본은 별도 평가 프로세스의 `gpt-6-luna / high / max_output_tokens=3200`이며 공개 기상 자료의 기존 frozen snapshot을 사용한다. 실제 최신 날씨나 개인 계정 자료가 아니다.

## 원인과 변경

1. 공항 질문에 이미 적용하던 TAF 변화군 시간 범위 정리가 경로 브리핑에는 적용되지 않았다. `get_route_briefing`과 `get_my_saved_route(current_briefing)`에도 같은 model-only projection을 적용했다. 비행시간 이후 변화와 이미 끝난 임시/확률 변화만 제외한다. 이전 FM/BECMG·시각 불명 그룹, 수치·coverage·누락은 유지하며 제외 인덱스/사유를 남긴다. UI 원본·보관 결과는 바꾸지 않는다.
2. projection만 적용한 실제 3턴 평가에서 경로 생성→브리핑까지 성공한 뒤, 세 번째 모델 호출이 상세 도구를 추가 요청해 `MODEL_CALL_LIMIT`로 끝났다. `max_output_tokens` 소진이 아니었다.
3. 기존 총 3회 한도 중 마지막 모델 호출은 답변 전용으로 예약한다. 그 호출에 추가 도구를 노출하지 않고, 확보한 사실과 미확인 부분을 짧게 설명하도록 지시한다. 호출당 3200토큰, 도구 4회, 45초 한도를 늘리거나 자동 유료 재시도하지 않는다. 모델이 마지막 단계에서 도구를 임의 생성해도 서버는 실행하지 않고 partial로 반환한다.
4. 정상 경로 생성→브리핑→설명은 여전히 3회에 가능하다. 인자 오류 수정 등으로 앞선 호출을 소진하면 추가 조회는 다음 질문이 필요하며 성공한 것으로 꾸미지 않는다. 상세 요청은 앞선 호출에서 처리할 수 있고 마지막 호출에서는 이미 얻은 결과만 설명한다.

OpenAI Docs 스킬로 [Luna 추론 설정](https://developers.openai.com/api/docs/models/gpt-6-luna)과 [추론·출력 한도](https://developers.openai.com/api/docs/guides/reasoning)를 확인했다. 추론 토큰도 출력 한도를 사용하므로 high 상향과 답변 예산은 함께 평가한다. 마지막 답변 단계 예약은 공식 권장 수치가 아니라 이 앱의 3회 제한에서 발견한 실패에 대한 구현 판단이다. 공식 GPT-6 공통 prompting 지침의 명시적인 응답 범위 원칙을 참고했지만 Astra로 모델을 바꾸지 않았다.

## 같은 3개 질문의 전후 표본

질문: 부족 조건 확인 → 김포/제주 IFR FL310·TAS450·21:03 KST 경로/브리핑 → FL310/FL330 비교. 각 실행은 새 대화이며 같은 frozen 시각과 자료를 사용했다.

| 평가 | 응답 완료 | 입력(캐시 포함) | 캐시 입력 | 출력(추론 포함) | 합계 지연 | 표준 비용 추정 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| TAF projection만 | 2/3 | 33,579 | 2,935 | 1,561 | 35.4초 | $0.00387 |
| 마지막 답변 단계 예약 추가 | 3/3 | 31,892 | 8,796 | 2,843 | 49.9초 | $0.00382 |

각각 1회 표본이며 캐시·도구 선택·답변 길이가 달라 전체 효율이나 성공률 개선으로 일반화하지 않는다. 후자는 실제 답변을 생성해 출력/지연이 늘었다. 비용은 [2026-09-24 Luna 표준 단가](https://developers.openai.com/api/docs/models/gpt-6-luna)의 입력 $0.10, 캐시 입력 $0.01, 출력 $0.50/1M 기준으로 실제 청구액이 아니다. 추론을 출력에 중복 가산하지 않았다.

후속 표본의 출발/도착 날짜·시각, TAF 유효기간, 관측 수치, 경로 기상 누락은 원 도구와 대조했다. 고도 비교의 `TIMELINE_EMPTY` 설명도 도구의 issue에 있다. 반면 부족 입력 응답의 “김포에서 제주로 설정했습니다”는 조건 접수와 실제 화면 설정을 혼동할 여지가 있어 표현 품질 과제로 남는다. 자동 평가의 completed만으로 의미 정확성을 통과 처리하지 않는다.
