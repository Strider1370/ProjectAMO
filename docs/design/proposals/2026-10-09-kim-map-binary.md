# KIM 지도 이진 형식과 정적 제공

작성 2026-10-09. 상태: 구현(로컬 시험 완료, 미배포).

## 문제

확대 영역(841×529, 44만 칸) 지도 한 장을 요청할 때마다 백엔드가 격자 읽기(0.2~0.3초) → 착빙·구름 계산(0.6~0.8초) →
지면 아래 표시(0.3초) → JSON 변환·압축(0.06~0.2초)을 했다(운영 측정). 백엔드는 요청을 하나씩 처리하므로 고도를 바꿔
레이어 다섯 개를 받으면 4~7초가 걸렸다.

## 레퍼런스

- 값을 정수로 담고 배율을 곁에 둔다: Mapbox webgl-wind, GeoServer PNG-WIND, deck.gl-particle(PNG 채널에 u·v).
- 회차마다 바뀌지 않는 파일을 미리 만들어 정적 저장소에서 브라우저가 직접 받는다: Vane(Zarr), CarbonPlan zarr-layer.
- 색은 브라우저가 칠한다(MapTiler 날씨).

## 결정

1. 형식 `KMB1`(shared/kim-map-binary.js): 머리말 JSON(격자·시각·통계 등) + 칸 수만큼의 배열을 정수(i16/i32, 필요하면 f64)로.
   정수 배열은 행 방향 차분 + 바이트 섞기를 거쳐 gzip(배열마다 더 작은 쪽을 고른다). 브라우저는 풀어서 JSON 응답과
   **똑같은 객체**를 만든다(그리기 코드는 그대로). 실측 압축 크기: 기온 737→317 KB, 바람 1,416→738 KB, 구름 1,089→624 KB,
   GKTG 575→316 KB, 착빙 213→130 KB.
2. 저장·제공: 회차 폴더 `derived/map-bin/<응답 이름>/<고도>/hfNNN.bin.gz`. 주소 `/data/<영역 폴더>/runs/...`로
   nginx가 백엔드 없이 내보낸다. 없으면 nginx `try_files`가 백엔드로 넘기고 백엔드가 만들어 저장한다.
3. 미리 만들기: 확대 회차 시각별 계산(GKTG → 권계면 → 지도 파일, 별도 계산 프로세스)에서 착빙·구름 전 고도와
   기온·바람 700 hPa를 만든다. 시각당 이 PC 약 10초(운영 25~30초 예상), 디스크 시각당 약 16 MB(회차당 약 0.55 GB).
4. 착빙 계산 개선: 칸마다 객체를 만들던 반복을 판정 조건 밖 칸은 바로 0으로 두게 바꿨다(결과 54장 동일, 장당 207→33 ms).
5. JSON API는 그대로 둔다(판 고정 요청·이진 파일 실패 시). 응답은 사용자 공용 메모리 캐시(64 MB).

## 로컬 측정(이 PC, 00 UTC +1h, 700 hPa, 다섯 레이어 동시)

| 경로 | 다섯 개 다 받기 |
|---|---:|
| JSON API 처음 | 1,303 ms |
| JSON API 메모리 캐시 | 221 ms |
| 이진 파일(GKTG만 요청 때 생성) | 372 ms |
| 이진 파일 저장본 | 105 ms |

운영에서는 저장본을 nginx가 보내므로 백엔드 처리 시간이 없다.

## 남은 일

- 멀리서 볼 때 줄인 해상도(0.25°) 파일.
- nginx 예시 설정에 `map-bin` 캐시 머리글(immutable) 추가(지금은 nginx 기본 ETag 재검증).
