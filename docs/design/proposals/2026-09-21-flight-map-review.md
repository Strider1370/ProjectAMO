# 내 지도 4단계·스타일 반영 독립 검증

클로드의 완료 기록을 실제 코드·명세·실행 결과와 대조했다. 기존 전체 검사와 실제 두 KMZ를 포함한 데스크톱 계약 17개는 통과했지만, 별도 시나리오에서 아래 네 결함을 재현했다. 이 문서는 그 검증과 후속 수정 기록이다.

## 발견한 문제와 수정

| 문제 | 재현 조건과 영향 | 수정 |
| --- | --- | --- |
| 편집 스타일이 원본 스타일로 표시됨 | 일반 KML → 개인 사본 → 색·굵기 변경 → KML 내보내기·재가져오기. 저장된 스타일은 맞지만 지도에서는 보존용 `source.properties`를 우선해 원본 색으로 돌아감 | 지도 표시가 정규화된 `item.style`과 `item.label`을 사용. 일반 KML의 이름표 숨김도 가져올 때 정규화. 원본 source는 변경하지 않음 |
| 그룹 없는 항목의 순서 손실 | 그룹 a/b/c 생성 → 그룹 없음 앞에 a 배치 → a 삭제. 정렬 키에 빈자리가 생기면 내보내기·평탄화에서 그룹 없음 위치가 바뀜. 보기·편집 목록에서도 항상 맨 뒤에 표시 | `ungroupedOrder`를 배열 index가 아닌 그룹과 공유하는 정렬 키로 해석. 평탄화 시 가상 블록 자리도 확보. 보기·편집·내보내기에 같은 상대 순서 적용 |
| 수정 메모가 표준 KML에 반영되지 않음 | 개인 사본에서 메모 수정 후 내보내기. 앱 예약 필드에만 수정 메모가 있고 표준 description에는 원문이 남아 다른 KML 프로그램에서 이전 메모를 보게 됨 | 변경한 메모와 빈 메모를 표준 description에 기록. 수정하지 않은 원문 HTML은 그대로 내보내고 source도 독립 보존 |
| 부분 내보내기 집계 불일치 | 3항목 지도에서 공역 폴더 1항목을 선택하면 대상 1개인데 그대로 포함은 3개로 표시 | 내보내기와 동일한 범위 선택 함수를 사용해 대상·포함·변환·제외·경고 모두 다시 계산 |

**이전 기록 정정:** 구현 계획의 4단계 기록에서 예약 marker에 범위 기준 index를 기록한다고 설명했으나, 폴더 order를 그대로 보존하는 한 marker도 원래의 정렬 키를 유지해야 한다. XML 삽입 위치만 남은 루트 기준으로 계산한다. 그룹 삭제 후 생긴 빈자리와 부분 내보내기가 함께 성립해야 한다.

메모 회귀 테스트를 추가하면서 Node의 XML DOM 구현에는 `body`가 없고 Document의 textContent가 비어 있는 차이도 확인했다. HTML 설명 추출에 documentElement fallback을 추가해 실제 브라우저와 같은 설명 텍스트를 검증하도록 했다.

## 검증

- 수정 전: `npm run check` 통과, 실제 두 KMZ를 포함한 데스크톱 계약 17개 통과. 녹색 테스트 외의 경로에서 위 네 문제를 독립 재현했다.
- 수정 후: 관련 도메인 단위 테스트 139개 통과. 새 회귀 테스트는 스타일의 실제 overlay 속성, 표준 description과 원본 source, 명령으로 만든 순서 공백, 범위별 집계·경고를 확인한다.
- 수정 후 전체 `npm run check` 통과: 프런트 1,659개, 백엔드 1,220개 통과·1개 건너뜀, 기타 offline 검사 및 프런트 빌드 성공.
- `MY_MAP_REAL_FILES=1 npm run dev:contract -- --grep 'my-map' --project desktop --retries 0`: 기존 17개 모두 통과. 실제 두 KMZ, 강화한 부분 내보내기 집계, 지도 스타일·배경 교체, 계정 이전을 포함한다. 새 그룹 순서 테스트 1개는 이름 옆 개수까지 읽는 선택자 오류로 실패했다. 화면의 순서는 기대와 같았으며 제품 결함이 아니었다.
- 이름 span으로 선택자를 좁힌 후 `npm run dev:contract -- --grep 'my-map 그룹 삭제 뒤' --project desktop --retries 0`: 1개 통과. 최종 18개 시나리오는 전체 실행 17개와 수정 후 단독 실행 1개로 검증했다. 수정 후 전체 18개를 다시 실행한 것으로 기록하지 않는다.
- 로그·독립 재현·캡처: ignored `artifacts/flight-map-review/`. 초기 재현 보고서 `report.md`, 단위 `fix-unit.txt`, 전체 검사 `fix-check.txt`, 브라우저 `fix-browser.txt` 및 `fix-group-browser.txt`. 첫 그룹 테스트 실패 근거는 `group-order-first-run/`에 보존했다.

## 범위와 남은 일

- 기관 공유, 작성 전 범위, 모바일·반응형·실제 iPad Safari 검증은 완료 판정하지 않는다. [재개 문서](2026-09-20-flight-map-resume.md)의 「4단계 이후 남은 일」을 따른다.
- 이전본의 compound 서버 형식 문제는 최신 코드가 이미 Multi*로 수정했다. 실제 이전 결과를 backend validator에 넣어 통과를 확인했으며 남은 결함으로 중복 보고하지 않는다.
- geometry가 없는 항목은 그림으로 제외되지만 사본 및 메타데이터용 Placemark에는 보존된다. 미리보기의 '제외'가 자료 삭제를 의미하지 않도록 안내 의미를 추후 정리할 여지가 있다.
- 커밋·배포·의존성 변경은 하지 않았다.

## 추가 작성 조작 검증 — 2026-09-21

현재 워킹트리에는 위 네 결함의 수정과 [기관 공유 화면 통합](2026-09-21-flight-map-sharing-progress.md)까지 들어 있다. 이 상태에서 명세의 작성 조작을 브라우저로 추가 점검했다. 아래는 최초 검증 당시 발견한 세 문제다. **후속 수정과 재검증은 [작성·그룹 보완 기록](2026-09-21-flight-map-authoring-progress.md)에 있으며 세 문제 모두 해결됐다.** 4단계 파일 저장·왕복 수정과 구분한다.

| 우선순위 | 재현 및 영향 | 원인·위치 |
| --- | --- | --- |
| P2 | 면 도구로 세 지점을 찍고 첫 점을 다시 눌러도 완성 항목이 생기지 않는다. Enter로 완성하는 경로는 동작한다. | `lib/mapEditorInteraction.js`의 click이 항상 addDraftPoint를 호출하고, `useMyMapEditor.js`에서도 첫 점을 통한 완료를 판별하지 않는다. UX 명세 3절의 첫 점 클릭 완료 미충족. |
| P2 | 같은 그룹의 셋째 항목을 첫째 앞에 드롭해도 첫째·둘째·셋째로 돌아간다. 되돌리기를 한 번 누르면 오히려 셋째·첫째·둘째가 된다. | `MapEditorTree.jsx`의 항목 onDrop이 부모 그룹 onDrop으로 전파되어 위치 지정 이동 후 맨 뒤 이동이 다시 실행된다. 드롭 한 번·되돌리기 한 단계 계약도 깨진다. |
| P2 | 검색 중 정렬 금지 안내가 나오지만 그룹 순서 메뉴는 계속 활성화된다. 실제로 A를 그룹 없음 앞으로 이동하고 검색을 지우면 전체 순서가 바뀌어 있다. | `MapEditorTree.jsx`는 draggable만 제한하고 순서 select 및 dropItems에는 query 방어가 없다. UX 명세 5절의 검색 중 정렬 금지 미충족. |

추가 계약은 `frontend/verification/contracts/my-map-authoring.spec.mjs`에 있다. 제품 코드는 최초 추가 검증에서는 변경하지 않았고, 후속 구현에서 수정했다. 기존 검사 통과만으로 작성 전 범위의 완료를 판단하지 않는다.

재검증 결과:

- 현재 코드의 `npm run check` 통과: 프런트 1,666개, 백엔드 1,227개 통과·1개 건너뜀, 기타 offline 검사 및 빌드 성공. `review-current-check.txt`.
- 실제 두 KMZ를 포함해 기존 데스크톱 계약 20개 모두 통과. 추가 작성 계약 3개는 첫 실행에서 실패했으며, 그중 기하 편집 계약은 시험 코드가 undo/redo 후 목록 복귀와 IndexedDB 복구 레코드의 중첩 구조를 놓친 문제여서 시험만 수정했다. 제품 결함으로 집계하지 않는다. `review-current-desktop.txt`, `review-current-authoring-confirm.txt`.
- 항목 삽입·한 번 되돌리기·검색 중 실제 순서 변경은 강화한 브라우저 단언으로 재현했다. 면 첫 점 완료 실패도 별도 계약으로 재현했다. 최초 캡처와 후속 캡처는 `authoring-current-initial/`, `authoring-confirm/`에 보존했다.
- 시험 코드를 고친 뒤 기하 편집 계약 1개 통과: Enter로 면 완성, 전체 이동 완료와 미리보기 격리, undo/redo, 중간점 추가·꼭짓점 삭제·최소 꼭짓점 보호, 취소 복구, 원 완성·반경 3.5NM 저장·중심 이동 후 반경 유지까지 확인했다. `review-current-geometry-final.txt`. 따라서 최종 시나리오별 결과는 기존 20개와 새 기하 1개 통과, 새 그룹·첫 점 완료 2개 실패(위 제품 결함 3건)다. 전체 23개를 시험 수정 후 다시 돌린 것으로 기록하지 않는다.
- 실제 KMZ 왕복 검사를 개수 비교에서 각 항목의 전체 `source` 값과 기하의 깊은 동등성 비교로 보강했다. 맥케이 2,135항목·공역정보 754항목의 원문·가변 메타데이터·좌표가 그대로 보존되며 코덱 13개 모두 통과. `review-current-metadata.txt`.
- 초기 독립 재현 스크립트도 다시 실행하여 스타일·메모·순서 수정과 /draw 복합 도형의 서버 형식 통과를 확인했다. `review-current-repro.txt`.
- 위 로그 경로는 모두 ignored `artifacts/flight-map-review/` 아래다. 모바일·실제 iPad Safari·작성의 모든 이탈 경로까지 검증한 것은 아니다.
