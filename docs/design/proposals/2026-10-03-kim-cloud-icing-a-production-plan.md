# KIM 구름·착빙 A안 — 프로젝트 적용 계획

작성·최종 결정 반영: 2026-10-03. 상태: **로컬 제품 구현 완료·테스트/빌드 통과. AWS 미배포.**

최종 결과와 검증 범위는 [A안 구현 보고](2026-10-03-kim-cloud-icing-a-implementation.md)를 참조한다.

연결성 재검토: 2026-10-03. 실제 import·호출·표시 조건을 대조해 하단 범례, 기관 발표 진입 경로, 난류 중첩, 지도 배경 입력과 mockup 의존성을 보완했다. 아래 코드상 확인과 적용 요구사항은 실행 검증 완료를 뜻하지 않는다.

승인 기준: 사용자가 [실제 앱 기반 지도 UI](2026-10-03-kim-cloud-icing-map-control-review.md)의 방향을 승인했다. 기상 패널의 `구름·착빙` 타일 하나와 기존 좌측 하단 `[범례] [구름] [착빙]` 한 줄을 사용한다. 등온선 버튼·메뉴·지도 −10°C 옵션은 제거하고, 0°C 실선·−20°C 파선 및 라벨을 모두 빨간색 `#c0291f`로 고정 표시한다. 이 문서가 후속 제품 구현의 정본이다.

## 1. 결정과 적용 후 화면

착빙 표현 기준은 [실제 저장 KIM 자료의 A안 HTML](../mockups/cloud-icing-variants.html), 지도 조작 기준은 [승인된 실제 App 기반 시안](../../../artifacts/cloud-icing-native-ui/index.html)이다. **기존 회색 구름 위에 등급별 착빙 색 면과 동일한 흰 점무늬를 표시하고, 윤곽선은 착빙 전체 최외각에만 그린다.** 지도·연직단면도·비행 전 브리핑·범례에 같은 표현을 적용한다.

| 항목 | 적용 후 |
| --- | --- |
| 진입·조작 | 기상 패널의 `구름·착빙` 타일 유지. 지도 기존 범례 옆에는 구름·착빙 두 버튼만 추가. 체크박스 상자·등온선 조작 없음 |
| 구름 | 현재 T−Td 기반 회색 표현, 농도·흐림 효과를 유지 |
| LIGHT / LGT | 밝은 파랑 `#ACC7FF`의 불투명 색 면 |
| MODERATE / MOD | 중간 파랑 `#6B88CD`의 불투명 색 면 |
| SEVERE / SEV | 어두운 남색 `#383D6F`의 불투명 색 면 |
| 점무늬 | 모든 등급에서 흰색, 기준 간격 9px·반지름 0.85px·점 불투명도 0.82. 등급을 점 밀도로 구분하지 않음 |
| 윤곽선 | 전 등급 합집합의 최외각에만 약 1.4px 실선. 내부 등급 경계·구멍에는 별도 선을 추가하지 않음 |
| 온도 | 지도는 0°C 실선·−20°C 파선과 라벨을 같은 빨간색 `#c0291f`로 고정 표시. 지도 등온선 버튼·−10°C 옵션 제거; 기존 단면 온도 기능은 유지 |
| 고도·시간 | 기존 KIM 기압층 레일·타임라인 유지. 구름·착빙 둘 다 OFF여도 등온선용 공통 선택·레일 유지. 부모 보기 OFF 시 숨김 |
| 단면·브리핑 | 같은 등급색·점무늬·범례 사용. 실제 단면 고도 축과 항로·예보 선택 유지 |
| 지점 조회 | 착빙 면이 구름을 가려도 같은 좌표의 기존 착빙·기온·구름 추정 값을 조회 |

등온선 고정 표시는 **수평 지도**에 적용한다. 단면의 기온 켬/끔·추가 등온선·색상 등 기존 온도 기능은 유지하고, 지도 규칙을 공유 상수 변경으로 단면에 강제하지 않는다. 시안의 첫 600 hPa와 고정 시계는 시각 확인용이다. 제품의 최초 고도·예보 선택이나 실제 시각을 이 값으로 바꾸지 않는다.

A안의 불투명 착빙 면 아래에서는 구름의 세부 명암이 가려진다. 구름 자체의 색·판정값을 바꾸는 것이 아니라 표시 우선순위를 착빙에 주는 것이다. 착빙을 끄면 기존 구름을 그대로 볼 수 있다.

이 작업은 **표현 교체**다. 기존 착빙 계산식·등급 임계값·T−Td 판정·GKTG를 변경하지 않고, 기상청 추가 API 호출·새 수집기·새 backend 데이터 종류를 만들지 않는다. HTML의 인공 기상장과 표시용 0–30,000ft 축을 제품 데이터·축으로 이식하지 않는다.

## 3. 세 렌더러를 같은 A안으로 맞추는 방법

### 공통 정의와 범례

- 공통 정의에 등급별 `fillColor`와 공통 `dotColor / dotOpacity / dotRadius / spacing`, 최외각 선 스타일을 둔다. 밑면색과 점색을 하나의 `color`로 취급하지 않는다.
- 기존 `p.color / p.radius / p.size / p.repeats` 소비자를 한 번에 대조한다. 제품 Mapbox·SVG·CSS·버튼 정의를 새 계약으로 바꾸고, 비교 mockup의 B–F 정의는 분리한다. 단순히 `color`를 삭제하거나 모든 소비자에게 새 면색을 넣어 과거 비교안까지 바꾸지 않는다.
- `icingPatternStyle()`은 불투명 등급 면과 흰 점을 생성한다. NONE은 채우지 않고 기존 결측·지원층 밖 의미를 유지한다.
- 지도·SVG·CSS가 같은 논리 단위의 간격과 반지름을 참조한다. Mapbox의 텍스처 픽셀 수와 화면에서 보이는 크기는 별도 값으로 관리한다.
- 범례는 색·명도·등급 텍스트를 함께 제공한다. 점무늬는 현상 구분의 보조 표식으로 설명하며 등급별 빈도 차이를 암시하지 않는다.

### Mapbox

- 기존 등급별 연결 영역과 전 등급 최외곽 GeoJSON을 그대로 사용한다. 색을 바꾸려고 영역을 재판정·평활화·확대하거나 구름 마스크로 잘라내지 않는다.
- 패턴의 바탕 픽셀은 해당 등급색이며 알파는 255다. 점 부분은 흰색과 바탕색을 점 불투명도·가장자리 coverage에 따라 합성한다. 현재 함수의 알파만 1로 바꾸면 흰 점이 만들어지지 않으므로 RGB 생성까지 수정한다.
- 전체 면 불투명도는 1을 유지한다. `fill-antialias: false`를 유지해 각 등급 도형에 암묵적인 내부 윤곽이 생기지 않게 한다.
- 패턴 반복의 이음새와 영상 해상도를 함께 맞춘다. Mapbox 공식 `fill-pattern` 규격은 연속 반복 이미지에 2의 거듭제곱 크기를 요구한다. 따라서 9px 목표 간격을 맞추려고 단순히 9×9 이미지를 등록하지 않는다. 기존 크기 계약과 이미지 픽셀비를 함께 설계한다. [공식 스타일 규격](https://docs.mapbox.com/style-spec/reference/layers/#fill-pattern)
- 초기 구현 후보는 **64×64 이미지에 축당 4번 반복, 표시 픽셀비 16/9**다. 논리 표시 폭 36px ÷ 4 = 9px에 맞추고, 이미지 내부 반지름은 논리 반지름에 픽셀비를 곱한다. 설치된 Mapbox의 `addImage`·표시 크기 처리와 실제 렌더 결과로 검증하며, 줌·DPR에 따른 크기를 상수 비교만으로 통과 처리하지 않는다. 모든 등급에 같은 조건을 적용한다.
- 이전 이미지가 남아 새 무늬를 가리는 일이 없도록 A 표현용 이미지 버전을 구분하고, 기존 레이어의 `fill-pattern` paint도 함께 갱신한다. 새 image만 등록하고 이미 존재하는 layer는 그대로 두는 방식으로 끝내지 않는다.
- 베이스맵 변경 후 이미지·소스·레이어 재설치를 확인한다. 정리 시 A의 세 등급 이미지와 소유 자원을 모두 제거한다. 표현 버전은 runtime 이미지 식별을 위한 것이며 기상 자료 revision과 구분한다.
- `MapView`는 현재 착빙 sync에 배경 정보를 넘기지 않는다. 기존 `basemapId`를 어댑터의 표시 입력과 sync 의존성에 연결하고, 이미 존재하는 외곽선의 paint도 갱신한다. Standard·남색/녹색/회청 outline·위성을 구분하며 앱 UI 테마를 지도 배경 밝기로 대용하지 않는다. 위성은 밝고 어두운 영역이 섞이므로 단색 배경 검사만으로 대비를 판정하지 않는다.
- 토글뿐 아니라 `enableWindOverlay`가 false로 바뀌는 경우에도 숨김 sync를 호출한다. 현재의 조기 return만 유지하면 이미 설치된 면·선이 남을 수 있다. 구름·착빙·등온선의 기존 소유 어댑터에 가시성 입력을 전달하는 방식으로 처리한다.
- 기존 그리기 순서인 구름 → 착빙 → 등온선·라벨을 유지하고, 실제 항로·공항·경보 표식이 불투명 면에 가려지는지 확인한다. 밝은 배경은 중립 짙은 외곽선, 어두운 배경은 대비가 확보되는 외곽선으로 같은 경계 의미를 유지한다.

### 지도 등온선 고정 표시

- 지도 어댑터는 `cloudIcingDetail`과 관계없이 `[0, -20]`만 생성한다. `DETAIL_ISOTHERMS`를 삭제하거나 전역적으로 바꾸지 않고, 지도 renderer·지도 범례의 입력을 고정한다.
- 0°C는 실선, −20°C는 파선이며 선과 온도 라벨은 모두 `color.level.red` (`#c0291f`)다. 가독성을 위한 기존 밝은 halo는 유지할 수 있다. 색을 바꾼다고 기온값이나 등온선 경로를 수정하지 않는다.
- 기존 레이어가 이미 설치된 경우에도 선·라벨 paint와 contour source를 갱신한다. style 교체 후 고정한 두 선·라벨이 같은 규칙으로 복원되며, 부모 OFF와 기능 gate OFF에서 halo까지 함께 숨긴다.
- “항상 표시”는 이 보기의 정상 T 필드로 두 등온선을 그린다는 뜻이다. 선택한 영역에 0/−20 경계가 없으면 선은 없을 수 있으며 오류가 아니다. 자료 결측이나 영역 밖 경계를 인위적으로 만들어 표시하지 않는다.
- 지도 범례의 기존 검은 온도 색 띠와 −10°C 항목을 제거하고 빨간 실선/파선과 `0°C / −20°C` 라벨을 넣는다. 공통 `CloudIcingLegend`는 지도/단면 입력을 구분해 단면 온도 기능을 보존한다.

### 연직단면과 비행 전 브리핑

- 각 등급 SVG pattern의 밑면을 불투명 색 면으로 바꾸고 공통 흰 점을 얹는다. `svgIdPrefix`로 여러 단면의 패턴 ID 충돌을 막는 기존 처리를 유지한다.
- 구름 밴드와 blur, 착빙 셀 위치·등급, 최외각 경로, 기압→고도 처리, 등온선·항로 정보는 그대로 사용한다.
- 독립 단면 창, 브리핑 인라인 단면, 브리핑 확대 단면이 같은 공통 정의를 읽는지 확인한다. 한 화면만 A안으로 바꾸고 다른 화면은 이전 점무늬로 남기지 않는다.
- 지도에 직접 그은 선의 단면, 고도 비교에서 열린 단면, AI 보관 결과의 단면, 기관 발표의 일반/확대 단면도 같은 소비자 목록에 포함한다. 공통 chart 변경만으로 각 진입 경로·자료 선택·조작까지 검증했다고 보지 않는다.
- 착빙과 난류의 겹침은 별도 처리한다. 현재 난류 셀 → 구름 → 착빙 순서여서 불투명 착빙 면이 난류를 가린다. 기관 발표는 두 현상을 항상 켜고, 브리핑도 난류가 발견되면 함께 켠다. 관련 화면에 기존 단면 토글을 제공하고, 두 현상이 겹치면 가려짐 안내와 난류 보기 전환을 제공한다. 난류 보기는 구름·착빙 면을 숨겨 원래 난류 셀을 보여주며 이전 구름·착빙 선택으로 돌아갈 수 있게 한다. GKTG 값·색·경계나 착빙 불투명도를 바꿔 해결하지 않는다. 기관 단면에는 현재 토글이 없으므로 연결 수정이 필요하다.
- 좁은 화면에서 점·선·범례가 지나치게 축소되지 않도록 기존 단면 스크롤·확대 구조를 사용한다. HTML처럼 앱의 고도 범위를 고정하지 않는다.

### 실제 지도 범례

`WeatherLegends.jsx`에는 우측 패널의 `CloudIcingLegend`와 하단 dock의 `HLegend`라는 두 경로가 있다. `MapView`가 `bottomDock={!isMobile}`을 넘겨 **일반 지도에서는 데스크톱·모바일 모두 하단 경로를 사용한다.** 현재 하단 착빙은 `ICING_COLOR_RAMP`의 단색 사각형이고, 구름 제목은 여전히 `습도 · T-Td °C`다. `CloudIcingLegend`만 수정하면 실제 지도는 새 범례를 사용하지 않는다.

- 하단에서도 공통 `CloudIcingLegend`를 compact 배치로 사용하고, 기존 temp/cloud/icing의 중복 `HLegend` 항목을 제거한다. 일반 `HLegend`를 착빙 전용 renderer로 만들지 않는다.
- 표시 여부는 현재의 가시성·정상 필드 조건을 유지한다. 꺼진 현상이나 지원층 밖 착빙을 정상 표시 중인 것처럼 범례에 넣지 않는다. 자료 상태 안내는 기존 컨트롤과 연결한다.
- `구름층 추정 · T−Td`, 등급 라벨, 흰 점과 최외각 설명, 빨간 0/−20°C 고정 표시를 함께 검증한다. 등온선은 실선/파선 표식으로 설명하고 연속 온도 색 띠와 혼동하지 않게 한다.
- dock의 `ResizeObserver` → `onOpenPanelHeightChange` → 지도 하단 여백 연결을 유지한다. 범례를 바꿔 타임라인·기압층 레일·모바일 sheet를 가리지 않게 한다.

구름·착빙·온도를 함께 켜면 단일 레이어만 켤 때보다 브라우저가 프로젝트 서버에서 읽는 필드는 많다. 이는 기존 통합 보기의 조회·캐시 계약이며 기상청 키를 통한 추가 원자료 수집과는 다르다. 이번 A안 표현 교체가 현재 통합 보기의 필드 수나 수집량을 추가로 늘리지 않는다.

표시 상태 호환 처리는 아래 규칙으로 국소 적용한다. 현재 버전의 OR 기반 부모 의미와 새 독립 부모 의미를 읽기 경계에서 구분한다. `cloudIcingPresentationVersion`은 기존 소비자의 읽기/직렬화 계약을 확인해 필요한 경우에만 갱신하며, 전 사용자 설정을 초기화하거나 기상 manifest·revision을 변경하지 않는다.

**구름 키와 시간 상태는 구분한다.** 지도 `metVisibility.cloud`는 T−Td 구름 추정이며 단면의 대응 키는 `layers.moisture`다. 단면 `layers.cloud`는 별도 KIM CLD 구름량 윤곽이다. 이름만 보고 두 cloud 키를 묶으면 다른 현상을 제어하게 된다. A 표현은 T−Td 구름과 착빙에 적용하며 CLD 윤곽은 기존대로 유지한다.

지도 timeline·기압층은 `useNwpOverlays`의 `nwpSelection`을 사용한다. 항로 단면의 예보시간·waypoint 보정은 `useRouteBriefing`의 `crossSection`·`nwpTimeSelection`, 지도 선 단면은 별도 `mapLineProfile`이 소유한다. 공유 renderer를 쓴다는 이유로 시간과 고도까지 자동 동기화되는 것은 아니다. 기존 소유권을 유지하고 각 화면의 tmfc/hf/유효시각을 명시하며, 이번 표현 교체에서 새 양방향 시간 동기화를 추가하지 않는다.

### 표시 상태와 이전 설정의 호환

현재 `isCloudIcingVisible()`과 부모 토글은 temp/cloud/icing의 OR로 보기를 판정하며, 저장 자식이 모두 false면 기본 ON으로 되돌리는 경로가 있다. 버튼 제거만으로 끝내지 않고 다음 계약으로 바꾼다.

| 전이 | 요구되는 결과 |
| --- | --- |
| 첫 구름·착빙 진입 | 부모 ON, 구름/착빙 기본 ON, 지도 등온선 ON. 이후에는 마지막 두 자식 선택 복원 |
| 구름 또는 착빙 토글 | 해당 면만 변경. 부모·지도 temp·발표/예보/기압층 선택 유지 |
| 구름·착빙 모두 OFF | 부모와 두 버튼·고도 레일·시각 카드 유지. T 필드 정상일 때 빨간 두 등온선 표시 |
| 부모 OFF 또는 전체 끄기 | 면·착빙 외곽·등온선/halo/라벨·관련 조작 숨김. 마지막 구름/착빙 선택 보관 |
| 부모 재진입 | 두 자식이 모두 false인 조합도 그대로 복원. temp는 반드시 ON으로 파생 |
| 바람/난류/운정 전환 후 복귀 | 기존 공통 레일 상호배제 유지. 다른 보기에서 A 면·선 잔존 없이 마지막 구름/착빙 선택 복원 |
| 기존 temp/cloud/icing 활성 상태 진입 | 기존 계약은 자식 활성 여부로 부모 보기 복구. 독립적인 부모 ON/OFF를 가진 새 계약은 명시한 부모 값을 우선. 활성 보기의 temp=false나 cloudIcingDetail=true는 지도에서 각각 temp=true와 기본 두 등온선으로 정규화 |
| 검색·AI `temp` enable | 통합 보기 진입과 동일한 파생 상태 적용. 이미 ON이면 OFF로 토글되지 않음. cloud/icing enable도 같은 상태 모델을 통과 |

`cloudIcingSaved`에서 두 자식의 false 값은 유효한 선택이다. 객체 존재 여부와 개별 boolean을 확인하고 “둘 다 false”를 설정 없음으로 취급하지 않는다. 지도 temp는 사용자 자식 선택으로 저장·복원하지 않고 부모의 파생 값으로 취급한다. 자료 성공/실패가 부모나 사용자 선택을 변경하지 않는다.

`MapView`의 패널 토글·`setLayerOn`·`clearMetLayers`·브리핑의 지도 칩이 위 동일 상태 경로를 사용하게 한다. 표시 문맥만 켜지고 자료 훅은 꺼지는 분리 상태나, 파생 temp만 남아 다른 KIM 보기와 충돌하는 상태를 만들지 않는다. 자료 필드·timestamp·지점 조회·레일은 정규화한 모델을 소비한다.

### 검사 도구와 잔존 코드의 연결

- `verify-cloud-icing.mjs`는 현재 `kim-icing-dots-1`을 하드코딩한다. A 이미지 ID를 바꿀 때 소유 모듈의 ID 목록으로 검사하도록 함께 갱신한다. layer/source ID는 기존을 유지하여 구름 삽입 순서·등온선·cleanup 연결을 보존한다.
- overlay 테스트의 map fixture는 현재 `addImage` 옵션과 paint 갱신을 기록하지 않는다. pixelRatio·기존 레이어 갱신을 확인할 수 있게 fixture를 보완하고, 실제 Mapbox 검사도 병행한다. 단순 이미지 존재 검사가 간격·흰 점·새 paint 검증을 대신하지 않는다.
- `icingPotentialOverlaySync.js`와 자체 테스트는 남아 있으나 현재 `MapView`의 실사용 import는 `icingPatternOverlay.js`를 이전 이름으로 alias한 것이다. 예전 overlay 테스트 통과를 제품 A 검증으로 보고하지 않고, 이번 작업을 이유로 무관한 legacy 파일 삭제까지 확대하지 않는다.
- variants mockup은 제품 공통 정의를 import하면서 B–F에서도 `p.color/radius/spacing`을 참조한다. 기존 비교 스타일을 mockup 소유 상수로 분리하고, A의 면색·점·간격은 제품 정의를 참조한다. HTML 재생성 후 A와 B–F를 각각 확인하여 재생성 때 채택안과 비교안이 달라지는 것을 막는다.
- 데이터 fixture 공급 코드가 backend 저장 자료를 읽는 것은 개발 검사 경로다. 제품 frontend에서 backend 생성기나 mockup renderer를 import하는 연결은 만들지 않는다.

### 적용 전후와 구체적인 UI/UX

비교 기준은 현재 로컬 작업본이다. 기존 통합 진입은 유지하고 지도 등온선은 빨간 0/−20°C로 고정하며 지도 자식 조작은 체크박스 대신 지도 위 버튼으로 옮긴다. 단면 중첩 안내/보기 전환과 기관 고정 발표의 표시 조작도 추가한다. AWS 화면과의 비교를 의미하지 않는다.

| 항목 | 적용 전 | 적용 후 |
| --- | --- | --- |
| 구름 위 착빙 | 옅은 밑색과 등급별 파란 점 밀도 | 불투명 3단계 파랑 면과 동일한 흰 점. 구름은 회색 그대로, 착빙 아래 명암은 가려짐 |

| AI 보관 결과·고도 비교·지도 선 단면 | 공유 chart의 기존 표현 | 같은 저장/선택 자료를 A로 표시하며 각 진입 경로의 기존 조작 유지 |

**지도 조작:** 기상 패널에는 기존 `구름·착빙` 진입 타일을 두고 자식 체크박스 설정 상자는 제거한다. 지도 위 `구름 / 착빙` 버튼으로 표시를 조작한다. 위치는 기존 좌측 하단 `범례` 옆 한 줄이며 [실제 App 기반 시안](../../../artifacts/cloud-icing-native-ui/index.html)을 승인 기준으로 사용한다. 기존 `--app-font`·회청색·버튼 스타일을 사용하고 지도 중앙 설정 카드는 추가하지 않는다. 모바일에서는 시간 슬라이더 재생 버튼의 터치 영역 위에 배치한다. 등온선 버튼·메뉴는 없앤다. 이 보기에서 0°C 실선과 −20°C 파선 및 라벨을 같은 빨간색으로 항상 표시하고 −10°C는 제외한다. 큰 설명 상자 없이 활성색·짧은 라벨로 현재 상태를 나타낸다.

착빙 OFF면 면과 외곽선이 함께 사라져 회색 구름을 확인할 수 있다. 부모 OFF→ON은 마지막 자식 선택을 복원한다. 구름·착빙 모두 OFF여도 등온선과 조작을 유지하고, 다른 주 보기로 전환하면 지도 위 조작을 숨긴다. 버튼은 기존 범례 dock의 레이아웃·열린 범례 높이에 연결한다. 간격은 기존 8px 토큰, 터치 영역은 각 44px 이상, 켬/끔은 회청색 활성 스타일과 `aria-pressed`로 표시한다. 모바일에서는 실제 시간 슬라이더의 재생/되감기·스크럽 시각과 하단 작업 바의 점유 공간을 함께 확인한다. 활성 항로 칩·경보·패널/모바일 sheet·펼친 범례도 함께 열어 실제 클릭 영역까지 검사한다. 시안의 CSS 위치 값만으로 기관 지도나 다른 진입 경로의 배치를 완료했다고 보지 않는다.

**지도 범례:** 기존 하단 범례 열기/접기 안에 표시 중인 현상만 배치한다. 순서는 구름층 추정 → LGT/MOD/SEV 착빙 → 빨간 0/−20°C 실선/파선 표식이다. 착빙 칸에도 같은 흰 점을 넣고 등급 텍스트를 붙인다. 모바일은 줄바꿈하며 범례 높이에 맞춰 타임라인과 레일 여백을 조정한다. 별도 떠 있는 범례 창은 추가하지 않는다.

**단면 중첩 안내와 전환:** 단면 레이어 토글 바로 아래에 한 줄 안내 `착빙 면에 가려진 난류 영역이 있습니다. [난류 보기]`를 둔다. 현재 표시 중인 착빙 면과 정상 난류 셀의 영역이 실제로 겹칠 때만 노출한다. 선택한 두 레이어가 ON이라는 이유만으로 안내하지 않는다. 모달·자동 보기 전환은 사용하지 않는다.

- `난류 보기`를 누르면 해당 단면의 구름층 추정·착빙·난류 켬/끔을 보관하고, 구름층 추정/착빙 면은 숨기며 난류를 켠다. 기온·바람·CLD 윤곽·항로·고도·경보와 자료 시각은 그대로 둔다.
- 전환 후 같은 자리에 `난류 보기 중 · 구름·착빙 면 숨김 [이전 표시로]`를 표시한다. 복귀는 보관한 세 현상의 선택만 복원하며, 그동안 바꾼 기온·바람 등 다른 설정을 되돌리지 않는다.
- 전환 중 구름층 추정·착빙·난류 토글을 직접 바꾸면 사용자의 새 선택을 적용하고 임시 보기 상태를 종료한다. 이미 버린 이전 상태를 나중에 자동 복원하지 않는다.
- 보기 전환은 단면 화면에만 적용한다. 배경 지도 레이어·예보시간·비교 고도를 함께 변경하거나 자료를 다시 수집하지 않는다. 일반/확대가 같은 단면인 경우 임시 보기와 복귀 상태도 공유한다.

**기관 고정 발표 지도:** 기존 기관 지도 패널 버튼 자리에서 `기상표시` 버튼을 제공하고, 기존 기상 패널을 재사용해 `바람 / 구름·착빙 / 난류` 진입을 노출한다. 구름·착빙의 자식 조작은 일반 지도와 같은 지도 위 버튼을 사용한다. 사용자는 보관된 자료의 화면 표시를 바꾸며, 고정 발표·예보시각을 패널과 범례에서 확인한다. 보관 범위의 기압층 선택은 허용하되 라이브 시간 이동·최신 자료 전환은 제공하지 않는다. 기관 발표의 최초 표시는 기존 바람 선택을 유지한다. 구름·착빙을 선택했을 때 가용한 고정 자료만 그린다.

**기관 발표 단면:** 제목 아래에 기존 공통 단면 토글을 배치한다. 현재 초기 선택은 유지하고 실제 중첩이 있으면 위 안내를 즉시 보여준다. 발표 일반/확대는 발표 소유 표시 상태를 공유하여 확대 후 복귀해도 선택이 바뀌지 않게 한다. 지도의 레이어 선택과 단면 선택은 별도로 관리한다.

**없는 자료와 일부 실패:** 지도 위 해당 현상 버튼의 짧은 상태 표시와 접근성 설명에 기존 `지원층 밖 / 자료 없음 / 자료 오류 / 고정 자료 없음` 의미를 연결한다. 정상 자료는 유지하고 사용할 수 없는 현상만 그리지 않는다. 일시적인 실패나 지원층 이동 때문에 사용자 선택을 자동으로 해제하지 않으며, 다시 가용한 층으로 돌아오면 선택한 표시를 복구한다. 단, 이전 시각/기압층 자료를 현재 정상 자료처럼 섞지 않는다. 등온선에는 새 조작 버튼을 만들지 않으므로 T 자료의 실패/부재는 기존 시각 카드·범례·부모 타일의 상태 표시를 사용한다. 정상 T 필드에 경계가 없는 경우와 자료 실패를 구분한다. 시안은 위치·조작 검증이며 실패 상태의 제품 연결 검증을 완료한 것은 아니다.

기관 고정 화면에서 새로 구름·착빙을 선택하면 프로젝트 서버의 기존 고정 필드 조회가 발생할 수 있다. A 표현 자체는 새 기상청 수집·원자료 종류를 요구하지 않는다. ADMIN·착빙 임계값·GKTG 계산은 이번 UI 변경으로 달라지지 않는다.

### 데이터와 기능 검증

- 저장 자료 `tmfc=2026091006`, F+6/F+9, 600/500/450 hPa와 착빙 지원층 밖인 250 hPa를 사용한다. 최신 자료로 위장하지 않는다.
- 실제 지도 205×169 격자와 RKSI→RKPC 21층 단면에서 T−Td, 착빙 점수·등급, 결측, 도형·윤곽선이 적용 전후 같은지 확인한다.
- 500 hPa F+6의 전체 격자 NONE/LGT/MOD/SEV 수는 31,314 / 3,196 / 134 / 1이다. 강한 등급은 전체 격자에 매우 적고 단면에는 없을 수 있으므로, 전 등급이 맞닿는 고정 fixture도 함께 사용한다. 실제 값의 등급을 늘려 시각 평가하지 않는다.
- 분리 영역·내부 구멍·좁은 띠·한두 셀 조각에서 최외각만 윤곽선이 있고 원래 등급 면은 유지되는지 확인한다.
- 이미지 픽셀 검사는 불투명 면, 흰 점과 가장자리 합성, 세 등급 공통 반복 간격, NONE 미표시를 실제 생성 결과로 확인한다.
- 기존 레이어가 이미 있을 때 표현 교체, 두 번의 style 변경, 토글·cleanup·같은 필드 재사용을 기존 overlay 검사에 포함한다.
- 등온선 600 hPa F+6의 실제 0°C 경계와 450 hPa F+6의 실제 −20°C 경계로 선·라벨 색과 path 불변을 확인한다. 500 hPa F+6에는 두 경계가 없음을 정상 사례로 검사하고, 두 경계·결측이 함께 있는 제한 fixture로 −10°C 미생성과 기존 layer paint 갱신도 검사한다.
- 부모/자식 전이·두 false 선택 복원·legacy temp=false/detail=true·검색/AI enable 멱등성을 검사한다. 지도 고정 표시가 단면의 기온 OFF·detail ON에 영향을 주지 않아야 한다.
- 기능 gate ON→OFF, 구름·착빙 모두 OFF→부모 재진입, 전체 끄기, 구름·착빙→난류/바람/운정→복귀도 검사한다. 기존 면·선·이미지가 잘못 표시되거나 사용자 자식 선택이 초기화되지 않아야 한다.
- 기관 pinned 자료의 변수별 revision은 서로 같다고 강제하지 않는다. 각 변수의 정확한 revision을 기존 요청·캐시 키로 읽되 tmfc/hf/기압층/격자가 호환되는지 확인한다. 빠진 변수, 이전 bundle, 만료된 자료를 live 자료로 보충하지 않는지 검사한다.
- 일반 단면·브리핑·기관 발표에서 착빙과 난류가 같은 셀에 있는 fixture를 사용한다. 가려짐 안내·난류 보기·이전 구름/착빙 선택 복원을 확인하고, linked item·NAVLOG 강조·경보 테두리·항로·고도선의 표시와 선택이 유지되는지 확인한다.
- AI 보관 결과는 시간 이동·재조회 없이 같은 보관 자료를 A로 표시한다. 지도 배경 시간과 달라도 결과를 최신으로 바꾸지 않는다. 저장 브리핑 다시 열기와 기관 일반/확대 전환도 별도 검사한다.
- 기존 visibility/selection/field/단면 검사를 실행하고, 영향 범위 검사 이후 전체 변경이 모인 시점에 `npm run check`를 수행한다. 검사가 통과하면 새로운 변경이나 실패가 없는 한 반복하지 않는다.

### 제품 렌더러와 화면 검증

- `node scripts/preview-cloud-icing.mjs`와 `node scripts/verify-cloud-icing.mjs`를 A 기준으로 갱신해 **실제 Mapbox 어댑터·React 단면·공통 범례**를 확인한다. Mockup 전용 SVG의 통과를 제품 검사 통과로 대체하지 않는다.
- 저장 fixture로 부모·자식 토글, 고도·예보 이동, 지원층 밖, 늦은 응답·부분 실패, pinned revision을 확인한다. 검증 중 기상청 수집을 유발하지 않는다.
- 밝은/어두운 배경, 확대·축소, 정수·비정수 줌, DPR 1/2, style 교체를 확인한다. 실제 Standard·위성 배경과 항로·공항·경보도 별도 캡처 항목에 포함한다.
- 데스크톱, iPad 가로 1180×820 또는 1024×768, 모바일 390px에서 범례·등급·점·윤곽선·터치·단면 스크롤을 확인한다. 결과물은 ignored `artifacts/`에 둔다.
- 승인한 일반 지도 시안의 1440/1180/1024/390px 캡처와 비교해 기존 패널·시각 카드·레일·시간 테이프 배치를 유지하고 두 버튼만 추가됐는지 확인한다. 등온선 버튼·메뉴·체크박스 상자·지도 −10°C가 없는지 검사한다. 시안의 검증 통과를 제품 구현 완료로 대신하지 않는다.
- 지도 우측 패널만이 아니라 실제 하단 dock의 열기/접기와 높이 보고, 부모/자식 상태에 맞는 범례를 검사한다. 일반 지도·기관 실시간/고정 지도·기관 발표 일반/확대·항로/지도 선/AI 단면 진입을 각각 기록한다.
- 현재 로컬 서버를 꺼두라는 지시를 유지한다. 먼저 파일 기반 제품 renderer/fixture 검사와 offline 검증을 수행한다. 서버 또는 실제 배포 환경이 필요한 항목은 확인 범위를 분리해 기록하며, 이 계획 작성으로 서버·API·배포를 실행하지 않는다.
