# 기관 라운지와 합동 브리핑 설계안

[HTML 디자인 시안](../mockups/2026-09-09-organization-lounge.html) · [시안 사용 방법과 범위](../mockups/2026-09-09-organization-lounge.README.md) · [구현 계획·실행 검증 결과](2026-09-10-organization-lounge-implementation-plan.md)

## 1. 목표와 전체 구성

**기관이 예정비행과 자료를 준비하면, 조종사는 해당 비행의 기상을 바로 확인하고 같은 자료로 합동 브리핑까지 진행할 수 있는 공간**을 만든다.

기존 비행경로 작성·기상 브리핑을 재사용하고, 기관의 공지·지도·문서·조종사 주의사항을 연결한다.

```text
메인 지도
  └ 기관 라운지
      ├ 홈
      ├ 예정비행 ─ 비행 상세 ─ 기상 브리핑 보기
      ├ 공유자료
      ├ 알림
      └ 합동 브리핑 ─ 준비 화면 ─ 발표 화면
```

- 데스크톱·iPad는 기존 사이드바에 진입점을 둔다. 현재 디자인 검토에서 모바일은 제외한다.
- 라운지는 독립된 페이지이며 기관명·내부 메뉴·날짜·사용자 정보를 한 줄의 공통 상단에 제공한다. 메인 지도 복귀는 기존 사이드바의 지도 메뉴를 이용한다.
- 합동 브리핑은 기관 설정에서 활성화하는 선택 기능이다. 사용하지 않아도 예정비행과 기상 브리핑은 동일하게 이용한다.
- HTML은 라운지 내부 정보 구성·동선·공간 활용을 검토한 시안이다. 실제 구현은 기존 프로젝트의 사이드바·메인 화면 구조·공통 컴포넌트를 우선한다. 시안의 전역 메뉴를 복제하지 않으며 치수·여백·배치는 기존 앱에 맞춰 조정할 수 있다. 중복되는 상단 정보·조작은 통합하고 핵심 기능과 동선은 유지한다.
- 기존 밝은 색상·디자인 토큰을 적용한다. 현재 시안과 검증 대상은 iPad 가로와 데스크톱이며 모바일 설계는 후속으로 둔다.

## 2. 구현됐을 때의 화면과 동작

### 라운지 홈 — 기관의 오늘 상황

```text
[기관명] 홈 | 예정비행 | 공유자료 | 알림 | 합동 브리핑 | 설정  [날짜 · 사용자]

[기관 소식: 주요 공지 · 최근 자료 수 / 열기] [합동 브리핑 준비]
[관심 공항: 공항별 관측 · 예보 · 경보를 가로로 요약]

┌─────────────────────────┬───────────────────────┐
│ 관심 권역 지도           │ 주요 기상 알림         │
│ 권역 선택 · 기상 레이어   │ 대상 · 내용 · 자료시각 │
│                         ├───────────────────────┤
│                         │ 오늘 예정비행          │
│                         │ 시간 · 경로 · 담당자   │
│                         │ [기상 브리핑 보기]      │
└─────────────────────────┴───────────────────────┘
```

- 기관명·기관 메뉴·사용자 정보를 한 줄의 공통 상단에 배치하며 시안 기준 높이는 56px이다. 홈에는 별도의 ‘오늘의 기관 상황’ 제목 줄을 두지 않으며, 날짜는 공통 상단에서 확인한다. ‘합동 브리핑 준비’ 버튼은 기관 소식 줄 오른쪽에 독립된 버튼으로 배치한다.
- 기관 소식 줄을 누르면 오른쪽 서랍에서 공지 전문과 최근 자료의 미리보기·제목·작성자·시각을 확인한다. 자료를 열고 닫으면 소식 목록으로 돌아온다. 브리핑 준비와 공유자료 화면으로도 이동할 수 있다.
- 홈에는 별도의 최근 자료 패널을 두지 않는다. 지도는 오른쪽 알림·예정비행의 합산 높이를 채우고 두 열의 하단을 맞춘다. 넓은 화면에서는 남은 화면 높이도 활용하며, iPad에서 내용이 길면 페이지를 스크롤한다.
- 관심 공항을 누르면 해당 공항 기상 상세로 연결한다.
- 권역·알림에 마우스를 올리면 홈 지도에서 해당 범위를 임시 강조한다. 클릭·iPad 터치로 선택을 고정한다. 상세 동작은 아래 ‘항목과 지도·단면도의 연결’을 따른다.
- 오늘 예정비행에서 상세를 거치지 않고 `기상 브리핑 보기`를 누를 수 있다.
- 관리자는 설정에서 관심 공항을 검색해 추가하고, 관심 권역을 지도에 그려 이름을 붙인다.
- 처음에는 설정 안내를 표시하고, 비행·자료·알림이 없으면 각각 실제 빈 상태를 표시한다.

### 예정비행 — 준비된 경로와 자료의 연결점

목록 상단에 날짜 선택·`내 담당 비행` 필터·`비행 등록`을 둔다. 비행 항목에는 제목, 출발시각, 경로, 담당자와 주요 행동을 표시한다.

```text
[비행명]                              [기상 브리핑 보기]
출발시각 · 경로 · 계획고도 · 담당 조종사

[경로 미리보기]

[조종사 주의사항]
[이 비행에 연결된 기관 자료·지도]

[비행계획 편집]                       [브리핑 자료 작성]
```

**등록 흐름**

1. 개인 저장 경로 또는 기관 공유 경로를 선택한다.
2. 운항 날짜·출발시각·계획고도·담당 조종사를 설정한다.
3. 기관 자료와 지도를 연결해 예정비행으로 저장한다.

기관 예정비행은 선택한 경로를 복사해 보관한다. 원본 개인 경로를 수정하거나 삭제해도 등록한 비행계획이 바뀌지 않는다.

**조회 흐름**

- `기상 브리핑 보기`는 기존 브리핑 화면으로 연결한다. 상단에 기관 예정비행임을 표시하고 `비행 상세로 돌아가기`를 제공한다.
- 기존 기상 브리핑에 `기관 자료·주의사항` 영역을 추가한다. 연결 자료가 있을 때 개수와 요약을 표시하고 펼쳐서 읽는다.
- 기상 조회 중 시간·고도를 바꿔 비교해도 공유 비행계획에는 저장하지 않는다.
- 과거 출발시각을 현재로 자동 변경하지 않는다. 조회 가능한 기상 범위를 안내하고 사용자가 시간을 바꿔 조회할 수 있게 한다.

### 공유자료 — 갤러리와 기관 자료함

- `전체 / 문서·이미지 / 지도 / 경로` 필터와 제목 검색을 제공한다.
- 이미지와 PDF는 썸네일, 제목, 작성자, 수정일을 보여준다. 지도와 경로는 종류와 범위를 표시한다.
- 자료 상세에는 설명·관련 공항·권역·연결된 비행을 표시한다.
- 이미지 확대, PDF 페이지 이동·확대, 지도 레이어 표시, 공유 경로로 예정비행 만들기를 지원한다.
- 자료는 공용자료함에 보관하거나 특정 비행에만 첨부할 수 있다. 비행 전용 자료도 기관 구성원에게는 공유된다.

**브리핑 자료 작성**은 제목·본문·이미지·PDF·링크 블록을 추가하고 순서를 바꾸는 간단한 편집기로 만든다. 별도의 슬라이드 편집기를 만들지는 않는다.

사용자는 NOTAM 발췌, 자체 운항 참고자료, 주의사항 등을 직접 등록할 수 있다. 작성자·수정시각·사용자가 입력한 출처를 표시하며, 자동 기상 분석과 구분한다.

### 지도에 연결하는 조종사 주의사항

주의사항 하나에 제목·설명과 지도 도형을 함께 저장한다. 도형 종류는 **지점·선·다각형 구역·원**이며, 글만 작성할 수도 있다. 초기 소유 범위는 해당 기관의 특정 예정비행이고, 비행 상세·개인 기상 브리핑·합동 브리핑에서 같은 내용을 사용한다.

1. 예정비행 상세 또는 합동 브리핑 준비에서 `지도 주의사항 추가`를 연다.
2. 지점은 한 번, 원은 중심과 가장자리를 두 번 찍는다. 선·구역은 꼭짓점을 찍고 `도형 완료`로 확정한다. 마우스와 iPad 터치에서 같은 흐름을 사용한다.
3. 제목·설명과 필요한 경우 고도 하한·상한을 입력한다. 고도는 선택 사항이며 단위와 기준을 `ft AMSL`로 명시한다.
4. 경로와의 연결 여부를 확인하고 저장한다. 작성자는 같은 화면에서 내용을 수정하거나 도형을 다시 그리고 삭제할 수 있다.

사용자 도형에는 점선과 ‘사용자 작성’ 표시를 적용한다. 자동 기상 영역의 색상·출처·유효시간과 구분하고, 사용자 도형을 기상 위험 등급으로 해석하지 않는다. 발표 종료 기록에는 글과 함께 도형 및 고도 범위의 사용 버전도 보존한다.

### 항목과 지도·단면도의 연결

| 조작 | 반응 |
|---|---|
| 위험기상·주의사항에 마우스 올리기 또는 키보드 초점 이동 | 해당 지도 영역과 연결 가능한 단면도 구간을 임시 강조. 지도 위치나 확대 수준은 바꾸지 않음 |
| 항목 클릭·iPad 터치 | 선택 고정. 지도에서 대상이 보이지 않을 때만 표시 범위를 조정 |
| 지도 도형 또는 단면도의 연결 표시 선택 | 같은 항목 카드를 강조. 자료 패널 내부에서 필요한 경우 해당 카드가 보이도록 스크롤 |
| 다른 항목 호버 후 벗어남 | 임시 강조를 끝내고 기존 고정 선택으로 복귀 |
| 같은 항목 다시 선택, `선택 해제`, 또는 Esc | 고정 선택 해제. 대화상자가 열려 있으면 Esc는 대화상자를 먼저 닫음 |

- 자동 기상과 사용자 주의사항은 같은 선택 동작을 사용하되 서로 다른 출처 표현을 유지한다. A·B 발표 배치를 전환해도 같은 비행의 선택은 유지하고, 비행이 바뀌면 이전 선택을 해제한다.
- 다각형·원은 경로와 겹치는 거리 구간을 연결한다. 지점·선은 경로상의 일치·교차 위치를 연결하며, 단순히 가까워 보인다는 이유로 넓은 위험 구간을 만들지 않는다.
- 경로가 같은 영역을 여러 번 통과하면 모든 해당 구간을 표시한다. 경로 밖의 도형은 지도에서만 강조하고 단면도에는 ‘현재 경로와 겹치지 않음’을 표시한다.
- 고도 범위가 있으면 단면도의 해당 거리·고도 범위를 강조한다. 고도가 없으면 점선으로 위치 구간만 표시하고 **‘위치만 연결 · 고도 미지정’**을 명시한다. 모든 고도에 위험이 있다는 의미로 표현하지 않는다.
- 라운지 홈처럼 단면도가 없는 화면에서는 지도와 항목만 연결한다. 현재 비행에 속하지 않은 조종사 도형을 기관 홈에 자동으로 섞어 표시하지 않는다.

### 합동 브리핑 — 준비와 발표

**준비 화면**

- 날짜와 회차 제목을 정한다. 같은 날 여러 회차를 만들 수 있다.
- 예정비행을 선택해 추가하고 위·아래 이동으로 발표 순서를 정한다.
- 왼쪽은 비행 목록, 오른쪽은 선택한 비행의 주의사항·자료 편집 영역이다.
- 회차 전체에 보여줄 공통 안내·자료도 추가할 수 있다.
- `발표 미리보기`와 `발표 시작`을 제공한다. 주의사항이 없어도 발표할 수 있다.

**발표 화면**

```text
[기관 · 회차]              [이전 / 다음 비행] [발표 종료]
[현재 비행 · 경로 · 출발시각 · 담당 조종사]

┌──────────────────────────┬──────────────────────┐
│                          │ 주요 위험기상         │
│ 평면 기상 지도 + 비행경로  ├──────────────────────┤
│                          │ 조종사 주의사항        │
├──────────────────────────┤ 기관 공통 안내         │
│ 연직단면도                │ 이미지·PDF 등 추가자료 │
└──────────────────────────┴──────────────────────┘
```

- 기본은 한 화면에서 함께 보기다. 지도·단면도·첨부자료를 각각 확대하고 원래 배치로 돌아올 수 있다.
- 위험기상과 지도에 연결한 조종사 주의사항은 지도·단면도·항목을 함께 강조한다. 호버와 고정 선택을 구분한다.
- 화면 내 발표 모드를 기본으로 제공하고, 브라우저가 지원하면 전체화면을 사용할 수 있다.
- 발표 배치는 B(왼쪽 전체 높이 지도, 오른쪽 위 단면도·아래 자료)를 기본으로 하고 A(왼쪽 지도 위·단면도 아래)로 전환할 수 있게 구현한다. 모바일 발표 배치는 현재 범위에 포함하지 않는다.
- 발표 중 새 기상자료나 작성 내용이 도착하면 갱신 표시를 띄운다. 발표자가 적용할 때 현재 화면을 변경한다.
- 지도도 표시 중인 모델 발표차수·유효시각과 레이더·위성 frame을 유지한다. 고도 변경·A/B 전환으로 최신 자료가 섞이지 않게 하고, 발표자가 적용할 때 지도·단면·요약을 함께 교체한다. 고정 자료가 만료되면 상태를 표시한다.
- 발표 종료 시 그 회차에서 사용한 비행계획·글·첨부자료 버전을 보존한다. 지난 회차에는 당시 기상 화면을 재현하지 않는다는 점을 표시한다.

### 화면 공간 배분

- 데스크톱·iPad 가로에서 지도와 브리핑 내용을 우선 배치한다. 공통 상단, 반복 제목·설명, 카드 내부 여백을 압축하고 주요 조작의 44px 터치 영역은 유지한다.
- 홈의 예정비행은 시간·계획 요약·브리핑 진입을 한 행에 배치한다. 공항 요약은 지도 위 가로줄에, 최근 자료는 기관 소식 서랍에 배치한다. 큰 썸네일 갤러리는 공유자료 화면에서 제공한다.
- 발표 화면의 지도 제목과 도구는 지도 안에 배치하고, 하단에는 기상자료·비행계획 시각을 간결하게 유지한다. 지도 선택 요약은 필요한 너비만 사용한다. A·B 배치 선택은 비행 제목 옆에 유지한다.
- 준비 화면은 자동 연결 자료를 한 줄로 요약하고 중복 제목·중첩 테두리를 줄인다. 조종사 입력창은 높이를 조절할 수 있고, 첨부자료는 두 열을 활용한다.
- 기상 출처·유효시간·작성자·고도 미지정 같은 판단에 필요한 정보는 유지한다. 긴 주의사항은 해당 영역에서 스크롤하며, 발표의 위험기상과 참고자료는 계속 접근할 수 있어야 한다.

### 알림 — 관심 대상에 발생한 사실

첫 버전의 자동 알림은 다음으로 한정한다.

- 관심 공항의 공항경보.
- 관심 권역과 겹치는 유효 SIGMET·AIRMET.
- 관심 공항 주변 또는 권역 안의 최근 낙뢰 건수.

낙뢰는 기본 조회창을 최근 30분, 공항 주변 기본 반경을 10km로 두고 기관 설정에서 변경한다. 이는 조회 조건이며 운항 판단 기준으로 표현하지 않는다.

알림에는 대상·내용·관측 또는 발표시각·유효시간을 표시하고, `지도에서 보기`와 `확인`을 제공한다. 개인 읽음과 기관 확인을 구분하고, 기관 확인에는 확인자와 시각을 남긴다. 동일 사건은 갱신하며 중복 알림을 쌓지 않는다.

`나중에 보기`는 개인별 30분 숨김으로 시작한다. 확인하거나 숨겨도 홈의 유효 위험기상 표시에서는 제거하지 않는다.

## 3. 구현 구조와 인터페이스

**기관 데이터와 권한**

- SQLite에 기관·회원관계·관심대상·공지·예정비행·공유자료·브리핑 회차·기관 알림을 추가한다.
- 모든 기관 자료에 소유 기관을 명시한다. 사용자가 기관을 옮겨도 기존 기관 자료가 따라가지 않는다.
- 기본 역할은 기관 관리자·비행계획 관리자·일반 회원이다. 기관 관리자는 구성원과 설정, 비행계획 관리자는 예정비행과 회차를 관리한다. 일반 회원은 조회·자료 등록·본인 작성 내용 편집을 한다.
- 담당 조종사는 배정된 비행의 주의사항과 첨부자료를 편집한다. 여러 사람의 수정은 버전 검사로 덮어쓰기를 방지한다.
- 서비스 관리자가 기관과 최초 기관 관리자를 등록한다. 가입 초대 자동화는 후속으로 둔다.

**화면과 API**

- `/lounge/:orgId` 아래에 홈·비행·자료·알림·회차 화면을 둔다. 발표는 `/lounge/:orgId/briefings/:sessionId/present`로 분리한다.
- 기존 메인 지도에 기관 예정비행용 진입 파라미터를 추가한다. 기존 개인 비행 링크와 구분하고, 기관 권한 확인 후 저장 경로를 연다.
- `/api/organizations/:orgId` 아래에 회원·관심대상·공지·비행·자료·회차·알림 API를 추가한다.
- 기존 `/api/me/routes`는 유지한다. 기관 비행은 기존 경로 스냅샷 형식을 재사용하되 별도로 저장한다.
- 예정비행의 주의사항 인터페이스에 제목·설명·선택적 공간 도형·선택적 고도 범위·작성자·수정 버전을 포함한다. 지점·선·다각형은 WGS84 GeoJSON, 원은 중심 좌표와 미터 단위 반경을 정본으로 저장한다. 원을 화면 표시용 다각형으로 바꾸더라도 원본 중심·반경을 유지한다.
- 주의사항 CRUD는 기관·예정비행 아래에 두고 기존 기관 권한과 버전 검사를 적용한다. 화면 연결에는 안정적인 출처 종류와 항목 ID를 사용한다. 호버·고정 선택은 화면 상태이며 서버 데이터에 저장하지 않는다.
- 기상 분석은 기존 분석 모듈을 기관 전용 브리핑 API에서 재사용한다. 일반 기관 브리핑의 최초 진입·시각/고도 변경·재조회도 기관 조회 공급자를 통해 검증된 지도·단면·요약을 함께 받는다. 기존 개인용 `/api/route-briefing`으로 우회하지 않으며, 추가 문서·작성 내용도 기관 권한으로 조회한다.

**지도·자료·기상 재사용**

- 라운지 화면은 새 기능 모듈로 분리한다. 기존 지도 레이어·경로 복원·연직단면도·위험기상 표시를 재사용하고 필요한 표시 인터페이스만 분리한다.
- 지도 도형은 브리핑 거리축에 투영해 연결한다. 경로 변경 시 거리 구간을 다시 계산하고, 고도 미지정·경로 밖·여러 번 교차를 구분한다. 운영 기능에는 지도 화면의 픽셀 좌표를 저장하거나 SVG 시안의 근사 판정을 재사용하지 않는다.
- 파일 원본은 공개 `/data` 경로 밖의 비공개 저장소에 보관한다. 파일·썸네일·다운로드 모두 기관 권한을 확인한다.
- 초기 첨부 형식은 PDF·JPEG·PNG·WebP, 공유 지도는 기존 지원 KML·KMZ로 한다. 크기·형식·압축 해제 한도를 서버에서 검사한다.
- PDF 페이지 표시와 썸네일은 PDF.js를 사용해 구현한다. [공식 예제](https://mozilla.github.io/pdf.js/examples/)
- 기존 기상 수집 결과를 이용해 관심대상별 알림을 평가한다. 누락·지연 자료를 ‘위험 없음’이나 낙뢰 0건으로 처리하지 않는다.
- 발표 중에는 조회 결과를 유지하며 새 자료 도착을 감지한다. 기상자료 시각과 비행계획 수정시각을 따로 표시한다.

## 4. 구현 순서와 단계별 완료 기준

| 단계 | 구현 내용 | 완료됐을 때 가능한 일 |
|---|---|---|
| **1. 기관과 예정비행** | 기관 권한, 라운지 기본 화면, 경로 공유·예정비행 등록, 기존 브리핑 연결 | 관리자가 저장한 비행을 조종사가 클릭해 기상 확인 |
| **2. 공유자료와 작성 공간** | 파일 저장·갤러리·뷰어, 공유 지도, 비행별 글·자료·주의사항 도형 연결 | 조종사가 기상과 기관 추가자료를 함께 확인 |
| **3. 합동 브리핑** | 회차 구성, 준비·발표 화면, 지도·단면도 연동 강조, 자료 확대, 도형을 포함한 종료 기록 | 실제 회의에서 비행별 브리핑 진행 |
| **4. 기관 기상 홈과 알림** | 관심 공항·권역 설정, 기상 요약, 단순 알림·확인 처리, 지도 연동 강조 | 기관이 관심 지역의 상황을 한곳에서 확인 |

각 단계에서 실제 데이터를 저장하고 다시 열 수 있는 흐름까지 완성한다. 아직 구현되지 않은 메뉴는 사용 가능한 것처럼 노출하지 않는다.

첫 버전에는 고급 권역 기상 해설, 강수 이동 예측, 공식 NOTAM 연동, 연료·성능 계산, 당시 기상 전체 재현, 외부 알림 발송을 포함하지 않는다.

## 5. 검증과 적용

- **권한:** 다른 기관의 비행·자료·파일 URL 접근 차단, 탈퇴 후 접근 차단, 역할별 편집 권한.
- **핵심 흐름:** 경로 선택 → 예정비행 등록 → 다른 회원이 기상 브리핑 열기 → 추가자료 확인 → 합동 발표.
- **자료 보존:** 원본 경로 변경·자료 교체 이후에도 예정비행과 종료한 회차의 보존 내용 유지.
- **기상·시각:** UTC 저장과 선택 시간대 표시, 과거 출발시각 유지, 일부 기상 실패, 낙뢰 경계·기간 계산, SIGMET 유효기간·교차 판정, 알림 중복 방지.
- **화면:** 직접 URL 진입·새로고침·뒤로가기, PDF 다중 페이지, 발표 확대·복귀, 비행 전환 중 늦게 도착한 이전 응답 차단.
- **홈 배치:** 기관명·메뉴·사용자 정보의 단일 상단, 별도 홈 제목 줄 없음, 소식 줄 옆 브리핑 준비 진입, 공항 가로 요약, 지도와 우측 패널 하단 정렬. 소식 서랍에서 자료를 닫은 뒤 목록·키보드 초점으로 복귀하는지 확인한다.
- **연동 강조:** 호버 후 복귀, 클릭·터치 고정, 지도에서 카드로 역방향 연결, 선택 해제, A·B 배치 전환 시 유지, 비행 전환 시 해제, 여러 지도·확대 단면도에서 동일 항목 표시.
- **주의사항 도형:** 지점·선·구역·원 작성·수정·삭제, 미완성 도형 저장 방지, 글만 저장, 고도 미지정·지정·잘못된 범위, 경로 밖·다중 교차·경로 변경 후 재계산.
- **기기:** iPad 가로·데스크톱에서 판독성·터치·키보드 접근성과 스크롤 확인. 모바일 검증은 후속 범위로 둔다.
- 단계별 관련 테스트와 브라우저 계약을 실행하고, 최종 `npm run check`를 통과시킨다. 기존 개인 경로·기상 브리핑의 회귀를 확인한다.
- DB 변경은 기존 개인 자료를 유지하는 추가 방식으로 적용한다. 비공개 파일 저장소를 백업 대상에 포함하고, 새 의존성이 포함된 배포에는 전체 배포 절차를 사용한다.
