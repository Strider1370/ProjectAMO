# 확대영역 3변수 실험 ACI 적용 계획

상태: **적용 전 검토·구현 계획**. 운영 수집·계산·배포는 아직 적용하지 않았다. 현재 개발 지도에는 2026-09-23 저장자료의 한반도 전체 격자를 계산한 실험 레이어만 있다.

목표는 확대영역의 원본 격자·전체 예보시각에 CAPE·강수·OLR 실험 점수를 제공하는 것이다. 보고서 원본 ACI와 같은 계산이라는 의미는 아니며, 확률·운정고도는 현 실험식이 직접 산출하지 않는다.

관련 문서: [확대영역 구현 계획](2026-10-08-kim-expanded-grid-implementation-plan.md), [운영 용량 검토](../../operations/kim-grid-scaling.md), [실험식·자료 설명](../mockups/aci-experiment/README.md).

## 1. 적용 범위와 현재 식

| 항목 | 적용 기준 |
|---|---|
| 영역 | 90–160°E, 6–50°N, 841×529 = 444,889개 격자 |
| 격자 간격 | 원본 1/12° 유지. 임의 표본화·격자 생략 없음 |
| 00 UTC 회차 | +0~24h 매시간, +27~36h 3시간: 29개 |
| 06 UTC 회차 | +0~24h 매시간, +27~48h 3시간: 33개 |
| 총 계산 대상 | 하루 62개 예보시각, 27,583,118개 연직 프로파일 |
| 산출물 | CAPE(J/kg), 강수강도(mm/h), OLR(W/m²), 실험 점수(0~1), 유효/결측 상태 |

기본값에서 `clip(x) = min(1, max(0, x))`로 두면:

```text
M_CAPE = clip(CAPE / 2500)
M_RAIN = clip((강수강도 - 0.2) / 4.8)
M_OLR  = clip((230 - OLR) / 50)
ACI_experiment = 0.2 * M_CAPE + 0.4 * M_RAIN + 0.4 * M_OLR
```

현재 UI처럼 임계값과 가중치를 조정하면 각 입력을 해당 구간에서 0~1로 변환하고 가중치 합으로 정규화한다. 입력 하나라도 결측이면 최종 점수도 결측이다. 점수 0과 결측을 구분한다. 계수는 실험 설정이며 관측으로 보정된 발생 확률이 아니다.

CAPE는 현재 기준 알고리즘인 MetPy 1.7.1 `surface_based_cape_cin` 결과를 기준값으로 삼는다. 지상기압·2m 기온·2m 비습과 기존 21개 등압면 기온·비습을 사용하고, 지하층을 제외한다. 강수는 `pr × 3600`인 mm/h 상당 강도다. 보고서의 3시간 최대 CAPE·누적강수·평균 OLR를 재현하는 계획은 아니다.

## 2. API 입력과 재사용

| 입력 | 현재 확보 경로 | 새 호출 |
|---|---|---:|
| 등압면 T·q·hgt | 확대영역 기본 KIM 격자 | 0 |
| 지상 t2m | 기본 수집의 10m 레벨 T | 0 |
| 지상기압 ps | GKTG 보조 입력 캐시 | 0 |
| 지상비습 q2m | 신규 단일면 입력 | 1/시각 |
| 강수 pr | 신규 단일면 입력 | 1/시각 |
| OLR ulwrtoa | 신규 단일면 입력 | 1/시각 |

- **예보시각당 3회, 00 UTC 87회, 06 UTC 99회, 하루 186회 추가.** 재시도·실패 요청은 별도다.
- 재사용 조건은 domain·모델·tmfc·hf·격자 범위·단위가 모두 같아야 한다. 한반도 자료를 확대영역 전체 자료로 대체하지 않는다.
- 지상 일기도의 강수는 영역과 예보시각이 다르므로, 확대영역 전 시각의 강수 재사용을 기본 전제로 두지 않는다. 정확히 일치하는 캐시가 있으면 해당 호출만 생략한다.
- ps 재사용은 같은 회차 GKTG 보조 입력 저장소를 함께 읽는 경로로 구현한다. GKTG 또는 q 수집이 비활성이라 입력이 없으면 이 호출수는 달라진다. 시작 전에 필요한 기존 입력의 활성 여부를 확인한다.
- 회차별 기존 자격증명 선택·대용량 키 시간 제한·사용량 장부를 그대로 따른다. 이미 받은 입력은 재시작 시 다시 요청하지 않는다.
- 사용자가 지도·단면도를 열 때 upstream API를 호출하지 않는다. 서버의 게시된 결과만 제공한다.

## 3. 추가 용량 추정

아래 MB/GB는 10진 단위다. 실제 한반도 자료 34,645개 격자의 텍스트·gzip·기존 NC 저장 방식 실측을 444,889개 격자로 비례 환산했다. 확대영역 전체의 압축률 실측은 아니며, 기상 분포에 따라 달라진다.

| 추가 항목 | 예보시각 1개 | 00 UTC 29개 | 06 UTC 33개 | 하루 62개 |
|---|---:|---:|---:|---:|
| API 응답 텍스트 수신 | 약17.6MB | 약510MB | 약580MB | 약1.09GB |
| 원문 gzip 캐시 | 약2.43MB | 약70.5MB | 약80.2MB | 약151MB |
| 입력3개 + CAPE·점수 NC | 약7.10MB | 약206MB | 약234MB | 약440MB |
| NC와 원문 합계 | 약9.54MB | 약277MB | 약315MB | 약591MB |

NC 추정은 현재 `kim-doc-store.js`의 배열 압축 방식으로 측정했으며 점수는 1e-4 간격 int16 저장안이다. 새 입력과 CAPE의 자료형·허용 오차를 확정한 후 다시 측정한다. JSON 저장 모드에는 이 수치를 적용하지 않는다.

게시 회차와 수집 회차를 최대 2개 보관하고 이전 회차를 제거하면 추가 디스크는 약0.6GB 수준이며, 33개 시각 두 회차면 약0.63GB다. 타일·계산 임시파일·인덱스는 제외한 값이다. 적용 전 약1GB 이상의 추가 디스크 여유를 잡고 실제 회차 크기로 기존 디스크 보호선의 예산을 갱신한다. 하루마다 계속 누적 보관하는 계획이 아니다.

표시 전송 추정:

- 점수 int16 배열만: gzip 약0.48MB/시각.
- CAPE·강수·OLR float32와 점수 int16: gzip 약2.88MB/시각.
- 현재 실험의 셀별 객체 JSON을 그대로 확대하면 무압축 약62.8MB, gzip 약11.1MB/시각이다. 운영 제공 형식으로 사용하지 않는다.
- 44만개 사각형 GeoJSON을 브라우저에 생성하는 방식도 유지하지 않는다. 기존 압축 격자/래스터·화면 범위 요청과 지점 조회를 사용한다.

측정 도구와 결과는 현재 로컬 `artifacts/aci-capacity/{measure.mjs,measurement.json,client-measurement.json}`에 있다. artifacts는 임시 산출물이므로 위 표가 추적 가능한 계획 기록이다.

## 4. 계산 시간: 선행 해결 사항

현재 Python/MetPy 함수를 기존 원본 격자에서 균등 추출한 518개 프로파일에 순차 실행한 결과:

| 항목 | 로컬 실측·환산 |
|---|---:|
| 518개 계산 | 2.263초 |
| 프로파일당 | 약4.37ms |
| 확대영역 1개 시각, 1코어 환산 | 약32.4분 |
| 하루62개 시각, 1코어 환산 | 약33.5 CPU시간 |

운영 VM 실측은 아니다. 로컬 측정만으로도 현재 구현을 그대로 전 시각에 적용하면 하루 CPU 작업이 24시간을 넘는다. 기존 GKTG·권계면 작업과 공유하는 운영 서버에 곧바로 추가하지 않는다.

최적화는 Python 격자별 호출 비용을 줄이는 일괄·컴파일 계산을 우선 검토한다. Numba/Cython/Fortran 등의 선택은 동등성 시험과 실제 속도 측정 후 결정한다. 병렬 프로세스를 늘리는 것만으로 해결했다고 판단하지 않는다. 계산 블록은 전체 원본 격자를 빠짐없이 처리하는 메모리·작업 분할이며, 격자 해상도를 낮추는 방식이 아니다.

기준 알고리즘과 비교할 항목은 parcel 상승, 수증기/가상온도 처리, LCL/LFC/EL 선택, 양의 부력 적분과 결측 처리다. 단순히 이름이 CAPE인 다른 알고리즘으로 바꾸지 않는다. 현재 비정상 음수 CAPE도 분석하고, 근거 없이 0으로 바꾸지 않는다. 자료 상한 150hPa에서 적분이 잘리는 상태는 별도 플래그로 남긴다.

**진행 조건:** 확대영역 실제 회차 전체를 운영과 같은 CPU 제한·기존 작업 동시 조건에서 측정하고, 해당 00/06 UTC 수집·게시 시간 내 모든 예정 시각이 처리되는지 확인해야 한다. 실패하면 계산 최적화를 계속하고 운영 활성화를 보류한다.

## 5. 구현 순서

### 1단계 — 계산 기준과 성능 검증

- 순수 계산 모듈과 과거 실제 자료 기준 결과를 만든다. 운영 코드가 frontend 또는 docs mockup을 import하지 않게 한다.
- 기존 MetPy를 검증용 기준으로 유지하고 일괄 계산 후보를 비교한다. 계산 오차 허용치는 명시적으로 정한 후 비교한다.
- 안정/불안정, 산악 지하층, 건조 상층, 복수 부력층, EL 미검출, 입력 결측 사례를 포함한다.
- 최적화 후 원본 확대영역 전 격자·전 시각의 시간·RSS·출력 용량을 측정한다.

### 2단계 — 입력 수집과 저장

- 확대 회차의 기존 예보시각별 수집에 q2m/pr/ulwrtoa를 추가한다. 기존 동시요청 상한을 함께 공유한다.
- ps와 T/q/t2m은 동일 회차의 이미 수집된 자료를 읽는다. 자료 식별자·단위·배열 크기를 검증한다.
- 원문은 현재 저장 정책에 맞춰 압축 캐시하고, 정규화 입력·파생 결과는 운영 NC 경로에 둔다.
- 계산 버전, 입력 revision, 고정 기준값, 결측 수, 적분 상한 상태를 기록한다.
- 신규 운영 플래그·설정은 기본 비활성으로 설계한다. 구체적인 환경변수명은 구현 시 확정한다.

### 3단계 — 계산·게시 연결

- 예보시각별 기존 derived worker 흐름에 ACI 작업을 연결한다. 무거운 계산 동시실행 수와 메모리 보호선을 공유한다.
- 입력 및 출력 전체 검증 후 결과·인덱스를 원자적으로 게시한다. 일부 실패가 기존 KIM 회차나 마지막 정상 ACI를 지우지 않게 한다.
- 누락 예보시각은 명시적으로 unavailable로 표시한다. 선택한 시각을 다른 시각의 결과로 대신하지 않는다.
- 재시작·재시도는 입력 revision과 계산 버전으로 중복 계산을 피한다. 같은 회차 정리 시 입력·결과·타일까지 함께 제거한다.

### 4단계 — 지도와 연직단면도

- 기존 위성 ‘대류 가능성’과 별개인 ‘대류 실험’ 레이어를 유지한다. 과거 고정 파일 대신 게시된 회차·시각 자료를 읽는다.
- 지도는 압축 격자에서 값 구간별 면 또는 래스터로 표시한다. 현재 임계값 0.25/0.50/0.75는 실험 기준으로 명시하고 결측을 0점과 구분한다.
- 지점 클릭으로 CAPE·강수·OLR·점수·실제 유효시각을 조회한다. 조절 가능한 가중치·임계값은 같은 입력으로 재계산하며 API 호출을 늘리지 않는다.
- 단면도에서도 같은 회차·예보시각·계수로 산출한 결과만 사용한다.
- **현재 점수는 단일면 값이므로 운정고도 선이나 고도별 색 띠를 직접 그릴 수 없다.** 운정고도 변환이 준비되기 전에는 항로 위치별 점수를 별도 보조 띠/차트로만 제공한다.

### 5단계 — 운정고도 선(별도 후속 범위)

- 사용자가 논의한 선 표시는 각 항로 위치의 ACI 기반 추정 운정고도를 세로축에 연결하는 방식이다.
- 현재 실험 점수에 맞는 고도 변환 관계를 관측자료로 도출·검증해야 한다. 보고서 원본 ACI의 `ACIintoFL` 표를 그대로 적용하지 않는다.
- EL은 다른 운정 추정 방법이며 이번 ACI 적용 계획의 대체 계산으로 혼용하지 않는다.
- 변환이 검증되면 지도에서 2,500ft 구간의 운정 높이를 표시하고, 단면도에서는 높이 선과 계획 비행고도를 비교한다. 결측에서는 선을 끊고 선 아래 전체를 구름으로 해석하게 만들지 않는다.
- 확률은 이번 범위에서 제외한다. 단일 예측 점수를 퍼센트로 표시하지 않는다. 향후 TLE를 추가한다면 동일 유효시각의 복수 회차를 정렬한 별도 계획이 필요하다.

## 6. 검증·배포·완료 기준

- 계산: 기준 MetPy와 실제 격자의 수치 비교, 경계·결측·지하층·자료상한 검증, 전 격자 처리 수 확인.
- 수집: 정상 반복 수집에 신규 요청이 시각당 최대3회인지, 캐시 재사용·키 선택·재시도·부분 실패를 확인.
- 운영: 전 회차 CPU/RSS/디스크 증가량과 기존 수집 게시 시각, 건강상태를 함께 측정한다. 표의 추정을 실측 결과로 갱신한다.
- 브라우저: 레이어 토글·지점조회·시간 변경·배경지도2회 전환·모바일·지도/단면도 값 일치와 UTC/KST 표시 검증.
- 해당 단위/통합 검사, `npm run check`, 관련 브라우저 계약을 완료한다.
- 의존성 변경이 있으면 full deploy 경로와 Python 환경 구성까지 준비한다. 배포와 활성화는 별도 실행 단계다.
- 초기에는 기본 비활성으로 배포하고 검증된 회차부터 활성화한다. 이상 시 플래그로 ACI 수집·계산·표시만 중지하고 기존 KIM/GKTG/권계면 기능을 유지한다.

완료는 단순히 레이어가 보이는 상태가 아니라, 원본 확대영역·모든 예정 시각을 처리하며 운영 시간·자원 예산을 충족하고 결과가 같은 시각으로 지도와 단면도에 제공되는 상태다. 운정고도 변환 완료 여부는 점수 레이어 완료와 별도로 기록한다.

## 7. 구체적인 계산 최적화안 (2026-10-09)

### 확인한 병목

로컬 기존 함수의 129개 연직 프로파일에 cProfile을 적용했다. 전체 2.075초는 프로파일러가 포함된 값이므로 앞의 속도 추정(프로파일러 없는 518개 실측)에 대입하지 않는다. 여기서는 상대적인 호출 구조만 확인한다.

- 129개에 약329만 함수 호출이 발생했다.
- `surface_based_cape_cin` 누적1.832초, `parcel_profile_with_lcl` 1.006초, `cape_cin` 0.793초였다.
- MetPy의 단위/xarray 래퍼와 Pint 객체가 반복 호출된다. Pint Quantity 생성만28,891회였다.
- `solve_ivp`를 프로파일마다129회 부르며 누적0.521초였다. 습윤 상승의 미분식이 Python 콜백으로14,851회 평가됐다.
- 누적시간은 상위/하위 호출이 중첩되므로 서로 더하거나 독립적인 비율처럼 해석하지 않는다.

근거는 로컬 설치된 MetPy1.7.1의 `thermo.py` 및 `artifacts/aci-capacity/{profile-cape.py,cape-profile.txt}`다.

### 권장 구현: 단위 변환 1회 + 컴파일 연직 커널 + 원본 격자 블록

1. **입력 전처리를 한 번에 수행한다.** NC에서 블록의 T/q/ps/t2m/q2m를 배열로 읽는다. 단위 검증·변환은 읽기 경계에서 수행하고 수치 커널에는 Pa/K/kg/kg의 숫자 배열을 전달한다. 격자마다 dict·Pint·xarray 객체를 만들지 않는다. 지하층 제외와 기존 이슬점 제한 정책은 유지한다.
2. **Numba를 첫 후보로 삼는다.** 운영 GKTG에 이미 쓰는 런타임을 재사용할 수 있다. 다만 기존 MetPy 함수에 `@njit`만 붙이는 것은 해결책이 아니다. 지상 parcel 초기화, LCL, 건조/습윤 상승, 가상온도, LFC/EL 교차점, 부력 적분을 숫자 배열만 쓰는 별도 커널로 구현한다.
3. **습윤 상승 적분기를 커널 안에 넣는다.** MetPy의 미분식·상수·적분 방향을 명시적으로 맞춘다. adaptive RK 계열 등 컴파일 가능한 적분기를 후보로 검토하되 LSODA와 수치 경로가 달라질 수 있으므로 결과 동등성을 검증한 후 채택한다. 오차 제어 없는 거친 고정 간격 적분으로 바꾸지 않는다. Numba 후보가 정확성/속도 기준에 실패하면 Cython/Fortran의 같은 계산을 다음 후보로 검토한다.
4. **64×64 또는128×128 블록으로 전체를 처리한다.** CAPE는 각 열의 연직 프로파일로 계산하므로 수평 이웃과 겹침 영역이 필요 없다. 마지막 가장자리 블록까지 모두 처리한다. 전역 객체·전체 연직 자료의 불필요한 복사를 줄이고 블록 결과를 기존 NC 저장 경로에 반영한다.
5. **운영은 우선1 worker/1 thread다.** 다운로드·GKTG·권계면과 기존 자원 예산을 공유한다. 검증용 로컬 병렬화와 운영 서버의 실행 수를 구분한다. 운영에서 무거운 작업을 무조건 동시에 추가하거나 스왑에 의존하지 않는다.
6. **강수·OLR 멤버십과 합성은 배열 연산으로 계산한다.** CAPE와 같은 시각의 입력에서 한번 계산한다. 사용자가 가중치·임계값을 바꿀 때 CAPE를 다시 적분하지 않고 이미 저장된 세 입력을 재사용한다.
7. **revision 캐시를 둔다.** `(domain,tmfc,hf,inputRevision,algorithmVersion)`이 같으면 CAPE와 점수를 재계산하지 않는다. 계수만 바뀌면 점수만 다시 계산한다. 계산 버전을 결과에 기록한다.

### 수치 검증과 속도 목표

**목표는 검증 전 예상 성과가 아닌 합격 기준이다.** 확대영역444,889열을1코어에서 우선90초 이하, 목표60초 이하에 처리한다. 현32.4분 추정 대비 약22~32배 개선이 필요하다. 90초면 하루62개에 약1.55 CPU시간, 60초면 약1.03 CPU시간이다. I/O·처음 JIT 컴파일 시간과 기존 작업 지연을 별도로 측정한다. 운영 VM에서 달성하지 못하면 활성화하지 않는다.

비교는 단계별로 수행한다:

- 검증용 다양한 과거 프로파일에서 MetPy의 parcel 온도/LCL/LFC/EL/CAPE/CIN과 비교한다. 0에 가까운 CAPE, 여러 부력층과 높은 지형, 프로파일 상한을 포함한다.
- 초기 CAPE 오차 합격 후보는 `max(1 J/kg, 기준 CAPE의0.1%)` 이내다. 이 기준은 실험 제안이며 parcel/교차점 검증 결과를 보고 확정한다.
- 오차 범위 안이어도 점수 색 구간 경계를 넘는 격자, 유효/결측 판정이 다른 격자는 따로 확인한다. 근거 없는 결측→0 변환은 금지한다.
- 한반도34,645열 전체를 기존 결과와 비교한 후 확대영역 실제 전 격자·전체62개 예보시각으로 확대한다.
- warm/cold 계산시간, worker RSS, CPU사용, 게시 완료시각을 함께 기록한다. 서버 건강상태와 GKTG·권계면 게시 시각이 기존 계약 안에 있어야 한다.

### 구현 우선순위와 적용하지 않을 지름길

전처리 배열화 → 동일 계산의 Numba 커널 → MetPy 비교 → 확대 전 격자 벤치마크 → 운영 worker 연결 순서로 진행한다. 각 단계에서 실제 측정을 남긴다.

8칸마다 계산하거나 예보시각을 줄이는 방식은 이 계획의 최적화가 아니다. CAPE/RH 등의 경험 임계값으로 계산 전에 격자를 삭제하거나, 기존 Fortran의 다른 parcel 방식으로 조용히 교체하지 않는다. 보고서의 고도 변환을 EL로 바꾸는 작업도 포함하지 않는다. 전체 입력과 계산 의미를 유지하면서 구현 비용을 줄이는 것이 목적이다.

## 11. 20hPa 채택 및 최초 방식 대비 시간 단축

2026-10-09 사용자 결정에 따라 실험 커널의 내부 습윤 상승 적분 최대 간격을 **20hPa(2000Pa)**로 채택했다. 원본 수평 격자나 입력 연직층을 줄이는 변경은 아니다. 향후 운영 적용 계획은 이 간격을 기준으로 한다.

운영서버에서 2026-10-09 00UTC +12h 확대영역 841×529=444,889개 격자를 전체 계산한 결과, ACI 생성은 **41.23초**였다. 이전 실측의 신규 입력3종 수집·파싱·캐시 저장 평균6.01초를 더하면 **약47.25초/예보시각**이다. 최대 RSS는340.38MiB, MetPy 비교 표본1,118개의 유효 판정·허용 오차 초과·색 구간 불일치는 각각0개였다.

| 단계 | 예보시각1개 | 00UTC 회차29개 | 06UTC 회차33개 | 측정 근거 |
|---|---:|---:|---:|---|
| 최초 MetPy 방식 | 약32.4분 | 약15시간40분 | 약17시간49분 | 로컬 일부 프로파일 계산의 확대 환산, 주로 CAPE 계산 비용 |
| 컴파일 후1hPa | 약2분21초 | 약68분 | 약78분 | 운영 실제 확대4개 시각 생성 평균135.14초 + 신규 입력 평균6.01초 |
| **현재20hPa** | **약47초** | **약23분** | **약26분** | 운영 실제 확대1개 시각 생성41.23초 + 기존 신규 입력 평균6.01초 |

00UTC 한 회차 기준 최초 추정 대비 약15시간17분 단축(약98% 감소, 약41배), 직전1hPa 대비 약45분 단축(약67% 감소, 약3배)이다. 이는 **ACI 추가 처리 시간** 비교이며 기존 KIM 전체 작업 시간의 감소를 의미하지 않는다. 최초의 로컬 환산과 이후의 운영 실측은 동일한 환경·범위의 직접 비교가 아니므로 개선 규모를 설명하는 추정으로 사용한다.

회차29/33개 시간은 예보시각별 비용의 합산 추정이며 20hPa에서 회차 전체를 실행한 결과가 아니다. 기존 GKTG186.37초·권계면38.55초와 ACI47.25초를 순차 합산하면, 00UTC 약2시간12분·06UTC 약2시간30분이다. 이 전체 합산에는 기존 KIM 원본 다운로드 시간이 제외되어 있고 병렬 처리·캐시 재사용에 따라 실제 게시 완료 시간은 달라진다.

로컬 커널 테스트8개와 한반도34,645개 검증도 통과했다. 상세 실측과 한계는 [운영서버 검증 기록](2026-10-09-expanded-aci-operating-server-validation.md#20hpa-채택-후-전체-확대영역-재측정)에 기록했다. 원본은 `artifacts/aci-operating-check/benchmark-20hpa.json`이다. 실험 기본값 변경과 독립 검증까지 완료했으며, 운영 자동 수집·게시 활성화는 아직 수행하지 않았다.

## 12. 로컬 확대영역 한 시각 지도 미리보기

2026-10-09 사용자 요청으로 00UTC +12h(유효12UTC / 21KST)의 확대영역 입력을 로컬에서 대용량 키로 직접 받았다. 21개 등압면 T·q와 ps·t2m·q2m·pr·OLR 총47회, 약274.23MB, 수집·파싱·캐시 저장 약42초였다. 기존 입력이 없는 독립 로컬 시험이라 모두 받은 횟수이며, 운영 추가 입력3회와 구분한다.

20hPa 커널로 원본841×529=444,889개 전부를 계산했고 유효443,071개, 로컬 계산 약13.64초였다. 운영 VM의41.23초와 같은 환경에서 측정한 값이 아니다. 지도에는 CAPE·강수강도·OLR의 float32 배열(약5.34MB)을 읽어 Web Mercator 행 보정·최근접 격자 이미지로 표시한다. 44만 개 Polygon 생성은 피하고 모든 격자를 계산·보존한다. 클릭 시 원본 격자의 입력3개·점수·기여도를 조회하고 가중치 변경은 CAPE를 재계산하지 않는다.

로컬 앱 `http://localhost:5173`의 기상정보 → 수치모델 → 대류 실험에서 확인한다. 발표/유효시각은 실제 저장 사례 메타에서 표시하며, 앱 타임라인 및 고도 선택과 독립임을 범례에 표시한다. **현재 점수는 연직 프로파일의 CAPE를 포함하는 수평 점수로서, 고도별 값·운정고도·보정된 발생 확률을 제공하지 않는다.** 운영 자동 수집·API 게시에는 연결하지 않았다.

입력 및 측정: `artifacts/aci-expanded-local/collection.json`, `calculation.json`. 표시 자료: `frontend/public/data/aci-experiment/expanded-latest.json`, `2026100900-hf012-expanded.f32`. 지도 화면: `artifacts/aci-expanded-local/expanded-map.png`.

미리보기 검증: 관련 단위 테스트4개와 프런트엔드 빌드 통과. 브라우저에서 원본 이미지 레이어·격자 클릭 값·가중치 변경·켜기/끄기·배경지도2회 변경 후 복구·모바일 가로 넘침 없음 확인. 133°E/15°N 조회 예: 점수0.693, CAPE2774J/kg, 강수1.04mm/h, OLR162.9W/m². 브라우저 검증 기록은 `artifacts/aci-expanded-local/browser.json`이다.

## 13. 임계값·가중치 비교 후보 지도

같은 확대영역 한 시각에서 현재 기준과 비교 후보를 실제 프런트엔드 계산 함수로 비교했다. 후보는 CAPE0~2500J/kg, 강수0.2~5mm/h, OLR230→180W/m²의 선형 점수와 가중치0.2:0.4:0.4이다. 색 경계0.25/0.50/0.75와 투명 처리 기준은 유지했다. 검증된 관측 보정 계수가 아닌 실험 설정이다.

| 유효443,071개 격자 중 비율 | 현재 기준 | 비교 후보 |
|---|---:|---:|
| 투명(0.25 미만) | 55.22% | 81.55% |
| 0.25~0.50 | 33.53% | 9.20% |
| 0.50~0.75 | 10.01% | 8.77% |
| 0.75 이상 | 1.23% | 0.48% |
| 강수0.1 미만·OLR230 초과인데 표시됨 | 22.13% | 0% |

표시 영역은44.78%→18.45%로 줄었다. 넓은 옅은 색 영역이 사라지고 필리핀·인도차이나 및 서태평양의 구름·강수 신호를 동반한 영역은 남는다. 이것이 탐지 정확도 개선을 입증하지는 않으며 위성·낙뢰 관측과 별도 대조해야 한다.

로컬 범례에 ‘현재 기준’·‘비교 후보’ 버튼을 추가하여 같은 자료에서 전환할 수 있다. 초기 기본값은 유지했다. 후보 적용과 원래 이미지 복구 및 입력값 일치를 브라우저로 확인했고 관련 단위 테스트4개·빌드도 통과했다. 추가 API 호출과 CAPE 재계산은 없었다. 원본 결과는 `artifacts/aci-expanded-local/threshold-comparison.json`, 화면은 `threshold-current.png`와 `threshold-candidate.png`, 브라우저 검증은 `threshold-browser.json`이다.

## 14. 비교 후보를 기본값으로 채택

2026-10-09 사용자가 비교 지도 확인 후 후보를 채택했다. 상단 계산식과 로컬 지도 기본값을 CAPE0~2500J/kg·강수0.2~5mm/h·OLR230→180W/m², 가중치0.2:0.4:0.4로 변경했다. 20hPa 적분 간격, 원본 격자, 입력3종, 색 경계0.25/0.50/0.75는 유지한다. ‘채택 기준’이 초기값 및 기본값 복귀 대상이고, ‘이전 기준’은 과거 설정과의 비교용이다. 기존 절의 측정 기록은 당시 설정의 결과로 보존한다.

기존 운영 독립 벤치마크의 저장 점수와 `verify_local.py`의 과거 점수 비교는 변경 전 기준의 검증 기록이며, 새 기본 점수로 재생성한 운영 산출물이 아니다. CAPE 커널 자체는 변경하지 않았고 추가 API 호출·CAPE 재계산도 필요하지 않다. 운영 자동 수집·게시 활성화는 별도 단계로 남는다.

채택 후 검증: 관련 단위 테스트4개·프런트엔드 빌드 통과. 브라우저에서 초기 채택 기준 선택, 이전 기준 전환, 채택 기준 복귀 시 원본 이미지 복구를 확인했다. 기록: `artifacts/aci-expanded-local/adopted-browser.json`.
