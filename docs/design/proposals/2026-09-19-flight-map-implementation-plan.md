# 내 지도 — 실제 구현 계획

정리: 2026-09-19

현재 프로젝트와의 대조 결과는 아래 **6. 구현 가능성 검토**에 기록한다. 핵심 UI/UX는 구현 가능하며, 지도 입력 충돌과 이탈 처리부터 확인한다.

사용자 동작과 범위는 UI/UX 명세를 따른다. 이 문서의 파일 분할·자료 구조·API는 구현 기본안이다. 기존 구조에 맞춰 조정할 수 있지만 점·선·면·원, 보기/편집 분리, 자료 보존 등의 계약은 유지한다. **실제 실행 순서·서브에이전트·모델은 7절을 기준으로 한다.** T1~T8은 기능별 작업 목록으로 유지하며, 파일 조회 부분은 후속 메타데이터 합의에 따라 앞당긴다. 제품 구현은 착수했으며 진행 기록과 검증 근거는 아래 표에 갱신한다.

## 2. 자료와 상태의 구현 기본안

### 영속 자료

| 자료 | 필요한 값·불변 조건 |
|---|---|
| 개인 지도 | id, ownerId, schemaVersion, revision, name, groups, items, createdAt, updatedAt |
| 그룹 | id, name, order. 한 단계만. 이름 변경으로 소속 불변 |
| 항목 | id, groupId 또는 null, order, kind, name, description, geometry/definition, style, label, altitude |
| 가져온 원본 항목 | sourceAssetId, sourceItemId, 원본 폴더 경로/식별자, 순서 있는 metadataEntries, 원문 설명, 복수 기하. 조회 원본과 편집 가능 도형을 구분 |
| 메타데이터 필드 | 원본 필드명·원본 값·형식·출처 위치를 순서 있는 배열로 보관. 중복 필드명 유지. 요약은 검증된 해석 결과이며 원본 필드를 대체하지 않음 |
| 렌더링 조각 | sourceItemId에 연결된 표시용 기하. 목록 개수·저장 revision·undo의 원본 항목 단위와 구분 |
| 점·선·면 | WGS84 GeoJSON. 좌표 순서는 경도·위도. 면은 닫힌 링 |
| 원 | kind=circle, center=[경도, 위도], radiusNm. 표시용 polygon은 계산 결과이며 편집 원본이 아님 |
| 스타일/이름표 | 색·투명도·굵기·채움·점 크기/아이콘·점선·이름 크기·기본 표시 정책. 종류별 유효 값 검사 |
| 고도 | floorFt, ceilingFt, datum. 신규는 MSL. null과 0 구분, floor<ceiling. 미지원 기준을 MSL로 추정하지 않음 |
| 기관 지도 | id, organizationId, publisherId, sourcePersonalMapId, latestVersion, 상태 |
| 기관 버전 | sharedMapId, version, sourceRevision, snapshot, note, createdBy, createdAt. 생성 후 불변 |

ID는 이름과 독립적이다. 복제·가져오기 시 지도/그룹/항목 ID를 새로 만들고 참조를 함께 치환한다. ‘그룹 없음’은 groupId=null의 표시이며 저장 그룹을 중복 생성하지 않는다. 개인 원본 삭제가 기관 스냅샷을 연쇄 삭제하지 않도록 참조 정책을 정한다.

### 화면·편집·저장 상태

- 화면: library / view / edit, 현재 지도 ID, 여러 표시 지도 ID, 선택 항목 ID, 펼침 상태. 읽기 표시 설정은 자료 변경과 분리한다.
- 편집: idle / creating / editingGeometry. 임시 기하와 완료 자료를 별도로 보관한다. 공유·내보내기에는 완료 자료만 사용한다.
- 저장: localOnly / dirty / saving / synced / offline / error / conflict와 마지막 확인 revision. 서버가 확인한 변경까지만 ‘계정에 저장됨’으로 표시한다.
- 되돌리기: 한 점 추가, 여러 항목 이동, 전체 형태 드래그, 입력창 수정 완료를 각각 한 번의 명령으로 처리한다. 지도별 이력이며 원격 revision과 동일 개념이 아니다.
- 복구: 계정별 완료 자료와 미완성 초안을 분리한다. 로그아웃/계정 전환 시 다른 계정 자료를 노출하지 않는다. 비로그인 자료는 명시적으로 가져오며 자동 귀속하지 않는다.

자동저장은 완료 변경을 묶어 전송하되 진행 중 요청과 후속 변경을 구분한다. 오래된 응답이 최신 상태를 덮거나 저장 완료로 표시하면 안 된다. revision 충돌은 자동 덮어쓰지 않고 내 변경 사본 보존과 서버본 다시 열기를 제공한다. 서버 확정 전 공유를 누르면 저장 완료를 기다리고, 실패하면 공유 성공을 표시하지 않는다.

### API 기본안 — 아직 존재하지 않는 경로

| 요청 | 역할·검증 |
|---|---|
| GET /api/me/maps | 소유한 지도 요약 목록 |
| POST /api/me/maps | 새 개인 지도 생성, 스키마·크기·좌표 검증 |
| GET /api/me/maps/:id | 소유자 검사 후 내용/ revision 반환 |
| PUT /api/me/maps/:id | expectedRevision과 완료 snapshot. 조건부 갱신, 충돌 409 |
| DELETE /api/me/maps/:id | 개인 지도만 삭제 |
| GET /api/organizations/:orgId/maps | 활성 멤버십 검사 후 기관 목록 |
| POST /api/organizations/:orgId/maps | personalMapId + expectedPersonalRevision. 서버가 소유 원본을 읽어 공유본 생성 |
| GET /api/organizations/:orgId/maps/:id | 활성 멤버십·기관 일치 확인 후 최신 자료 |
| POST /api/organizations/:orgId/maps/:id/versions | 게시자/관리자 검사, 소유한 원본 revision과 expectedSharedVersion으로 새 버전 생성 |
| DELETE /api/organizations/:orgId/maps/:id | 게시자/관리자의 공유 중단 |

공유 입력의 snapshot·ownerId·organizationId를 그대로 신뢰하지 않는다. 읽기 검사와 버전 생성은 트랜잭션으로 묶는다. 관리자의 업데이트도 본인 소유 원본/개인 사본에서 수행하며, 게시자의 개인 원본 접근 권한을 주지 않는다. 과거 기관 버전 조회 API가 필요하면 동일 권한 검사를 적용한다.

모든 쓰기에는 기존 인증·신뢰 출처 검사 패턴을 따른다. UTC 시각을 저장한다. 요청 크기·항목 수·좌표 수·KMZ 해제 크기 제한은 현재 Express/프록시와 실제 표본을 확인하여 일관되게 정하고 오류 메시지로 알린다. 수치를 임의로 하드코딩한 프론트 검사만으로 끝내지 않는다.

## 3. 기능별 작업과 완료 조건

T 번호는 기능별 추적용이다. 실제 착수·병렬 합류 순서는 7절의 1~6단계를 따른다. T7의 원본 조회/메타데이터는 T2와 함께, 편집 변환/내보내기는 저장 통합과 함께 진행한다.

### T1. 도메인 모델과 편집 상태 분리

- [ ] 지도/그룹/항목 스키마와 순서·ID 규칙, 원의 정의를 구현한다.
- [ ] /draw의 기하·명령 이력을 지도 인스턴스 생성 코드와 분리한다.
- [ ] 생성/속성/형태 수정/초안 취소 전환을 명령으로 정의한다.
- [ ] 유효성·ID 재매핑·취소 복구·한 행동 한 undo를 검증한다.

완료 조건: React/Mapbox 없이 도메인 변경과 취소를 검증할 수 있고 기존 /draw 기하 테스트가 유지된다. 관련 FM-05, 06, 10, 12.

### T2. 기존 지도에 목록·보기 연결

선행: T1.

- [ ] V1/V2/V3을 기존 내 지도 진입점에 연결하고 빈 상태·검색·표시 토글을 제공한다.
- [ ] V3에 가변 속성표·글/표 설명·인식된 형식의 선택적 요약을 구현한다. 특정 공역 파일의 필드 수나 이름을 고정 양식으로 삼지 않는다(FM-21).
- [ ] 여러 지도 표시, 목록/지도 선택 동기화, 하단 읽기 상세를 구현한다.
- [ ] 지도 카메라·배경·기상 상태를 유지하고 기존 KML 원본 보기와 공존한다.
- [ ] style 변경 이후 source/layer/image와 선택 상태를 복원한다.
- [ ] 일반 조회 레이어와 편집용 Draw를 분리하고 기존 지도 도구와 Draw 활성 상태를 상호 배타적으로 관리한다.

완료 조건: 보기에서 편집 손잡이가 나오지 않고, 배경지도 두 번 전환 후에도 자료·표시 상태가 유지된다. 관련 FM-01~03, 09, 13, 20.

### T3. 네 도구와 속성·형태 편집

선행: T1~2.

- [ ] E1~E4를 같은 왼쪽 패널 교체로 구현한다. 기본 도구는 점·선·면·원만 노출한다.
- [ ] 단건/연속 지점, 선/면 완료, 중심·반경 원 작성을 구현한다.
- [ ] 속성 즉시 반영, 전체 이동·꼭짓점 추가/이동/삭제·반경 수치 편집을 연결한다.
- [ ] 완료/취소와 두 선택지 이탈 대화상자, undo/redo를 구현한다.
- [ ] 사이드바·검색·다른 지도 등 이탈 경로에도 같은 확인을 연결하고, 작성 중 공항 클릭·경로 드래그·전역 단축키 우선순위를 정한다.

완료 조건: 미완성 초안만 폐기되고 완료 항목은 남는다. 형태 취소는 시작 상태로 정확히 복구된다. 원 반경은 픽셀 환산을 쓰지 않는다. 관련 FM-04~06, 10.

### T4. 반복 작성·그룹 정리

선행: T3.

- [ ] 한 단계 그룹·대상 그룹·다중 선택·그룹 해제/삭제를 구현한다.
- [ ] 항목/그룹 정렬, 그룹 간 드래그, 다중 드래그, 접힌 그룹 펼침·스크롤·삽입 표시를 구현한다.
- [ ] 이동 메뉴·키보드 대체, 검색 중 순서 조작 제한을 제공한다.
- [ ] 좌표 여러 줄 붙여넣기·오류 행 확인·대상 그룹 선택을 구현한다.
- [ ] 이름표와 종류별 스타일·최근 스타일 상속을 연결한다.

완료 조건: 여러 점 작성→묶기→그룹 이동→한 번 되돌리기가 동작한다. 표시 끄기와 선택은 독립적이다. 관련 FM-07~09, 18, 20.

### T5. 개인 저장·복구·지도 관리

선행: T1. UI 연결은 T2~4 후.

- [ ] 개인 지도 DB/API, 서버 경계 검증·소유권 검사·revision 충돌 처리를 구현한다.

## 4. 검증 실행 지침

제품 구현 시 변경 영역에 맞춰 기존 단위 테스트를 확장한다. 실제 위험인 기하 취소·불변 공유본·revision·원본 보존·권한에 집중하고 단순 마크업 복제 테스트는 피한다.

| 검증 | 대상 |
|---|---|
| 기하·도메인 단위 테스트 | 기존 shapeBuilders/history 및 새 명령·ID/그룹 순서·좌표 오류 |
| 파일 왕복 | 기존 importKml/kmlWrite/roundtrip에 원·고도·폴더·중첩·미지원 표본 추가 |
| 가변 상세 | 알려진 공역 요약, 미지 필드 5/50개, 중복 필드명, 긴 값, 글/표 설명, 0/false/빈 값, 설명 없음, 부분 해석 실패, HTML 비실행 |
| 백엔드 통합 | 소유권·멤버십·출처·동시 revision·불변 버전·삭제 독립성 |
| 브라우저 | V1→E1→E2→V2, 연속 추가·드래그·이탈·복구·저장 실패·기관 수신 |
| 지도 회귀 | 기상/공역 켠 상태, 배경 2회 교체, 편집 종료 후 클릭/팬 동작 정상 |

기본 명령:

~~~sh
npm run check
npm run dev:contract -- --grep my-map
npm run dev:contract -- --grep map-base
~~~

check는 오프라인 테스트와 빌드이며 브라우저 검증을 대신하지 않는다. 현재 my-map 계약은 기존 파일 기능 중심이며 모바일 진입 검증은 빠져 있다. 새 흐름에 맞게 계약/fixture를 추가한 뒤 실행한다. 새 계약 ID는 등록 전부터 존재하는 것처럼 문서화하지 않는다. 서버·캡처 운영은 [운영 안내](../../operations/dev-server-and-capture.md), 레이어는 [지도 계약](../../policies/engineering/map-and-layers.md), 시각 스타일은 [디자인 언어](../../policies/design/design-language.md)를 따른다.

## 6. 구현 가능성 검토 — 2026-09-19

### 판단

**현재 기술과 프로젝트 구조로 시안의 핵심 화면·동작을 구현할 수 있다.** 지도 엔진 교체나 별도 편집 애플리케이션 신설이 필요한 근거는 발견하지 못했다. 기존 내 지도 진입점과 MapView에 기능을 통합하는 방향이 맞다. 다만 시안 전체가 바로 제품 코드로 옮겨지는 상태는 아니다. 계정 저장·기관 지도·그룹 자료 구조는 새 구현이며, 기존 /draw도 편집 생명주기 분리가 필요하다.

| 영역 | 현재 기반 | 판정 |
|---|---|---|
| 화면·패널 | 내 지도 진입점, 패널 교체 위치, 320~420px 공통 폭 토큰 | 시안의 목록/보기/편집/하단 상세를 React로 구현 가능 |
| 점·선·면·원 | Draw, 실제 좌표 기반 원 생성, 속성·이력·가져오기 함수 | 계산·도구 로직 재사용. 선택과 형태 수정 모드는 분리 필요 |
| 그룹·다중 드래그 | 기존 폴더 문자열, 단일 선택 중심 UI | ID 기반 그룹·순서·다중 선택과 조작 UI 신규 구현 |
| 이름표·스타일 | 점·선·면 이름 레이어와 색/굵기/채움 | 크기·표시 우선순위·스타일 상속 등 보완 |
| 개인 저장 | /draw localStorage, 원본 파일 IndexedDB | 여러 지도·계정 저장·revision API 신규 구현 |
| 기관 공유 | 인증·멤버십·독립 비행 공유·불변 버전 패턴 | 기반 재사용, 지도 전용 테이블/API/UI 신규 구현 |
| KML/KMZ | 파서·원본 보기·기본 작성기 및 테스트 | 재사용 가능, 왕복 보존 계약 보완 필요 |
| 모바일 조회 | 공통 모바일 메뉴·시트, 기존 내 지도 진입점 없음 | 진입점·목록/지도 전환 추가 필요 |

시안의 패널 안 정보 구조·버튼·조작 흐름은 유지한다. 시안의 상단바·하단바·지도 옆 고정 열 전체를 그대로 이식하면 기존 기상 타임라인과 앱 셸까지 변경된다. 제품에서는 기존 셸·공통 토큰·지도 컨트롤에 맞춰 배치하고, 패널에 가리지 않는 카메라 이동 영역을 계산한다. 이 배치 조정은 합의된 보기/편집 분리를 바꾸지 않는다.

### 통합 전에 처리해야 할 구체적인 차이

1. **두 Draw를 동시에 붙일 수 없다.** useDrawMap은 자체 Mapbox를 생성하고 cleanup에서 지도 전체를 제거한다. 이를 기존 MapView에 그대로 넣지 않는다. 기존 useMapTools/usePolygonDraw도 Draw를 사용하며, 설치된 Draw의 내부 source ID는 mapbox-gl-draw-hot/cold로 고정되어 있다. 서로 다른 스타일 이름만 주는 것으로 동시 설치 문제가 해결되지 않는다. 단일 편집 소유자를 정하고 이전 제어 제거 후 다음 제어를 설치한다. 일반 보기의 도형은 별도 GeoJSON 레이어로 유지한다.

2. **앱 전체의 이탈 경로가 필요하다.** 현재 App의 togglePanel은 즉시 activePanel을 바꾸고, 여러 진입점에서도 직접 패널을 전환한다. 새 편집 패널의 ‘편집 마침’에만 확인을 넣으면 사이드바·검색·공항 상세 등 다른 경로로 미완성 작업이 끊길 수 있다. 완료 자료와 초안을 패널 생명주기 밖에 두고, 편집을 떠나는 요청을 공통 전환 처리로 보낸다. 기존 폴리곤 도구는 제어 제거 시 미완성 점을 폐기하므로 해당 cleanup을 그대로 재사용하면 안 된다.

3. **지도 입력과 단축키의 우선순위가 필요하다.** MapView의 공항 클릭은 곧바로 공항 선택을 실행하고, routePreview에는 경유점/선 드래그가 있다. MapView의 전역 방향키는 타임라인/고도 슬라이더로 전달된다. 새 작성/형태 수정 중 이들 동작을 잠시 양보시키고, 종료·취소 후 원래 상태로 복원해야 한다. DOM stopPropagation만으로 Mapbox 내부 이벤트 충돌이 모두 해결된다고 가정하지 않는다. 이는 코드상 겹치는 처리 경로를 확인한 것이며 실제 통합 충돌을 브라우저에서 재현한 결과는 아니다.

4. **레이어와 초안은 배경지도 교체를 견뎌야 한다.** 기존 /draw는 top 슬롯, my-map 원본 보기는 기상 아래 middle 슬롯을 쓴다. 편집본의 채움이 기상을 덮지 않도록 표시 도형과 편집 손잡이의 순서를 구분한다. Draw 자체에 스타일 복구 처리는 있지만 앱의 아이콘·추가 레이어·선택·미완성 초안까지 보장하지 않는다. styleRevision에 맞춰 현재 자료로 재설치하며, 배경 변경만으로 초안을 버리지 않는다.

5. **저장·공유는 신규 기능이다.** 기존 routes API는 지도 스키마와 revision 갱신을 제공하지 않는다. backend/server.js의 현재 JSON 요청 한도는 1mb다. 큰 지도 업로드를 약속하기 전에 지도 스키마·한도·저장 단위를 함께 정하고 413 응답도 처리한다. 기관 인증·버전 패턴은 재사용할 수 있지만 기존 비행 공유 API에 지도 payload를 끼워 넣지 않는다.

6. **파일 보존을 현재 왕복 테스트만으로 완료 처리하지 않는다.** 현재 작성기는 그룹·원 정의·바닥 고도를 충분히 보존하지 않는다. useDrawMap의 내보내기용 coords는 polygon의 첫 링만 가져오므로 구멍이 있는 가져온 면도 보존 시험이 필요하다. 미지원 변환은 미리보기에서 알리고 원본을 유지한다. 외부 아이콘과 KMZ 내부 리소스의 지원 범위도 별도로 명시한다.

7. **휴대전화 진입과 대량 자료 검증이 남는다.** MobileMoreMenu에는 현재 내 지도 항목이 없고 기존 my-map 브라우저 계약은 모바일을 skip한다. 좁은 HTML이 열린다는 것만으로 제품 조회가 완성되지 않는다. 그룹 목록·전체 상태를 복사하는 undo·다수 이름표는 대표적인 큰 파일로 별도 확인하며, 아직 성능 상한을 약속하지 않는다.

### 가장 먼저 실제 지도에서 확인할 흐름

T1의 자료·명령 계약을 만든 뒤 실제 KMZ의 목록·가변 상세를 먼저 연결하고, 이어서 **내 지도 열기 → 수정 → 점/선/면/원 작성 → 형태 수정/취소 → 보기 복귀**를 기존 Mapbox 위에 연결한다. 이때 기상과 기존 경로를 켠 상태로 입력 충돌, 다른 메뉴로 이동할 때 두 선택지 확인, 배경지도 두 번 교체를 검증한다. 파일 조회를 뒤로 미루지 않는 최신 실행 순서는 7절에 명시한다.

## 7. 확정된 실행 순서와 서브에이전트 운영 — 2026-09-19

사용자가 주 에이전트에게 최종 배정을 위임하여 확정한 실행 계획이다. **자료 계약 → 실제 파일 조회 → 작성/정리 → 개인 저장/파일 왕복 → 기관 공유 → 통합 검증** 순서로 진행한다. 각 단계는 실제 확인 가능한 화면/행동으로 마무리한다. 아래의 다음 단계 진입 조건은 기술 검증 조건이며 매번 사용자에게 재승인을 요청하는 절차가 아니다. 확정 이후 사용자의 시작 지시에 따라 제품 구현에 착수했다.

### 담당과 모델

동시에 **주 에이전트 1명 + 서브에이전트 최대 3명**을 사용한다. 현재 세션의 도구에 명시된 총 4개 동시 슬롯을 기준으로 한다. 슬롯을 항상 채우지 않고 독립 작업이 있을 때만 실행한다.

| 담당 | 확정 모델·추론 수준 | 소유 작업 |
|---|---|---|
| 주 에이전트 | 현재 대화의 모델 유지 | 최종 자료/상태 계약, MapView·앱 셸 통합, 입력 우선순위·이탈·style 복구, 검토 반영, 최종 브라우저 확인과 사용자 보고 |
| A: 자료·저장 구현 | gpt-5.6-terra / high | 주 에이전트가 확정한 계약에 따라 원본 항목/메타데이터 파서, 파일 왕복, 개인 지도 API·DB, 기관 지도 버전·권한 구현. 한 번에 한 단계의 경계가 분명한 작업을 받음 |
| B: UI 구현 | gpt-5.6-terra / high | 확정된 자료·콜백 계약에 따라 React 목록/상세/편집/그룹/공유 UI, 스타일·접근성 구현 |
| C: 독립 검토 | gpt-6-astra / high | 구현자가 아닌 관점에서 자료 유실·입력 충돌·저장 경합·권한·테스트 누락 검토. 기본은 읽기 전용, 수정은 해당 소유자에게 반환 |

모델명은 현재 세션에서 실제 선택 가능한 목록에서 골랐다. 이 배정은 이 프로젝트에 대한 작업 분담 판단이며 모델 간 성능 배율·정확한 요금·완료 시간의 보장이 아니다. **자료·저장과 UI의 일반 구현은 Terra / high, 독립 검토는 Astra / high**로 통일한다. 저장이라는 이유만으로 구현 전체를 Astra에 맡기지 않는다.

주 에이전트는 작업 배정 전에 원본 자료/메타데이터 보존, 편집 가능한 기하, revision 충돌, 응답 순서, 계정 격리, 기관 공유 권한·버전 규칙과 해당 검증 예시를 확정한다. A와 B는 이를 구현하고, 새 형식이나 모순으로 계약 변경이 필요하면 주 에이전트에게 근거를 반환한다. 독립적인 구현 작업은 계속하되 미확정 규칙을 추측해서 완성하지 않는다.

C는 단계별 합류 결과를 검토하고 수정은 해당 구현 담당자에게 돌린다. 모델 재배정은 재현 가능한 반복 실패 등 구체적인 이유가 있을 때 주 에이전트가 범위를 좁혀 결정하고 기록한다. Astra가 일반 구현까지 포괄하도록 자동 확대하지 않는다.

작업별 모델/추론 설정과 작은 범위의 병렬 작업 운영은 [OpenAI 공식 서브에이전트 안내](https://learn.chatgpt.com/docs/agent-configuration/subagents)를 참고했다. 공식 안내도 동시 코드 수정의 충돌과 추가 토큰 사용을 설명한다. 역할별 모델 배정은 위의 프로젝트 판단을 따른다. 전역 Codex 설정을 변경하거나 새 API 제품을 구축하는 작업은 필요하지 않다.

### 1단계. 자료·상태·연결 계약 고정

대상: T1과 T7 조회 모델의 선행 부분.

- 주 에이전트: 개인 지도/읽기 원본/원본 항목/렌더링 조각을 구분하고 그룹·항목 ID, 선택, 명령, 초안, 취소·저장 경계를 정의한다. 가져온 복합 도형을 네 가지 신규 작성 도구에 억지로 맞추지 않는다.
- A: 계약 결정을 돕는 제한된 원본 자료 매핑과 용량 실측을 담당한다. 754개 메타데이터와 2,135개 원본 항목을 보존할 입력/출력 예시를 제시한다.
- B: 읽기 전용으로 시안의 컴포넌트/화면 상태를 계약에 매핑한다. 미확정 상태에 의존하는 제품 UI 작성은 시작하지 않는다.
- C: 계약 초안이 나온 뒤 파일 계층·중복 필드·복합 기하·고도 기준·초안 보존 누락을 검토한다.

확정 산출물: 스키마/예제, 편집 명령과 결과, 패널 props/callback, API 요청/응답·revision 규칙, 모듈별 소유 파일 목록. 로컬 원본은 로컬 검증에 사용하며, 자동화용 작은 합성 fixture를 별도로 만든다. 실제 KMZ 전체를 저장소 fixture로 복제하지 않는다.

진입 조건: 계약 검토가 끝나고, 지도 렌더링 없이 ID/복사/그룹 순서/원 정의/메타데이터 보존을 검증할 수 있다. 이 단계부터 자료 구조를 각 에이전트가 따로 발명하지 않는다.

### 2단계. 실제 KMZ를 시안의 보기 패널로 열기

대상: T2, T7 중 원본 조회·가변 메타데이터. **첫 번째 눈으로 확인할 결과물.**

- A: 원본 항목 ID와 복수 기하를 보존하는 가져오기 어댑터, 필드 배열·글/표 설명 추출·부분 실패 상태를 구현한다.
- B: 지도 목록·원본 폴더 트리·개별 항목·하단 상세를 구현한다. 알려진 형식의 요약과 일반 가변 속성표를 분리한다.
- 주 에이전트: 기존 my-map 진입점, 라이브 지도 렌더링, sourceItemId에 따른 선택/숨김, style 복구에 연결한다.

- A: 1단계에서 확정한 계약으로 개인 지도 DB/API·소유권·revision 검증을 구현한다. 기존 map 원본 저장소는 계속 보존한다.

### 지도 스타일 반영 — 2026-09-20

FM-09에서 남아 있던 항목이다. 편집 패널에 있으나 지도에 반영되지 않던 네 가지를 `mapDocumentOverlay`에 연결했다.

- **선 모양.** `line-dasharray`는 자료로 지정할 수 없어 `my-map-line`/`-dashed`/`-dotted` 세 레이어로 나누고 `dash` 값으로 필터한다. 점선은 `line-cap: round` + `[0, 2]`로 둥근 점을 찍는다. dasharray 값은 선 굵기의 배수라 굵기를 바꿔도 비율이 유지된다. 이전에는 `dashed` 불리언만 만들고 어디서도 읽지 않았으며 'dotted'는 계산조차 하지 않았다.
- **아이콘.** 점용 `my-map-icon` symbol 레이어를 추가하고 `icon` 값에 따른 글리프를 그린다. `dot`은 기존 circle 레이어가 그대로 맡는다. 이미지 대신 글리프를 쓰므로 배경지도를 바꿔도 다시 등록할 필요가 없고 항목별 색을 그대로 따른다. 이전에는 무엇을 골라도 같은 원으로 나왔다.
- **이름 항상 표시.** `my-map-label-always`를 분리해 `text-allow-overlap: true`로 항상 그리되 `text-ignore-placement: false`로 자리를 계속 차지하게 했다. Mapbox는 겹침 판정을 위에 있는 레이어부터 하므로 이 레이어를 일반 이름표보다 **나중에** 놓아야 자리를 먼저 잡는다. 처음에 순서를 반대로 두고 ignore-placement까지 켜서 이름 두 개가 한자리에 겹쳐 찍히는 것을 캡처에서 확인하고 고쳤다. 선택 항목도 같은 레이어로 보내 우선순위를 준다. 이름표를 끈 항목은 '항상 표시'를 켜도 나오지 않는다.
- **점 투명도.** `circle-opacity`와 `circle-stroke-opacity`가 없어 점만 투명도가 먹지 않았다. 기호 레이어의 `text-opacity`도 함께 연결했다.

가져온 원본은 `dash` 기본값이 `solid`, `icon` 기본값이 `dot`이라 기존과 같은 레이어로 그려진다. 원본 색·굵기 우선 규칙도 그대로다.

검증: 단위 `mapDocumentOverlay.test.js` 7개 통과. 필터 표현식을 직접 해석해 한 도형이 정확히 한 선 레이어에만 들어가는지, 점이 아이콘에 따라 원/기호로 갈라지는지, 한 항목이 두 이름표 레이어에 겹쳐 들어가지 않는지 확인한다. 브라우저 계약 `my-map 선 모양·아이콘·이름 항상 표시가 지도에 실제로 그려진다`가 실제 Mapbox에서 `queryRenderedFeatures`로 레이어 이동을 확인하고, 배경지도 2회 전환 후 복구까지 본다. `npm run check` 통과(단위 1,654개), my-map 데스크톱 계약 16개 통과(실제 KMZ 포함). 로그는 `artifacts/flight-map-design/style-check.txt`, `style-contract.txt`, `my-map-desktop-contract.txt`, `real-kmz-contract.txt`.

미검증: 글리프 모양은 배경지도 글꼴에 의존한다. 데스크톱 Chromium 캡처(`style-applied.png`)에서 별·파선·이름표를 눈으로 확인했으나 모든 배경지도·기기의 글꼴을 확인한 것은 아니다. 모바일 계약과 iPad Safari는 실행하지 않았다.

### 이전본 계정 저장 실패 수정 — 2026-09-21

사용자가 로그인 상태에서 `/draw` 이전을 실행해 "지도 저장 요청을 처리하지 못했습니다"를 보고했다. 원인 두 가지.

- **compound 기하 형식 위반(제품 결함).** `backend/src/maps/schema.js`는 `compound` 항목의 기하를 `MultiPoint`/`MultiLineString`/`MultiPolygon`/`GeometryCollection`만 받는다. `convertDrawSpike`가 회랑·섹터를 단일 `Polygon`, 호·화살표를 `LineString`, 글자를 `Point`로 만들어 넣어 개인 저장이 `kind_mismatch`로 400을 받았다. 한 조각짜리 Multi*로 감싸도록 고쳤다. `parts()`가 렌더링에서 다시 펼치므로 화면 모양은 같고 좌표도 그대로다. 원과 일반 점·선·면은 감싸지 않는다.
- **안내·오류가 화면을 따라다님.** `setNotice`/`setError`가 계정 전환과 파일 가져오기에서만 지워져, 이전 안내와 저장 실패가 이후 편집 화면까지 남았다. `navigate()` 게이트에서 화면을 옮길 때 지우고, 배너마다 닫기 단추를 붙였다(`dismissMessages`).

**검증 공백이었던 점:** 기존 이전 계약은 비로그인으로만 실행해 기기 저장만 거쳤고 서버 검증을 통과한 적이 없었다. 로그인 상태 계약 `my-map 로그인 상태에서 그리기 이전본이 계정 저장을 통과하고 안내가 화면을 따라오지 않는다`를 추가했다. 이 계약의 API 스텁은 서버와 같은 compound 규칙을 적용하므로 같은 회귀가 다시 나면 실패한다. 단위 쪽에도 `compound 항목의 기하는 서버가 받는 Multi* 형식이어야 한다`를 추가했다.

검증: `npm run check` 통과(단위 1,655개, 실패 0). my-map 데스크톱 계약 17개 통과(실제 KMZ 포함). 로그는 `artifacts/flight-map-design/fix-check.txt`, `my-map-desktop-contract.txt`, `draw-account-contract.txt`.
