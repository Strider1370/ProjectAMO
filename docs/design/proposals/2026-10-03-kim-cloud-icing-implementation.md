# KIM 구름·착빙 통합 보기 — 1차 구현 결과

2026-10-03. 기존 KIM 계산·API·수집 설정을 유지하고 지도와 연직단면의 표시를 통합했다. 배포 전 저장 자료로 검증한 결과다.

> 이 문서는 A안 선택 전의 1차 제품 구현 결과다. 등급별 점 밀도·12% 밑색에 대한 기존 검증을 A안 검증으로 해석하지 않는다. 후속 작업은 [A안 프로젝트 적용 계획](2026-10-03-kim-cloud-icing-a-production-plan.md)을 따른다.
> 최종 지도 UI 결정: 사용자가 범례 옆 구름·착빙 두 버튼과 빨간 0°C/−20°C 고정 등온선을 승인했다. 아래 지도 체크박스·등온선 독립 조작·−10°C 옵션은 과거 구현 기록이며 후속 제품 구현에서는 정본 계획을 따른다.

## 구현한 동작

- 지도 `기온 / 습도 / 착빙` 타일을 `구름·착빙` 하나로 묶었다. 첫 사용은 세 항목 모두 켜지고, 자식별 독립 전환과 마지막 설정 복원을 지원한다. 기존 자식 ID와 검색 별칭은 유지한다.
- 구름 추정은 회색 T−Td 밴드다. 일반층 4°C / 500 hPa 6°C 기준을 유지한다. 착빙 등급 계산은 그대로 사용한다.
- 착빙은 등급별 파랑 점의 색·밀도로 표시한다. 모든 등급을 합친 착빙 영역의 최외곽에만 선을 그린다. 등급 경계·내부 구멍에는 선을 그리지 않고, 채움의 구멍과 결측은 유지한다. Mapbox 채움의 암묵적인 내부 테두리도 끈다.
- 구름은 푸른 기 없는 무채색 회색, 착빙은 선명한 코발트 파랑으로 분리했다. 예시 HTML의 착빙 표현을 기준으로 작은 단색 점을 약 11 / 9 / 7 px 간격으로 배치하고, 구름이 비치는 12% 파랑 밑색을 넣었다. 지도·단면·범례는 같은 점 색·크기·간격을 사용하며, 착빙 전체 최외곽도 같은 파랑이다. 기존 단색 착빙 토큰은 유지하고 점무늬 전용 테마 토큰을 추가했다. 후속 수정 범위는 착빙 표시뿐이며 구름의 농도·흐림 효과, 화면 배치, 고도 선택은 유지한다.
- 등온선은 0°C 실선과 −20°C 점선이 기본이며 −10°C를 추가할 수 있다. 어두운 배경에서도 읽도록 밝은 밑선을 사용한다. 실제 기온은 기존 지점 조회에서 읽는다.
- 지도와 단면은 공통 색·패턴·범례·등온선 계산을 사용한다. 단면의 구름 추정과 착빙 상호배제를 제거했다. 기존 CLD는 `모델 구름량 윤곽` 상세 옵션으로 구분한다.
- 공통 타임라인과 21개 기압층을 사용한다. 바람 지상층 선택이 남아 있어도 통합 보기는 기압층으로 전환한다. 250/200/150 hPa에서는 착빙을 `지원층 밖`으로 표시하고 구름·등온선을 유지한다.
- 같은 시간·고도·격자의 자료만 겹친다. 일부 자료 실패 시 정상 자식은 유지하고, 취소된 이전 요청의 결과를 새 선택에 섞지 않는다.
- timestamp는 `구름·착빙` 한 줄이다. 지도 포인트 조회는 활성 자식별 수치 표시를 유지한다. 브리핑의 관련 레이어 칩, 인라인/확대 단면, 기관 지도, 검색과 AI에 연결했다. AI 화면 상태에는 실제 레이어의 boolean 값만 제공한다.

## 코드 소유권

| 모듈 | 역할 |
| --- | --- |
| `frontend/src/shared/weather/cloudIcingPresentation.js` | 테마 토큰 기반 착빙 색, 점무늬, 회색 구름, 기본/추가 등온선 정의 |
| `frontend/src/shared/weather/gridContours.js` | 연결 셀의 외곽/구멍, 합집합 외곽, 등온선 계산·연결 |
| `frontend/src/features/weather-overlays/lib/cloudIcingModel.js` | 기압층 인덱스, 선택/격자 검사, 캐시된 지도 기하 |
| `icingPatternOverlay.js`, `temperatureContourOverlay.js` | Mapbox 자원 설치·가시성·style 재생성·정리 |
| `frontend/src/features/route-briefing/lib/cloudIcingProfile.js` | 독립 구름/착빙 셀과 전체 착빙 최외곽 SVG 경로 |
| `CloudIcingLegend.jsx` | 지도·단면 공통 범례 |
| `metLayerVisibility.js`, `useNwpOverlays.js`, `useKimTemperature.js` | 부모/자식 상태, 공통 선택, 자료별 훅 연결 |
| `scripts/preview-cloud-icing.mjs` | 보관 KIM 자료와 제품 렌더러를 HTML로 묶음 |
| `scripts/verify-cloud-icing.mjs` | HTTP를 가로채는 화면/조회 훅 검증 및 캡처 |

MapView는 조합만 담당하고 자료 생성·렌더링 어댑터는 weather-overlays에 둔다. backend는 frontend 공통 모듈을 가져오지 않는다.

기상 표시의 현재 세션 상태는 `metLayerVisibility.js`와 `crossSectionLayers.jsx`가 소유한다. `cloudIcingPresentationVersion: 1`을 갖고 과거 자식 활성 상태를 해석한다. 기관 고정 자료는 기존 `pinnedMapDataSelection.js`의 자료별 revision과 backend `pinned-map-resources.js`의 정확한 revision 조회를 사용한다. KML/my-map 저장, 과거 기상 manifest, 수집기, ADMIN의 기존 KIM 가용성/저장량 계약은 변경할 필요가 없다. 새 데이터 종류나 수집기를 추가하지 않았다.

## 실자료와 검증 범위

- 보관 KIM: `tmfc=2026091006`, F+6/F+9. 발표 2026-09-10 06:00 UTC = 15:00 KST. 유효 시각은 9월 10일 21:00 / 9월 11일 00:00 KST다. 현재 예보라는 의미로 사용하지 않았다.
- 지도: 실제 205×169 격자의 600/500/450/250 hPa 필드. 500 hPa F+6의 전체 격자 등급 수는 NONE 31,314 / LIGHT 3,196 / MODERATE 134 / SEVERE 1이다.
- 단면: 인천→제주 직선 시험 항로의 실제 KIM 21개 기압층. 시험 화면의 배경 지도는 로컬 시도 경계다. 실제 위성/Standard 배경과 지형은 이 캡처에 포함하지 않았다.
- 제품 Mapbox 어댑터, 패널, 단면 컴포넌트를 그대로 묶어 렌더링했다. 이전 합성 HTML 예시의 기상장은 제품 코드로 옮기지 않았다.
- 브라우저: 부모/자식 전환, 점·윤곽 동시 제거, −10°C, F+6→F+9, 250 hPa 지원 범위, 배경 스타일 교체 2회 이상, 두 줌 수준, 단면 독립 전환, 390px 모바일 확인. JavaScript/Mapbox 오류 0, 모바일 문서 가로 넘침 0.
- 실제 조회 훅에 저장 자료를 반환하는 네트워크 fixture를 연결했다. 늦은 이전 응답, 일부 구름 실패, T 인덱스 실패, 기관 자료별 revision, pinned 지상층 전환, pinned T 누락, live 대체 조회 방지를 검증했다.
- 연결 영역의 여러 등급/구멍/분리 영역, 결측·정확한 0°C·안장형 등온선, cache 재사용, style 재설치와 cleanup을 단위 테스트로 검증했다.
- 실제 500 hPa 자료에서 렌더링 전후 필드 hash가 같았다. 이 환경의 Node 단회 측정은 착빙 기하 약 6 ms / 상세 등온선 약 15 ms / 캐시 재사용 약 0.01 ms, 생성 GeoJSON 약 56 KB다. 휴대전화 성능 측정으로 해석하지 않는다.
- `npm run check`와 브라우저 검증 명령을 사용했다. 결과 로그·JSON·캡처는 `artifacts/cloud-icing-*`에 둔다.

브라우저 자동 검증은 Mapbox 인증/telemetry를 포함한 HTTP를 모두 가로채며 외부 통신을 하지 않는다. 생성 HTML을 직접 열면 Mapbox의 정상 인증이 필요하므로 공개 Mapbox 토큰을 포함하고 인증 통신은 발생할 수 있다. 기상청 호출·자료 수집·로컬 서버 실행은 없다.

## 직접 확인

저장 KIM과 공개 `VITE_MAPBOX_TOKEN`이 있는 저장소 루트에서:

```bash
node scripts/preview-cloud-icing.mjs
node scripts/verify-cloud-icing.mjs
```

첫 명령은 `artifacts/cloud-icing-real-kim.html`을 만든다. 브라우저로 열어 자식 표시·기압층·예보시간·배경·단면을 조작할 수 있다. 두 번째 명령은 같은 제품 렌더러와 조회 훅을 검증하고 PNG/JSON을 생성한다. F+6/F+9와 시험 대상 기압층의 보관 자료가 필요하다.

## 이번 확인에 포함하지 않은 범위

상세 농도 슬라이더는 추가하지 않고 기본 농도를 사용했다. 실제 서비스의 위성/Standard 배경, 실기기 모바일 성능, 실제 기관 세션의 승인/만료 흐름, AWS 배포 검증은 이번 캡처 범위에 포함하지 않았다. 공유 MapView/단면과 기존 수집/고정 자료 API를 유지하며, 배포는 실행하지 않았다.
