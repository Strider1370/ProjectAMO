## 2. 원본에서 실제로 하는 계산

검토한 파일:

- `reference/ACIM/_SRC/src_ACI_{DJF,MAM,JJA,SON}/Simplified_Conv.f90`
- 같은 디렉터리의 `ACI_Indices.f90` 네 개
- `reference/ACIM/DABA/ACIintoFL`
- `reference/ACIM/SHEL/amo_gdps_diag_acim_{job,body,tle_body}.ksh`
- `reference/ACIM/SHEL/NCL/amo_gdps_diag_acim_{plot,tle_plot_prob}.ncl`

### 2.1 입력과 계산 순서

네 계절의 입출력 프로그램은 동일하다. NetCDF의 `lons`, `lats`, `ulwrtoa`, `precc`를 읽고 `CONVINDEX(nx,ny,olr,apcp,idx)`를 호출한다. 2026년 KIM 기반 변경 주석이 있으며, 파일명에 남은 GDPS/UM 표기만으로 현재 입력 모델을 단정하지 않는다.

실제 기상 입력은 **OLR와 대류성 강수량 두 개**다. 좌표와 발표 월은 격자·계절 메타데이터다. SON에 선언된 `Mcape`는 계산에 쓰이지 않는다. CAPE·기온·습도·연직속도를 새 입력으로 요구하지 않는다.

```text
OLR 점수 Molr:
  OLR > OLR2                  → 0
  OLR1 < OLR <= OLR2          → Σ(cOLRn × OLR^n), n=0..6
  OLR < OLR1                  → 1

강수 점수 Mapcp:
  precc <= APCP1              → 0
  APCP1 < precc <= APCP2      → Σ(cAPCPn × precc^n), n=0..6
  precc > APCP2               → 1

ACI = clamp(0.5 × Molr + 0.5 × Mapcp, 0, 1)
```

**원본은 두 조건의 AND 판정이 아니라 점수의 가중합**이다. 한 점수가 1이고 다른 점수가 0이어도 ACI=0.5이고, 원본 표로는 FL225에 대응한다. 대류성 강수가 반드시 양수여야 한다는 별도 마스크나 CAPE 조건을 추가하면 원본과 다른 알고리즘이 된다. 이번 도입에서는 추가하지 않는다.

두 점수 각각을 먼저 0–1로 자르는 처리도 원본에 없다. 최종 ACI만 제한한다. 강수 `precc`는 입력값을 그대로 사용하고, 시간 차분·3시간 합산·강수율 변환 코드는 없다.

### 2.2 계절별 임계값

| 계절 | OLR1 | OLR2 | APCP1 | APCP2 |
| --- | ---: | ---: | ---: | ---: |
| DJF | 175.1087 | 203.5141 | 0.0184 | 0.3305 |
| MAM | 151.9182 | 206.5427 | 0 | 0.9491 |
| JJA | 130.4021 | 207.2141 | 0.0326 | 2.3718 |
| SON | 152.0966 | 216.9666 | 0.0173 | 1.2813 |

6차 다항식의 계수는 네 `ACI_Indices.f90`에서 추출하고 원본 SHA-256을 기록한다. 임계값만 복사하거나 계수를 임의로 보정하지 않는다. 연구 어댑터: [acim-reference.mjs](../../../scripts/lib/acim-reference.mjs), 순수 계산: [acim-calculation.mjs](../../../scripts/lib/acim-calculation.mjs).

MAM은 APCP1=0이고 강수 다항식 상수항이 0.92685363이다. 따라서 강수 0과 극미량 양수 사이에서 점수가 크게 달라질 수 있다. 이번 실제 API에서도 최소 강수값이 정확한 0이 아니었다. 원본을 임의로 수정하지 않고, 봄철 입력의 수치 하한과 원본의 의도는 검증 사례에 포함한다.

### 2.3 상단고도 변환

`DABA/ACIintoFL`는 **FL025 간격의 15개 임계값**이다. 해당 임계값 이상이 되는 가장 높은 FL을 선택하며, 선형 보간하지 않는다.

| FL | ACI 임계값 | FL | ACI 임계값 | FL | ACI 임계값 |
| --- | ---: | --- | ---: | --- | ---: |
| 000 | 0.0017 | 125 | 0.2017 | 250 | 0.5681 |
| 025 | 0.0179 | 150 | 0.2532 | 275 | 0.7422 |
| 050 | 0.0595 | 175 | 0.3119 | 300 | 0.8545 |
| 075 | 0.1149 | 200 | 0.3986 | 325 | 0.9370 |
| 100 | 0.1588 | 225 | 0.4782 | 350 | 0.9736 |

계산 결과는 `topFl`과 `topFt=topFl×100`으로 저장한다. 원본의 FL 표기를 계승하며, 모델 `hgt`로 구한 실제 고도나 AGL 고도와 혼동하지 않는다. UI의 5,000ft 구간은 표시용 집계이며 계산 자체는 FL025 간격을 유지한다.

### 2.4 확률은 별도 처리

원본 TLE는 발표시각 0/−6/−12/−18/−24시간의 5회분을 사용한다. 각각의 리드시간에 0/6/12/18/24시간을 더해 **동일 유효시각**의 CCT로 맞춘다. FL050부터 FL350까지 FL050 간격으로 검사하고, 각 고도 이상의 멤버 수÷5×100을 그린다. 출력은 20% 간격의 경험적 멤버 비율이며, 보정된 발생확률이라고 확인된 것은 아니다.

원본 단일 예보는 F000–F048을 3시간 간격으로 만들고, TLE는 F000–F024를 3시간 간격으로 만든다. 전체를 재현하려면 예보 기간과 회차 저장을 확장해야 한다. 이번 F000–F012 단일 예보 도입과 분리한다. 현재 회차 저장 설정 1회분만으로는 5멤버 처리를 재현할 수 없다.

## 3. 유지하는 부분과 명시적으로 보완하는 부분

| 원본에서 확인한 사실 | 프로젝트 적용 방식 |
| --- | --- |
| 계절별 계수, 6차식, 가중치 0.5/0.5, 최종 clamp | 유지 |
| `olr == OLR1`이 분기에서 누락되어 Molr 미대입 | `olr <= OLR1`을 1로 정의. 원본의 미정의 동작과는 비교하지 않음 |
| NCL의 CCT에 `+0.1 FL`을 붙임 | 순차 `where`의 재변환을 막는 표시 처리를 물리량에 포함하지 않음. 예: 250.1 대신 FL250 / 25,000ft |
| ACI < 0.0017은 NCL에서 원래 소수로 남음 | FL000으로 정규화. 화면에서는 5,000ft 미만 숨김 |
| 결측·NaN·NetCDF 실패 방어 부족 | 입력 경계에서 검출하고 null. 결측을 맑음/대류 없음으로 바꾸지 않음 |
| 격자 차원 4320×2160 고정 | API 응답의 205×169를 사용하고 형태·범위·순서 검증 |
| 본체는 `input,output,forecast`, 셸 호출에는 `infile1,infile2`도 존재 | 참조 환경 파일은 미수록, 두 변수는 본체에서 미정의. 빈 값은 셸 확장에서 사라져 3인자가 되므로 반드시 불일치한다고 단정할 수 없음. 이식에서는 위치 인자에 의존하지 않음 |
| 원본 REAL은 단정도, 예시 계산은 JS 배정도 | 식·계수 일치와 바이너리 일치를 분리. 운영 전에 단정도와 독립 비교 필수 |

기존 Intel/NetCDF 실행파일은 이 Linux 환경에서 필요한 공유 라이브러리가 부족하다. 현재 원본 바이너리 실행 결과와 비트 단위 일치는 검증하지 않았다. 원본이 강수 배열 전체 0일 때 파일을 다시 읽는 처리는 무조건 재다운로드하는 동작으로 이식하지 않는다.

## 5. 프로젝트 구현 단계

### 단계 A: 입력 시간 정의와 수치 호환성 확정

1. API 사양이나 원본 NetCDF의 변수 속성으로 `precc` 누적 구간과 `ulwrtoa` 순간/평균 정의를 확인한다. 원본이 읽던 입력과 같은 의미인지 확인한다.
2. F000/F001/F003/F006 등을 비교한다. 값의 증감만으로 누적 정의를 단정하지 않고 원본 NetCDF와 공식 사양을 우선한다.
3. 사계절 샘플·결측·경계 조건을 준비해 원본 단정도 실행 결과와 비교한다. ACI 수치 오차와 FL 구간이 달라지는 격자 수를 집계한다. JS 배정도를 채택하면 차이의 근거를 기록한다.
4. 시간 변환이 필요하다고 확인된 경우에만 입력 어댑터에 추가하고 알고리즘 버전·API 호출량을 갱신한다. 확인되지 않은 누적 구간을 사용자 설정으로 고르게 하지 않는다.

### 단계 B: 독립적인 ACIM 수집·저장

- `backend/src/lib/kim-acim.js`: 순수 계산, 계절·계수·표·결측 계약. 계수를 추적 가능한 파일로 가져오고 원본 SHA-256을 기록한다. 무시되는 `reference/`를 운영 시 의존하지 않는다.
- `backend/src/processors/kim-acim-processor.js`: 기존 KIM과 같은 대상 발표를 선택하고 레이더·위성 키로 리드별 2변수만 수집한다. 기존 시각별 255요청의 완료 조건에 ACIM을 추가하지 않는다.
- API 작업 레지스트리에 `kim_grid_acim`을 추가하고 `precc`/`ulwrtoa`를 구분한다. API client는 기존 typ06 URL 생성과 공통 관측 트랜스포트를 재사용한다. 관리 화면에 실제 키 구분·횟수·byte 수를 표시한다.
- 수집기 레지스트리에 전용 job/lock/중단 처리를 등록하고 현재 KIM 공개·재확인 시간대를 이용한다. 동일 발표·리드·변수를 캐시하고 실패 입력만 재수집한다.
- 초기 기능 플래그는 OFF. 개발 환경에서 입력 정의와 수치 호환성을 확인한 후 활성화한다.
- `DATA_PATH/kim_acim/`에 독립 저장한다. 모델/발표/리드/계산 버전/계수 해시/입력 해시와 전용 raw 캐시를 저장한다. 기존 KIM의 `keep_raw=false`여도 ACIM의 성공한 한쪽 입력을 재사용할 수 있게 한다.
- 두 입력이 같은 시각·같은 격자일 때만 계산한다. 성공 리드는 단계 저장하고 13시각이 모두 있는 run을 latest로 원자적 공개한다. 부분 실패로 이전 정상 run을 덮지 않는다. 전 격자 결측 결과를 정상 latest로 처리하지 않는다.
- ACI는 정밀도를 낮추기 전 계산값에서 `topFl`을 정한다. ACI를 양자화한 후 고도 구간을 판정하지 않는다. FL은 0/25/50…350, 결측은 null로 저장한다.

### 단계 C: 읽기 API와 지도

- 신규 읽기 API안: `GET /api/kim/acim/index`, `GET /api/kim/acim/field?tmfc=…&hf=…&revision=…`. 기존 `/api/kim/gktg/*`와 맞추고 index는 재검증, revision이 있는 field는 불변 캐시를 사용한다.
- 메타데이터에 `runAt`,`validAt`,`collectedAt`,`availableHours`,`algorithmVersion`,`revision`,`status`를 포함한다. 미확정 `precipitationPeriod`를 가공의 값으로 채우지 않는다.
- 필드 계약은 격자 정의·`topFl`·결측 마스크·메타데이터다. ACI 0~1 값을 공개 화면에서 %로 표시하지 않는다.
- 지도 제어는 `frontend/src/features/weather-overlays/lib/`의 전용 adapter/hook이 소유한다. `MapView.jsx`에 개별 bare useEffect를 추가하지 않는다.
- `layerActions.js`, MET 레이어 정의, visibility, 범례, 시각 선택에 ACIM을 등록한다. 별도 작업 중인 구름·착빙 통합과 독립적인 표시이며 hPa 선택으로 ACIM을 바꾸지 않는다.
- 5,000ft 구간을 공통 표시 정의로 만들고 연한 황색~진한 갈색 순서색·명도·고정 범례·영역 내 고도 구간 라벨을 쓴다. 지리 경계는 채색 위에 가늘게 표시한다.
- 지도는 이산 색으로 그린다. 보간·평활화로 원본에 없는 세부 고도나 새 고고도 영역을 만들지 않는다. 클릭/hover 상세 조회를 전제로 하지 않는다.
- 시각은 UTC로 비교하고 선택 KST/UTC로 표시한다. 이전 시각 응답이 새 선택을 덮지 않도록 중단·세대 검사를 한다. 없는 선택 시각을 다른 run의 결과로 조용히 채우지 않는다.

### 단계 D: 검증 후 공개

- 과학적 타당성: 사계절·무강수·전선성 강수·강한 대류 사례에서 위성 운정·낙뢰·사용 가능한 레이더 자료와 비교한다. 임계값 조정이 필요하면 원본과 구분되는 버전으로 관리한다.
- 수치/수집: 시각·격자 불일치, 한쪽 결측, 전 결측, 계절 경계, 임계값 일치, 재실행의 추가 API 0회, 한쪽 실패의 재수집 1회, 이전 정상 run 보존을 검증한다.
- 브라우저: 5,000ft 범례, 숨김/표시, 13시각, 결측, UTC/KST, 태블릿/모바일, 지도 스타일 변경 2회, 레이어 겹침, 이전 응답 경쟁을 확인한다.
- 구현 범위 backend/frontend 테스트, 해당 browser contract, frontend build를 실행하고 결과와 미실시 사항을 기록한다. 기능 공개 시 Architecture와 운영 문서를 갱신한다.

### 후속 연직단면도

같은 수평 CCT를 항로를 따라 샘플링하고 상단 선/경계로 표시한다. 지표에서 CCT까지를 실제 CB 구름체로 채우지 않는다. ACI는 구름 하단이나 두께를 주지 않는다. 이 표시만을 위한 고도별 API 추가 수집은 필요하지 않다.

## 6. API 호출량

하루 4회 발표·13시각을 정상 수집하고 입력 정의를 그대로 사용할 수 있는 조건으로 계산한다.

```text
2변수 × 13시각 = 26회/발표
26회 × 4발표 = 104회/일 (모두 레이더·위성 키)
```

기존 KIM 본 수집 3,315회/발표 대비 0.784%다. 공항 비교·GKTG·지상 일기도를 포함한 현재 로컬 설정 3,525회/발표 대비 0.738%다. 13시각 정상 캐시는 재확인 일정마다 다시 받지 않는다. 5,000ft 구간·줌·단면 표시도 기상청 호출을 추가하지 않는다.

이번 2변수 실측 912,191byte와 같은 응답 크기라면 **약 47.4MB/일**이 추가된다. 한 시각 실측을 52배 한 추정이며 실패·재시도·다른 영역은 제외한다. 장부의 현재 로컬 용량 제한은 키당 5GB/일, 중단 임계값은 4.75GB/일이다. 기존 위성·레이더 사용량과 합산된다.

입력 기간 변환이나 TLE 5멤버를 추가하면 다시 산정한다.

## 7. 이번 작업과 검증 기록

- 운영 collector/API/UI는 연결하지 않았다. 문서·수동 시험·순수 계산 연구 코드·단독 HTML을 작성했다.
- 원본 4계절 계수를 독립 Python Decimal(40자리) 404사례와 비교했다. 최대 절대 오차 **2.353672812205332e-14**.
- 계절 선택·결측·양 임계값·15개 고도 임계값·5,000ft 구간을 확인했다. 수식 이식 확인이며 단정도 바이너리 비교나 예보 성능 검증은 아니다.
- HTML은 실제 F006을 기본 표시한다. 확인하지 않은 12시각을 실제 자료로 표시하지 않는다. 합성 입력 모드는 13시각을 별도로 제공하고 두 모드를 명시한다. HTML에 키·외부 API 호출을 포함하지 않는다.
- 브라우저 검증 기록: `artifacts/acim-preview/browser-verification.json`. 1440/1024/390px에서 가로 넘침 없음·7구간·단일 실제 시각·UTC/KST·표시 전환·합성 시각 전환을 확인한다.
- 남은 사항: 원본/API 누적 구간 일치, 원본 단정도 비교, 예보 성능 검증, 운영 연결.
