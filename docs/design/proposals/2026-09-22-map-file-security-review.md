# 지도 파일·서버 저장 보안 점검

2026-09-22, 기준 커밋 `1ff35647`. 개인 내 지도, 기관 개인지도 공유 API, 기관 라운지 자료 업로드·원본 열기 경로를 점검했다. 코드 검토와 격리된 로컬 재현 결과이며 운영 서버 설정·전체 의존성 취약점·모든 브라우저에 대한 보안 감사는 아니다. 아래 최초 점검 이후 사용자 요청으로 보완을 적용했다. 현재 조치 상태는 문서 끝의 「보완 기록」을 우선한다.

## 결론

확인한 경로에서 지도 파일 내용이 서버 명령이나 JavaScript로 실행되는 동작은 발견하지 않았다. 그러나 파일을 통한 서비스 지연·저장공간 소진·미검사 부속 파일 유통을 막는 장치가 부족하다. 개인 계정의 1개·5MiB 제한만으로 기관 업로드 및 브라우저 파일 읽기가 보호되지는 않는다.

## 조치가 필요한 사항

### 1. 높음 — 기관 원본·버전 누적 저장 한도 없음

- 근거: `backend/src/organizations/materials.js:263`의 create와 300행 이후 update는 파일 하나를 25MiB 이하로 검사하지만, 기관·계정·전체 누적 사용량을 확인하지 않고 파일과 버전을 보관한다. remove는 deleted_at만 기록한다.
- 영향: 업로드 권한이 있는 기관 구성원이 서로 다른 파일이나 버전을 반복 등록하면 디스크 사용량을 계속 늘릴 수 있다. 동일 바이트는 해시로 중복 저장을 피하지만 바이트가 다른 파일에는 적용되지 않는다.
- 개인지도 공유 API의 기관당 256MiB 버전 한도는 별도 테이블/API에만 적용된다. 라운지 자료 업로드를 보호하지 않는다.
- 조치: 원본·버전·변환 메타데이터를 포함한 누적 한도, 동시 요청 예약, 최소 디스크 여유 공간, 버전 보존·정리 정책. 기존 자료를 임의 삭제하면 안 된다.

### 2. 높음 — 기관 도형 분석이 서버 이벤트 루프를 동기 점유

- 근거: `backend/src/lib/organization-kml.js:38` 동기 압축 해제, 53행 XML 분석, 84행 `kinks(polygon(rings))`. 설치된 Turf 구현은 선분 쌍을 비교한다. `materials.js:148`에서 요청 처리 중 직접 실행한다.
- 재현: 자체 생성한 정상 원형 다각형 1,000/4,000/12,000개 꼭짓점의 분석 시간이 각각 10/51/479ms였다. 12,000개 샘플은 약 444KB이며 파서가 받아들였다. 현재 좌표 상한은 50,000개다.
- 영향: 악성 스크립트가 없어도 권한 있는 사용자의 반복 업로드가 다른 요청을 지연시킬 수 있다. 운영 서버 지연 시간이나 실제 장애를 측정한 것은 아니다.
- 조치: 본문 처리 전 계정·IP 요청/전송량 제한, 동시 처리 제한, 분석 작업을 시간·메모리가 제한된 worker로 분리, 도형 분석 비용 상한. 파일 크기 제한만으로 해결되지 않는다.

### 3. 중간 — 개인 KMZ 압축 해제 크기 제한 없음

- 근거: `frontend/src/features/my-map/lib/kmzUnzip.js:20`에서 해제 스트림 전체를 arrayBuffer로 모은다. `useMyMap.js:509`의 파일 검사도 확장자를 확인한 뒤 크기 검사 없이 전체를 읽는다.
- 재현: 8,376바이트 KMZ가 8,388,738바이트 KML로 정상 해제됐다. 약 1,001배 팽창이며 실험은 8MiB에서 멈췄다.
- 영향: 사용자가 파일을 열면 브라우저 메모리와 UI 응답성에 영향을 준다. 서버 코드 실행이나 서버 압축 해제 취약점으로 확인한 것은 아니다.
- 조치: 읽기 전 파일 크기, ZIP 항목 수, 실제 스트리밍 해제 바이트, XML/도형 복잡도를 제한. ZIP 헤더의 선언 크기만 믿으면 안 된다.

### 4. 중간 — KMZ 부속 파일 전체가 검사·제거되지 않은 채 원본 보관

- 근거: `organization-kml.js:36`은 KML 항목만 해제·검사한다. `materials.js:169`는 검증 이전의 원본 ZIP 전체를 저장하고 345행 original 핸들러로 제공한다.
- 재현: 정상 `doc.kml`과 `payload.exe`라는 이름의 무해한 식별 문자열을 담은 KMZ가 경고 없이 통과했다. 실제 실행파일이나 악성코드는 사용하지 않았다.
- 영향: 지도 미리보기 검증을 통과한 원본에 지도와 무관한 내용이 들어 있을 수 있다. 서버가 이를 실행한다는 뜻은 아니며, 악성 파일 탐지·무해화가 완료됐다고 볼 수 없다는 의미다.
- 조치: 허용할 부속 형식과 검증 범위를 명시하고 불필요한 항목을 거부하거나 안전한 지도 파일로 재구성한다. 원본 보존이 필수라면 검사·격리 상태와 다운로드 정책을 별도로 설계한다. 확장자 검사나 백신 하나만으로 안전을 보장하지 않는다.

### 5. 보강 필요 — 지도 전용 요청 제한·전체 저장량 제한 미구현

- `backend/src/maps/router.js:34`는 인증·활성 사용자 확인 후 본문 파서를 실행한다. Origin 검사는 POST/PUT 핸들러에 있어 파싱 뒤에 실행된다. 계정별 요청 횟수·전송량 제한은 없다.
- `deploy/nginx/projectamo.conf.example`에는 IP별 일반 5r/s·burst 60이 있지만 운영 적용 여부는 미확인이다. 개인 지도 location의 본문 제한은 여전히 32m이며 백엔드는 5MiB로 거부한다.
- 앞서 제안한 분당 30회/20MB, 전체 500MB, 디스크 여유 3GB 정책은 제안이며 구현된 상태가 아니다. 운영 환경에 적절한 수치 검증도 필요하다.
- 조치: 인증·요청 출처·요청 제한을 본문 처리 전에 적용하고, 프록시와 앱 제한을 맞춘다. 자동저장은 429의 재시도 시간을 따라야 한다.

## 확인된 방어

- 개인 지도: 로그인·활성 계정 확인, 소유자가 다른 지도 읽기/수정/삭제 거부, 구조·좌표·고도·용량 검증과 파라미터 바인딩 SQL.
- 기관 자료: 활성 기관 멤버십, 수정·삭제 역할/소유권, 다른 기관 원본 접근 차단. Origin 검사는 원본 업로드 본문 처리 전에 실행한다.
- 기관 KML: DTD/ENTITY 선언, NetworkLink, 잘못된 좌표 거부. 아이콘/외부 자원은 서버가 가져오지 않는다.
- 기관 KMZ: 경로 이탈·암호화·지원하지 않는 압축 방식·선언 해제 크기·KML CRC/실제 크기 검사. KML 해제에는 maxOutputLength가 적용된다. 브라우저의 제한 부재와 구분해야 한다.
- 저장 원본: 해시 기반 이름, 공개 기상자료 경로 밖에 저장, 파일 권한 0600. ZIP 항목을 OS 파일 경로에 풀지 않는다.
- 개인 설명 화면: 원문 HTML을 DOM에 삽입하지 않고 React 텍스트/표로 표시한다. Chromium에서 script/onerror/onload/iframe을 포함한 설명 분석 샘플의 실행·외부 요청은 관찰되지 않았다. 전체 XSS 부재를 보장하는 결과는 아니다.

- 저장 대상 파일시스템에서 여유 공간 3GiB를 유지하지 못하는 증가는 507로 거부. 개인 지도 축소와 조회·삭제는 가능하며, 자료 삭제만으로 보존된 버전의 사용량이 줄지는 않는다. 보존 자료를 자동 삭제하지 않는다.
- 개인/기관 공유 지도 쓰기는 계정당 분당 30회·20MiB, 라운지 자료 쓰기는 분당 30회·50MiB 제한. 소켓 IP별 한도는 각각 10배. 전달 헤더로 IP 버킷을 바꿀 수 없게 소켓 주소를 사용하므로 프록시 뒤에서는 여러 사용자가 IP 버킷을 공유한다. 개인 쓰기 동시 4개·기관 자료 동시 2개, 계정당 동시 2개. Content-Length 없는 요청은 최대 본문 크기로 예산을 예약하고 HTTP 압축 본문을 거부한다. 거절 계정·사유는 버킷당 분당 한 번 로그에 남긴다.
- 인증·Origin·요청 제한 이후 JSON/원본 본문을 처리한다. 읽기 요청은 지도 JSON 파서를 통과하지 않는다. 자동저장은 429의 Retry-After를 따라 최신 편집 내용을 보관하고 재시도한다. Nginx 예시의 개인 지도 본문 제한도 5m로 맞췄다.

- 기관 KMZ 부속 파일은 KML 및 PNG/JPEG/GIF/WebP만 허용(디렉터리 제외). 모든 파일의 실제 해제 크기·CRC를 검사하고 이미지에는 형식 시그니처 검사도 적용한다. EXE·JS·HTML·SVG 등과 위장된 이미지 헤더를 거부한다. 이는 백신 검사 또는 임의 악성코드가 전혀 없다는 보장이 아니다. 개인 KMZ에도 부속 확장자 허용 목록을 적용한다.
