# 구름·착빙 표현 재검토 — 공식 레퍼런스와 새 제안

검토일: 2026-10-03. 이번 작업은 조사와 제안이다. 제품 렌더링, KIM 계산·임계값·수집 방식은 변경하지 않았다.

## 결론

권장 방향은 **착빙 등급을 명도 차이가 큰 색 면으로 표시하고, 구름은 중립적인 맥락으로 분리하는 것**이다. 점의 밀도·크기·사선 각도를 등급 판독의 주된 수단으로 삼지 않는다. 점무늬를 유지한다면 모든 등급에 같은 무늬를 사용하여 ‘착빙’이라는 현상을 나타내는 보조 표식으로만 쓴다.

비교한 후보는 세 가지다. A는 현재 구름 표현을 유지하고 착빙만 바꾼다. B는 구름을 경계로 바꾸고 착빙에 색 면을 전용한다. C는 두 원본 필드를 동기화된 별도 화면에 놓는다. **사용자가 A안을 선택했다.** B/C는 비교 자료로 남기며 이번 적용 방향은 A다. 조종사 사용성 검증 결과는 아니다.

### 선택된 방향: A — 구름 배경 + 착빙 색 면

- 현재 구름의 회색 표현을 유지한다.
- 착빙 LGT/MOD/SEV는 비교 보드 A의 밝은 파랑/중간 파랑/어두운 남색 면으로 구분한다.
- 점무늬는 등급별 밀도를 바꾸지 않고, 모든 등급에 동일하게 적용하는 보조 표식으로 둔다.
- 윤곽선은 전체 착빙 영역의 최외각에만 표시한다. 등급 사이에는 윤곽선을 추가하지 않는다.
- 지도·연직단면도·범례에서 같은 착빙 표현을 사용한다. 온도는 기존 등온선 역할을 유지한다.
- 착빙 면 아래의 구름 세부 명암이 가려지는 점은 A안의 표현상 한계다. 팔레트·범례는 실제 저장 자료에서도 확인한다.

현재 반영 범위는 디자인 선택 기록·비교 보드와 [기존 지도·연직단면 예시 HTML](../mockups/cloud-icing-comparison.html)이다. 예시 HTML의 착빙은 등급별 고정 색 면과 같은 크기·간격의 흰 점으로 변경했고, 구름 표현과 가상 기상장은 유지했다. 제품 렌더링 구현은 변경하지 않았다.

[저장 KIM 실자료 HTML](../mockups/cloud-icing-variants.html)에도 A안을 적용했다. 기본 화면은 실제 저장 자료의 500 hPa와 첫 예보시간, A안 지도·단면이다. 600/500/450 hPa와 두 예보시간을 선택할 수 있고, 기존 6안 비교와 합성 시험장 전환도 유지한다. 자료는 2026-09-10 06 UTC 발표분이며 추가 API 호출 없이 읽었다. 구름·등급 영역·최외각 경계·원자료 불변과 화면 전환·모바일 표시, 네트워크 요청 0건을 `node scripts/verify-cloud-icing-variants.mjs`로 확인했다.

실제 프로젝트 반영은 [A안 프로젝트 적용 계획](2026-10-03-kim-cloud-icing-a-production-plan.md)에 정리했다. Mockup 적용과 제품 적용의 완료 상태를 구분한다.

## 실제 레퍼런스

### 1. ForeFlight — 착빙·난류 동시 연직 표시

- [공식 Weather in Profile View 예시](https://www.foreflight.com/enhancements/weather-in-profile-view), July 2020 소개 자료.
- 직접 확인한 화면에는 파란 계열 착빙 면과 녹색·황색 계열 난류 면이 함께 나타난다. 지형·항로·공역은 별도 선·기호로 나타낸다.
- 공식 설명은 지도와 단면도에 같은 등급색을 사용하며 착빙 한 종류와 난류 한 종류를 함께 표시할 수 있다고 명시한다.
- 가져올 원칙: 현상별 역할 분리, 등급의 색 면 표현, 지도·단면도·범례의 동일한 의미.
- 적용 범위: **구름+착빙을 동일하게 겹친 예시는 아니다.** 동시 표시 기능이 있다고 해서 완전히 겹치는 두 색 면의 판독 문제까지 해결된 것은 아니다. 자료의 해칭은 예보 데이터가 없는 영역을 뜻하므로 착빙 강도 해칭으로 해석하지 않는다.

### 2. Met Office — SIGWX / F215의 경계·기호·주석

- [Aviation Briefing Service User Guide](https://www.metoffice.gov.uk/binaries/content/assets/metofficegovuk/pdf/services/transport/aviation/ga/aviation-briefing-service-user-guide.pdf#page=30), 인쇄 페이지 30(F215), 33(상층 SIGWX). 가이드 V3 May 2022, 화면 안 예보는 2018년의 예시다.
- F215는 지도 영역 A/B/C 등과 오른쪽 기상 설명표를 연결한다. 상층 SIGWX 예시는 구역 경계, 제트류 선, 기상 기호, 고도 주석을 함께 사용한다.
- 가져올 원칙: 모든 정보를 채색 면에 맡기지 않고 **경계·선·기호·텍스트에 역할을 나누는 방식**.
- 우리 적용은 구름 참고 영역을 회색 경계로, 착빙 등급을 색 면으로 표시하는 재해석이다. 공식 SIGWX 기호를 KIM 포화층의 관측 구름 경계처럼 그대로 복제하지 않는다.

### 3. NOAA AWC GFA — 강도는 색, 다른 위험은 별도 표현

- [GFA 공식 도움말의 Icing 항목](https://aviationweather.gov/gfa/help/?page=tutorial).
- 도움말은 착빙 강도를 색으로 표시하고, SLD 위험은 빨간 해칭으로 표현한다고 설명한다. 관련 기상 경보 구역도 겹쳐 표시한다.
- 가져올 원칙: **한 현상의 등급 구분과 다른 현상의 구분을 별개로 설계**한다. 색은 강도, 추가 무늬는 다른 위험/현상이라는 식으로 의미를 나눈다.
- AWC의 Trace/Light/Moderate/Heavy 또는 FIP 기준을 우리 KIM 착빙 등급·임계값으로 가져오는 제안은 아니다.

### 4. Esri — 동기화된 두 지도와 스와이프

- [Apps you can use to swipe or compare](https://www.esri.com/arcgis-blog/products/arcgis-online/mapping/swipe-compare-apps), March 14, 2024 문서.
- 같은 문서는 좌우/상하 두 지도 연결, 동기화, 한 화면의 두 레이어를 가르는 스와이프를 실제 앱 예시로 설명한다. 오래된 데모 링크 중 일부는 대체 페이지로 연결되므로 구현 의존성으로 채택하지 않는다.
- 가져올 원칙: 두 필드 모두 자세히 읽어야 한다면 **색을 섞는 대신 동일 위치의 독립 화면을 비교**한다.
- 기본 비교는 두 화면이 더 적합하다. 스와이프는 이동하는 경계 양쪽에서 다른 필드를 보므로, 같은 지점의 두 값을 동시에 읽는 데 한계가 있어 보조 후보로 둔다.

### 5. Esri — 반투명 혼색과 이변량 범례

- [Set legend colors to match feature layer transparency](https://www.esri.com/arcgis-blog/products/product/mapping/set-legend-colors-to-match-feature-layer-transparency), January 23, 2008. 오래된 ArcGIS 조작 절차는 차용하지 않고 배경에 따른 색 합성 설명만 참고한다.
- 반투명 색은 배경에 따라 화면 색이 달라진다. 우리 회색 포화층 위의 착빙색도 배경 명암에 따라 바뀌므로, 투명도를 강도의 주된 기준으로 삼으면 범례와 실제 지도색이 어긋날 수 있다.
- [Building a Bivariate Color Scheme](https://www.esri.com/arcgis-blog/products/arcgis-living-atlas/mapping/building-a-bivariate-color-scheme), January 21, 2026. 두 변수의 조합을 명시적인 색 행렬로 정의한 실제 지도 예시가 있다.
- 구름×착빙 조합을 별도 색으로 정의하는 것도 가능하지만, 조합 범례를 학습해야 하고 같은 착빙 등급이 구름 값에 따라 다른 색이 된다. 이번 비행 전 빠른 등급 판독의 기본안으로는 권장하지 않는다. 단순 반투명 중첩을 검증된 이변량 지도라고 부르지 않는다.

| 후보 | 수평 지도 | 연직단면도 | 강점 | 감수할 점 |
| --- | --- | --- | --- | --- |
| A. 구름 배경 + 착빙 색 면 | 기존 회색 구름 그대로. 착빙 LGT/MOD/SEV는 고정된 밝은 파랑/중간 파랑/어두운 남색 면. 필요하면 동일한 점무늬 병기 | 회색 포화층 위에 동일한 등급색. 온도는 이름 있는 선 | 가장 작은 변경으로 작은 착빙 영역의 등급 단서 확보 | 착빙 면이 덮는 지점에서는 구름 세부 명암이 가려짐. 투명도를 낮추면 다시 혼색 문제 |
| B. 구름 경계 + 착빙 색 면 | 기존 포화층 판정 영역의 회색 경계. 착빙에는 같은 등급색 면을 전용. 온도는 0°C 실선/−20°C 파선과 직접 라벨 | 포화층 구역을 중립 경계로, 착빙 층을 색 면으로. 온도·비행 경로 선은 따로 유지 | 면·경계·등온선의 역할이 분리되고 착빙을 우선 읽기 쉬움 | 구름의 연속적인 진하기 정보가 줄어듦. 구름 상세 모드나 지점 값으로 보완 |
| C. 구름/착빙 동기화 비교 | 좌우 지도, 같은 위치·배율·발표/유효시각·기압층·포인터. 각 필드 독립 범례 | 같은 거리·고도 축의 단면도를 상하 배치. 같은 거리/고도 커서 연결 | 어느 필드도 다른 필드에 가려지지 않음. 중첩 원인과 범위를 직접 비교 | 화면 면적과 시선 이동 증가. iPad 가로를 검토하고 휴대폰은 큰 화면의 탭/전환을 사용 |

색 면의 명도 차이는 현행의 서로 가까운 진한 파랑 점색보다 크게 벌린다. 첫 개념도는 프로젝트 기존 착빙 램프 `#ACC7FF / #6B88CD / #383D6F`를 사용한다. 최종 팔레트는 실제 작은 영역과 배경, 색각 특성에서 비교한 뒤 정한다. 별도의 빨강·노랑 등급안은 현재 GKTG 의미색과 충돌할 수 있어 기본 제안에서 제외한다.

색 면은 등급 판독의 주된 수단이고 단독 수단은 아니다. 명도 차이, 항상 보이는 범례, 충분한 공간의 LGT/MOD/SEV 표기, 선택 지점의 등급 텍스트를 함께 제공한다. 작은 영역을 모두 글자로 덮지는 않는다.

## 공통으로 지켜야 할 것

- 우리 구름 필드는 포화층을 통한 구름 참고 정보다. 표시 역할을 바꾸더라도 관측 구름량·구름 확률·실제 구름 경계로 의미를 변경하지 않는다.
- 착빙 영역의 최외각 윤곽선만 표시한다. 등급이 맞닿는 곳에 별도 윤곽선을 추가하지 않는다. 내부 등급은 색 면 차이로 읽는다.
- NONE, 결측, 데이터 없음의 의미를 각각 유지한다. 무채색 또는 무늬 하나로 이 상태들을 혼동시키지 않는다.
- 구름 참고 영역 바깥에서 계산된 착빙도 숨기지 않는다. 구름 마스크로 착빙을 자르지 않는다.
- 작은 착빙 영역을 보기 좋게 확대·결합·평활화하거나 대표 점 하나로 대체하지 않는다. 확대 시 원래 격자·영역을 읽을 수 있어야 한다.
- 지도·단면도·비행 전 브리핑은 같은 필드·등급·범례를 사용한다. 비교 화면도 같은 시각·기압층과 축을 공유한다.
- 온도선은 강도색으로 채우지 않는다. 0/−20°C 선은 온도 참고 정보이며 이 선 사이만 착빙으로 단정하지 않는다.

## 다음 비교에서 확인할 항목

1. 같은 불규칙 격자에 여러 등급이 맞닿는 경우, 한두 셀의 작은 영역, 좁은 띠, 고립된 영역을 넣는다. 아름다운 타원형만으로 평가하지 않는다.
2. 기존 저장 KIM 자료와 인공 판독 사례를 구분한다. 저장 자료에 강한 등급이 적다면 LGT 위주의 실제 사례만으로 MOD/SEV 구분이 검증됐다고 하지 않는다.
3. iPad 가로와 휴대폰에서 등급을 읽을 수 있는지, 회색 구름·밝은 지도·어두운 지도에 따라 달라지는지 확인한다.
4. 색각 시뮬레이션, 명도, 직접 등급 텍스트를 함께 검토한다. 색 면을 써도 화면 한 픽셀의 영역까지 안정적으로 판독된다고 보장할 수는 없다.
5. 구름·착빙·등온선 각각의 위치와 등급을 틀리지 않고 읽는지 비교한다. 최종 제품 반영은 이 비교 결과로 결정한다.
