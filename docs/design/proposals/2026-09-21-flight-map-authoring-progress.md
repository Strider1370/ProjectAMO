# 내 지도 작성·그룹 검증과 보완

2026-09-21. [독립 검증](2026-09-21-flight-map-review.md)에서 재현한 세 결함을 고쳤고, 명세 5절의 그룹 조작 누락을 보완했다. 전체 기능 완료 기록이 아니다. 전체 요구사항은 [UX 명세](2026-09-19-flight-map-ux-design.md), [구현 계획](2026-09-19-flight-map-implementation-plan.md)을 유지한다.

## 수정한 결함

- 면 작성 중 입력점이 세 개 이상일 때 첫 점의 화면 위치에서 10px 이내를 클릭하면 기존 완료·유효성 검사 경로를 실행한다. 첫 점을 중복으로 추가하지 않는다. Enter/완료 버튼 경로도 유지한다.
- 항목 drop 이벤트가 부모 그룹까지 전파되어 두 번 이동하던 것을 차단했다. 자기 항목에 놓기·잘못된 drag payload는 변경하지 않는다. 드롭 한 번이 undo 한 단계가 된다.
- 검색 중 그룹 순서 select를 비활성화하고 이벤트 처리에도 query 방어를 둔다. 항목 순서 메뉴도 같은 제한을 따른다.
- 가상 ‘그룹 없는 항목’을 맨 끝으로 옮기는 명령이 `id === beforeGroupId === null` 때문에 자기 자신 이동으로 오인되던 추가 결함을 고쳤다. 제자리 그룹 이동은 새 이력을 만들지 않는다.

## 그룹 기능 보완

- 다중 선택 이동 메뉴의 ‘새 그룹으로 묶기…’에서 이름을 입력해 그룹 생성과 이동을 하나의 `groupItems` 명령으로 처리한다. 상대 순서·원본 속성을 보존하며 한 번 undo로 그룹도 사라진다.
- 각 항목에 맨 위/위/아래/맨 아래 순서 메뉴를 제공한다. 가상 영역에도 그룹 순서 메뉴를 제공해 드래그 대체 수단을 연결했다.
- 항목 드롭 삽입 선, 빈 그룹 안내, 마지막 그룹 드롭 영역을 추가했다. 기존 접힌 그룹 펼침은 중복 hover가 접기 토글로 바뀌지 않도록 명시적인 expand 동작으로 바꿨다.
- `useMapTreeAutoScroll.js`가 실제 스크롤 부모를 찾아 패널 가장자리에서 스크롤한다. 패널 밖에서는 움직이지 않고, drop/dragend/해제 시 animation frame과 전역 이벤트를 정리한다.
- 그룹 이름과 도구를 두 줄로 나눠 이름 공간을 확보했다. 그룹 접기/펼치기와 검색에 접근 가능한 이름을 부여했다.
- 그룹 삭제 확인에 함께 삭제할 항목 수를 표시한다.

## 검증 근거

- 세 결함 수정 직후 작성 계약 3개 모두 통과: 면/원·기하 편집·반경·undo/redo, 좌표 일괄·다중 이동·항목/그룹 드래그·검색 제한, 면 첫 점 완료. `artifacts/flight-map-review/authoring-fix-browser.txt`.
- 그룹 보완 후 `npm run check` 통과: 프런트 1,668개, 백엔드 1,227개 통과·1개 건너뜀, 기타 offline 검사 및 빌드 성공. `group-check.txt`.
- 새 명령 단위 검증은 source 값·원본 불변·상대 순서·잘못된 선택의 전체 거절·가상 영역 맨 끝 이동·제자리 명령 무변경을 확인한다. `mapCommands.test.js`, `group-commands.txt`.
- 그룹 관련 브라우저 4개 중 첫 실행 3개 통과: 기존 좌표/정렬 계약, 새 그룹 생성·undo/redo·순서 메뉴·해제·다중 드래그·삭제 개수, 그룹 삭제 후 보기/편집 순서 회귀. 긴 목록 계약은 스크롤 검증까지 통과했으나 두 번째 드래그의 시작점이 고정 헤더에 가려 접힌 그룹 펼침에 도달하지 못했다. `group-browser.txt`.
- 시험에서 시작 항목을 패널 중앙으로 스크롤하고 실제 dragstart 발생을 확인하도록 고친 뒤 긴 목록 계약도 통과했다. 자동 스크롤·외부 드롭 후 정지/자료 유지·접힌 그룹에 머물 때 펼침·이동 후 한 번 undo까지 확인. 제품 코드 재수정은 없었다. `group-scroll-confirm.txt`.
- 위 로그는 모두 ignored `artifacts/flight-map-review/` 아래다. 시험 수정 뒤 전체 4개를 다시 실행한 것으로 기록하지 않는다.
- 일반 개인 지도 복제와 현재 편집 지도에 KML/KMZ를 추가하는 흐름을 보완했다. 원본과 기존 항목을 유지하고, 추가는 한 번의 undo/redo로 되돌리며, 파일 드롭·취소·재열기·메타데이터와 사용자 메모 보존까지 데스크톱 계약으로 확인했다. 변환 중 사용자가 먼저 입력한 이름이 파일 분석 완료 시 덮어써지던 오류도 수정했다. `my-map-files.spec.mjs`의 두 계약이 통과했다.
- 좌표 일괄 입력에 네 번째 열이 있으면 이전에는 조용히 무시했다. 이제 해당 행을 오류로 만들고 전체 추가를 막는다. 단위 테스트와 프런트 전체 단위 1,669개가 통과했다.
- 모바일 조회 계약 3개도 Pixel 5 Chromium에서 통과했다. 파일 열기, 폴더 표시 전환, 재열기 후 표시 설정 복원을 확인했다.
- 연속 점으로 만든 새 항목은 가장 최근 점의 색·크기를 상속하고, 직접 패널을 닫을 때도 ‘계속 그리기 / 그냥 나가기’가 미완성 선과 완료 항목을 정확히 나눈다는 것을 데스크톱 계약으로 확인했다.
- DD 좌표 파서는 `37north`처럼 숫자 뒤에 붙은 문자를 더는 허용하지 않는다. DMS 좌표 수정, 형식 오류 표시, 오류 뒤 기존 좌표 보존을 브라우저에서 확인했다. `coordFormat.js` 단위 회귀도 추가했다.
- iPad Pro 11 가로 Chromium에서 파일 열기·폴더 표시 전환·재열기·배경지도 두 번 전환 뒤 선택/숨김 복원 4개 계약이 통과했다. 실제 iPad Safari 장비 검증은 남아 있다.
- 최신 전체 검증은 `npm run check` 통과다. 백엔드 1,231개 통과·1개 건너뜀, 프런트 1,669개 통과, offline 검사와 프로덕션 빌드가 성공했다.
- 실제 공역 KMZ(AIRAC AIP 5_26)의 CHEONGJU 원본 필드 `DistVertUpper_Val: "5000"`가 개인 편집본과 개인 사본까지 그대로 유지됨을 확인했다. 화면 요약의 `5000 Feet Height`는 원본 값에 단위를 붙여 보여 주는 표현이며, 둘을 혼동하지 않도록 계약은 원본 메타데이터 값을 비교한다.
- 한글 조합 입력은 조합 중에 중간 문자열을 저장하지 않고, blur 뒤 하나의 undo 단계로 되돌린다. 미완성 선에서 검색을 열 때도 `계속 그리기 / 그냥 나가기`를 먼저 선택하게 하며, 후자는 완료된 점만 남기고 검색을 연다. 데스크톱 브라우저 계약으로 확인했다.
- 작성·그룹 계약 8개를 자동 스크롤 수정 뒤 다시 묶어 통과시켰다. 이어 전체 내 지도 데스크톱 계약을 실행해 27개 통과·실제 외부 파일 환경 변수 미설정 1개 건너뜀을 확인했다. 장시간 단일 브라우저 실행에서는 기존의 `새 지도 작성`과 `기기 저장·초안 재개`가 각각 90초 시간 제한에 걸렸으나, 새 브라우저에서 두 흐름을 함께 다시 실행하면 2개 모두 통과한다. 마지막 전체 제품 검사 `npm run check`도 통과했다.

## 다음 구현·검증

1. **실기기 확인만 남음:** 실제 iPad Safari에서 모바일 진입·종료·표시 복원을 한 번 확인한다. 장비가 없으면 위 FM-20 한계를 유지한다.
2. **회귀 실행 시 유의:** 전체 데스크톱 묶음은 장시간 Mapbox 브라우저 세션에서 두 기존 계약의 90초 제한에 걸릴 수 있다. 해당 흐름은 독립 재실행으로 통과했으므로, 재현 시 제품 오류로 단정하지 말고 새 브라우저 범위 재실행 결과와 함께 판단한다.

커밋·배포·push·PR·의존성 변경·AGENTS/CLAUDE 수정은 하지 않았다. `/draw`와 기존 보관 원본은 유지한다.
