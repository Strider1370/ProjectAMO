# 연직단면도 판독성과 공간 활용 개선 검토

작성: 2026-10-12. 상태: 최초 조사 기록.

> 사용자 피드백 반영: 아래의 별도 분석 화면·지도 분할·인사이트 패널 제안은 채택하지 않는다. 현재 방향은 **기존 메인 지도 위의 정돈된 연직단면도 창**이며, 이동·크기 조절이 핵심이다. 최신 시안은 `frontend/src/features/vertical-profile-concept/README.md`를 따른다.

## 결론

연직단면도를 크기 조절 가능한 주 작업 영역으로 바꾸고, 비행 경로와 위험 기상을 먼저 읽도록 시각적 위계를 정리한다. 기본은 지도+단면 분할 화면, 정밀 분석은 단면 집중 화면을 권장한다. 기존 라이트·slate 디자인과 기상 등급색은 유지한다.

근거는 사용자 첨부 화면, 현재 소스, 프로젝트 디자인 계약, 기존 조종사 피드백, 아래 공식 제품 자료다. 운영 화면의 동작을 직접 재현하지 않았으므로 화면에서 드러난 문제와 코드에서 확인한 제약을 구분한다. 그림의 선·구역은 배치 설명용이며 실제 예보가 아니다.

## 코드에서 확인한 원인과 재사용 지점

- `frontend/src/features/route-briefing/VerticalProfileChart.jsx`: 데스크톱 SVG 기본 높이 380px. `fitHeight`와 ResizeObserver 기반 크기 측정이 이미 있다. 거리 비례 최소 폭, waypoint lane에 따른 하단 padding, 바람깃 간격이 주요 조정 지점이다.
- `frontend/src/features/route-briefing/VerticalProfileWindow.jsx`: 현재 `fitHeight`는 `mobile-full`에만 전달한다. 데스크톱에 공간을 더 배정해도 차트 높이 정책을 함께 바꿔야 한다.
- `frontend/src/features/route-briefing/RouteBriefing.css`: `is-side`에서 왼쪽 640px 여백, 최대 폭 1080px, 최대 높이 620px. 일반 창은 `max-height: 56vh; overflow: auto`. 이 제약과 고정 SVG가 중첩 스크롤을 만들 수 있다.
- `crossSectionLayers.jsx`, `ProfileLegend.jsx`: 레이어 선택·활성 범례·예보시간 선택을 재사용한다. 기본 난류는 꺼져 있으므로 첨부 화면의 모든 레이어가 기본으로 켜진다고 해석하지 않는다.
- `lib/crossSectionLayerState.js`: 난류 집중 시 가리는 면 레이어를 끄고 복원하는 상태 전환이 이미 있다.
- `VerticalProfileChart.jsx`: `linkedItems`, 선택 구간 강조와 고정 기능이 이미 존재한다. 지도와 단면의 연결 자체를 처음부터 만드는 작업으로 잡지 않는다. 별도 창과 브리핑에서 전달되는 상태의 차이를 먼저 확인한다.
- `shared/gktg.js`: 현재 난류 등급색의 코드 정본. 디자인 문서의 예시 색과 차이가 있으므로 이번 개편에서 임의로 저채도 색으로 교체하지 않는다.

## 참고 사례와 차용할 표현

### ForeFlight — 항로와 기상, 시각을 함께 읽기

[Weather in Profile View](https://www.foreflight.com/enhancements/weather-in-profile-view), 2020-07 공식 소개는 지도와 단면의 같은 색상표, 선택적 착빙·난류 표시, 웨이포인트 통과시각, 예보 범위 밖의 해칭을 설명한다. 차용할 것은 경로 중심 판독과 명확한 데이터 범위다. 우리 구간별 수동 NWP 적용시각을 자동 통과시각으로 표현해서는 안 된다.

[Clouds in Profile View](https://www.foreflight.com/enhancements/clouds-in-profile-view-3d-preview), 2020-11 공식 소개는 구름과 위험 기상의 선택적 결합을 설명한다. 우리 구름 추정 필드를 실제 관측 구름 경계처럼 꾸미지 않으면서도 배경·위험 면의 역할은 분리할 수 있다.

[Dispatch Route Builder: Profile View](https://ba.foreflight.com/releases/route-builder-profile-view), 2023-03 공식 소개의 하단 단면과 접기 동작은 지도+단면 작업 구조의 참고가 된다. 아래 제안의 면적 비율과 크기 조절 방식은 ProjectAMO를 위한 제안이며 해당 제품의 기능을 그대로 설명한 것이 아니다.

### meteoblue — 현상별 보기와 확대

[공식 커뮤니티의 cross-section 안내](https://community.meteoblue.com/topic/96/how-can-i-create-and-view-a-weather-cross-section)는 지도에서 경로를 지정하면 하단 단면이 나타나고, Larger 확대와 RH/Clouds·Wind·Precipitation·CAT/Icing 전환을 설명한다. 페이지는 삭제 안내도 함께 노출되지만 본문은 조사 시점에 확인 가능했다. 기존 사례의 표현 패턴으로 참고하며 최신 제품 사용성 검증으로 취급하지 않는다.

차용할 것은 목적별 보기 전환이다. 모든 현상을 겹쳐 놓고 매번 개별 스위치를 조절하기보다, 빠른 종합 판독과 바람·착빙·난류의 상세 분석을 나눈다. 원래 레이어 선택 기능은 유지한다.

### Garmin Pilot — 고도별 현상 읽기

[Garmin 공식 Flight Profile icing 소개](https://www.garmin.com/en-US/newsroom/press-release/aviation/2018-garmin-pilot-ios-incorporates-new-weather-features-airspace-alerting-and-more/), 2018-05 자료는 비행계획 옆에서 고도별 착빙 확률·심각도를 읽는 구조를 설명한다. 차용할 것은 고도별 면 표현이며, 그 제품의 확률색을 우리 착빙 등급색으로 가져오지는 않는다.

## 제안하는 화면과 표현

1. **기본: 지도+단면 분할.** 지도는 작업 영역 높이의 약 25~35%, 단면 작업 영역은 나머지 65~75%를 시작점으로 검토한다. 이는 확정 수치가 아니라 실제 iPad·데스크톱 판독 시험용 비율이다. 경계 드래그와 명시적 크기 버튼을 함께 제공한다. 입력 폼은 경로·고도 요약으로 접는다.
2. **집중: 단면 중심 화면.** 지도를 접어 차트를 크게 보고 필요할 때 다시 펼친다. 상세 정보도 선택 전에는 공간을 차지하지 않는다. iPad에서는 고정 우측 상세 패널 대신 탭으로 여는 상세 시트를 우선한다.
3. **경로 중심의 시각적 위계.** 계획 경로를 먼저 읽고, 위험 영역, 지형·구름 배경, 보조 기호 순으로 읽게 한다. 경로의 위험 교차 부분은 짧은 강조와 라벨로 연결하되 비행 가능·불가능을 임의 판정하지 않는다.
4. **현상별 시각 역할.** 구름은 기존 회색 추정 영역, 착빙은 기존 파랑 등급면+점무늬, 난류는 공통 등급색, SIGMET/AIRMET는 경계·기호·이름. 바람은 일정 화면 간격으로 간소화한다. 서로 가리는 면을 혼색해 새 의미색을 만들지 않는다. 중첩이 심하면 같은 축의 두 단면을 비교한다.
5. **직접 라벨.** 온도선에는 `0°C`, `−20°C`, 선택 경로에는 계획 고도, 경보에는 현상명을 보이는 구간에 배치한다. 작은 영역은 상세에서 읽고 모든 셀에 텍스트를 넣지는 않는다.
6. **전체 보기와 확대를 분리.** 첫 화면은 전체 항로의 상승·순항·하강과 위험 구간을 보여 준다. 확대할 때 웨이포인트·바람깃·격자 상세를 늘린다. 축은 거리 비례를 유지하며 고도 확대 상태와 화면 밖 범위를 표시한다.
7. **차트 아래 구간 요약.** `SIGMET`, `난류`, `착빙`을 짧은 행으로 분리해 해당 구간을 표시하고 선택 시 확대한다. 종합점수로 합치지 않는다. 겹친 항목 수, 결측 구간, 무엇의 교차인지도 읽을 수 있어야 한다.
8. **선택 커서와 상세.** 거리·고도·적용시각·풍향/풍속·현상 등급을 읽는 커서를 지도 위치와 연결한다. 데스크톱 hover뿐 아니라 탭 고정·키보드 조작을 지원한다. 지도 이동이나 고도 변경은 사용자가 명확히 선택했을 때 적용한다.
9. **시간의 역할 명시.** 상단은 선택 예보 유효시각과 시간대, 상세는 발표시각·필드별 상태, 하단 구간선은 그 구간에 적용한 예보시간이다. 예상 통과시각은 계산 근거가 있는 경우에만 별도 표기한다.

세련됨의 목표는 채도를 낮추거나 곡선을 매끈하게 만드는 데 있지 않다. 여백·선 굵기·직접 라벨·조작의 위치를 정리해 먼저 봐야 할 정보가 먼저 보이게 한다. 작은 위험 영역의 삭제·확대·보간은 이번 표현 개선에 포함하지 않는다.

현재 수행한 검증은 소스와 문서 대조 및 공식 자료 조사다. 제품 소스는 변경하지 않았으며 런타임 테스트·실기기 사용성 검증은 수행하지 않았다.
