# 레이더 WISSDOM 바람장 및 초단기 강수예측 전환 — 설계 명세

**작성일**: 2026-08-04  
**상태**: 설계안 (사용자 검토 대기)  
**대체 대상**: 레이더 에코 관측 이동벡터 기능

---

## 1. 목적

기존 레이더 에코 이동벡터는 연속 레이더 영상에서 추정한 이동 경향만 보여 주며, 사용자가 기대하는 바람장으로 읽기 어렵고 성능 대비 효용도 낮다. 이를 기상청 WISSDOM 레이더 바람장으로 교체한다.

동시에 지도 시간축에서 레이더 관측이 끝나는 지점 이후에는 MAPLE 초단기 강수예측을 보여, 사용자가 **관측된 강수**와 **앞으로 한 시간의 예상 강수**를 하나의 연속된 시간 흐름으로 읽게 한다.

이 기능은 항공 운항 판단을 대신하지 않는다. WISSDOM은 레이더 기반 분석장이고 QPF는 MAPLE 예측이라는 자료 성격을 화면에서 명확히 구분한다.

## 2. 범위

### 2.1 포함

- 기존 `레이더 에코 이동벡터 표시` 제어와 그 백엔드 산출물을 WISSDOM 바람장으로 교체한다.
- 기상청 `nph-rdr_wis_ana_imgp` API로 WISSDOM 투명 이미지와 공간·시각 메타데이터를 수집한다.
- WISSDOM 고도(`ht`, m)를 기존 우측 연직 레일 UI에 연결한다.
- 기상청 `nph-qpf_ana_imgp` API로 MAPLE 초단기 강수예측 투명 이미지와 예측 시각 메타데이터를 수집한다.
- 통합 타임라인에서 관측 프레임과 QPF 예측 프레임을 구분해 선택·재생한다.
- QPF가 표시될 때 지도 위 상태 카드로 출처·기준시각·선택시각·리드타임·단위를 표시한다.
- Mapbox 스타일 교체와 베이스맵 전환 뒤에도 모든 새 이미지 레이어의 설치·표시 상태를 복원한다.

### 2.2 제외

- WISSDOM PNG에서 특정 지점의 수치 풍속·풍향을 역산하거나 클릭 조회하는 기능
- WISSDOM을 particle animation 또는 원시 벡터장으로 재구성하는 기능
- 관측 레이더와 QPF의 수치 병합, 보정, 또는 둘을 한 장의 강수장으로 표시하는 기능
- 레이더 에코 이동벡터와 WISSDOM의 동시 제공
- API 키를 브라우저에 전달하거나 외부 이미지 URL을 클라이언트에서 직접 인증 호출하는 방식
- 기상청 `nph-rdr_cmp1_imgp`(4.1 HSR 그래픽)로 현재 레이더 관측 레이어를 교체하는 작업

### 2.3 레이더 관측 소스 결정

현재 원자료 HSR 레이더 수집·dBZ→강수강도 렌더·고해상도 PNG 발행 경로를 **유지한다.** 이번 변경은 이동벡터만 WISSDOM으로 교체하고, WISSDOM과 QPF만 `imgp` 그래픽 API에서 추가한다.

기상청 4.1 HSR 그래픽은 같은 API 계열의 관측 표현이라는 장점이 있지만, 실제 비교에서 전국 이미지가 457×483으로 반환됐다. 현재 ProjectAMO 레이더는 1600×1830이므로, 이번 범위에서 4.1을 추가·병행·교체하지 않는다.

MAPLE QPF가 현재 레이더와 실제 운용 화면에서 강수 영역·강도·해상도가 크게 달라 사용자가 자료 전환을 혼동한다고 확인된 경우에만, 4.1 HSR 전환은 별도 설계·검증 과제로 다시 검토한다. 그 전에는 두 자료의 차이를 인위적으로 보정하거나 일치시키지 않으며, 관측/예측 자료 성격과 시각을 명시해 읽게 한다.

## 3. 자료 계약

| 항목 | WISSDOM 레이더 바람장 | 초단기 강수예측 |
|---|---|---|
| API | `nph-rdr_wis_ana_imgp` | `nph-qpf_ana_imgp` |
| 자료 성격 | 레이더 기반 분석 바람장 | MAPLE 강수강도 예측 |
| 지도 표시 | 바람 화살표가 포함된 투명 래스터 | 투명 강수강도 래스터 |
| 시간 | 자료시각 `tm` | 분석 기준시각 `tm` + 예측시간 `ef` |
| 공간 메타데이터 | JSON의 `imageCoverage*ProjX/Y` | JSON의 `imageCoverage*ProjX/Y` |
| 범례 | API 응답의 `bar` | API 응답의 `bar`, 단위 mm/h |

수집기는 서버의 `KMA_RADAR_SATELLITE_AUTH_KEY`만 사용한다. 브라우저는 ProjectAMO가 발행한 이미지·메타데이터만 읽는다.

`imgp` 응답은 `PROJ=LCC`와 KMA 경량 지도 viewport 좌표를 반환하지만, KMA는 해당 viewport 좌표의 원점·축·단위 변환식을 공개하지 않는다. 이 기능은 사용자가 승인한 실용 경로로, 이미 ProjectAMO가 KMA HSR 이진 격자에서 재투영해 발행하는 전국 레이더의 검증된 WGS84 범위를 WISSDOM/QPF 이미지의 고정 지도 범위로 사용한다. 이는 KMA 지도와의 **시각 정합**이며 측량급 또는 100 m 정합 보장은 주장하지 않는다. 이미지를 별도로 재투영하지 않고 Mapbox image source에 해당 bounds로 올리며, 실제 해안선·주요 공항으로 브라우저 정합을 확인한다.

## 4. WISSDOM 바람장

### 4.1 제어와 가시성

기상 레이어 패널의 `레이더/위성` 그룹 제목 줄에 있는 기존 제어를 다음으로 교체한다.

```text
레이더 바람장 (WISSDOM) · {선택 고도} m
```

- 레이더가 켜져 있을 때만 제어를 보인다.
- 기본값은 OFF다. 사용자가 켜면 해당 레이더 프레임 위에 WISSDOM을 중첩한다.
- 레이더를 끄면 WISSDOM 요청 상태도 해제하고 즉시 숨긴다.
- 선택 시각에 일치하는 WISSDOM 자료가 없으면 제어는 비활성화하며 `표시 시각의 WISSDOM 자료 없음`을 알린다.
- WISSDOM은 독립 MET 타일이나 KIM `바람` 토글로 등록하지 않는다. 레이더에 종속된 분석 보조 레이어다.

### 4.2 정확한 시각 일치

WISSDOM은 선택된 레이더 프레임의 `tm`과 **정확히 같은** `tm`을 가진 경우에만 표시한다.

- 가장 가까운 과거·미래 WISSDOM 프레임으로 대체하지 않는다.
- 레이더가 10:25이고 WISSDOM이 10:20 또는 10:30뿐이면 표시하지 않는다.
- 범례·상태 문구의 자료시각은 선택 시각이 아니라 실제 WISSDOM `tm`을 사용한다. 정확 일치 조건 때문에 두 값은 같아야 한다.
- 타임라인 재생과 스크럽은 프레임마다 이 조건을 다시 적용한다.

### 4.3 연직 선택

WISSDOM은 `ht`를 미터 단위로 받는다. 실시간 API 검증으로 FL010–FL100의 1,000 ft 간격을 미터로 환산한 `305, 610, 914, 1219, 1524, 1829, 2134, 2438, 2743, 3048 m` 요청이 각각 별도 이미지 경로와 해당 고도 제목으로 반환됨을 확인했다. 구현은 이 10개 검증값만 선택지로 노출하고 기본 선택값은 `1524 m`로 둔다.

- 기존 우측 연직 레일의 시각적·접근성 패턴을 재사용한다.
- WISSDOM 선택 상태는 `radarWindHeightM`처럼 KIM 선택과 별도로 소유한다.
- KIM은 기압면, WISSDOM은 고도(m)이므로 두 값을 자동 변환하거나 같은 선택값으로 묶지 않는다.
- KIM 바람과 WISSDOM이 동시에 켜진 경우, 연직 레일은 현재 조작 대상 출처를 명확히 표시·전환한다. 예: `WISSDOM · 1,500 m` / `KIM · 850 hPa`.
- 1,000 ft 간격은 항공 사용자의 선택 간격 감각을 위한 것이며, API 문서가 기준면을 확정하지 않았으므로 AGL, MSL, FL을 덧붙이지 않고 실제 요청값인 `고도 {m} m`으로 표기한다.

### 4.4 범례와 성능

- API가 돌려주는 WISSDOM 범례 이미지를 자료 시각·고도와 함께 표시한다.
- PNG 자체의 화살표 방향·색만 사용한다. 색 구간의 단위나 수치를 프로젝트가 추측해 재정의하지 않는다.
- 기존 레이더 이동벡터의 GeoJSON 생성, 프레임 간 비교, 화살표 source/layer 및 UI는 제거한다. 레이더 PNG 수집·발행은 이 변경으로 영향받지 않는다.

## 5. 초단기 강수예측(QPF)

### 5.1 시간축 전환

통합 타임라인은 하나의 절대 시각 축을 유지한다.

```text
과거 관측 (실선) ── 레이더/WISSDOM ── 분석 기준시각 ┆ QPF 예측 (점선) ┆ +60분
```

- 관측 구간에서는 레이더를 표시한다. WISSDOM은 사용자가 켰고 정확한 시각 프레임이 있을 때만 함께 보인다.
- QPF의 유효시각(`tm + ef`)이 선택된 미래 구간에서는 QPF만 표시한다.
- 선택 시각이 QPF 유효시각이면 관측 레이더를 최신 프레임으로 고정해 함께 남기지 않는다. 관측과 예측을 겹쳐 한 장의 강수장처럼 보이게 하지 않는다.
- QPF 프레임만 미래 tick으로 등록한다. `ef`가 없는 시각을 보간하거나 가장 가까운 예보로 대체하지 않는다.
- 재생 중 관측 마지막 프레임에서 첫 QPF 유효시각으로 넘어갈 때 레이어를 교체한다. 관측/예측 경계는 벽시계의 현재 시간이 아니라 API 응답의 분석 기준·유효시각으로 정한다.

### 5.2 지도 상태 카드

QPF가 실제로 표시될 때만 지도 위 고정 위치에 다음 정보를 표시한다.

```text
초단기 강수예측
MAPLE · 기준 10:25 KST
선택 10:55 KST · +30분 · mm/h
```

- `기준`은 API의 분석 기준시각, `선택`은 현재 타임라인 선택 유효시각이다.
- `+N분`은 선택 시각과 분석 기준시각의 차이이며, API가 반환한 `ef`와 일치해야 한다.
- 시간대 표기는 앱의 KST/UTC 설정을 따른다.
- QPF가 없거나 관측 구간이면 카드를 표시하지 않는다.
- QPF 범례는 지도 상태 카드와 충돌하지 않는 위치에 API 제공 `bar` 이미지로 표시한다.

## 6. 실패·신선도·저장

- 수집 실패는 직전 완전한 프레임 집합을 지우거나 새 빈 메타데이터를 발행하지 않는다.
- 이미지와 메타데이터는 임시 경로에 완성한 뒤 원자적으로 발행한다. 메타데이터는 존재하지 않는 이미지 경로를 가리키지 않는다.
- 프레임에는 API가 실제로 반환한 분석·유효시각, 고도, 경로, 범례 경로, bounds를 기록한다.
- WISSDOM은 레이더 프레임과 정확한 `tm` 조합을 프런트에서 검증할 수 있게 한다.
- QPF는 기준시각과 `ef`에서 유효시각을 재현할 수 있게 한다.
- API 오류·무자료·이미지 검증 실패는 해당 레이어만 비가용 상태로 만들며, 기존 레이더·위성·KIM 레이어를 중단시키지 않는다.

## 7. 검증 기준

### 7.1 자동 테스트

- WISSDOM: 레이더 OFF, WISSDOM OFF, 정확 일치, ±1 프레임 불일치, 고도 변경, 자료 없음, 스타일 재설치 상태를 검증한다.
- WISSDOM과 KIM이 동시에 활성일 때 각자의 고도/기압면 선택 상태가 서로 바뀌지 않음을 검증한다.
- QPF: 기준시각·유효시각·`ef` 계산, 관측→예측 전환, 누락 tick, 상태 카드 문구를 검증한다.
- 기존 레이더 이동벡터 source/layer, API 산출, 제어 문자열이 제거됐음을 검증한다.
- API 키가 프런트 번들·응답 메타데이터·정적 URL에 노출되지 않음을 검증한다.

### 7.2 브라우저 계약

실제 개발 서버와 Playwright에서 다음을 증명한다.

1. 레이더 ON 후 WISSDOM 제어가 보이고, 정확 일치 프레임에서만 켜진다.
2. 고도를 바꾸면 WISSDOM 이미지·문구·범례가 함께 바뀌며, KIM 선택값은 유지된다.
3. 불일치 레이더 시각에서는 WISSDOM이 지도에 남지 않고 제어가 비활성이다.
4. 타임라인을 미래 QPF tick으로 옮기면 레이더가 숨고 QPF와 상태 카드가 정확한 시각·`+N분`으로 나타난다.
5. 타임라인을 관측 구간으로 되돌리면 QPF와 상태 카드가 사라지고 레이더가 복원된다.
6. 베이스맵을 두 번 바꾼 뒤에도 중복 source/layer 없이 같은 가시성·시각 조건이 유지된다.
7. 지도에서 해안선·주요 공항을 기준으로 WISSDOM/QPF 이미지의 공간 정합을 확인한다.

## 8. 구현 전 확인 항목

- API가 지원하는 WISSDOM 고도 전체 목록과 고도 기준면
- 실제 WISSDOM 발행 주기 및 레이더 5분 프레임과의 일치율
- MAPLE QPF의 제공 `ef` 목록·간격·최대 리드타임
- KMA 경량 지도 viewport의 공식 변환식 부재를 기록하고, 기존 HSR 전국 bounds를 사용하는 시각 정합·무재투영 경로를 유지할지 여부
- API 반환 이미지와 범례의 캐시 수명 및 서비스 이용 조건

## 승인 요청

이 설계는 다음 결정을 고정한다.

1. 레이더 이동벡터를 제거하고 WISSDOM 제어로 교체한다.
2. WISSDOM은 레이더 선택 시각과 정확히 일치하는 프레임만 표시한다.
3. WISSDOM 고도(m)와 KIM 기압면은 같은 UI 패턴을 쓰되 상태를 공유하지 않는다.
4. 미래 타임라인에서는 QPF만 표시하고, 관측 레이더와 겹치지 않는다.
5. QPF의 출처·기준·유효시각·리드타임은 지도 위 상태 카드에 항상 명시한다.

승인 후 구현 계획을 작성한다.
