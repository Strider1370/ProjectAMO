# 태풍 지도 심볼·영향반경 판독성 개선

- 상태: 명세 검토 대기
- 작성일: 2026-08-07
- 선행 명세: `2026-07-26-typhoon-track-and-route-warning-design.md`

## 1. 목적

기존 태풍 지도는 태풍별 고유색으로 경로·영향반경·라벨을 모두 그린다. 바다 배경에서 파랑 계열 태풍의 반경 채움과 라벨이 묻히고, 강풍반경에 윤곽선이 없어 경계가 즉시 읽히지 않는다.

태풍별 식별색의 장점은 유지하면서, 모든 실황·예보 시점의 강도와 위치를 빠르게 판독하고 풍속 영향반경의 경계를 분명히 보이게 한다.

## 2. 범위

포함:

- 모든 분석·예보 지점의 강도 심볼 표시
- 지점 hover와 키보드 focus 상세 카드
- 태풍별 색상 팔레트의 바다 배경 대비 개선
- 강풍·폭풍 영향반경의 채움과 윤곽선 동시 표시
- 예보 오차영역과 풍속 영향반경의 시각적 구분
- 선택형 미니멀 태풍 패널
- 단위 테스트와 실제 Mapbox 브라우저 검증

제외:

- 태풍 원천 데이터, 수집 주기, 반경 도형 계산 변경
- 경로/공항 노출 판정 변경
- 태풍 목록 패널 정보 구조 변경
- 시간 슬라이더 연동 변경

## 3. 확정된 지도 표현

### 3.1 경로와 강도 심볼

- 분석 경로는 실선, 예보 경로는 점선으로 유지한다.
- 분석·예보를 막론하고 **모든 지점**에 강도 심볼을 표시한다. 현재 위치에만 라벨을 붙이는 기존 동작은 제거한다.
- 심볼은 참조 화면과 같은 태풍 모양이며 중앙에 강도(`1`~`5`, `TD`)를 검정 숫자로 표시한다. 강도는 기존 최대풍속 기반 구간을 사용한다.
- 실황/예보의 구분은 아이콘 투명도가 아니라 경로의 실선/점선이 맡는다. 두 종류의 아이콘은 같은 선명도로 유지한다.
- 심볼에는 태풍 번호·중심기압의 상시 텍스트 라벨이나 흰색 라벨 박스를 추가하지 않는다.

### 3.2 복수 태풍 식별색

- 태풍번호별 고유색 배정은 유지한다. 사용자가 여러 태풍의 경로와 영향영역을 계속 구별할 수 있어야 한다.
- 해양 배경과 충돌하는 파랑·청록 계열은 팔레트에서 제외한다. 남은 색은 충분히 다른 색상·명도를 가져야 한다.
- 색은 유일한 식별 수단이 아니다. 각 심볼에는 강도 숫자가 있고, hover 카드에는 태풍번호·이름을 표시한다.

### 3.3 영향반경과 예보 오차영역

KMA 원천의 `RAD15`/`RAD25` 비대칭 도형은 그대로 사용한다. 도형의 의미와 시각적 역할만 다음처럼 분리한다.

| 요소 | 채움 | 윤곽선 | 목적 |
| --- | --- | --- | --- |
| 강풍반경 (`RAD15`) | 태풍 고유색, 낮은 불투명도 | 같은 색의 진하고 불투명한 선 | 태풍별 바람 영향영역과 경계 판독 |
| 폭풍반경 (`RAD25`) | 태풍 고유색, 강풍반경보다 높은 불투명도 | 같은 색의 진하고 불투명한 선 | 더 강한 바람 영향영역 판독 |
| 예보 오차영역 (`RAD`) | 태풍 고유색, 가장 낮은 불투명도 | 같은 색 점선 | 중심 위치의 70% 확률 범위. 바람 영향반경이 아님 |

강풍·폭풍반경은 기존처럼 선택한 시점의 도형을 표시한다. 패널 행 hover/focus나 지도 지점 hover/focus로 선택 시 해당 시점의 반경으로 바뀐다. 선택이 없을 때는 최신 현재 시점 반경을 보인다.

영향반경에 공통 노랑/빨강을 쓰지 않는다. JMA는 30/50 kt 풍역에 이 표기를 쓰지만, 이 제품은 동시에 보이는 복수 태풍을 구별해야 한다는 사용자의 우선 요구를 따른다. 대신 **같은 색의 채움과 불투명 윤곽선**으로 경계 가시성을 보장한다.

## 4. Hover/focus 카드

마우스 포인터가 심볼 위에 있거나 키보드 focus가 심볼에 있을 때만 Mapbox popup을 연다. 카드에는 다음을 보인다.

- 태풍번호와 이름
- 실황 또는 예보 상태
- 유효시각: KST와 UTC
- 위치
- 진행방향과 이동속도
- 강도
- 최대풍속
- 중심기압

포인터가 심볼과 popup 양쪽에서 벗어나거나 focus가 해제되면 카드를 닫는다. popup은 지도 위의 영구 라벨을 대체하며, 심볼의 접근 가능한 이름에도 태풍번호·시각·강도를 제공한다.

## 6. 태풍 패널

여러 태풍을 세로로 모두 펼쳐 보이지 않는다. 상단의 태풍 선택 탭은 고유색 점과 `번호 + 이름`을 함께 보이고, 선택된 탭만 밑줄로 표시한다. 첫 탭은 현재 활성 목록의 첫 태풍으로 하고, 탭을 바꾸면 지도 focus와 상세 내용도 같은 태풍으로 바꾼다.

선택된 태풍의 본문 순서는 다음과 같다.

1. **현재 상태 요약:** 번호·이름·발표시각, 현재 강도·풍속·기압, 위치를 조금 큰 글자로 보인다. 탭과 같은 고유색은 작은 점과 제목 옆의 가는 세로선에만 쓴다. 배경색 카드, 색 글자, 알약 배지는 쓰지 않는다.
2. **예상 경로:** 모든 예보 행에 `시각 · 강도 · 풍속 · 기압 · 위치`를 유지한다.
3. **지난 관측:** 기본적으로 접고, 사용자가 열면 같은 열 구조로 보인다.

예보 헤더와 모든 데이터 행은 **같은 CSS grid 열 정의**를 사용한다. 열 정렬은 시각·위치는 왼쪽, 강도는 가운데, 풍속·기압은 오른쪽이다. 행은 기존보다 넉넉한 세로 padding을 두고 구분선을 사용해, 인접 수치를 한 행으로 오독하지 않게 한다.

모바일 시트에서는 같은 정보를 유지하되 첫 줄에 `시각 · 강도 · 풍속 · 기압`을 고정 grid로 두고, 위치는 다음 줄 전체 폭에 배치한다. 가로 스크롤이나 축소 글꼴로 5개 열을 억지로 유지하지 않는다.

## 7. 오류·접근성

- 최대풍속이 없으면 `TD` 또는 이용 가능한 약한 상태 심볼을 쓰고, popup 수치는 `—`로 표시한다. 수집 실패를 태풍 없음으로 바꾸지 않는 현재 계약은 유지한다.
- 심볼은 pointer뿐 아니라 keyboard focus로 popup을 열 수 있어야 하며, popup의 텍스트는 색에 의존하지 않는다.
- 강도는 심볼 형태·숫자와 popup 텍스트로, 실황/예보는 선종류와 popup 텍스트로 함께 전달한다.

## 8. 검증

1. 순수 모델 테스트: 풍속→심볼 강도, 누락 값, 안정적인 색 배정, popup 표시 필드.
2. Mapbox 레이어 테스트: 모든 분석·예보 행이 심볼 feature가 되고, 강풍·폭풍 면에 fill과 outline 레이어가 모두 설치되며, 예보선만 점선이다.
3. 브라우저 계약: 실제 태풍 fixture에서 파랑 계열이 없는 복수 태풍 색, 선명한 모든 시점 심볼, 강풍반경 윤곽선, hover와 keyboard-focus 카드의 필드를 캡처로 확인한다.
4. 패널 브라우저 계약: 복수 태풍 탭 전환, 현재 상태 강조, 헤더와 예보 행의 열 정렬, 지난 관측 접기, 모바일 위치 행 재배치를 캡처로 확인한다.
