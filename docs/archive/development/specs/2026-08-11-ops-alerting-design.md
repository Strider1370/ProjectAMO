# 운영 알림 — 대규모 장애와 하루 요약

## 목표

**화면은 볼 때만 일한다.** 1단계에서 관리자 콘솔을 다시 만들어 이상한 것이 눈에 띄게 했지만, 그건 열어봤을 때의 이야기다. KIM 지상바람이 64일간 수집되지 않은 진짜 이유는 화면이 나빠서가 아니라 **아무도 보고 있지 않아서**였다.

이 스펙은 화면을 안 보는 시간을 메운다. 다만 **울리는 순간 손쓸 일이 있는 것만** 보낸다 — 무시하게 되는 알림은 없느니만 못하다.

## 선행 조건

- [1단계](2026-08-10-admin-console-redesign-design.md)가 구현돼 있다. 자료 34종의 판정(`freshness.js`의 `judge()`)과 출처 분류(`data-health-catalog.js`)를 그대로 쓴다. **판정 규칙을 새로 만들지 않는다.**
- [2단계](2026-08-10-server-observability-design.md)는 **선행 조건이 아니다.** 보류 상태이며, 이 스펙은 2단계 없이 독립적으로 동작해야 한다. 나중에 2단계가 들어오면 상태 판정 틱을 함께 쓴다.
- Web Push 기반이 이미 있다 — VAPID 열쇠 설정됨, `push_subscriptions` 표 있음, 구독 등록·해지(`/api/me/push/*`), 관리자 테스트 발송, 서비스워커의 수신 처리(`frontend/public/sw.js`)까지. **현재 구독자 0명**이라 아무도 못 받는 상태다.

## 보내는 것

### ① 출처 하나가 통째로 죽음 — 즉시

한 출처(API 열쇠)에 속한 자료가 **전부** 멈추면 보낸다. 열쇠 만료·차단·기관 서버 다운이면 그 열쇠로 받는 자료가 한꺼번에 죽는다. 이것이 "대규모 호출 불가"의 실제 모습이다.

- 판정 대상: `stopped`와 `never`
- **쉬는 시간(`quiet`)인 자료는 분모에서 뺀다.** 야간에 위성 가시가 쉬는 것 때문에 "전부 멈춤"이 성립하거나 깨지면 안 된다
- 한 출처의 자료가 전부 `quiet`이면 판정하지 않는다
- 개별 자료 하나가 멈춘 것은 **여기서 보내지 않는다** — 화면에서 본다

| 출처 | 자료 수 |
|---|---|
| 기상청 항공키 | 15 |
| 레이더·위성키 | 10 |
| 수치예보키 | 2 |
| NOAA | 3 |
| 공항공사 | 2 |
| 기타 외부 | 2 |

### ② API 전송량 한도 임박 — 즉시(하루 한 번까지)

기상청 API Hub 열쇠의 하루 전송량이 **90%를 넘으면** 보낸다. 다 쓰면 그날 남은 시간 동안 그 열쇠로 아무것도 못 받는다 — **터지기 전에 알려주는 유일한 경보**다.

`api-hub-usage.js`의 `snapshot()`이 이미 열쇠별 소진율을 준다. 04:00 KST 초기화에 맞춰 하루 한 번까지만 보낸다.

### ③ 서버 자체 — 하루 한 번까지

- **디스크**: 소진 예상이 7일 이하 (`disk-forecast.js`가 이미 계산한다)
- **재시작 반복**: 1시간에 5회 이상. 정상 배포로도 몇 번은 오르지만 그보다 잦으면 뭔가 죽고 있다는 뜻이다

### ④ 오래 멈춘 자료 — 하루 한 번 요약

개별 자료가 **24시간 넘게** 멈춰 있으면, 하루에 한 번 **묶어서 한 통** 보낸다.

이 항목이 없으면 ①의 규칙만으로는 KIM 지상바람 사건을 못 잡는다. 수치예보키 2종 중 KIM만 멈추고 KTG는 멀쩡했으므로 "전부 멈춤"이 성립하지 않는다. **이 작업 전체의 출발점이 된 사건을 못 잡는 규칙은 미완성이다.**

- 멈춘 지 24시간이 지난 자료를 모아 한 통
- 하루 한 번, **09:00 KST**
- 대상이 없으면 보내지 않는다

## 보내지 않는 것

- **개별 자료의 지연·멈춤 그 순간** — 지연은 대개 저절로 돌아온다. 그때마다 울리면 진짜 사건이 묻힌다
- **복구 알림** — 복구는 화면이 답한다. 확인 필요 목록이 비어 있으면 끝난 것이다
- **쉬는 시간** — 야간 위성 가시, 새벽 운항편·해외예보
- **이벤트성 자료의 0건** — 위험기상이 없는 것은 정상이다
- **자료 나이가 오래된 것** — 관측소가 늦는 것은 우리가 손쓸 수 없다(1단계에서 정한 원칙)

## 중복 방지

5분마다 판정하므로 조건만 보고 보내면 자료 하나로 하루 288번 울린다. **보낸 기록을 남겨 같은 사건을 다시 보내지 않는다.**

```sql
CREATE TABLE IF NOT EXISTS alerts_sent (   -- 운영 알림 발송 기록(중복 방지, 90일 보관)
  kind    TEXT NOT NULL,        -- 'source_down' | 'quota' | 'disk' | 'restarts' | 'daily_summary'
  subject TEXT NOT NULL,        -- 출처 id, 열쇠 id 등. 대상이 하나뿐이면 ''
  sent_at TEXT NOT NULL,
  PRIMARY KEY (kind, subject, sent_at)
);
CREATE INDEX IF NOT EXISTS idx_alerts_sent ON alerts_sent(kind, subject, sent_at);
```

- **① 출처 죽음**: 그 출처가 죽어 있는 동안 한 번만. 한 종이라도 살아나면 사건이 끝난 것으로 보고, 다시 전멸하면 새 사건으로 친다
- **②③**: 마지막 발송이 24시간 안이면 보내지 않는다
- **④**: 하루 한 번(발송 시각 기준)

## 전달 수단

**Web Push.** 이미 깔려 있어서 새로 붙일 것이 없다.

한계를 분명히 해둔다:
- 브라우저가 받는다. 폰에서 받으려면 폰 브라우저로 한 번 열어 구독해야 하고, **iPhone은 홈 화면에 추가해야** 알림이 온다
- 브라우저 알림 권한을 거부하면 아무것도 안 온다
- **메일은 이번에 만들지 않는다.** 보내는 수단(SMTP 계정 등)이 지금 없어 새로 붙여야 한다. 푸시가 실제로 안 닿는 것이 확인되면 그때 검토한다

받는 사람은 **`admin` 역할 사용자의 구독 전부**다. 조종사 구독(#13 경로 기상 알림)과 섞이지 않도록 발송 대상을 역할로 거른다.

## 돌리는 자리

`server.js` 시작 시 5분 틱을 건다 — 리소스 샘플러(`metrics.js`의 `startSampler`)와 같은 자리다.

수집기(`src/index.js`)에 붙이지 않는다. 수집이 꺼진 테스트 인스턴스에서도 알림 판정 코드는 돌아야 하고(끄는 것은 환경변수로), 무엇보다 **수집이 통째로 죽었을 때도 알림은 살아 있어야 한다.**

`ALERTS_DISABLED=1`이면 판정만 하고 발송하지 않는다 — 개발 중에 실제 알림이 날아가지 않게.

## 화면 변경

**어드민 → 계정 관리(또는 개요 상단)**
- **"이 기기로 알림 받기"** 버튼. 누르면 브라우저 권한을 묻고 구독한다. 이미 구독돼 있으면 "해지"로 바뀐다
- 구독 상태와 마지막 발송 시각을 함께 보여준다 — 구독한 줄 알았는데 안 돼 있는 것이 가장 흔한 실패다
- **테스트 발송 버튼**. 실제로 폰에 뜨는지 확인하는 것이 구독 UI보다 중요하다(엔드포인트는 이미 있다)

**최근 알림 이력**
- `alerts_sent`를 그대로 보여준다. 무엇이 언제 나갔는지 확인용

## 검증

- 출처 죽음 판정 단위 테스트 — 전부 멈추면 참, 한 종이라도 살아 있으면 거짓, `quiet`이 분모에서 빠지는지, 전부 `quiet`이면 판정하지 않는지
- 중복 방지 단위 테스트 — 같은 사건이 이어지는 동안 한 번만 나가는지, 복구 후 재발하면 새로 나가는지, ②③이 24시간 안에 두 번 안 나가는지
- 하루 요약 단위 테스트 — 24시간 미만은 빠지는지, 여러 개가 한 통으로 묶이는지, 대상이 없으면 안 보내는지
- 대상 거르기 단위 테스트 — 조종사 구독으로 운영 알림이 가지 않는지
- 무효 구독 정리 — 404/410이 오면 `push_subscriptions`에서 지우는지(`send.js`가 그대로 던지므로 호출 측에서 처리)
- `ALERTS_DISABLED=1`이면 발송하지 않는지
- 실제 발송 확인 — 브라우저에서 구독하고 테스트 발송이 실제로 뜨는지. 단위 테스트로 증명되지 않는 부분이다

## 안 하는 것

- 메일·SMS
- 사용자가 임계값을 화면에서 바꾸는 기능 — 값은 코드에 둔다. 바꿀 일이 생기면 그때 꺼낸다
- 알림 등급·조용한 시간대(야간 억제) — 지금 규칙이면 하루 한 통도 드물다. 시끄러워지면 그때 넣는다
- 개별 자료 멈춤의 즉시 알림
- 복구 알림
