## 무엇을 만드나

지도에 도구 버튼 두 개를 단다.

- **단열선도** — 한 지점을 클릭하면 그 지점의 Skew-T log P 다이어그램이 뜬다.
- **연직단면도** — 두 지점을 클릭하면 그 두 점을 잇는 연직단면도가 뜬다.

둘 다 클릭 즉시 그리지 않는다. 먼저 확인창이 떠서 어디를 찍었는지 보여주고, 이용자가 「생성」을
눌러야 그린다.

단열선도는 **기상청 GDAPS 단열선도의 배치와 색을 그대로 따른다.**

## 왜 만드나

앱은 KIM 수치모델 격자를 21개 기압면으로 이미 받아 저장하고 있다. 바람·기온·착빙·구름 오버레이가
그 자료를 쓴다. 그런데 지금 그 자료를 **연직으로 세워서 보는 길이 없다.** 지도의 지점 팝업
(`WeatherPointInspector`)은 화면에 떠 있는 **한 개 고도, 한 개 시각**의 값만 보여준다.

역전층이 언제 무너지는지, 캡이 얼마나 강한지, 습윤층이 어디서 어디까지인지 — 전부 연직 구조를
한 장에 세워 놓아야 읽힌다. 그 그림이 단열선도다.

`BriefingSynopsis.jsx:23`이 기상청 단열선도 png를 **정적 샘플 이미지로 박아 두고 있다는 사실
자체가** 이 그림이 필요하다는 증거다. 이 스펙은 그 고정 이미지를 아무 지점·아무 시각에서
살아 움직이는 그림으로 바꾼다.

### 이미 반영된 선행 작업

이 스펙 이전에 다음이 끝나 있다(같은 세션에서 수행, 백엔드 테스트 831개 통과).

- KIM 수집에 **비습 `q`를 21개 층 전부에 추가**했다. 인코딩 스케일 `2e-6`.
  (`backend/src/config.js` `kim_nwp.collect_specific_humidity`, `KIM_NWP_COLLECT_Q=0`으로 끌 수 있다)
- 이유: `rh`는 물/빙정 혼합 기준이라 영하층 이슬점을 그대로 못 낸다. 물 기준 `rh_liq`은 착빙용이라
  300hPa 아래에만 있다. `q`는 기준 구분이 없어 전 층에서 이슬점과 가강수량을 편향 없이 낸다.
- 실측 대조: 850hPa `q` = 12.3 g/kg (rh 역산 12.7과 3% 내 일치). 가강수량 q 기준 54.8mm 대
  rh 기준 55.1mm(−0.5%). int16 왕복 최대 오차 0.001 g/kg, 상한 여유 약 4배.

## 자료의 출처와 한계

**출처.** `backend/data/kim_nwp/runs/<runId>/normalized/hf###/<level>hPa/grid.json`.
모델 `KIMG/NE57`(전구). 이미 디스크에 있는 것만 읽는다. 이 기능은 외부 API를 새로 호출하지 않는다.

| 축 | 범위 |
| --- | --- |
| 공간 | 동경 119~136도 / 북위 30~44도, 격자 간격 0.083333도(약 9km), 205 x 169 = 34,645점 |
| 연직 | 1000 · 975 · 950 · 925 · 900 · 875 · 850 · 800 · 750 · 700 · 650 · 600 · 550 · 500 · 450 · 400 · 350 · 300 · 250 · 200 · 150 hPa (기존 21층) **+ 100 · 70 · 50 hPa (추가, 합 24층)** |
| 시간 | 예보시간 0~30시간을 3시간 간격 11스텝. 런은 발표 후 약 6시간 뒤 도착하므로 **현재 시각 기준 앞으로 +18~24시간** |
| 변수 | `T` `q` `rh` `hgt` `u` `v` (150hPa 아래 21층) / `T` `hgt` `u` `v` (100 · 70 · 50hPa) / `rh_liq` `w` `tqc` `tqi` `tqr` `tqs` `cld` (300hPa 아래) / **단일면 `ps`** (아래 절) |

**1000hPa 아래에는 등압면이 없다.** KIM 전구모델의 최하 등압면이 1000hPa이다. 층을 더 받아도
지면~1000hPa 구간은 메워지지 않는다. 다만 기상청 정의가 「1000hPa **또는 1000hPa 이하의 최하층**
기압의 공기괴」이므로, `ps`로 최하층을 고르면 규격상 문제가 없다.

**100 · 70 · 50hPa에는 습도를 받지 않는다.** 성층권 수증기는 물리적으로 무의미하다.
이슬점 곡선은 150hPa에서 끝난다.

**한계는 화면에 적는다.** 아래 세 가지는 없앨 수 없는 성질이므로, 감추지 말고 표시한다.

1. **관측이 아니라 모델이다.** 라디오존데 사운딩이 아니다.
2. **24층이라 성기다.** 기상청 그림은 L91(91층) 원본에서 뽑은 것이다. 얇은 역전층, 날카로운
   건조층, 캡 강도는 뭉개진다. CAPE는 층 간격에 민감하므로 참고치다.
3. **최하 등압면이 1000hPa이다.** 지상기압이 1000hPa 아래로 내려가는 저기압·태풍에서는
   1000hPa면 자체가 지면 아래 외삽값이 된다. 이때 하층 판독을 신뢰하면 안 된다.

세 번째는 `ps`로 정확히 판정한다. **`ps < 1000hPa`이면** 그 아래 등압면들을 회색 마스크로 덮고
「지상기압 {ps}hPa — 1000hPa면이 지면 아래, 하층 판독 불가」를 붉게 표시한다.
`ps > 1000hPa`인 평상시에는 `P_sfc` 선을 긋고 그 아래만 덮는다.

**지형고도는 KIM이 아니라 기존 DEM에서 얻는다**(결정 15). `backend/data/terrain/korea3sec.bin`은
3 arc-second(약 90m) 격자로 KIM `topo`(약 9km)보다 100배 가까이 정밀하다. 이미
`backend/src/terrain/terrain-sampler.js`와 `/api/terrain/elevation`으로 배선돼 있다.
지형고도와 지상기압은 역할이 다르다 — DEM은 「땅이 얼마나 높은가」, `ps`는 「기압이 얼마인가」다.
DEM으로 `ps`를 대신할 수 없다.

## 수집 확장

이 기능을 위해 KIM 수집에 세 가지를 더한다. 기준은 **「기상청 그림의 어느 칸을 채우는가」**이며,
채울 칸이 없는 변수는 받지 않는다.

### 1. 등압면 상층 3개 (결정 13)

`100` · `70` · `50` hPa에 `T` · `hgt` · `u` · `v`.

- **100hPa** — 기상청 단열선도의 상단이 100hPa이다. 여기까지 있어야 그림이 같아진다.
- **70hPa** — 권계면을 WMO 정의로 확정하려면 권계면 위 2km 구간의 기온감률을 봐야 한다.
  100hPa(약 16km)이 권계면일 때 이를 확인하려면 70hPa(약 18.5km)이 필요하다.
- **50hPa** — 여유분. 순항고도(150hPa ≈ FL450)는 이미 덮여 있어 운항상 추가 이득은 없다.

### 2. 단일면 `ps` 하나 (결정 14)

| 변수 | 단위 | 쓰이는 곳 |
| --- | --- | --- |
| `ps` | Pa | `P_sfc` 선 · 지면 아래 마스크 · 「1000hPa 이하 최하층」 판정 |

**단일면은 이것뿐이다.** 설계 대화 초기에 12개까지 늘렸다가, 기상청 「단열선도 사용설명서」로
표의 정의를 확인한 뒤 전부 걷어냈다. 아래가 그 기록이다.

| 뺀 변수 | 뺀 이유 |
| --- | --- |
| `tcld` · `lcld` · `mcld` · `hcld` | `Cloud`/`Upper`/`Middle`/`Lower`는 **운량이 아니라 습수(T−Td) 최소 지점**이다. 처음부터 엉뚱한 변수였다 |
| `tmax` · `tmin` | `Max/Min Temp`는 예보기온이 아니라 **850hPa에서 끌어내린 값**이다. 사운딩에서 계산된다 |
| `t2m` · `td2m` | 기상청도 「1000hPa 또는 그 이하 최하층」 공기괴를 쓴다. 곡선이 최하 등압면에서 끝나는 10hPa 남짓 틈은 눈에 띄지 않는다 |
| `topo` | `ps < 1000`이면 지면 아래이므로 중복이고, 지형고도는 기존 DEM이 100배 정밀하다 |
| `ccb` · `cct` | `CCL`은 사운딩에서 직접 계산한다. 대류운 운저·운정은 다른 값이라 칸이 없다 |
| `frl` | `FL(gpm)`은 프로파일에서 이미 낸다. 대조용일 뿐이다 |
| `hpbl` · `gust` | 기상청 단열선도에 해당 칸이 없다 |

**교훈은 기록해 둔다.** 「표의 빈칸을 채운다」를 목적으로 삼으면 필요 없는 자료를 받게 된다.
자료를 더 받기 전에 **그 칸의 정의부터 확인**해야 한다. 여기서는 정의를 확인하자
받을 것이 12개에서 1개로 줄었다.

### 3. 저장 구조

등압면 목록(`KIM_NWP_LEVELS`)에 단일면을 끼워 넣지 **않는다.** 끼우면 고도 슬라이더
(`pressureLevelModel.js`)를 비롯한 소비자가 전부 영향을 받는다. 별도 묶음으로 따로 저장한다.

```
hf000/1000hPa/grid.json    기존 등압면
    …
hf000/150hPa/grid.json
hf000/100hPa/grid.json     새 상층 (T·hgt·u·v)
hf000/70hPa/grid.json
hf000/50hPa/grid.json
hf000/surface/grid.json    새 단일면 묶음 (등압면 목록 밖)
```

고도 슬라이더는 등압면 목록만 읽으므로 화면은 바뀌지 않는다.

### 4. 예산

기상청 API허브 한도는 호출 횟수가 아니라 **바이트**다 — 키마다 하루 5.0 GB, 4.75 GB에서 차단
(`backend/src/api-hub-usage.js:7`). KIM 격자용 키의 실측 사용량은 **런당 약 1.2 GB, 하루 2런**이다.

| 항목 | 호출/런 | 전송/런 |
| --- | --- | --- |
| 현행 | 2,541 | 1.20 GB |
| 비습 `q` (이 스펙 이전에 반영됨) | +231 | +0.11 GB |
| 등압면 상층 3층 x 4변수 | +132 | +0.06 GB |
| 단일면 `ps` 하나 | +11 | +0.005 GB |
| **합계** | **2,915** | **1.375 GB** |

하루 2런이면 **2.75 GB / 5.0 GB**로 차단선까지 2.0 GB 남는다.

수집 소요 시간도 제약이 아니다. 실측으로 한 런(231개 파일)을 **8분**에 받는다.
(같은 저장소의 다른 런이 399분 걸린 기록이 있으나, 이는 실패한 변수를 몇 시간에 걸쳐 되받는
증분 재시도이지 정상 수집 속도가 아니다.)

## 두 도구와 진입 흐름

### 도구 버튼

지도 도구모음에 버튼 두 개를 추가한다.

```
[ 단열선도 ]  [ 연직단면도 ]
```

- **한 번에 하나만** 활성화된다. 하나를 켜면 다른 하나는 꺼진다.
- 켜면 지도 커서가 십자로 바뀐다.
- 같은 버튼을 다시 누르거나 `Esc`를 누르면 꺼진다.
- 도구가 켜져 있는 동안 **수집 영역 경계(119~136E / 30~44N)를 지도에 흐리게 표시**한다.
  영역 밖을 찍는 헛수고를 미리 막는다.
- 도구가 켜져 있는 동안 기존 지점 팝업(`WeatherPointInspector`)은 뜨지 않는다. 클릭의 뜻이
  달라졌기 때문이다.

### 클릭

- **단열선도**: 한 점 클릭 → 확인창
- **연직단면도**: 첫 점 클릭 → 마우스를 따라 선이 늘어남 → 둘째 점 클릭 → 확인창

### 확인창

작은 모달. 클릭한 자리가 맞는지 눈으로 확인하는 자리다.

```
┌────────────────────────────────────┐
│  인천국제공항 (RKSI)                │
│  Site   37.463N 126.440E           │
│  Model  37.500N 126.417E  (4.2km)  │
│  유효   2026-08-15 21KST (+18h)    │
│           [ 취소 ]   [ 생성 ]      │
└────────────────────────────────────┘
```

- 클릭 지점에서 **10km 안에** 공항이 있으면 **공항 이름과 ICAO 부호**를 제목으로 쓴다.
  없으면 좌표만 쓴다. 공항 자료는 앱에 이미 있다. 10km는 격자 간격(약 9km)보다 조금 넓게 잡은
  값이다 — 격자 하나 안쪽이면 사실상 그 공항의 값이기 때문이다.
- `Site`는 클릭한 자리, `Model`은 실제로 값을 읽어 올 격자점, 괄호 안은 둘 사이 거리.
  **기상청 그림이 하는 그대로다.** 9km 격자로 스냅된다는 사실을 숨기지 않는다.
- 연직단면도는 제목이 `RKSI → RKPC` 꼴이고 거리(NM)를 함께 보인다.
- 영역 밖이면 「생성」이 잠기고 「수집 영역 밖입니다」를 띄운다.

### 결과

「생성」을 누르면 하단 창이 열리고 해당 탭이 선택된다. 지도에는 핀(단열선도) 또는 선(연직단면도)이
남아, 창을 닫아도 다시 열 수 있다.

## 하단 창과 탭

기존 `VerticalProfileWindow`의 창 껍데기(하단 배치, 모바일 전체화면, 닫기)를 그대로 쓴다.
새 껍데기를 만들지 않는다.

```
[ 단열선도 ]  [ 연직단면도 ]        🔗 지도와 연동 중            ✕
```

**경로 브리핑 안의 연직단면도는 그대로 둔다.** 브리핑 흐름에서 항로를 따라 보는 것과, 지도에서
즉석으로 두 점을 긋는 것은 쓰임이 다르다. 둘은 같은 창을 공유하되 서로를 덮지 않는다.
지도 도구로 만든 것이 있으면 그것을, 없으면 경로 브리핑의 것을 보인다.

### 시간축 연동

- 평소에는 지도 시간 슬라이더(`NwpSliderBar`)와 한 몸이다. 지도 시간을 옮기면 따라온다.
- **사운딩 창 안의 슬라이더를 건드리는 순간 연결이 끊긴다.**
- 끊기면 헤더가 바뀐다:
  `🔗 지도와 연동 중` → `⛓️‍💥 지도와 다른 시각 (지도 15Z · 단열선도 21Z)` + `[지도에 맞추기]`
- 끊긴 동안 **지도의 핀과 창 테두리가 같은 경고색으로 물든다.**

이 표시가 없으면 위성은 15Z, 사운딩은 21Z를 보면서 같은 시각이라 착각하는 사고가 난다.
연결 해제는 반드시 눈에 띄어야 한다.

### 자르기와 스큐 — 프로토타입에서 실제로 틀렸던 곳

**스큐는 「등온선을 화면상 45도」로 잡으면 안 된다.** 표준대기의 기온곡선이 대략 수직으로 서도록
잡아야 한다. 지면 25℃에서 100hPa −75℃까지 약 100℃가 떨어지므로, 그만큼을 가로로 밀어준다.
기상청 그림에서 빨간 실선이 거의 곧게 서 있는 것이 이 때문이다.

**자르기(clip)는 직사각형으로 한다.** 사다리꼴로 자르되 그 빗변을 최저 등온선(−40℃)에 맞추면
**−40℃보다 추운 상층이 전부 잘려 나간다.** 프로토타입에서 실제로 이 일이 일어나
250hPa 위의 기온·이슬점 곡선이 사라졌다. 압력 눈금과 고도축은 100hPa·16km까지 그려져 있는데
정작 그 자리에 선이 없어, 상층 3층을 새로 수집해 놓고 화면에는 못 그리는 상태였다.

### 선과 색

| 요소 | 색·형태 |
| --- | --- |
| 기온 | 굵은 빨강 실선 |
| 이슬점 | 빨강 점선 |

| 등온선·바깥 테두리 | 금갈색 |

기괴 경로가 검정 실선인 점에 유의한다.

### 기괴와 기준선

기괴는 **1000hPa 기단 하나만** 띄운다(결정 11). 기상청 그림의 좌측 표가 `1000 hPa Air-mass`
기준이고 지수도 `LI (SFC-500)`이므로, 기상청을 모사하는 이 스펙에서는 그것이 맞다.
설계 대화 중 검토했던 혼합층(mixed-layer) 기괴와 선택기는 **넣지 않는다** — 기상청 그림에 없다.

1000hPa에서 띄운 기괴는 LCL까지 건조단열, 그 위로는 가단열을 따른다. 부력 적분은 가온도로 한다.

LCL · CCL · LFC · EL을 차트 안에 가로선과 라벨로 표시한다.

**네 선 모두 그림판을 가로질러 긋고 색으로 구분한다** — EL 보라, LFC 빨강, CCL 주황, LCL 청록.
프로토타입에서 오른쪽 끝 60px만 그렸더니 「나오다 만 선」으로 보여 무슨 선인지 읽히지 않았다.
라벨끼리 겹치면 라벨만 세로로 밀어 표시한다(선은 제자리).
**CCL을 빠뜨리기 쉽다** — 지수표에는 값이 있는데 그림에는 안 그리는 실수를 프로토타입에서 했다.

### `P_sfc`와 지면 아래 마스크

지상기압 `ps`를 수집하므로(결정 10) 기상청 표기를 그대로 쓴다.

- 차트 하단에 `P_sfc: 1008.8` 꼴로 지상기압을 적고, **그 아래를 회색으로 덮는다.**
- 기온·이슬점 곡선은 **최하 등압면에서 끝난다.** `P_sfc`가 1000hPa보다 높으면 마스크 위에
  10hPa 남짓 빈 띠가 생기는데, 전체 높이의 1% 정도라 눈에 띄지 않는다. `t2m`·`td2m`을 받아
  메울 수도 있으나 기상청도 「1000hPa 또는 그 이하 최하층」 공기괴를 쓰므로 받지 않는다.
- **`ps < 1000hPa`이면** 1000hPa면이 지면 아래다. 그 아래 등압면을 전부 마스크로 덮고
  「지상기압 {ps}hPa — 하층 판독 불가」를 붉게 표시한다. 기괴는 지면 위 최하 등압면에서 띄운다.

기괴 기준(결정 11)은 그대로 「1000hPa 또는 그 이하 최하층」 기단이다.
별도로 **최대불안정(MU) 기괴**를 속에서 하나 더 돌리는데, 이는 `CPTP` 계산 전용이며
화면에는 그리지 않는다.

### 이슬점 곡선의 출처 구분

이슬점은 비습 `q`에서 낸다. `q`가 없는 옛 런에서는 `rh_liq`(300hPa 아래) → `rh`(그 위) 순으로
물러서며, `rh`로 낸 구간은 **점선을 더 옅게** 그려 구분하고 그림 아래에 이유를 적는다.
빙정 기준 `rh`는 실제보다 습하게 나오기 때문이다.

오해해 단일면 운량 변수(`tcld`·`lcld`·`mcld`·`hcld`)를 받으려 했으나, 정의를 확인하고 전부 뺐다.

**`Max Temp`·`Min Temp`도 예보 최고·최저기온이 아니다.** 850hPa에서 끌어내린 값이므로 사운딩에서
계산된다. 단일면 `tmax`·`tmin`도 뺐다.

### CPTP (Cloud Physics Thunder Parameter)

구름물리 기반 낙뢰 가이던스 지수. NOAA SPC의 Bright et al.(2005).

```
CPTP = ( -19℃ - T_EL ) x ( CAPE_20 - K ) / K
```

| 기호 | 뜻 |
| --- | --- |
| `T_EL` | EL(평형고도) 온도 (℃) |
| `CAPE_20` | **최대불안정(MU) 기괴**의 0℃~−20℃ 층 CAPE |
| `K` | 상수. 100~200 J/kg. **기본값 100**(구름물리 안개가이던스가 쓰는 값). 설정으로 뺀다 |

**MU 기괴의 LCL 기온이 −10℃ 이하이면 `CPTP = 0`이다.** 과냉각 수적이 없어 전하 분리가 일어나지 않기 때문이다.

배경 조건(적란운 전기발생): LCL ≥ −10℃(과냉각 수적 존재), 0~−20℃ 층 CAPE ≥ 100~200 J/kg
(charge-reversal 층으로 향하는 상승운동), EL 온도 ≤ −20℃(구름꼭대기가 charge-reversal층 위).

**구현상 주의 두 가지.**

1. **최대불안정(MU) 기괴가 따로 필요하다.** 화면에 그리는 기괴는 결정 11대로 1000hPa 기단
   하나뿐이고, MU 기괴는 **CPTP 계산용으로 내부에서만** 돌린다. 표시 규격은 바뀌지 않는다.
2. **`CAPE_20`은 0℃~−20℃ 층만 적분한다.** 그 층은 보통 700~500hPa 부근이라 우리 격자로
   5~6개 층밖에 걸리지 않는다. 얇은 층을 성긴 자료로 적분하는 것이라 오차에 민감하다.
   값 옆에 이 사실을 도움말로 붙인다.

**위성 산출물 `CTPS`와 혼동하지 말 것.** `CTPS`는 GK2A 위성이 관측한 운정 산출물
(`CTH` 운정고도, `CTT` 운정온도, `config.js:252`)이며 이 앱이 이미 `대류 CI·CTPS`로 받고 있다.
글자가 비슷할 뿐 **`CPTP`(사운딩 지수)와는 완전히 다른 것**이다.
(다만 위성 `CTH`는 단열선도의 `HEL`(평형고도)과 대조하기 좋은 값이다 — 이 스펙 범위 밖이나
나중에 「위성 운정 겹쳐 보기」를 한다면 그 근거가 된다.)

### 우측 바람 깃 레일과 호도그래프

- 바람 깃은 knots. 하층은 로그 간격이 좁아 깃이 겹치므로 **세로 간격이 22px 이상일 때만** 그린다
  (프로토타입에서 겹침이 사라진 값). 최대풍 고도에는 `M/W` 표시를 붙인다.
- 호도그래프는 우상단 박스. 단위 m/sec. **1000hPa부터 300hPa까지의 바람 벡터 끝을 순서대로 잇고**,
  850 · 700 · 500 · 400 hPa 지점에 라벨을 붙인다.

### 토글

항로 단면이 이미 쓰는 `CrossSectionToggles` 패턴을 그대로 쓴다.

```
[배경격자] [기괴·CAPE] [착빙] [바람] [지수표]
```

| 토글 | 켜면 보이는 것 |
| --- | --- |
| 배경격자 | 건조단열선 · 습윤단열선 · 포화혼합비선 (등압선과 등온선은 축이므로 항상 보인다) |
| 기괴·CAPE | 기괴 경로(검정 실선) · CAPE 음영 · CIN 음영 · LCL/CCL/LFC/HEL 기준선 |
| 착빙 | 0℃선 · −20℃선 · 그 사이에서 습수가 작은 구간 음영 |
| 바람 | 우측 깃 레일 · 호도그래프 |
| 지수표 | 좌측 PREDICTION ANALYSIS |

**구름 띠 음영은 그리지 않는다.** 단열선도는 기온과 이슬점 사이 간격으로 구름을 읽는 그림이고,
기상청 그림 본체에도 구름 음영이 없다. 착빙 표시도 전부 T와 Td에서 나오므로 `cld`가 필요 없다.
(`cld` 수집은 기존 착빙 산출이 쓰므로 그대로 두되, **이 기능에서는 쓰지 않는다.**)

용도가 넷이므로(결정 1) 기본은 전부 켜고, 필요 없는 겹을 끄게 한다.

### 판독선

차트 위에 커서를 올리거나 손가락을 대면 그 높이에 가로선이 붙고 작은 판독창이 뜬다.

```
─────────────────────  680 hPa · 3.2 km
                       T -2.4℃  Td -6.1℃  270°/38kt
```

### 테마

차트 본체는 **다크모드에서도 밝은 종이 배경 그대로** 둔다(결정 8). 기상청 그림을 모사하는 것이
목적인데 색을 뒤집으면 그 목적이 사라진다. 창 테두리·헤더·탭만 `tokens.css`를 따른다.

### 모바일

하단 창의 전체화면 모드를 그대로 쓴다. 세로로 길어 단열선도에 유리하다.
지수표는 접어 두고 눌러서 펼친다. 시간은 손가락으로 좌우로 문질러 넘긴다.

## 연직단면도 (두 점)

`VerticalProfileChart`의 그리는 코드를 재사용하고, **입력만 바꾼다.** 항로 대신 두 점을 잇는
대권 경로를 따라 격자를 표본한다.

- 두 점 사이를 일정 간격으로 나눠 각 지점의 21층 값을 뽑는다.
- **표본 개수는 60개로 고정하되, 간격이 격자 간격(약 9km)보다 좁아지면 개수를 줄인다.**
  격자보다 촘촘히 뽑아 봐야 같은 격자점을 여러 번 읽을 뿐이라 그림이 더 정밀해지지 않는다.
  즉 표본 개수 = `min(60, 두 점 거리 / 9km)`.
- 기존 항로 단면과 같은 겹(기온·바람·착빙·구름·난류)을 쓴다.
- **지형 단면은 기존 DEM에서 공짜로 따라온다.** `backend/src/terrain/terrain-sampler.js`의
  `sampleAxis()`에 같은 표본 축을 넘기면 되고, `VerticalProfileChart.jsx:226`이 이미
  그 결과를 받아 바닥에 지형을 그리고 있다. 새로 만들 것이 없다.

## 서버 창구

브라우저는 21개 층 파일(각 약 5MB)을 읽을 수 없다. 서버가 읽어 한 지점만 뽑아 넘긴다.

```
GET /api/kim/sounding?lat=&lon=&hf=
GET /api/kim/cross-section/adhoc?lat1=&lon1=&lat2=&lon2=&hf=
```

응답은 숫자 꾸러미다(단열선도 약 3KB).

```
{
  model, runId, tmfc, hf, validTime,
  site:  { lat, lon, name, icao, terrainM },      // terrainM은 DEM(약 90m)에서
  model_point: { lat, lon, distanceKm },
  surface: { psHpa, baseLevelHpa, belowGround },   // belowGround = psHpa < 1000
                                                  // baseLevelHpa = 기괴를 띄우는 최하 등압면
  levels: [ { p, tC, tdC, tdSource, q, rh, hgtM, u, v, cld } , … ],
  parcel: { kind: "sfc-1000", path, pLcl, pCcl, pLfc, pEl, cape, cin },
  indices: { … },
  notes:  [ "q 미수집 런", "19/21층" ]
}
```

`notes`는 화면에 그대로 표시할 한계 목록이다. 서버가 아는 사실을 화면까지 그대로 전달한다.

### 파일 구성

계산과 그림을 분리한다. 열역학은 자료와 무관한 순수 계산이므로 따로 두면 자료 없이 시험할 수 있다.

| 새 파일 | 역할 |
| --- | --- |
| `backend/src/lib/thermo.js` | 포화수증기압 · 이슬점 · 혼합비 · 온위 · 건조/습윤단열 · LCL · CAPE. **순수 함수만.** 프로토타입 `prototypes/skewt/skewt.mjs`의 검증된 코드를 옮긴다 |
| `backend/src/briefing/sounding-composer.js` | 격자에서 한 지점의 21층을 뽑아 `thermo.js`로 지수를 낸다 |
| `frontend/src/features/sounding/SoundingChart.jsx` | SVG 렌더러. 받은 숫자만 그린다 |
| `frontend/src/features/sounding/SoundingPanel.jsx` | 탭 내용 · 슬라이더 · 연동 상태 |
| `frontend/src/features/sounding/lib/soundingGeometry.js` | 기압·기온 → 화면 좌표 변환. 순수 함수 |
| `frontend/src/features/sounding/SoundingConfirmDialog.jsx` | 확인창. 두 도구가 함께 쓴다 |

`VerticalProfileChart.jsx`는 이미 736줄이다. 단열선도를 여기에 밀어 넣지 않는다.

## 어긋날 때

| 상황 | 처리 |
| --- | --- |
| 수집 영역 밖 클릭 | 확인창에서 「생성」을 잠그고 안내. 도구 켜는 동안 영역 경계를 지도에 표시 |
| 런 교체 중이라 파일이 사라짐 | **이전 런으로 물러선다.** 실제로 겪은 상황이다 — 수집기가 돌면서 런 디렉터리가 나타났다 사라진다 |
| 고른 예보시간이 아직 수집 안 됨 | 가장 가까운 수집된 시간으로 대체하고 배지로 알린다 |
| 일부 층에 변수가 비어 있음 | 그 층을 건너뛰고 `notes`에 「19/21층」을 담아 화면에 표시 |
| 비습 `q`가 없는 옛 런 | 상대습도로 물러서고 이슬점 곡선의 그 구간을 옅은 점선으로 구분 |
| **지상기압 `ps`가 없는 옛 런** | `P_sfc` 선과 마스크를 생략하고 1000hPa에서 끊는다. 「지상기압 미수집」을 적는다 |
| **`ps < 1000hPa`** | 그 아래 등압면을 마스크로 덮고 「지상기압 {ps}hPa — 하층 판독 불가」를 붉게 표시 |
| **상층 3층이 없는 옛 런** | 150hPa에서 끊고 권계면(`T/P`)은 `----`로 둔다 |
| **MU 기괴의 LCL 기온 ≤ −10℃** | `CPTP = 0`. 오류가 아니라 정의상 값이다 |
| **`CAPE_20` 층이 2개 층 미만** | `CPTP`를 `----`로 둔다. 적분할 층이 없으면 값이 무의미하다 |

원칙은 하나다. **모자란 건 모자란 대로 보여주되, 모자라다는 사실을 반드시 화면에 적는다.**
조용히 그럴듯한 값을 그리는 것이 가장 위험하다.

## 빠르기

- 한 지점 21층 추출은 서버에서 약 0.3초다(측정값, 캐시 더움).
- 창이 열리면 **앞뒤 예보시간을 미리 받아 둔다.** 슬라이더를 문질러도 끊기지 않는다.
- 클릭 지점은 격자로 스냅되므로 **같은 격자·같은 시각이면 다시 계산하지 않는다.**
  캐시 열쇠는 `(runId, gridX, gridY, hf)`.

## 확인 방법

1. **열역학 단위 시험** — 프로토타입 `--check`가 이미 통과시킨 항목을 정식 테스트로 올린다.
   포화수증기압 기준값(0℃=6.112hPa, 20℃=23.39hPa), 이슬점 역함수 왕복, 온위 보존
   (20℃/1000hPa → 700hPa = −8.4℃), LCL 범위, 가단열이 건조단열보다 항상 덜 식는지, 가단열 단조성.
2. **좌표 변환 시험** — 기압·기온 ↔ 화면 좌표 왕복, 등온선이 정말 45도인지.
3. **서버 창구 시험** — 고정된 가짜 격자를 넣어 알려진 지수 값이 나오는지. 층 누락·런 교체·영역 밖
   같은 어긋남도 각각 시험한다. **`ps < 1000hPa`일 때 마스크와 경고가 나오는지**도 시험한다.
4. **지수 대조 시험** — 기상청 문서의 정의대로 나오는지 손으로 검산한 값과 맞춘다. 특히
   `CVT Temp`(CCL에서 건조단열 하강), `Max Temp`(850hPa에서 건조단열 하강),
   `Min Temp`(850hPa에서 포화혼합비선 하강), `Upper/Middle/Lower`(구간별 습수 최소).
   `CPTP`는 `CAPE_20 < K`일 때 음수가, MU LCL 기온 ≤ −10℃일 때 정확히 0이 나오는지 확인한다.
5. **수집 확장 확인** — 100·70·50hPa과 `ps`가 실제로 받아지는지 실물 호출로 확인하고,
   하루 전송량이 예산(5.0 GB) 안에 있는지 `api-hub-usage.json`으로 검증한다.
6. **기상청 그림과 눈으로 대조** — `docs/일기도/kim_gdps_skew_47163_s000_2026070200.png`와
   나란히 놓고 배치·색·눈금·지수표 항목을 맞춘다.
7. **실제 브라우저 확인** — 도구 켜기 → 클릭 → 확인창 → 생성 → 그림이 뜨는 전 과정을 Playwright로
   돌리고 화면을 캡처한다. 미리보기가 아니라 실제 앱으로 확인한다
   (`docs/policies/verification/browser-verification.md`).

## 하지 않는 것

- **실시간 추가 API 호출.** 이 기능은 디스크에 있는 것만 읽는다. `ps`도 수집해 두고 읽는다.
- **KIM `topo` 수집.** 기존 DEM이 100배 정밀하다(결정 15).
- **성층권 습도.** 100·70·50hPa에는 `rh`·`q`를 받지 않는다. 이슬점 곡선은 150hPa에서 끝난다.
- **`ccb` · `cct` · `frl` · `hpbl` · `gust` 수집.** 기상청 단열선도에 해당 칸이 없다.
- **관측 사운딩(라디오존데) 겹쳐 그리기.** 기상청 API허브의 고층 자료는 별도 활용신청이 필요하다
  (실측 확인: `upp_temp.php`가 403 「활용신청이 필요한 API」를 돌려준다). 나중 과제다.
- **예보시간 1시간 간격.** API는 주지만 저장이 3배가 된다. 3시간 간격을 유지한다.
- **ft/FL 고도축.** 기상청과 같이 km만 쓴다(결정 7).
- **차트 다크 테마.** 본체는 밝게 고정한다(결정 8).
- **경로 브리핑의 기존 연직단면도 교체.** 그대로 둔다.
