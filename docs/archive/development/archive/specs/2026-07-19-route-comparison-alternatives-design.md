# 경로비교 — 우회안 편집·비교 설계

> 작성: 2026-07-19 · 상태: 리뷰 수정 반영됨, 구현 계획 전
> 탭 이름: **경로비교**
> 대체 범위: `2026-07-17-route-input-map-interactions-design.md`의 두 번째 단계 명칭, 클릭 추가·자유곡선 그리기·별도 구간 우회 모드, 그리고 해당 편집 도구 UI 결정을 대체한다. 그 문서의 자동 대안 생성 금지, 기준 경로 복제, 사실 기반 비교, MapView 소유 경계는 유지한다.

## 1. 목적

경로비교는 최초 경로 생성 화면이 아니다. 이미 적용한 **기준 경로**에 뇌우, 착빙, 난류, 저시정 등 위험기상이 있을 때 조종사가 기준 경로를 보존한 채 우회안을 만들고, 각 경로의 운항상 차이를 비교하는 작업 공간이다.

사용자는 이 탭에서 다음을 할 수 있어야 한다.

1. 기준 경로가 어떤 위험기상에 얼마나 노출되는지 확인한다.
2. 기준 경로 또는 기존 우회안을 복제해 새 우회안을 만든다.
3. 선택한 우회안을 문자열 또는 지도 드래그로 빠르게 편집한다.
4. 기준 경로 대비 거리, 예상 시간, 위험 현상별 수평 노출의 증감을 비교한다.
5. 하나의 경로를 선택해 고도 비교와 브리핑으로 넘긴다.

이 탭은 자동 회피, 안전 판정, 최적 경로 추천, 운항 허가를 제공하지 않는다. 모든 수치는 조종사가 판단하는 사실 정보다.

## 2. 범위와 경계

### 포함

- IFR·VFR 모두의 기준 경로와 사용자 우회안 비교
- 기준 경로를 보존한 설계안 복제·이름 변경·삭제·되돌리기
- 선택한 우회안의 항로 문자열 편집
- 선택한 우회안의 경유점 및 구간 드래그 편집
- 거리·ETA·위험 현상별 수평 노출의 기준 대비 변화 표시
- 지도에서 기준 경로, 선택 우회안, 다른 우회안, 위험 구간의 구분 표시

### 제외

- 자동 우회안 생성·추천 순위·위험 점수·안전성 판단
- 자유곡선 그리기, 빈 지도 클릭으로 경유점 추가, 독립적인 지도 상호작용 모드 선택
- 새 기상 데이터나 새 위험 레이어
- 첫 번째 `비행 설정` 탭의 기본 경로 생성·VFR 단일 초안 계약 변경
- 고도 비교·브리핑 계산 방식 자체 변경

## 3. 용어와 단일 소유자

| 용어 | 뜻 |
| --- | --- |
| 기준 경로 | 첫 번째 탭에서 적용한 경로. 비교 기준이며 이 탭에서 직접 바꾸지 않는다. |
| 우회안 | 기준 경로 또는 다른 우회안을 복제해 만든 독립 설계안. 이 탭에서 편집하는 대상이다. |
| 선택 우회안 | 지도 편집과 상세 비교의 대상인 설계안 하나. |
| 초안 변경 | 문자열 입력·드래그 뒤 아직 적용하지 않은 선택 우회안 변경. |
| 적용 우회안 | 확인 뒤 거리·ETA·위험 노출 계산과 다음 단계에 쓰는 설계안. |
| 위험 노출 | 선택한 경로가 같은 기상 자료 시각의 각 위험 현상 영역과 수평으로 겹치는 거리(NM). |

기준 경로와 각 우회안은 서로 독립적으로 다음을 소유한다.

```text
applied: { routeForm, procedures, enroute, userWaypoints, routeResult,
           routeModel, routeExposure, routeString, undoStack }
draftEditor: { rawText, preview, previewWaypoints, error, requestVersion }
pendingEdit: { kind, beforeDraft, proposedDraft } | null
```

- `applied`만 거리·ETA·위험 노출·고도 비교·브리핑·저장에 쓴다.
- `draftEditor`와 `pendingEdit`는 저장하지 않는다. 선택을 바꾸면 아직 적용하지 않은 초안과 확인 카드는 폐기하고, 새 선택 설계안의 적용 문자열을 새 초안의 시작값으로 쓴다.
- 비동기 미리보기·노출 응답은 `designId + requestVersion`이 현재 선택·현재 요청과 모두 일치할 때만 반영한다. 늦게 끝난 A의 응답은 B 또는 A의 새 초안을 덮을 수 없다.
- 기준 경로에는 `draftEditor`나 `pendingEdit`를 만들지 않는다. 선택 우회안의 초안 변경은 기준 경로, 다른 우회안, 저장된 브리핑을 바꾸지 않는다.

## 4. 사용자 흐름

```text
비행 설정 → 경로 설정 → 경로비교 → 고도 비교 → 브리핑

경로비교
  기준 경로 위험 확인
    → “이 경로에서 우회안 만들기”
      → 우회안 선택·편집
        → 변화량 비교
          → 선택 경로로 고도 비교
```

경로가 하나뿐일 때도 화면은 “대안 목록”보다 기준 경로 요약과 `이 경로에서 우회안 만들기`를 먼저 보여 준다. 우회안이 만들어진 뒤에만 비교 목록과 선택 우회안 편집 영역을 보인다.

## 5. 화면 구조

### 5.1 상단: 기준 경로와 위험 요약

상단은 상태를 먼저, 컨트롤을 나중에 보여 준다.

```text
기준 경로
RKSI → RKPC · 244 NM · 예상 2시간 02분
뇌우 146 NM · 저시정 149 NM · 착빙 0 NM

[이 경로에서 우회안 만들기]
```

위험 문구는 단순 경고의 반복이 아니라 현상과 노출 거리만 표시한다. `Embedded Thunderstorm 수평 교차 146 NM` 같은 시스템 문구는 `뇌우 구역 통과 146 NM`처럼 조종사 언어로 쓴다.

### 5.2 중간: 경로 목록

기준 경로는 목록 맨 위에 고정하고, 삭제·직접 편집 대상이 아니다. 우회안은 최대 3개이며 기준 경로까지 최대 4개다.

각 행은 이름보다 비교에 필요한 변화량을 먼저 보여 준다.

```text
기준 경로                 244 NM
우회안 A · 선택됨          +18 NM · +9분 · 뇌우 -146 NM · 착빙 +22 NM
우회안 B                   +31 NM · +14분 · 저시정 -137 NM
```

선택 상태는 테두리, 체크 표시, 지도 강조선으로 함께 표현한다. `선택됨` 텍스트만으로 상태를 전달하지 않는다.

### 5.3 하단: 선택 우회안 편집과 비교

선택 우회안이 있을 때만 편집 영역을 보인다.

```text
선택한 우회안 A
항로 문자열 직접 편집
[BULIT Y711 MEKIL DCT MANGI DCT BEDES]
[적용] [되돌리기] [더보기]

기준 경로 대비
거리          +18 NM
예상 시간     +9분
뇌우 노출     146 → 0 NM      -146 NM
저시정 노출   149 → 12 NM     -137 NM
착빙 노출     0 → 22 NM       +22 NM

[이 우회안으로 고도 비교]
```

`더보기`에 이름 변경, 우회안 복제, 삭제를 넣는다. 삭제는 확인 카드 또는 실행 취소 없이는 확정하지 않는다.

## 6. 편집 계약

경로비교의 편집 방식은 **문자열**과 **지도 드래그** 두 가지뿐이다.

### 6.1 항로 문자열 직접 편집

- 라벨은 `항로 문자열 직접 편집`이다. `호환 경로 문자열`이라는 표현은 쓰지 않는다.
- IFR 문자열은 선택 우회안의 en-route 정본을 표현한다. SID/STAR/IAP와 공항은 별도 구조 데이터로 유지한다.
- VFR 문자열은 기존 단일 문자열 계약을 그대로 쓴다. 즉 `DEP DCT … DCT ARR` 전체가 `draftEditor.rawText`의 정본이며, 내부 `enroute`·`userWaypoints`는 그 문자열에서만 파생한다. 공항을 별도 값으로 다시 조합해 VFR 문자열을 만들지 않는다.
- `DCT`, 공개 FIX, 항공로, 좌표 token은 기존 파서·formatter 계약을 그대로 따른다.
- 입력은 초안이다. `적용` 또는 Ctrl+Enter 전에 적용 우회안, 비교 수치, 고도 비교, 브리핑을 바꾸지 않는다.
- 파싱·연결 검증이 실패하면 실패 token과 이유를 입력 근처에 표시하고 기존 적용 우회안을 유지한다.
- 적용 뒤 문자열, 지도 경유점, 거리, ETA, 위험 노출은 같은 설계안에서 함께 갱신한다.

### 6.2 지도 드래그

별도의 `지도 클릭 추가`, `그리기`, `구간 우회` 버튼이나 모드는 만들지 않는다.

- 선택 우회안의 편집 가능한 경유점을 드래그하면 해당 경유점을 옮기는 초안을 만든다.
- 두 편집 가능한 경유점 사이의 작은 `+` 핸들을 드래그하면 새 경유점을 그 구간에 삽입하는 초안을 만든다.
- 빈 지도에서의 드래그는 항상 지도 이동·확대에 쓴다. 빈 지도 클릭은 경로를 바꾸지 않는다.
- 놓은 위치 근처에 유효한 공개 FIX가 있으면 FIX를 제안한다. 없으면 허용된 좌표 waypoint를 제안한다.
- IFR에서는 제안한 FIX/좌표와 기존 SID·STAR·항공로가 전체적으로 연결되는지 검증한다. 연결이 실패하면 적용하지 않고 이유를 표시한다.
- VFR에서는 설계안별 전체 문자열 초안과 drag 확인·취소 계약을 재사용한다. 취소는 해당 우회안의 rawText·previewWaypoints·pendingEdit를 drag 직전 값으로 되돌리고 확인 카드를 닫는다.
- 드래그 후 확인 카드에는 삽입·변경 위치, 제안 FIX 또는 좌표, 문자열 변화 조각을 표시한다. `적용` 전에는 비교 수치와 기준 경로가 바뀌지 않는다.
- 모바일에서는 경유점 또는 `+` 핸들을 길게 눌러 끈다. 모든 기능은 문자열 편집으로도 수행 가능해야 한다.

### 6.3 되돌리기와 삭제

- 적용한 우회안 변경은 해당 우회안의 undo stack에만 기록한다. 복제한 우회안의 undo stack은 항상 빈 상태에서 시작한다.
- `되돌리기`는 변경이 있을 때만 보이거나 활성화한다.
- 우회안 삭제 전에는 `우회안 A를 삭제할까요?` 확인 카드에 삭제·취소를 제공한다. 확인 중에는 선택·초안을 바꾸지 않는다. 확정 삭제 시 해당 초안·확인 카드·지도 pending 표시를 함께 지우고, 바로 앞 우회안이 있으면 그것을, 없으면 기준 경로를 선택한다. 기준 경로는 삭제할 수 없다.

## 7. 지도와 위험 표시

지도는 편집과 비교의 공통 도구다. 색만으로 구분하지 않고 작은 범례를 항상 제공한다.

| 지도 표현 | 의미 |
| --- | --- |
| 옅은 회색 점선 | 기준 경로 |
| 진한 실선 | 선택 우회안 |
| 낮은 대비 보조선 | 선택하지 않은 우회안 |
| 강조 구간 | 기준 경로와 선택 우회안이 달라진 구간 |
| 기상 영역 | 레이더·낙뢰·SIGMET·AIRMET·착빙 등 기존 레이어 |

기상 레이어 칩은 유지하되 경로 편집 버튼 사이에 두지 않는다. `위험 표시` 접이 영역 안에서 해당 레이어만 켜고 끈다. 칩은 경로, 위험 계산, 비교 결과를 바꾸지 않는다.

## 8. 비교 계약

모든 경로는 같은 기준으로 비교한다. 수치가 없는 경우 `자료 없음`을 명시하고 0으로 보이지 않는다.

- ETD와 TAS는 비행 전체의 공통 설정이다. 각 설계안의 비행시간과 ETA는 같은 TAS·ETD에서 적용 경로 거리로 다시 계산한다.
- 한 번의 비교 행들은 서버가 한 번 고정한 같은 기상 자료 snapshot/version과 ETD로 계산한다. 자료 시각 또는 snapshot version이 다르면 행마다 자료 시각을 표시하고 변화량 대신 `동일 자료로 비교 불가`를 표시한다.
- 수평 노출 geometry는 모든 설계안에서 같은 `finalRouteGeometry` 정책(선택된 SID/STAR/IAP 포함 여부)을 쓴다. en-route만 사용하면 모든 행과 기준 경로도 en-route만 써야 하며, 혼용하지 않는다.

| 항목 | 표시 원칙 |
| --- | --- |
| 거리 | 총 NM과 기준 경로 대비 증감 NM |
| 예상 시간 | ETA 또는 비행시간과 기준 대비 증감 |
| 위험 노출 | 현상별 수평 교차 거리 NM과 기준 대비 증감 |
| 바람 | 기존 계산이 있을 때만 사실 정보로 표시 |
| 고도 영향 | 이 단계에서는 고도 추천을 하지 않고 다음 고도 비교 단계에서 다룬다 |

위험 노출은 현상을 합쳐 하나의 점수로 만들지 않는다. 뇌우를 피한 대신 착빙 노출이 늘어난 경우를 각각 보여 준다.

한쪽 경로에만 있는 현상은 없는 쪽을 `0 NM`으로 표시한다. 자료가 없거나 계산할 수 없는 현상은 `자료 없음`으로 표시하며 0 또는 변화량으로 바꾸지 않는다. 거리와 노출은 가장 가까운 1 NM, 시간은 가장 가까운 1분으로 반올림한다.

## 9. 접근성·반응형 원칙

- 기준 경로·우회안 목록은 선택 상태를 `aria-selected` 또는 동등한 명시 상태와 보이는 체크·테두리로 함께 제공한다.
- 지도 범례는 색 이외에 선 모양과 텍스트를 포함한다.
- 드래그 가능한 경유점과 `+` 핸들은 충분한 hit area, 이름, 키보드 대체 조작을 제공한다. 키보드 사용자는 문자열 편집으로 같은 결과를 만들 수 있어야 한다.
- 위험 변화는 색뿐 아니라 `-146 NM`, `+22 NM` 같은 방향·단위 텍스트로 표현한다.
- 데스크톱과 모바일은 같은 기준 경로, 우회안, 초안, 비교 모델을 공유한다. 모바일은 목록 → 선택 우회안 → 비교를 세로로 배치하고 하단에는 그 순간의 주 행동 하나만 둔다.

## 10. 완료 기준

1. 탭 이름이 데스크톱·모바일 모두 `경로비교`다.
2. 기준 경로는 우회안 생성·편집·삭제로 바뀌지 않는다.
3. 우회안은 기준 경로 또는 기존 우회안에서 복제해 만들 수 있고, 기준 1개 + 우회안 최대 3개(총 4개) 제한을 지킨다.
4. 선택 우회안은 문자열 편집과 지도 드래그만으로 수정할 수 있다. 클릭 추가·그리기·별도 구간 우회 모드는 없다.
5. 드래그 변경은 적용/취소 전까지 초안이며, 취소하면 문자열·지도·비교 수치가 드래그 전 상태로 돌아간다.
6. 각 우회안은 기준 경로 대비 거리, 예상 시간, 현상별 위험 노출의 증감을 같은 단위로 보여 준다.
7. 뇌우·착빙·저시정 등 현상 간 상쇄를 점수 하나로 숨기지 않는다.
8. 지도에서 기준 경로, 선택 우회안, 다른 우회안, 변경 구간, 위험 영역을 범례와 함께 구분한다.
9. 기상 레이어 토글은 지도 표시만 바꾸고 경로·비교 결과를 바꾸지 않는다.
10. 삭제에는 확인 또는 실행 취소가 있고, 되돌리기는 선택 우회안에만 적용된다.
11. 고도 비교와 브리핑은 사용자가 `이 우회안으로 고도 비교`를 눌러 넘긴 적용 경로 하나만 받는다. 목록에서 선택만 바꿔서는 기존 고도 비교·브리핑 결과를 지우거나 바꾸지 않는다.
12. VFR 우회안의 전체 문자열·지도 초안·drag 취소는 다른 VFR 우회안이나 적용 기준 경로와 섞이지 않는다.
13. 기상 응답이 늦게 도착해도 다른 설계안 또는 더 최신 초안을 덮지 않는다.

## 11. 후속 구현 전 확인 사항

- 기존 `RouteAlternativesStep`의 자동 대안·클릭 추가·그리기·segment-detour UI 및 상태를 실제 코드에서 제거하거나 이 스펙의 drag 핸들 모델로 수렴한다.
- IFR drag가 현재 `resolveMapInteraction`과 전체 항로 연결 검증을 재사용하는지 확인한다. 지도 좌표만 route result에 덧붙이는 임시 경로는 허용하지 않는다.
- VFR 전체 문자열 단일 초안·적용 base 분리 계약을 변경하지 않는다.
- `MapView.jsx`에 새 state 또는 `useEffect`를 추가하지 않는다. 지도 이벤트 연결은 기존 route preview 경계에서 처리한다.
- 구현 계획에는 기존 `mapInteractionMode`, click/draw/segment-detour binder·draw source·UI 버튼·테스트·구 스펙 문구를 새 drag 핸들 계약으로 제거하는 순서를 적는다. 새 `+` 핸들만 경로 위에서 pointer event를 잡고 빈 지도 상호작용을 가로채지 않는다.
- 구현 계획에는 source/layer별 writer·표시 대상·style reload·pending draft 격리 표를 포함한다. 기존 source/layer를 재사용할 수 있는지 먼저 검증하고, 필요한 추가 source/layer가 있다면 이유와 소유자를 명시한다.
- 구현 계획에는 desktop, iPad landscape, mobile의 드래그·문자열·취소·되돌리기·비교 검증 흐름을 각각 포함한다.
