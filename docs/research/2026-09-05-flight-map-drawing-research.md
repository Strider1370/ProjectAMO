# 비행 지도(그리기)와 사용자 항공자료 — 조사 기록

**작성일:** 2026-09-05
**성격:** 조사 기록. 스펙이 아니다. 조각 3~6의 스펙을 쓸 때 근거로 쓴다.
**선행 자료:** [구글어스 작성 기능 전수 조사](../superpowers/status/2026-08-16-google-earth-authoring-survey.md) · [KML 표출 스파이크 설계](../superpowers/specs/2026-08-12-kml-viewer-spike-design.md) · [내 지도 설계](../superpowers/specs/2026-08-14-my-map-design.md)

## 0. 이 문서가 존재하는 이유

「비행 지도 그리기」를 설계하다가 범위가 여섯 조각으로 갈라졌다. 첫 조각(조직 계정 + 경로 공유)만 먼저 스펙으로 쓰기로 했고, 나머지 조각에서 쓸 조사 결과와 확정 사항이 대화에만 남으면 나중에 다시 조사하게 된다. 그것을 막으려고 남긴다.

---

## 1. 방향 전환 — 이 기능의 목적

처음에는 "구글어스 대신 우리 앱에서 지도를 그린다"로 시작했으나, 논의 끝에 목적이 다시 정의되었다.

> **사용자와 조직이 만든 항공 자료를, 앱의 기존 기능들이 우리 내장 자료와 똑같이 취급하게 하는 것.**

그리기는 그중 **구역을 만드는 입력 수단 하나**일 뿐이다.

### 뿌리에 있는 문제

앱에 공역·NOTAM 자료가 들어 있지만 **AIRAC 주기마다 갱신할 여력이 없다.** 그런데 앱이 표시하고 있으면 조종사는 그것을 최신으로 믿는다. **틀린 자료를 맞는 것처럼 보여주는 것이 아무것도 안 보여주는 것보다 위험하다.**

그래서 **책임의 위치를 옮긴다.** 우리가 "이게 정답"이라고 하는 대신, 조종사나 소속 기관이 자기 책임으로 관리하는 자료를 우리 판정 엔진에 태운다. 우리는 판정하고, 자료의 정확성은 자료를 넣은 사람이 진다.

이 방향은 [KML 스파이크 설계](../superpowers/specs/2026-08-12-kml-viewer-spike-design.md)에 이미 적혀 있던 것과 같다 — *"우리는 기상기관이다. … 이용자가 준비한 자료를 그대로 보여주는 역할을 맡으면 그 부담이 사라지고, 우리는 기상이라는 본업에 집중할 수 있다."*

### 따라오는 요구

- 우리 내장 공역의 위상을 **"참고용 출발점, 갱신 책임 없음"**으로 낮추고 화면에 명시한다.
- 내장 공역을 **「내 지도로 복사」**할 수 있게 해서, 맨땅이 아니라 우리 자료를 출발점으로 고쳐 쓰게 한다.
- 모든 경고에 **출처와 갱신 시점**을 붙인다. 앱 내장인지, 어느 조직의 몇 판인지.
- 우리 자료와 사용자 자료가 충돌하면 **둘 다 보여주고 출처를 구분한다.** 우리가 임의로 하나를 고르지 않는다.

## 2. 여섯 조각 분해

| 조각 | 무엇 | 끝나면 | 선행 |
| --- | --- | --- | --- |
| 1 | 조직 계정 | 계정에 소속이 생김 | — |
| 2 | 경로 조직 공유 | 기관 노선을 골라 브리핑 | 1 |
| 3 | 비행 지도 (그리기 정식화·계정 저장·버전·조직 공유) | 구역·지점을 만들고 나눠 씀 | 1 |
| 4 | 사용자 구역 → 브리핑 경고 | 내 구역이 경고를 냄 | 3 |
| 5 | 지역 기상 브리핑 | 구역을 고르면 기상이 나옴 | 3 |
| 6 | 조직 단위 알림 감시 | 내 구역에 위험기상 들어오면 알림 | 4·5 |

1·2번은 [조직 계정과 경로 공유 스펙](../superpowers/specs/2026-09-05-organization-accounts-and-route-sharing-design.md)으로 분리됨.

### 자료 종류와 연동 지도

조각 3~6에서 만들 것의 전체 그림. **칸 하나하나가 붙여야 할 배선이다.**

| 자료 | 만드는 법 | 비행 전 브리핑 | 알림 감시 | 경로 만들기 | 지역 기상 | 지도 표시 | NOTAM 패널 |
| --- | --- | --- | --- | --- | --- | --- | --- |
| **구역** (고도 포함 면) | 그리기 / 내장 공역·KML에서 복사 | **저촉 경고** | 내 구역에 SIGMET | 회피 대상 | 구역 요약 | ✔ | 목록에 함께 |
| **경로** | **기존 경로 만들기** (그리기 아님) | 골라서 브리핑 | 그대로 감시 | 불러와 수정 | — | ✔ | — |
| **지점** | 그리기 (점) | 경유 지점 기상 | — | 경유지로 찍기 | 지점 기상 | ✔ | — |
| **참고 그림** | 그리기 | — | — | — | — | ✔ | — |

**경로는 그리지 않는다.** 기존 저장 경로가 이미 출발·목적·교체공항, 경유지, 순항고도, 출발 예정시각, 비행규칙, 도착 예정시각, 알림 감시 설정 일체, 직전 브리핑 스냅샷을 들고 있고, 예보관 문의와 발송 이력이 이를 참조한다. 지도에 선을 그으면 이 전부가 없는 껍데기다.

## 3. 우리 코드의 현재 상태 (실측)

### 이미 있는 것

| 무엇 | 어디 | 비고 |
| --- | --- | --- |
| 그리기 시험판 | `frontend/src/features/draw-spike/` (`/draw`, 개발 빌드만) | 점·선·면, 원·섹터·호·화살표·회랑·글자, 아이콘, 폴더, 되돌리기, 측정, 바닥/천장 고도, 브라우저 자동저장, KML 넣고 빼기. **스펙 없이 만든 것** |
| 내 지도 (KML/KMZ 표출) | `frontend/src/features/my-map/` | 올린 원본을 IndexedDB에, 목록을 localStorage에 |
| 측정 도구 | `frontend/src/features/map-tools/` — 우상단 **「그리기」** 버튼 | 구역·좌표·거리·반경·방위·고도. **폴리곤을 그려도 기상 요약이 안 나온다** |
| 좌표 3형식 입력 | `frontend/src/features/custom-area/coordFormat.js` | |
| 공역 레이어 18종 | `frontend/public/data/*.geojson` | FIR·섹터·CTR·TMA·제한·금지·위험·MOA·ATS항로·RNAV항로·웨이포인트·항행표지·공항 + 해외분 |
| **정적 공역 → 경고 판정** | `backend/src/briefing/airspace-zones.js` | 정적 공역을 **NOTAM 아이템 모양으로 변환해 `matchRouteNotams()`에 태운다** |
| 교차 판정 도구 | `backend/src/briefing/geo-time-match.js` | `routeIntersectsGeometry`, `routeIntervalInGeometry`, `routeCorridorInGeometry`, `timeWindowsOverlap` |

**가장 중요한 발견:** 판정기에 자료를 태우는 길이 **이미 뚫려 있다.** 사용자 구역도 같은 모양으로 바꿔 같은 판정기에 태우면 된다. 조각 4는 판정 로직을 새로 만드는 일이 아니다.

### 없는 것

꼭짓점 편집 · 스냅 · 여러 개 선택 · 스타일 물려받기 · 스타일 복사 · 버퍼 · 검색 · 유효 시간 · 이미지/PDF 내보내기 · 계정 저장 · 공유 · 버전 · **그린 도형과 기상의 연결**.

### 스냅이 싸다

스냅에 필요한 자료(`airports.geojson`, `navaids.geojson`, `waypoints.geojson`, `airways.geojson`)가 **전부 로컬 정적 파일로 이미 앱에 있다.** 서버 호출도 새 자료 확보도 필요 없다.

### 고도 처리 선례

`airspace-zones.js` 주석: *"고도 둘 다 원본에 없는 구역은 … 판정할 근거가 없으니 브리핑 매칭에서 아예 제외한다."* 이유는 "미상=저촉 간주"로 하면 근거 없는 경고만 매번 뜨기 때문. **사용자 구역도 같은 규칙을 따른다 — 고도 없으면 경고를 내지 않는다.**

### 우리 공역 geojson의 고도는 글자다

| 자료 | 개수 | 고도 표기 |
| --- | --- | --- |
| 금지구역 | 19 | `"UNL"` / `"GND"` |
| 제한구역 | 85 | `"6 000 AMSL"` / `"GND"` |
| 위험구역 | 32 | `"3 000 AGL"` / `"GND"` |
| 군작전구역 | 75 | `"9 000 AMSL"` / `"3 000 AGL"` |
| TMA | 55 | `"FL 225"` / `"1 000 AGL"` |

숫자가 아니라 **화면에 찍을 글자**다. 기준도 뒤섞여 있다(AMSL·AGL·FL·UNL·GND). 파싱은 `shared/airspace-altitude.js`가 이미 하고 있다.

## 4. 정부 공역 KMZ 실물 분석 (실측)

`공역정보(AIRAC AIP 5_26 기준).kmz` — 715KB, 안에 `doc.kml` 3.98MB 하나. **구글어스 Pro 7.3.7로 만든 정부 공식 배포본.**

| 도형 종류 | 개수 |
| --- | --- |
| TMA | 108 |
| 기타 | 133 |
| 제한구역 | 58 |
| 위험구역 | 55 |
| 관제권 | 20 |
| ATZ | 15 |
| 관제구 | 14 |
| FIR | 10 |
| 경계구역 | 10 |
| 금지구역 | 4 |
| ADIZ | 1 |
| 항로(재래식+RNAV) | 314 |
| **합계** | **754** (면 440 · 선 316) |

**도형마다 설명란에 표로 붙어 있는 속성:**

| 키 | 예시 값 |
| --- | --- |
| `Name_Txt` / `Ident_Txt` | `CHEONGJU` / `A582` |
| `DistVertUpper_Val` / `_UOM` / `_Code` | `5000` / `Feet`·`Flight Level` / `Height`·`Altitude`·`SFC` |
| `DistVertLower_Val` / `_UOM` / `_Code` | `8000` / `Feet` / `Surface`·`Altitude` |
| `Type_Code` | `Control Zone`, `Restricted Area`, `Danger Area`, `FIR` … |
| `Class_Code` | `B` / `C` / `D` |
| `TrueTrack_Val` / `MagTrack_Val` (+역방향) | `307.4` / `144` |
| `Length_Val` | `21.6` (NM) |
| `Output_Name` | `[D] CLASS CHEONGJU CTLZ` |

**핵심:** 고도가 **값·단위·기준으로 분리되어** 들어 있다. 우리 geojson의 `"6 000 AMSL"` 같은 글자보다 훨씬 쓰기 좋다. 그런데 **KML 고도 태그(`altitudeMode`)는 0개, 기둥 태그(`extrude`)도 0개** — 구글어스에서는 전부 평면으로 보인다. **정부도 구글어스도 못 하는 것을 우리는 할 수 있다.**

**우리 자료와 개수가 어긋난다** (금지 19 vs 4, 제한 85 vs 58, 위험 32 vs 55, TMA 55 vs 108). 분류 기준 차이인지 한쪽이 오래된 것인지 **확인 못 함.** 별도 작업으로 대조 필요.

## 5. 경쟁 도구 조사

### 아무도 못 하는 세 가지 — 우리는 이미 둘을 갖고 있다

| 기능 | 경쟁 도구 | 우리 시험판 |
| --- | --- | --- |
| 바닥·천장 고도 | 확인한 도구 전부 없음. ForeFlight는 KML 고도를 **버림** | **있음** |
| 방위·거리로 호·부채꼴 작도 | 확인한 도구 중 없음 | **있음** (자북/진북 구분 포함) |
| 도형에 유효 시간 | 없음 | 없음 |

> 주의: SkyDemon·Jeppesen·Lido·onX는 공개 문서를 못 찾아 **확인 못 함**. "세상에 없다"가 아니라 **"확인한 범위에서 없었다"**이다.

### 제품별 요약

| 제품 | 도형 | 고도 | 배포 | 출처 |
| --- | --- | --- | --- | --- |
| **ForeFlight** | 점·선·면만 | **KML 고도 무시** | Content Pack (AirDrop·이메일·링크, 200MB) | [User Map Shapes](https://foreflight.com/support/user-map-shapes/) · [User Map Layers](https://support.foreflight.com/hc/en-us/articles/23405736446487-2-User-Map-Layers) |
| **CalTopo** | 표식·선·면 + **거리 링·부채꼴·방위선·버퍼** | 없음 | 팀 협업(유료). KML/GeoJSON/GPX/Shapefile 내보내기 | [Other Objects](https://training.caltopo.com/all_users/objects/other-objects) |
| **Garmin Pilot** | 동심원만 | 없음 | — | [Garmin](https://www.garmin.com/en-US/blog/aviation/garmin-pilot-adds-graphical-airspace-and-obstacle-notams-updated-flight-profile-view/) |
| **FalconView** | 방위·거리로 점 생성 가능, 호 작도 확인 못 함 | 확인 못 함 | — | [NIFC 매뉴얼](https://www.nifc.gov/sites/default/files/blm/aviation/BLMairspace/FalconView.pdf) |
| **ATAK** | 방위·거리 선, 극좌표 입력 | 없음 (수평만) | — | [ATAK 5.3 매뉴얼](https://static1.squarespace.com/static/5404b7d2e4b0feb6e5d9636b/t/6756e0a435922f074199ba09/1733746857539/ATAK+5.3+Software+User+Manual.pdf) |

### 베낄 것

- **CalTopo의 스냅** — 도로·강·기존 도형에 자동으로 붙는다. 우리는 공항·항행표지·픽스·항로에 붙이면 된다.
- **CalTopo의 버퍼** — 선·점 둘레로 일정 거리 띠. "경로 좌우 5NM"이 회랑 도구보다 범용적.
- **ForeFlight의 Content Pack** — 배포 꾸러미 모델.
- **구글어스 웹판의 자동 스타일 물려받기** — [조사 문서](../superpowers/status/2026-08-16-google-earth-authoring-survey.md)가 "반드시 베껴야 한다"고 지목.

### 우리가 이미 이긴 것

- **독립 글자 도구** — CalTopo에 없어서 사용자들이 요청 중([기능 요청](https://help.caltopo.com/hc/en-us/community/posts/9709269936155-Text)).
- **임의 반경 원** — ForeFlight·SkyVector에서 안 되어 포럼에 요청이 있음([Van's Air Force](https://vansairforce.net/threads/drawing-an-arbitrary-radius-circle-around-arbitrary-point-on-foreflight-or-skyvector.234707/)).

### 내보내기 함정

ForeFlight는 사용자 KML의 고도를 버린다. 그래서 내보낼 때 **대상을 물어야 한다.**

| 대상 | 처리 |
| --- | --- |
| 구글어스 | 바닥·천장 있는 면을 **기둥으로** 변환 |
| ForeFlight 등 EFB | 평면으로 내보내되 **이름에 고도를 적어 넣음** (`훈련공역A 2000-8000`) |

## 6. 조종사가 실제로 그리는 것

| 무엇 | 근거 |
| --- | --- |
| 훈련구역 경계 | ForeFlight 공식 문서가 이 용도를 직접 언급. SCAUWG·펜사콜라가 KML로 배포 ([ChartAware](https://scauwg.org/chartaware)) |
| 산악 통과지점 | 콜로라도 항공청이 VFR GPS 웨이포인트 배포 ([AOPA](https://www.aopa.org/advocacy/advocacy-briefs/vfr-waypoints-checkpoints-for-mountain-passes)) |
| 비상착륙 후보지 | 야간 비행에서 필수 ([CFI Notebook](https://www.cfinotebook.net/notebook/aircraft-operations/night-operations)) |
| 사설 활주로 | 백컨트리 조종사가 KML·GeoJSON으로 수집 ([ForeFlight](https://foreflight.com/products/foreflight-mobile/user-content/content-packs/)) |
| 급유지 + 대체 급유지(50마일 내) | [Bravo 6](https://bravo6flightacademy.com/how-to-plan-fuel-stops/) |

### 고도 요구의 실증 사례

시애틀 보잉필드(KBFI). 조종사가 *"구글어스에서 KBFI 주변 반경 25NM 원을 그려 KML로 내보냈다"*고 썼는데, 그 원 안에서도 고도별 규칙이 다르다 — *"학생 조종사 훈련 때문에 이 구역에서는 4,000ft 이상 유지"*. 도형에 고도를 붙일 방법이 없어 **종이 메모로 관리**하고 있었다. ([Pilots of America](https://www.pilotsofamerica.com/community/threads/kbfi-practice-areas-in-foreflight.131399/))

### 유효 시간 — 근거가 갈린다

군 훈련항로(MTR)는 시간에 따라 활성 여부·고도·폭이 달라지고, FAA가 조종사에게 확인을 지시한다([FAA AIP 3-5](https://www.faa.gov/air_traffic/publications/atpubs/aip_html/chap3_section_5.html)). 항공사·기관 비행계획에서는 시간 창이 표준. **그러나 개인 조종사·비행학교 커뮤니티에서 "도형에 시간을 붙여달라"는 요구는 찾지 못했다.**

→ 단, **경고를 낸다면 필수가 된다.** 군 공역이 평일 09–17시만 활성인데 시간이 없으면 일요일 새벽에도 경고가 뜨고, 그러면 조종사가 경고를 끈다. 판정기에 `timeWindowsOverlap`이 이미 있다.

### 규모 — 못 찾았다

구체적 숫자를 언급한 글을 하나도 못 찾았다. 공개 사례에서 역산하면 비행학교 훈련구역 5~20개, 백컨트리 사설활주로 10~50개 수준. **이것은 추정이다.** 기관이 만든 것은 규모가 다르다 — 정부 공역 KMZ 754개, 맥케이 지도 2,135개.

→ **설계 목표: 수백 개까지 쾌적, 수천 개에서 죽지 않음.**

### 확정된 배치 (조각 3에서 그대로 구현)

실제 화면이 이미 점유한 자리 — 왼쪽 아이콘 레일(≈56px) · 「내 지도」 패널(≈420px) · **상단 가운데 경보 배지** · 우상단 배경지도·측정 버튼 · **하단 시간 막대(≈75px)** · 우하단 확대·축소.

| 무엇 | 어디 | 왜 |
| --- | --- | --- |
| **도구띠** | **왼쪽 패널 맨 위, 가로 두 줄** (위: 손으로 그리기 점·선·면·글자 + 자물쇠 / 아래: 숫자로 그리기 원·섹터·호·화살표·회랑) | 상단 가운데는 경보 배지가 점유. 패널 폭 420px에 두 줄이면 충분하고 **지도를 하나도 안 가린다** |
| **도형 목록** | 왼쪽 패널 아래 — **지금 폴더 목록 UI 그대로 재사용** | 「폴더 이름으로 찾기 + 체크박스 + 개수」가 이미 있고 필요한 것과 동일 |
| **속성** | **오른쪽에 떠 있는 고정 카드** | 업계 표준. 도형을 바꿔 골라도 지도·목록이 안 흔들림 |
| **상태 표시** | 도구띠 바로 아래 한 줄 (`⬠ 면 도구 켜짐(고정) · 끄기 Esc`) | 하단은 시간 막대가 점유. 도구 버튼 바로 밑이 눈이 가장 자주 가는 자리 |
| **우클릭 방사형 메뉴** | 지도 아무 곳 | 패널까지 왕복 제거. 15% 빠름 |
| 지도 이동 | **스페이스바 누른 동안만** | OSM의 가장 흔한 사고 차단 |
| 단축키 | 버튼에 병기 (`면 F`) | 안 쓰는 이유가 "못 찾아서" |
| 꼭짓점 잡는 반경 | 화면 12픽셀 | QGIS 권장값 |
| 시간 막대 | **그대로 둔다** | 그린 도형 위로 기상 시각을 옮겨보는 것이 우리 강점 |

### 패널 구조 (확정)

- 이름: **「내 지도」 → 「비행 지도」.** 코드 폴더도 `my-map` → `flight-map`.
- **그리기가 본체, 파일 올리기는 곁다리.**
- 패널 상단에 **가로 탭 3개** — 내 지도 · 공유 · 가져온 파일. **「공유」 탭에 안 본 지도 개수 배지.**
- 탭 아래 **「＋ 새 지도 그리기」 큰 단추.**
- 그리기는 탭이 아니라 **화면 전환** (「← 목록」으로 복귀). 사이드바 하위 아이콘은 만들지 않는다 — 이 앱에 하위 항목을 쓰는 기능이 하나도 없어 규칙이 어긋난다.
- **우상단 기존 「그리기」 버튼을 「측정」으로 이름 변경.** 그것은 구역·좌표·거리·반경·방위·고도를 재는 일회성 도구이고, 저장되는 「비행 지도」와 성격이 다르다.
- `/draw` 시험 주소는 없앤다.

## 8. 기상 앱으로서 반드시 지킬 것

이 앱은 기상을 보여주는 앱이다. 그리기가 기상을 방해하면 목적을 배반한다.

| 규칙 | 왜 |
| --- | --- |
| **기상 우선** — 레이더·위성처럼 화면 전체를 덮는 기상 레이어를 켜면 도형 채움이 자동으로 옅어진다. 경계선은 남는다 | 맥케이 지도 176개 폴더를 켜면 점이 화면을 뒤덮어 그 아래 레이더가 안 보인다 (실측) |
| **채움보다 테두리** — 새 면의 기본값을 「테두리만」으로 | 같은 이유 |
| **겹침 순서** — 경계선은 기상 **위**, 채움은 기상 **아래** | 경계선은 기준선 역할, 채움은 가림막 |
| **색 팔레트에서 기상 색을 뺀다** — 비행카테고리 4색(VFR 초록·MVFR 파랑·IFR 빨강·LIFR 자홍)과 레이더 강도색을 기본 팔레트에서 제외 | 훈련공역을 빨강으로 그리면 **IFR로 오독된다.** 현재 `custom-area/usePolygonDraw.js`의 `COLOR_OPTIONS`는 빨강·연두·노랑·주황을 담고 있고, 주석은 "레이더 에코와 겹쳐도 구별되도록"만 고려했을 뿐 **의미 충돌은 고려하지 않았다** |

**색 분리와 가림 방지는 조각 3에 반드시 넣는다.** 나중에 고치려면 이미 그려진 도형의 색을 전부 손봐야 한다.

### 도형 × 기상 = 우리만 가능한 것

| 무엇 | 설명 |
| --- | --- |
| **도형이 곧 질문** | 면 → 그 안의 기상 요약 / 선 → 선을 따라가는 단면 / 점 → 지점 기상 |
| **시간축 연동** | 시간 막대를 끌면 도형 옆 상태 배지가 바뀐다. **"내 훈련공역이 몇 시부터 나빠지나"** |
| **고도 교차 판정** | "이 SIGMET은 FL180~300, 내 공역은 2,000~8,000ft → **겹치지 않는다**". 평면 폴리곤이면 "겹친다"밖에 못 한다. **헛경보를 줄이는 결정적 차이** |
| **기상을 도형으로 (역방향)** | SIGMET·AIRMET 구역, 태풍 강풍반경, 레이더 에코 윤곽을 「내 지도로 복사」 → 예보관이 고쳐서 조직에 배포 |

## 9. 사용자 구역이 경고를 내려면 (조각 4용)

도형에 네 가지가 더 필요하다.

### ① 역할

색이 빨강이라고 금지구역이 아니다. 도형에 **무엇인지**를 붙인다.

| 역할 | 경로가 지나가면 | 기존 등급 |
| --- | --- | --- |
| 금지구역 | 치명 경고 | `prohibited` |
| 제한구역 | 경고 | `restricted` |
| 위험구역 | 경고 | `danger` |
| 군 훈련·작전구역 | 주의 (진입 금지 아님) | `moa` |
| 주의구역 (내가 정한) | 주의 | 새로 |
| **참고용** | **경고 안 냄** | — |

**기본값은 「참고용」.** 아무 도형이나 경고를 내면 조종사가 경고를 통째로 무시한다.

### ② 고도 — 없으면 판정하지 않는다

`airspace-zones.js`의 선례를 따른다. 경고용 도형은 바닥·천장이 필수이고, 없으면 그 자리에서 "이 도형은 고도가 없어 경고를 못 냅니다"라고 알린다.

### ③ 유효 시간 — 경고용 도형에는 필요하다

판정기에 `timeWindowsOverlap`이 이미 있다. 시간을 안 넣으면 "항상 활성"으로 처리한다(정적 공역의 현재 방식과 동일).

### ④ 출처 표시 — 책임을 옮기려면 필수다

```
⚠ 비행금지구역 저촉
   RK P73A · GND~UNL
   출처: 앱 내장 자료 (AIP 기준일 미상)

⚠ 비행금지구역 저촉
   훈련공역 서편 · 2000~8000 ft
   출처: ○○비행교육원 「표준 공역 3판」 (2026-09-01 갱신)
```

### 위험한 지점

1. **경고 남발** → 기본값 「참고용」, 경고용은 명시적 지정
2. **사용자가 잘못 그림** → 경고에 항상 출처와 만든 사람을 붙이고, 눌러서 원본을 바로 확인
3. **내 자료와 남의 자료 충돌** → 둘 다 보여주고 출처 구분. 우리가 임의로 고르지 않음

## 10. 자료 구조 초안 (조각 3용)

### 도형 하나

시험판이 이미 쓰는 모양(`useDrawMap.js`) 그대로 + 두 칸 추가.

| 칸 | 예시 |
| --- | --- |
| 종류 / 좌표 | `polygon` / `[[126.8,37.5],…]` |
| 이름 / 메모 / 폴더 | `훈련공역 A` |
| 색·굵기·선 투명도·면 투명도 | `#2563eb`, `2`, `1`, `0.3` |
| 아이콘 (점만) | `wht-circle` |
| 바닥 ft · 천장 ft | `2000` · `8000` |
| 숫자 정의값 (원·섹터·호·회랑) | 반경 5nm, 090→150, 자북 |
| 글자 전용 여부 | `true` |
| **스냅 출처** ★ | `RKSS` — 나중에 항공자료 갱신 시 어긋난 도형을 찾는 실마리 |
| **역할** ★ | 조각 4에서 사용 |

### 지도 한 벌

이름 · 만든 사람 · 소속 조직 · 공개 범위 · 도형 전체 · 폴더 목록 · 만든/고친 시각.

**도형을 쪼개지 않고 JSON 한 덩어리로 저장한다.** 지도를 열면 항상 전부 불러오고 저장할 때도 전부 저장하므로, 도형 단위 조회가 필요 없다. 기존 `routes.payload`가 같은 방식을 쓴다.

### 서버 표 (조각 3)

```
그린 지도     id · 만든이 · 이름 · 공개범위 · 내용(JSON) · 도형 개수 · 만든/고친 시각
지도 이전본   id · 어느 지도 · 내용(JSON) · 저장한 사람 · 저장 시각
```

조직은 조각 1에서 만들어진다. 경로와 마찬가지로 **소유자의 현재 소속을 따라간다.**

### 상한선 (서버 강제)

| 무엇 | 상한 |
| --- | --- |
| 지도 한 벌 크기 | 2MB |
| 도형 개수 | 5,000 |
| 좌표점 총합 | 50,000 |
| 이름 / 메모 | 200자 / 2,000자 |
| 계정당 지도 수 | 50 |
| 이전본 보관 | 최근 20벌 |

**숫자 자체는 근거 있는 짐작이다.** 실제로 넘치면 조정한다. 다만 상한이 없으면 서버가 죽는다.

### 보관 위치

| 무엇 | 어디 | 왜 |
| --- | --- | --- |
| 가져온 KML/KMZ 원본 | 브라우저 (IndexedDB) | 16MB급이라 서버에 못 올림. 조직원 50명이 올리면 무너진다 |
| 그리는 중인 지도 | 브라우저 + 서버 | 인터넷이 끊겨도 안 날아가게. **입력 손실이 최우선 불만** |
| 로그인 안 한 사람 | 브라우저만 | 그려볼 수는 있되 저장·공유는 로그인 후 |

**가져온 파일을 고치려면 「편집본 만들기」** — 도형이 「내가 그린 지도」로 복사되고, 그때부터 서버에 올라가고 공유된다(JSON으로 바뀌며 수십 KB로 줄어든다). **원본은 그대로 남는다.**

### 공유 규칙

**받은 사람은 보기만 한다. 고치려면 사본을 뜬다.** 권한 문제를 통째로 없애는 가장 단순한 규칙이며, 경로 공유(조각 2)와 동일하다.

### 버전

저장할 때마다 **지도 전체를 한 벌 통째로** 남긴다. 항목별 비교는 하지 않는다. **되돌리기도 새 저장으로 처리한다** — 2판으로 되돌리면 그게 4판이 되어 이력이 사라지지 않는다.
