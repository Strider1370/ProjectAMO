# 사용자 알림 수신 시험

운영 사이트에 새 코드가 배포되고 백엔드가 재시작된 뒤, 시험할 계정으로 로그인한다. 휴대폰 푸시를 확인하려면 **그 휴대폰에서** 사이트를 열고 알림 권한과 `이 기기 푸시 수신`을 켠다. 시험 푸시는 요청한 기기의 구독으로만 간다.

1. 공항 패널의 종을 눌러 감시 조건을 저장한다. 전역 종의 `알림 설정`에서도 공항을 추가할 수 있다.
2. 설정의 `실제 수신 테스트`에서 METAR·급변풍·어는 비·새 TAF·TAF AMD·공항경보·낙뢰 중 **저장한 조건에서 켠 종류**를 고르고 `테스트 알림 보내기`를 누른다.
3. 경로는 경로 생성 패널의 `현재 경로 알림 설정…` 또는 저장 경로 옆 종에서 SIGMET 감시를 시작한 뒤, 경로 설정의 `SIGMET 테스트 알림 보내기`를 누른다.
4. PC에서는 `테스트 · 모의 자료` 팝업을 눌러 상세로 이동한다. 휴대폰에서는 시스템 푸시를 눌러 같은 상세를 연다. TAF 전문 끝과 SIGMET 유효기간·교차 구간이 보이는지 확인한다.
5. 푸시가 표시되지 않으면 설정의 기기 구독 상태와 브라우저 알림 권한을 확인한다. 화면의 `기기 발송 접수`는 푸시 서비스가 요청을 받았다는 뜻이며, OS에 표시됐는지는 기기에서 직접 확인해야 한다.

시험에는 서버가 만든 모의 기상자료를 **실제 종류별 판정기**에 넣는다. 시험 결과는 실제 진행 중/지난 알림, 안 읽음 수, 감시 상태에 섞이지 않으며 24시간 뒤 만료·정리된다. 시험 성공은 화면·푸시·딥링크 연결을 확인하는 것이고, 실제 기상자료의 수집·정확성을 증명하지는 않는다.

현재 서버는 공항·경로를 한 주기 실행기로 판정하고, 새 이벤트를 공통 기기별 발송 대기열에서 전송한다. 기존 예정 비행 감시의 등록·발송은 종료되었고 이력만 읽기 전용으로 남는다. 기관 알림은 기존 기관 판정·저장소를 유지하며 개인 알림 목록에서도 확인할 수 있다. 독립 상황판의 기존 알림 판정·팝업·소리 설정은 중단되었고, 설정 화면에서 통합 알림으로 이동할 수 있다. 시스템 운영 알람은 이 전환 대상이 아니다.

자동화된 서버·브라우저 시험만으로 운영 환경의 실제 푸시 표시를 보증할 수 없다. 운영 배포 후 PC와 휴대폰 각각에서 위 수신 시험을 실행하고, 브라우저·OS 알림 권한, 잠금화면 표시, 탭 이동을 직접 확인한다.
