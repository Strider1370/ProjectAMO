# 경로 토큰 입력 — 진행 상황

**갱신:** 2026-08-15
**스펙:** [경로 토큰 입력 설계](../specs/2026-08-15-route-token-input-design.md)
**계획:** [구현 계획](../plans/2026-08-15-route-token-input.md)

## 상태

계획의 **Task 1~6 구현 완료.** Task 7(브라우저 확인)은 데스크톱까지 끝났고 **iPad 실기기 확인만 남았다.**

## 확인한 것 (데스크톱, Playwright)

`RKSI`를 출발공항으로 고른 뒤 `BINIL A582 ANDOL CG050 GONXA`를 쳐서 확인했다.

| 확인 항목 | 결과 |
| --- | --- |
| 알약 생성 (스페이스/엔터) | 6개 정상 |
| 종류별 색 구분 | 공항·지점·항공로가 서로 다르게 표시됨 |
| 오타 판정 | `GONXA`만 빨간 알약 + 테두리 |
| 「⚠ 1 error」와 이유 펼치기 | 정상 — 「GONXA — 그런 지점이 없습니다」 |
| 옛 textarea / 「경로 적용」 버튼 | 두 화면 모두에서 사라짐 |
| 선택기 → 토큰 목록 | 출발공항을 고르면 `RKSI` 알약이 목록 맨 앞에 들어감 |
| React 실행 오류 | 없음 |

시험 1,216개 통과, 프로덕션 빌드 정상.

## 브라우저 확인에서만 잡힌 것 세 가지

소스 검사 시험과 빌드를 모두 통과했는데도 실제로는 깨져 있던 것들이다. **이 세 가지가 Task 7을 건너뛰면 안 되는 이유다.**

1. **`Cannot access 'routeTokenField' before initialization`** — 데스크톱 화면이 입력칸을 정의하기 전에 참조해서 그 화면이 통째로 죽었다. 정의를 두 화면보다 위로 옮겨 해결.
2. **알약이 오른쪽 끝으로 밀림** — 타이핑 칸이 알약보다 앞에 있으면서 남은 공간을 다 차지했다. 맨 끝에 있을 때만 늘어나게 해서 해결(`.rtf-input.is-last`).
3. **터미널 구역 FIX가 전부 오류로 잡힘** — `BINIL`·`CG050`처럼 절차 자료 안에만 있는 FIX는 `enroute.json`에 없다. 절차를 불러올 때 그 안의 FIX 이름도 함께 판정 자료에 담아 해결(`procedureFixIds`).

## 덧붙여 고친 것

옛 입력칸의 예시 문구가 `예: OSPAT Y711 GONA …`였는데 **`OSPAT`·`Y711`·`GONA`가 이 앱의 항법자료에 없다.** 예시를 그대로 따라 치면 오류가 뜨고 이용자는 자기가 틀린 줄 안다. 실제로 있는 이름(`RKSI BINIL A582 ANDOL RKPC`)으로 바꿨다.

## 남은 것

**iPad 실기기 확인** — 계획 Task 7 Step 3. 데스크톱에서는 재현되지 않는다.

- 알약 사이를 눌러 입력칸이 옮겨갈 때 **키보드가 닫히지 않는지**. 이 설계에서 가장 위험한 지점이다
- 긴 경로에서 알약 줄이 여러 줄로 접히는 모양
- 밝은 곳에서 네 색이 구분되는지
- 절차를 공항보다 먼저 쳤을 때, 공항을 넣은 뒤 제 색을 찾는지

**아직 안 한 것** — 스펙의 "이번 판에 넣지 않는 것" 4가지(알약 끌어 순서 바꾸기, 알약 안 고도 표시, 연료·바람 요약, 알약을 눌러 글자로 풀기)는 의도적으로 제외했다.

## 알려진 순서 의존

절차 판정은 공항 판정 뒤에만 된다. 절차와 그 안의 FIX는 공항에 딸린 자료라 어느 공항인지 모르면 불러올 수 없다. 공항보다 절차를 먼저 치면 잠깐 오류로 보였다가 공항이 들어온 뒤 제 색을 찾는다. 경로는 공항부터 치는 것이 자연스러운 순서라 실제로 걸릴 일은 드물다.
