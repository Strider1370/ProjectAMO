# UI 모션 (마이크로 인터랙션) — 설계 스펙

**작성일:** 2026-08-15
**근거 조사:** 이 스펙 작성 시점의 전수 조사 — `frontend/src` CSS 34개 파일, 지도·데이터·앱 껍데기·비행 전 브리핑 흐름 직접 열람
**이 스펙의 범위:** 0~2단계. 3단계는 목록만 남기고 판단은 미룬다.
**구현 상태:** 0~2단계 구현 완료 (2026-08-15). 구현 중 조사와 달랐던 네 곳은 아래 "구현하며 고친 것"에 기록.

## 무엇을 하나

화면이 바뀔 때 아무 예고 없이 툭 바뀌는 자리에, 무슨 일이 일어났는지 알려주는 짧은 움직임을 넣는다. 새 기능이 아니라 기존 화면의 마감이다.

## 왜 하나

세 가지가 실제 문제로 확인됐다.

1. **기다림과 실패를 구분할 수 없다.** 브리핑 흐름과 「내 지도」의 대기 표시가 정지된 회색 글자 한 줄이고, 일부는 실패 문구와 **같은 옷을 입고 있다**. 자료가 없는 것인지 아직 안 온 것인지 사용자가 판단할 근거가 없다.
2. **지도가 순간이동한다.** 지도에서의 순간이동은 다른 UI의 순간이동과 급이 다르다 — 어디로 얼마나 왔는지를 사용자가 스스로 다시 맞춰야 한다.
3. **값이 흩어져 있다.** 코드 전역 `transition` 61곳이 각자 제 숫자를 쓴다. 전체 조정이 불가능하다.

## 공통 규칙

1. **시간** — 자주 누르는 작은 것 120ms, 패널·모달·탭 200~300ms. 500ms 이상 금지.
2. **속도곡선** — 나타날 때는 빠르게 출발해 부드럽게 멈추고(`ease-out`), 사라질 때는 천천히 출발해 빠르게 빠진다(`ease-in`).
3. **방향** — 그 물건이 실제로 있는 쪽에서 온다. 왼쪽 패널은 왼쪽에서, 아래 시트는 아래에서.
4. **동작 줄이기 존중** — 기기 설정이 켜져 있으면 이동·확대는 끄고 흐림만 남긴다. 지도 카메라는 `duration: 0`으로 되돌린다.
5. **판단에 쓰는 값은 즉시 교체** — 아래 "하지 않는 것" 참조.
