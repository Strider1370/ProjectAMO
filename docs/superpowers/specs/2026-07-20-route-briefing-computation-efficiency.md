# Spec: 경로 브리핑 계산 낭비 제거

**Status:** Approved
**Created:** 2026-07-20

## Problem / Goal

경로 브리핑은 동일한 입력과 동일한 기상 스냅샷에 대해 고도 대안, 수평 위험구역 노출, KIM NWP 수집을 수행한다. 현재 구현은 결과를 만들기 위해 필요한 계산 외에도 원시 격자 재읽기·재파싱, 전체 격자 크기의 임시 배열 생성, 동일 경로의 중복 위험 판정, 수집 중 전체 격자 보관 및 반복 직렬화를 수행한다.

이 작업의 목표는 항공 운용 판단, 수치 결과, 응답 계약, 최신성 계약을 바꾸지 않고 그러한 낭비만 제거하는 것이다. 특히 수집 cron의 일시적인 메모리·CPU 피크와 동시에 들어온 경로 브리핑 요청의 대기 시간을 낮춘다.

## Requirements

- FR-001: 고도 대안 API는 동일한 `routeGeometry`, `routeModel`, KIM/KTG run, SIGMET/AIRMET/NOTAM 스냅샷, ETD/ETA 및 계획 고도에 대해 현재와 동일한 후보 고도, 바람, 착빙, 난류, 위험구역 및 NOTAM 결과를 반환해야 한다.
- FR-002: 고도 대안 계산은 활성 KIM/KTG의 현재 `tmfc`와 `hf`가 같은 후속 요청에서 이미 로드한 원시 격자를 다시 파일에서 읽고 JSON으로 파싱하지 않아야 한다. 각 데이터군은 현재 `tmfc`/`hf` 한 조합만 유지하고, run·예보시각·`latest/index` revision(content hash 또는 갱신 시각)이 바뀌면 이전 조합을 즉시 폐기해야 한다.
- FR-003: 고도 대안 계산은 요청별 중간 결과에서 경로 표본에 필요한 값만 보관해야 한다. FR-002의 현재 run/hf 원시 격자 캐시와 별개로, 원시 격자 전체 크기의 임시 배열을 변수별로 만들어 경로 표본을 표현해서는 안 된다.
- FR-004: 수평 위험구역 노출은 현재의 경로 표본 간격, 폴리곤 내부 판정, 시간 판정 및 응답 계약을 유지해야 한다. 최종 정밀 판정 전에 경로와 공간적으로 겹칠 수 없는 위험구역을 안전하게 제외할 수 있어야 한다.
- FR-005: 동일한 경로 지오메트리, 경로 모델, ETD/ETA 및 KIM, KTG, SIGMET, 해외 SIGMET, AIRMET, 낙뢰, NOTAM 스냅샷 버전으로 한 사용자 작업 안에서 이미 산출한 수평 노출 결과를 다시 산출해서는 안 된다. 단일 조회와 batch 조회가 같은 경로를 중복 계산하지 않아야 한다.
- FR-006: KIM NWP 수집은 현재와 같은 forecast hour, level, 변수, 정규화 격자, index, latest 및 legacy surface-wind 결과를 발행해야 한다. 수집 중에는 이미 안전하게 저장되어 인덱스에 반영할 수 있는 전체 격자를 메모리에 유지하지 않아야 한다.
- FR-007: KIM NWP 수집은 각 격자의 구성요소를 합친 최종 정규화 격자를 한 번의 원자적 발행으로 저장해야 한다. 현재의 partial-run 발행 의미를 유지한다. 즉 `complete:false` run의 index/latest 발행과 이전 complete run 보존·retention 규칙은 바꾸지 않는다.
- FR-008: KIM NWP 수집과 경로 브리핑 계산은 cache hit/miss, 처리 단계별 소요 시간, 처리한 격자 수, 유지한 전체 격자 수 및 process RSS 피크를 구조화된 결과로 기록해 동일한 입력의 전후 성능을 비교할 수 있어야 한다.
- FR-009: KIM 수집과 KTG 등 다른 대형 수집 작업의 시작·종료 시각을 기록해 cron 겹침 여부를 확인할 수 있어야 한다. 이번 범위는 측정만 포함하며, 전역 작업 큐나 cron 재배치는 포함하지 않는다.

## Non-Goals (out of scope)

- KIM NWP의 예보시각 수, 기압면, 착빙 변수 또는 기상·위험 판정 모델을 축소하지 않는다.
- 수평 위험구역의 근사 표본 판정을 선분-폴리곤 알고리즘으로 변경하거나 정확도를 재정의하지 않는다.
- Redis, 별도 GIS 데이터베이스, 새 캐시 서버, 새 외부 의존성을 도입하지 않는다.
- 워커 스레드, 다중 Node 인스턴스, 작업 큐를 이번 범위에 포함하지 않는다.
- 프런트엔드 화면, API URL, 응답 스키마, 사용자 설정의 의미를 변경하지 않는다.

## Success Criteria

- SC-001: 기존 고도 대안·수평 위험 노출 fixture에 대해 최적화 전후의 계산 결과 필드가 동일하며, 수집 시각·처리 시간·메트릭처럼 계산 결과가 아닌 동적 필드는 비교 대상에서 제외한다. KIM NWP의 index/latest 및 정규화 격자 계약 회귀 테스트가 통과한다.
- SC-002: 같은 KIM/KTG run과 예보시각으로 연속 실행한 고도 대안 요청은 원시 격자 파일 재읽기·재파싱 없이 완료한다.
- SC-003: 고정된 KIM NWP fixture와 동일한 `KIM_NWP_CONCURRENCY`로 `peakRssBytes`, 전체 격자 유지 수, 정규화 격자 전체 쓰기 수를 기록한다. 전체 격자 유지 수는 하나 이하이고, 정규화 격자 전체 쓰기 수는 완료 또는 partial task당 하나이며, 정상 발행된 격자·index·latest 결과는 동일하다.
- SC-004: 구성요소가 정상 수집된 격자는 정규화 파일 전체 재직렬화를 작업당 한 번만 수행한다.
- SC-005: 동일한 경로와 위험기상 스냅샷의 단일 조회 직후 batch 조회는 이미 계산된 경로를 다시 공간 판정하지 않는다.
- SC-006: 수평 위험구역 결과는 경로와 BBox가 겹치지 않는 위험구역에 대해 폴리곤 내부 판정을 실행하지 않는다.

## Expected Impact (not acceptance gates)

- 고도 대안: 동일 run/hf의 웜 요청은 CPU 시간과 응답 시간이 약 30~70% 감소할 것으로 예상한다. 경로 표본 전용 보관은 요청당 임시 메모리와 GC 부담을 약 60~95% 낮출 가능성이 있다.
- 수평 경로: BBox 후보 제거와 단일/batch 결과 재사용은 위험구역 밀도에 따라 공간 판정량을 약 20~90% 줄일 것으로 예상한다. 넓거나 겹치는 폴리곤이 많은 스냅샷에서는 효과가 작을 수 있다.
- KIM NWP 수집: 전체 격자 보관 제거와 최종 1회 직렬화는 cron RSS 피크를 약 25~50%, 격자 파일 재직렬화·재쓰기를 최대 약 80% 줄일 것으로 예상한다.

## Alternatives Considered

| Option | Trade-off | Why not chosen |
|---|---|---|
| Redis 또는 별도 캐시 서버 | 여러 프로세스에서 공유할 수 있지만 운영·장애·신선도 관리가 추가된다 | 현재는 단일 프로세스의 반복 I/O와 임시 배열이 먼저 해결할 문제다 |
| R-tree/GIS 데이터베이스 | 대량 폴리곤에서 강력하지만 저장 구조와 의존성이 커진다 | 먼저 BBox 사전 필터와 현재 메모리 스냅샷을 사용한다 |
| forecast hour 하나만 수집 | 수집량을 약 91% 줄일 수 있다 | 미래 NWP 타임라인과 브리핑 사용성을 축소한다 |
| 착빙 변수 수집 중단 | API 요청과 가공량을 줄인다 | 착빙 기능과 고도 대안의 입력 계약을 바꾼다 |
| 워커 스레드·작업 큐 | 메인 이벤트 루프의 응답성을 지킬 수 있다 | 낭비 자체를 줄이지 않으며, 최소 개선 후에도 동시 부하가 문제일 때 검토한다 |

## Open Questions

- 활성 KIM/KTG 격자 캐시의 안전한 메모리 상한은 실제 production Node RSS와 격자 크기를 측정한 뒤 확정한다.
- KIM과 KTG cron의 실제 겹침 시간은 수집 단계별 소요 시간 측정 후 일정 분리 또는 전역 처리량 제한 중 하나를 선택한다.
