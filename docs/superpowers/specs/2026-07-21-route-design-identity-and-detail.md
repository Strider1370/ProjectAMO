# Spec: 경로 설계안 색상 구분·표시 토글·위험기상 상세

**Status:** Approved
**Created:** 2026-07-21

## Problem / Goal

경로비교 탭에서 기본 경로와 대안(최대 A/B/C)이 지도 위에 그려질 때 색이 "선택됨(주황)/미선택(회색)" 두 가지뿐이라 어떤 선이 어떤 경로인지 구분할 수 없다. 하나를 선택하면 나머지가 흐린 회색이 되긴 하지만, 선택을 풀거나 여러 경로를 동시에 훑어볼 때는 전부 같은 색이라 식별이 안 된다. 또한 지도에 특정 경로선을 잠깐 숨기는 기능이 없고, 기본 경로는 애초에 패널에서 선택할 수 없었다(별도로 수정 완료, 커밋 `858cb36`). 위험기상 정보는 카드 안에 현상명과 거리만 나오고 고도대·시간 겹침 여부는 안 보인다.

이 작업의 목표는 조종사가 여러 경로 후보를 지도와 패널 양쪽에서 색으로 식별하고, 필요 없는 경로선을 지도에서 잠깐 지웠다가 다시 켤 수 있게 하며, 위험기상을 더 깊이 들여다볼 수 있게 하는 것이다. 이번에도 판단(위험/추천 등)은 추가하지 않는다 — 기존 원칙(FR-010, `2026-07-21-hazard-comparison-display` 스펙)을 유지한다.

**범위 한정 — 색 구분은 en-route(순항) 구간에만 적용한다.** 코드 확인 결과 "우회안 만들기"는 기본 경로의 SID/STAR/IAP(출발·도착·접근 절차)를 그대로 복사하고, 이후 어떤 편집 경로("항로 문자열 직접 편집" 포함)도 절차를 바꾸지 않는다 — 대안 간 실제로 달라지는 부분은 en-route 구간뿐이다. 지금 지도에 그려지는 선(`ROUTE_DESIGN_LINE`)은 `augmentRouteWithProcedures()`로 SID/STAR 곡선까지 이어붙인 전체 선이라, 이 선 전체에 경로별 색을 칠하면 4개 경로가 똑같은 SID/STAR 구간에서 서로 다른 색으로 겹쳐 그려져 실제로는 같은 경로인데 여러 개처럼 보이는 착시가 생긴다. 그래서 색 구분 대상은 절차 병합 전의 원본 선(`role: 'route-preview-line'`, SID/STAR 곡선 절차를 아직 안 붙인 상태)으로 한정한다. SID/STAR/접근절차는 지금처럼 공통 처리(색 구분 없음)로 유지한다.

## Requirements

- FR-001: 기본 경로와 대안 A/B/C는 서로 다른 고유색을 가져야 한다. 기본 경로=`#f97316`(기존과 동일, 회귀 없음), 경로 A=`#2563eb`, 경로 B=`#7c3aed`, 경로 C=`#0d9488`.
- FR-002: 지도 위 경로선의 **en-route 구간**은 선택된 경로일 때 자신의 고유색·굵은 선·불투명, 선택되지 않은 다른 경로는 짙은 회색(`#475569`, 기존 `tokens.css`의 `--level-gray`와 동일 값)으로 표시해야 한다. SID/STAR/접근절차 구간은 색 구분 대상이 아니며 현재 표시 방식을 그대로 유지한다.
- FR-003: 패널의 각 경로 카드(기본 경로 포함) 이름(`<strong>{name}</strong>`) 옆에 같은 고유색 점을 표시해야 한다. 지도와 패널의 색이 항상 일치해야 한다.
- FR-004: 각 경로 카드에 표시/숨김 토글(눈 아이콘)을 추가해야 한다. 숨긴 경로는 지도 소스 데이터에서 제외되어 그려지지 않는다. 선택된 경로도 숨길 수 있다 — "선택됨(비교 대상)"과 "지도에 보임"은 서로 다른 상태다.
- FR-005: 표시/숨김 상태는 경로비교 탭에 머무는 동안 유지되어야 하며, 경로 설계안이 삭제되면 그 설계안의 표시 상태도 함께 정리되어야 한다.
- FR-006: 각 경로 카드(기본 경로 포함)에 "상세보기" 토글 버튼을 추가한다. 펼치면 그 경로의 위험기상 각 건에 대해 출처, 현상명, 고도대, 시간 상태(겹침/불명), 교차거리(NM)를 한 줄씩 보여줘야 한다. 이 데이터는 이미 `routeExposure.hazards[]`(`source`, `label`, `bandFt`, `timeStatus`, `horizontalExposure`)에 있으므로 백엔드 변경 없이 프런트에서만 조립한다.
- FR-007: 표시/숨김·상세보기 상태는 어떤 판단도 담지 않는다("위험" 대신 "겹침 시간 확인 필요"처럼 사실만 표시).

## Non-Goals (out of scope)

- 경로 설계안 최대 개수(4개: 기본+A+B+C)를 늘리지 않는다.
- 위험기상 강도(SIGMET/AIRMET)에 등급을 새로 부여하지 않는다 — 이전 스펙(FR-002, `2026-07-21-hazard-comparison-display`)과 동일한 제약.
- 지도 레이어 아키텍처(소스/레이어 이름, role 태그 체계)를 새로 설계하지 않는다 — 기존 `ROUTE_DESIGN_LINE`/`routePreviewSync.js`의 `designId`/`selected` 프로퍼티 체계를 그대로 확장한다.
- SID/STAR/접근절차 자체의 표시 방식(`PROC_PREVIEW_SOURCE`)을 바꾸지 않는다 — 색 구분 대상에서 빠질 뿐, 지금처럼 그대로 그려진다.
- 대안 설계안별로 독립적인 SID/STAR를 선택하는 기능은 이번 범위가 아니다(현재도 없음, 대화에서 확인).
- 고도 비교 탭(`AltitudeWeatherComparison.jsx`)은 이번 범위에 포함하지 않는다.
- 색 팔레트를 사용자가 커스터마이징하는 기능은 넣지 않는다(고정 4색).

## Success Criteria

- SC-001: 대안 경로 A/B/C를 만들고 지도에서 각각 다른 색(주황/파랑/보라/청록)으로 그려지는지 확인한다.
- SC-002: 경로 A를 선택하면 경로 A는 자신의 색으로 굵게, 기본 경로·경로 B·경로 C는 짙은 회색으로 바뀌는지 확인한다.
- SC-003: 경로 B의 눈 아이콘을 끄면 지도에서 경로 B 선이 사라지고, 다시 켜면 돌아오는지 확인한다. 선택된 경로를 숨겨도 패널의 "선택됨" 표시(2px 테두리)는 유지되는지 확인한다.
- SC-004: 기본 경로의 "상세보기"를 누르면 위험기상 각 건이 출처·현상명·고도대·시간상태·거리로 펼쳐지는지 확인한다.
- SC-005: 경로 설계안을 삭제하면 그 설계안의 표시/숨김 상태도 같이 사라져 다음에 같은 이름(경로 A 등)이 재사용돼도 이전 숨김 상태가 새 설계안에 잘못 적용되지 않는지 확인한다.
- SC-006: 기존 `route-workflow` Playwright 계약과 `npm test` 전체가 회귀 없이 통과한다.

## Alternatives Considered

| Option | Trade-off | Why not chosen |
|---|---|---|
| 선택 시 항상 주황 유지, 비선택은 각자 고유색 유지(현재 방식의 역) | 구현이 더 단순함 | 사용자가 명시적으로 "다른 경로는 짙은 회색"을 요청함 — 선택 강조가 우선 |
| 표시/숨김을 전역 상태(useRouteBriefing)가 아닌 지도 컴포넌트 로컬 상태로 관리 | 상위 컴포넌트를 안 건드려도 됨 | 패널의 눈 아이콘과 지도 렌더링이 같은 상태를 봐야 하므로 반드시 공유 상태 필요 |
