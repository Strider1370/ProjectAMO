# 기상 기반 대체 항로 비교 스펙

- 작성일: 2026-07-14 / 최종 갱신: 2026-07-15
- 상태: 설계 확정 (프로토타입 범위), 미구현
- 적용 범위: 국내 IFR 사전 비행계획

> **규칙은 한 군데에만 둔다.** 같은 규칙을 요약 절에 다시 적지 않는다 — 반드시 갈라진다.

## 0. 확정된 결정

| 항목 | 결정 | 근거 |
|---|---|---|
| 후보 제외 기준 | **대류 + VA + TC** (§4.1) | 한국 여름 SIGMET의 대부분이 뇌우 계열. 대류를 빼면 정작 필요한 계절에 기능이 죽는다 |
| 완전 회피 후보 전멸 시 | **"완전 회피 후보 없음" 명시 + 후보별 기상 노출을 사실로 나열** (§4.3) | 대류를 넣으면 여름철 전멸이 흔하다. "아무것도 안 보여줌"은 §1의 약속을 어긴다 |
| 탐색/표시 개수 | **탐색 5개 → 표시 최대 3개** (§4.2) | 3개만 탐색하면 기상이 3개를 다 죽였을 때 보여줄 게 0. 5개 탐색 비용은 3개와 거의 같다 |
| 구현 위치 | **전부 프론트엔드. 백엔드 변경 0줄** (§7) | 항공로 그래프·SIGMET·낙뢰를 브라우저가 **이미** 받고 있다. 서버로 보내면 왕복만 늘고 서버 부하가 생긴다 |

## 1. 목적

조종사가 계획한 항로와 **같은 출발·도착 절차를 유지한** 대체 en-route 항로를 기상 정보로 비교할 수 있게 한다.

이 기능은 항로를 추천하거나 안전 여부, 연료·성능·관제 수용성, 법적 대체공항 필요 여부를 **판단하지 않는다.**
각 경로에서 **어떤 기상 현상이 사라지고 어떤 것이 새로 나타나는지**만 보여 주며, 최종 판단은 조종사가 한다.

> ⚠️ **"판정하지 않는다"와 "정보를 주지 않는다"는 다르다.** 절제가 지나쳐 화면이 비면 이 기능은 실패다.
> §4.3과 §6의 후보 카드가 위 약속(사라진 것/새로 생긴 것)을 실제로 지키는지가 수용 기준이다.

## 2. 비교 경로의 구성

```text
사용자가 선택한 SID → en-route 항공로 후보 → 사용자가 선택한 STAR → 선택한 IAP(있을 때)
```

- 국내 8개 공항의 SID/STAR 절차 데이터와 각 절차의 구간 거리·좌표를 사용한다
  (`frontend/src/features/route-briefing/lib/procedureData.js` — `KNOWN_AIRPORTS` 8개).
- **자동으로 바꾸는 범위는 SID와 STAR 사이의 en-route 항공로뿐이다.** SID·STAR·IAP는 사용자가 선택한 것을 그대로 붙인다.
- 따라서 이 기능은 **절차 변경을 제안하지 않는다.**
- 절차 데이터가 없거나 사용자가 절차를 선택하지 않으면, 기존 경로 표시만 제공하고 대체 후보 생성은 하지 않는다.
- 모든 후보는 항공로/FIX 그래프(`route-graph.json`)에서 방향·항로 종류 규칙을 지키는 경로여야 한다.
  **지도 위 임의 선은 후보가 될 수 없다.**

### 2.1 계획 경로 설정과 en-route 직접 수정

기존 자동 경로 선택 흐름을 유지한다. 출발·도착 공항을 입력하면 앱이 SID, en-route 기본 항로, STAR, IAP를 자동 선택한다.
사용자는 `ENR 수정` 영역에서 **en-route 부분만** 직접 바꾼다.

```text
SID  BINIL3C
ENR  BINIL → Y711 → OLMEN
     [+ FIX 추가]  [+ 항공로 추가]
STAR OLMEN1Y
IAP  RWY 33L
```

- `FIX 추가`: 알려진 FIX/NAVAID만 자동완성으로 검색해 현재 위치에 삽입.
- `항공로 추가`: 현재 FIX에서 **연결 가능한 항공로만** 제시. 이어서 이탈 FIX를 선택.
- **유효한 입력 단위는 `진입 FIX → 항공로 → 이탈 FIX`.** 자유 형식 문자열은 해석하지 않는다.
- 항공로 이름은 간결히 표시하되, 내부적으로 중간 FIX를 모두 펼쳐 연결·방향·거리를 검증한다.
- SID/STAR/IAP를 바꾸면 en-route의 시작·끝 연결을 다시 검증한다. 연결 안 되면 사용자에게 수정 필요를 알린다.
- 확정된 en-route가 이후 기상 비교의 **기준 경로**가 된다.
- 저장 경로에는 수동 en-route 목록과 선택한 SID/STAR/IAP를 함께 저장·복원한다. **재불러오기 때 자동 선택으로 덮어쓰지 않는다.**

MVP 제외: 지도 위 임의 지점 작도, 자유 형식 항로 문자열 붙여넣기.

## 3. 입력과 계획 통과시각

사용자가 이미 입력하는 **ETD, TAS, 순항고도**를 사용한다.

```text
구간 통과시각 = ETD + (출발지부터 해당 지점까지의 누적 거리 / 입력 TAS)
```

- TAS는 **성능·연료 계산에 쓰지 않는다.** 오직 계획 통과시각 계산용.
- SID/STAR/IAP의 구간 거리도 누적에 포함한다.
- ETD를 바꾸면 모든 후보의 구간 통과시각과 SIGMET 유효시간 비교를 다시 계산한다.

> ⚠️ **알려진 한계 — 바람 미반영 (TAS = GS 가정).**
> 실제 통과시각은 대지속도(바람 반영)로 정해진다. 이 스펙은 TAS만 쓴다.
> **국내선 단거리(인천–제주 약 45분)라 SIGMET 유효기간(통상 4~6시간) 대비 오차가 작아 수용한다.**
> 프로젝트에 이미 바람 데이터가 있으므로, 장거리 확장 시 GS로 재검토한다.
> (명시하지 않으면 "왜 바람을 안 썼지?"로 반드시 다시 파게 된다.)
> climb/descent, 관제 지연, 실제 속도 변화도 반영하지 않는다. 화면에 **`입력 TAS 기반 계획 시각`**으로 표기한다.

## 4. 대체 후보 생성

### 4.1 제외 기준 — 대류 + VA + TC

다음 SIGMET이 경로의 **위치 · 계획 통과시각 · 순항고도**와 모두 겹치면 그 후보를 **제외**한다.

| 분류 | 코드 |
|---|---|
| **대류 (뇌우 계열)** | `TS` · `CB` · `OBSC_TS` · `EMBD_TS` · `FRQ_TS` · `SQL_TS` |
| 화산재 | `VA` |
| 열대저기압 | `TC` |

> **대류를 제외 기준에 넣는 이유.** 한국 여름 SIGMET의 대부분이 뇌우 계열이다.
> 대류를 빼면 **정작 뇌우철에 대체항로를 안 만들어 주는 기능**이 된다. 빼지 말 것.

**난류·착빙·바람·구름·운고·시정, 그 밖의 AIRMET/SIGMET은 제외 기준이 아니다** — 비교 정보로만 표시한다(§6).
서로 다른 현상에 임의 가중치를 주어 앱이 위험도를 판단하지 않기 위해서다. **단일 "기상 위험 점수"를 만들지 않는다.**

### 4.2 탐색 — 5개 찾고, 3개 보여준다

1. 항공로/FIX 그래프에서 현재 경로와 **다른** 합법 en-route 경로를 탐색한다.
2. 각 경로에 선택된 SID/STAR/IAP를 붙이고 구간별 계획 통과시각을 계산한다.
3. §4.1 제외 기준에 걸리는 경로를 뺀다.
4. 남은 것을 **총거리 오름차순으로 최대 3개** 표시한다.

**탐색 상한 (프로토타입 값 — 없으면 조합이 폭발해 브라우저가 멈춘다):**

| 항목 | 값 | 이유 |
|---|---|---|
| 탐색 후보 수 | **5개** | 3개만 탐색하면 기상이 3개를 다 죽였을 때 보여줄 게 0이 된다. 5개 탐색 비용은 3개와 거의 같다 |
| 우회 상한 | **원 경로 거리의 1.3배** | 그 이상은 현실적으로 관제 승인이 안 난다 |
| 탐색 시간 예산 | **200ms** | 초과 시 그때까지 찾은 것으로 마감 |
| 표시 | **최대 3개** | |

**중복 제거:** 중간 FIX/항로 순서가 같은 미세 변형은 **하나의 후보로 본다.** 실제로 다른 중간 FIX 또는 항로 구간이 있는 것만 남긴다.

**표시 순서는 거리순일 뿐 추천·안전 순위가 아니다.**

### 4.3 완전 회피 후보가 없을 때 ⭐

**대류를 제외 기준에 넣으면 여름철 전멸이 흔하다.** 이때의 행동을 명시한다.

- **`완전 회피 후보 없음`을 명시한다.**
- 그리고 **현재 경로를 포함한 모든 탐색 후보(최대 5개)의 기상 노출을 사실로 나란히 나열한다:**
  교차 구간 길이(NM) · 계획 통과시각 범위 · 고도 범위 · SIGMET 유효기간 · 현상 코드.
- **정렬은 거리순 그대로.** 순위·추천·`덜 위험함`·`최선` 표현은 **쓰지 않는다.**
- 앱이 "덜 위험한 경로"를 **판정하지 않는다.** 사실을 병렬로 늘어놓을 뿐이다.

> 이것이 §1의 약속("무엇이 사라지고 무엇이 새로 생기는가")을 지키는 방식이다.
> 후보가 전멸했다고 빈 화면을 주면 기능이 죽는다. **판정하지 않는 것과 정보를 주지 않는 것은 다르다.**

### 4.4 고정 절차 구간 (SID/STAR/IAP)

사용자가 선택한 고정 구간이며 자동 후보 생성으로 **바꾸지 않는다.**

- 고정 구간에 대류/VA/TC 교차가 있으면, en-route 후보가 그걸 **해결한 것처럼 표시하지 않는다.**
- 후보 카드에 `선택한 출발/도착 절차 구간에 교차가 남아 있음`을 **별도로** 표시한다.
- 절차 변경은 사용자가 경로 설정 화면에서 직접 바꾼 뒤 다시 실행하는 흐름으로 둔다.

### 4.5 SIGMET 교차 판정 — 위치 · 시간 · 고도

- **선분-폴리곤 교차로 판정한다.** 점 샘플만 쓰면 좁은 위험구역을 뚫고 지나가도 못 잡는다.
- 모든 경로 선분과 Polygon/MultiPolygon의 교차를 구해 **진입·이탈 지점과 누적 거리**를 얻는다.
- 그 거리에서 계획 통과시각을 구하고, **그 구간의 통과시각만** SIGMET 유효기간과 비교한다.
  (전체 ETD~ETA 시간창 겹침이 아니다.)
- SIGMET 고도 범위가 있으면 입력 순항고도와 비교한다. **상한/하한만 있는 값도 그대로 보존·비교한다.**
- 고도 정보가 없으면 고도 필터를 적용하지 않고 **`고도 정보 없음`**으로 표시한다.
  **이를 근거로 "위험이 없다"고 표시하지 않는다.**

## 5. 낙뢰 — 출발 임박 실황

낙뢰는 예보가 아니라 **현재 관측**이다. **후보 생성·제외 조건이 아니다.**

- 지도에 최근 60분 낙뢰 지점 표시.
- 각 후보에 `경로 20 NM 이내 최근 60분 낙뢰 수`, `가장 최근 낙뢰 시각`, `자료 갱신시각` 표시.
- ETD가 현재부터 60분 이내이고 자료가 최신이면 **`출발 임박 관측`**으로 강조.
- ETD가 더 먼 미래면 낙뢰는 여전히 실황으로 표시하되, **그 시각의 예보가 아님을 명시**한다.
- **20 NM은 읽기 쉬우라고 쓰는 참고 거리이며 자동 회피 기준이 아니다.**
- 낙뢰 위치를 이동시키거나 미래 낙뢰를 추정하지 않는다.

**20 NM 버퍼를 일반 TS/CB SIGMET에 일괄 적용하지 않는다.** SIGMET 폴리곤 교차만 쓴다.
현 데이터에 '강한 에코'·'심한 뇌우'를 판정할 신뢰할 속성이 없으므로 **레이더 에코 강도 기반 자동 제외는 MVP 밖**이다.
FAA의 20 NM 회피 지침은 참고 문맥으로만 제공하고 앱 규칙으로 쓰지 않는다.

## 6. 화면

### 지도

- 현재 계획 경로와 비교 후보를 표시하되, **강조는 선택한 후보 하나만.**
- SIGMET 폴리곤과 최근 60분 낙뢰를 겹쳐 표시.
- 기존 route-briefing 경로 미리보기 source/layer를 **재사용한다.**
- ⚠️ **이 기능을 위해 `MapView`에 새 상태나 `useEffect`를 추가하지 않는다.**
  (`docs/adr/0001-mapview-layer-gravity.md` — 새 레이어/오버레이 로직은 소유 feature 모듈의 `useXOverlay` 훅으로 간다.)

### 후보 카드

| 순서 | 항목 |
|---|---|
| 1 | 사용한 ETD · TAS · 순항고도 (`입력 TAS 기반 계획 시각` 표기) |
| 2 | 원래 경로 대비 **거리 차이** |
| 3 | ⭐ **원래 경로 대비 사라진 현상 / 새로 생긴 현상** |
| 4 | 선택한 SID/STAR/IAP **고정 구간에 남아 있는** 대류/VA/TC 교차 |
| 5 | 비교 전용 현상(난류·착빙 등)의 교차 구간 · 계획 통과시각 · 고도 범위 · 유효기간 |
| 6 | 최근 60분 · 경로 20 NM 이내 낙뢰 수 · 최신 관측시각 |
| 7 | SIGMET 발표시각·유효기간 · 낙뢰 자료 갱신시각 |

> ⚠️ **③을 "대류/VA/TC 교차 여부"로 바꾸지 말 것.** 살아남은 후보는 **정의상 교차가 0**이므로
> (§4.2에서 교차하면 탈락) 항상 `교차하지 않음`만 찍히는 공허한 항목이 된다.
> 의미 있는 것은 **무엇이 사라지고 무엇이 새로 생겼나**이며, 이것이 §1이 약속한 것이다.

표현은 `교차` · `교차하지 않음` · `유효기간 겹침` · `고도 정보 없음`처럼 **검증 가능한 사실로 한정**한다.
`추천` · `최선` · `안전` · `대체공항 필요` 같은 결론 표현은 **쓰지 않는다.**

- 항공로 그래프(`route-graph.json`) · SIGMET · 낙뢰를 **브라우저가 이미 받고 있다.**
  (`routePlanner.js`가 `/data/navdata/*`를 클라이언트에서 로드, SIGMET·낙뢰는 이미 프론트 상태에 있음)
- 백엔드로 보내면 **후보 경로를 직렬화해 왕복시키는 비용만 늘고, 서버 CPU 부하가 새로 생긴다.**
- "계산 로직을 화면 코드와 섞지 말 것"은 **프론트 안에서 `lib/` 순수 모듈로 분리**하면 동일하게 지켜진다.

**모듈 배치:**
- 후보 생성 · 수동 경로 검증 → 기존 `frontend/src/features/route-briefing/lib/routePlanner.js` **확장**
- 교차 판정 → **`backend/src/briefing/geo-time-match.js`를 `shared/`로 옮긴다.**
  순수 함수뿐이고, 프론트는 이미 `shared/`에서 import한다(`shared/airports.js` 선례). 양쪽이 같은 코드를 쓴다.

## 8. 기존 코드에서 바꿔야 할 것 (2026-07-15 코드 확인 완료)

### 8.1 교차 판정 — **새로 만들지 않는다. 교체한다.**

[`geo-time-match.js:24 routeIntersectsGeometry`](../../../backend/src/briefing/geo-time-match.js)는 현재
**경로의 점이 폴리곤 안인지만** 본다(`pointInPolygon`). 선분-폴리곤 교차가 아니다 → 좁은 구역을 놓친다.

다만 같은 파일 **`:44 routeIntervalInGeometry`가 이미 구간 진입·이탈을 구한다.** 점 샘플이라 정확도가 낮을 뿐 **뼈대는 있다.**

→ **`routeIntervalInGeometry`의 점 샘플을 선분-폴리곤 교차로 교체한다.** 처음부터 만들지 않는다.

### 8.2 en-route 경로 생성 — 경유 FIX 지원 추가

현재 `buildBriefingRoute({ departureAirport, entryFix, exitFix, arrivalAirport, routeType })`는
`진입 FIX → 이탈 FIX`의 **단일 최단경로만** 만든다.

- 경로 상태에 **사용자가 확정한 순서 있는 en-route FIX 목록**을 저장한다.
- 생성기는 `진입 FIX → 경유 FIX 1 → … → 경유 FIX n → 이탈 FIX`의 각 구간을 그래프에서 연결하고,
  **항공로 종류와 방향 규칙을 구간마다 검증**한다.
- **대체 후보 생성은 기존 단일 최단경로 탐색을 대체하지 않는다.** 별도 기능으로 얹는다.

### 8.3 ⚠️ 국내 SIGMET 파서의 고도 병합 — **착수 전 반드시 확인**

[`iwxxm-advisory-parser.js:245`](../../../backend/src/parsers/iwxxm-advisory-parser.js)는
여러 analysis 조각을 합칠 때 **고도 범위를 첫 번째 것만 취한다** (`altitudes[0]`).

한 SIGMET이 구역마다 다른 고도를 가지면 **나머지가 버려진다.** §4.5의 고도 비교 정확도에 직결된다.

→ **실제 발생 여부를 표본으로 확인하고, 발생하면 파서를 먼저 고친다.**

> **국내 SIGMET 확인 완료 (2026-07-15):** `altitude{lower_fl, upper_fl}` · `valid_from/to` · `geometry` 모두 보존된다
> (`iwxxm-advisory-parser.js:211, 363, 369`). **남은 위험은 위의 고도 병합 하나뿐이다.**
> 이 기능은 국내 IFR 전용이므로 **해외 SIGMET 파서는 확인 대상이 아니다.**

- 자유 형식 항로 문자열 해석 · 지도 위 임의 작도
- 바람(GS) 반영 (§3 한계)

## 10. 수용 기준

1. 사용자가 선택한 SID/STAR/IAP와 en-route 후보가 **하나의 전체 경로**로 지도·기상 비교에 쓰인다.
2. 대류/VA/TC SIGMET과 위치·**구간별** 계획 통과시각·고도가 겹치는 기존 경로에 대해,
   그래프 기반 후보를 **5개 탐색해 최대 3개** 표시한다.
3. ETD 변경 시 후보별 SIGMET 유효시간 비교가 **구간 통과시각 기준으로** 바뀐다.
4. **완전 회피 후보가 없을 때 빈 화면이 나오지 않는다** — `완전 회피 후보 없음` + 후보별 기상 노출이 사실로 나열된다. (§4.3)
5. 후보 카드에 **원래 경로 대비 사라진 현상 / 새로 생긴 현상**이 표시된다. (§6-③, §1의 약속)
6. 후보 카드와 지도에 최근 60분 낙뢰가 표시되며, ETD 60분 이내일 때만 출발 임박 관측으로 강조된다.
7. 낙뢰와 20 NM이 후보 자동 생성·제외 조건으로 **쓰이지 않는다.**
8. 어떤 화면도 항로 추천 · 안전 판정 · 법적 대체공항 필요 여부를 **말하지 않는다.**
9. 앱이 `덜 위험한` 후보를 **자동으로 판정·제시하지 않는다.** (사실 병렬 나열은 판정이 아니다 — §4.3)
10. 사용자는 en-route에 FIX·항공로를 직접 추가할 수 있고, 앱은 모든 입력이 그래프에서 **유효하게 연결되는지 검증**한다.
11. **백엔드 코드가 변경되지 않는다.** (§7)

## 11. 검증

**단위 테스트 (순수 모듈):**
- 선분-폴리곤 교차: 좁은 위험구역 **관통**(점 샘플이 놓치는 것), MultiPolygon, 경계 접선
- 유효기간 경계값, 고도 정보 없음, 상한/하한만 있는 고도
- 항로 방향 위반, 연결 불가 수동 구간
- 경로 20 NM 이내 낙뢰 집계
- **탐색 상한**: 5개 초과 탐색 안 함, 우회 1.3배 초과 후보 제외, 200ms 예산 초과 시 마감
- **§4.3 전멸 경로**: 모든 후보가 제외됐을 때 빈 배열이 아니라 노출 비교 데이터가 나온다

**착수 전 확인:**
- 절차의 끝 FIX와 en-route 시작 FIX가 **실제로 연결되는지**
- SID/STAR/IAP 구간 거리 누적값과 지도 선형의 **순서가 같은지**
- **§8.3 국내 SIGMET 고도 병합** — 표본으로 실제 발생 여부 확인
