# 조직 계정과 경로 공유 — 설계 스펙

**작성일:** 2026-09-05
**이 스펙의 범위:** [비행 지도·사용자 항공자료 조사](../../research/2026-09-05-flight-map-drawing-research.md)에서 나눈 **여섯 조각 중 1·2번만**.

## 무엇을 만드나

계정에 **소속 조직**을 붙이고, 저장한 비행경로를 **같은 조직 사람끼리 나눠 쓰게** 한다. 관리자가 별을 단 경로는 목록 맨 위에 뜬다.

## 왜 만드나

운항기관에서 비행계획을 관리하는 담당자가 상용 노선을 만들어 두면, 그 기관 소속 조종사가 **목록에서 골라 바로 비행 전 브리핑을 볼 수 있어야** 한다. 지금은 각자 자기 경로를 처음부터 다시 만들어야 하고, 같은 노선을 스무 명이 스무 번 입력한다.

조직이라는 개념은 뒤따라올 조각(비행 지도 공유, 사용자 구역 경고, 조직 알림 감시)이 전부 딛고 설 바닥이기도 하다. 여기서 만들어두면 그 조각들은 "우리 조직에 공개" 한 줄만 얹으면 된다.

## 판 나누기에서의 위치

| 조각 | 무엇 | 상태 |
| --- | --- | --- |
| **1** | 조직 계정 | **이 스펙** |
| **2** | 경로 조직 공유 | **이 스펙** |
| 3 | 비행 지도 (그리기 정식화·계정 저장·버전·조직 공유) | 다음 |
| 4 | 사용자 구역 → 브리핑 경고 | 3 뒤 |
| 5 | 지역 기상 브리핑 | 3 뒤 |
| 6 | 조직 단위 알림 감시 | 4·5 뒤 |

1·2번을 묶은 이유: 조직만 만들면 화면에 아무 변화가 없다. 경로 공유까지 붙어야 "기관 노선을 골라 브리핑"이 실제로 돈다.

## 요구사항

### 조직

1. 관리자 콘솔에서 조직을 **만들고, 이름을 바꾸고, 지운다.**
2. 조직을 지우면 그 조직에 속한 계정은 **「소속 없음」**이 된다. 계정은 지우지 않는다.
3. 회원가입 화면에서 **소속 조직을 고른다.** 목록에서 고르거나 「소속 없음」을 고른다. 필수가 아니다.
4. 가입은 지금과 같이 **관리자 승인제**를 유지한다. 승인 대기 목록에 **본인이 고른 소속이 함께 표시**되고, 관리자는 승인하면서 소속을 **고쳐줄 수 있다.**
   - 기관별 승인자는 만들지 않는다. 승인자는 지금처럼 전역 관리자 하나다.
5. 관리자 콘솔의 계정 목록에서 **이미 있는 계정의 소속을 바꿀 수 있다.**
6. 사용자는 자기 소속을 스스로 바꿀 수 없다. 관리자만 바꾼다.

### 경로 공유

7. 저장한 경로마다 **공개 범위**를 정한다 — **「나만」** 또는 **「우리 조직」**. 기본값은 **「나만」**.
8. **조직원 누구나** 자기 경로를 「우리 조직」으로 공개할 수 있다. 권한 구분을 두지 않는다.
9. **소속이 없는 계정은 「우리 조직」으로 공개할 수 없다.** 서버가 거절한다.
10. 공개 범위는 **소유자의 현재 소속을 따라간다.** 소유자의 소속이 바뀌면 그가 공개한 경로는 **이전 조직의 목록에서 즉시 사라지고**, 새 조직의 목록에 나타난다. 소속이 없어지면 아무 조직에도 안 보인다.
11. **관리자가 조직 공유 경로에 별을 단다.** 별 달린 경로는 목록 **맨 위**에 뜬다. 별은 조직 단위로 관리된다.
12. 경로 목록 화면은 세 묶음으로 나뉜다 — **별표 → 내 경로 → 우리 조직**. 각 묶음 안에서는 최근 순.
13. 남의 경로(우리 조직 공유)에서 할 수 있는 것:
    - **비행 전 브리핑 보기** — 출발 시각을 입력하면 그 경로로 브리핑이 나온다. 브리핑을 만들 때 서버는 **소유자가 아니어도 조직 공유 경로이면 허용**한다. 이때 입력한 출발 시각은 **원본 경로에 저장하지 않는다** — 그 자리에서만 쓰고 버린다.
    - **「내 경로로 복사」** — 내 경로 목록에 사본이 생긴다. 그때부터 자유롭게 고치고 알림 감시를 켠다. 사본에는 **알림 감시가 꺼진 채로** 만들어진다.
14. 남의 경로를 **직접 고치거나 지울 수 없다.** 알림 감시도 남의 경로에는 걸 수 없다 — 복사한 뒤에 건다.
15. 경로 목록에 **누가 만든 경로인지** 표시한다.

### 안 깨져야 하는 것

16. 기존 화면(`/`, `/monitoring`, `/admin`)이 깨지지 않는다.
17. 소속 없는 기존 계정들이 지금과 똑같이 동작한다. 소속은 있으면 좋은 것이지 없으면 막히는 것이 아니다.
18. 알림 감시, 예보관 문의, 발송 이력은 지금 동작을 유지한다. 이들은 전부 경로를 참조하므로, 경로에 칸을 더하는 것이 이들을 건드려서는 안 된다.

## 설계

### 자료 구조

기존 SQLite 스키마(`backend/src/db/schema.sql`)에 표 하나를 더하고, 두 표에 칸을 더한다.

```sql
CREATE TABLE IF NOT EXISTS organizations (
  id         INTEGER PRIMARY KEY,
  name       TEXT NOT NULL UNIQUE,
  created_at TEXT NOT NULL
);

-- users 에 추가
--   org_id INTEGER REFERENCES organizations(id)      -- NULL = 소속 없음

-- routes 에 추가
--   visibility TEXT NOT NULL DEFAULT 'private'
--              CHECK (visibility IN ('private','org'))
--   pinned     INTEGER NOT NULL DEFAULT 0            -- 관리자 별표
```

`routes`에 `org_id`를 **두지 않는다.** 요구사항 10의 "소유자의 현재 소속을 따라간다"를 만족시키려면 조회할 때 소유자의 `org_id`를 조인해서 판정해야 한다. 경로에 소속을 박아두면 사람이 조직을 옮긴 뒤에도 이전 조직에 남아 정보가 새어 나간다.

조회 조건:

```
내 경로       routes.user_id = 나
우리 조직     routes.visibility = 'org'
              AND 소유자.org_id = 나.org_id
              AND 나.org_id IS NOT NULL
              AND routes.user_id <> 나
```

`pinned`는 경로에 붙지만 의미는 조직 단위다. 별을 단 경로가 조직 공유가 아니게 되면(공개 범위를 「나만」으로 되돌리면) 별은 자동으로 의미를 잃는다 — 조직 목록에서 사라지므로 따로 지울 필요가 없다.

| POST | `/api/admin/organizations` | 관리자 | 조직 만들기 |
| PATCH | `/api/admin/organizations/:id` | 관리자 | 이름 바꾸기 |
| DELETE | `/api/admin/organizations/:id` | 관리자 | 지우기 (소속 계정은 소속 없음으로) |
| PATCH | `/api/admin/users/:id/org` | 관리자 | 계정 소속 바꾸기 |

### 화면

**가입 화면** — 아이디·비밀번호 아래에 「소속 기관」 고르기. 목록에서 고르거나 「소속 없음」. 목록이 비어 있으면(조직이 하나도 없으면) 이 칸 자체를 감춘다.

**관리자 콘솔** — 조직 항목을 더한다. 조직 목록(이름 + 인원 수) · 만들기 · 이름 바꾸기 · 지우기. 승인 대기 목록과 계정 목록에 **소속 칸**이 보이고 거기서 바꾼다.

**경로 목록** — 세 묶음으로.

```
⭐ RKSI → RKPC   김철수      ← 별표 (관리자가 단 것)
⭐ RKPC → RKSI   김철수
────────────────
내 경로
   RKSS → RKPU              8/28   [나만 ▾]
우리 조직
   RKTU → RKJB   이영희      9/2    [내 경로로 복사]
```

- 내 경로에는 공개 범위 스위치가 붙는다. 소속이 없으면 스위치가 꺼진 채 잠기고 이유를 적어둔다.
- 남의 경로에는 「내 경로로 복사」와 「브리핑 보기」만 있다. 고치기·지우기·감시 켜기는 없다.
- 관리자로 로그인하면 조직 공유 경로마다 별 단추가 보인다.

### 오류·경계

| 상황 | 어떻게 |
| --- | --- |
| 소속 없는 계정이 「우리 조직」 공개를 시도 | 서버가 400으로 거절. 화면에서는 스위치가 애초에 잠겨 있음 |
| 가입할 때 없는 조직 id를 보냄 | 400. 소속 없음으로 처리하지 않고 거절 — 조용히 다르게 저장하면 안 된다 |
| 조직을 지웠는데 그 조직 경로가 공개 중 | 소속이 없어지므로 조직 목록에서 사라짐. 경로 자체는 소유자에게 남음 |
| 남의 경로에 고치기·지우기·감시 요청 | 403 |
| 별표를 관리자가 아닌 사람이 요청 | 403 |
| 조직 이름 중복 | 400 (표에서 UNIQUE) |
| 조직 이름 길이 | 1~64자, 앞뒤 공백 제거 후 검사 |
| 남의 경로로 브리핑 요청 | 조직 공유이면 허용, 아니면 403 |

`GET /api/organizations`는 로그인 없이 열리므로 조직 이름이 외부에 드러난다. 가입 화면에서 소속을 고르려면 불가피하다. **이름만 내보내고 인원 수·소속자 정보는 내보내지 않으며**, 가입 API와 같은 속도 제한을 건다.

### 하지 않는 것

- 기관별 승인자 — 승인자는 전역 관리자 하나로 유지한다.
- 한 사람이 여러 조직에 속하기 — 소속은 하나다.
- 조직 안의 역할 구분(기관 관리자 등) — 조직원은 전부 동등하다. 별표만 전역 관리자가 단다.
- 「기관 표준 노선」이라는 별도 개념 — 별표가 그 역할을 대신한다.
- 원본이 바뀌면 사본에 알려주기 — 사본은 복사한 시점에서 끊긴다.
- 조직 단위 지도 공유 — 조각 3.
- 조직 단위 알림 감시 — 조각 6.

## 검증

브라우저 계약(`frontend/verification/contracts/`)에 다음을 확인한다. [브라우저 검증 정책](../../policies/verification/browser-verification.md)과 [계약 등록부](../../policies/verification/contracts.md)를 따른다.

1. 관리자가 조직을 만들고 계정에 소속을 준 뒤, 그 계정으로 로그인해 경로를 「우리 조직」으로 공개하면 **같은 조직 다른 계정의 목록에 뜬다.**
2. **다른 조직 계정의 목록에는 안 뜬다.**
3. 소속 없는 계정은 공개 스위치가 **잠겨 있다.**
4. 관리자가 별을 달면 그 경로가 **목록 맨 위**로 간다.
5. 남의 경로에서 **「내 경로로 복사」**를 누르면 내 목록에 사본이 생기고, 사본은 고칠 수 있다.
6. 남의 경로에는 고치기·지우기·감시 켜기 단추가 **없다.**
7. 소유자의 소속을 관리자가 바꾸면, 그가 공개한 경로가 **이전 조직 목록에서 사라진다.**

서버 쪽은 `backend/test/`에 조회 조건과 거절 규칙(요구사항 9·10·14, 오류표 전부)에 대한 단위 테스트를 둔다.
