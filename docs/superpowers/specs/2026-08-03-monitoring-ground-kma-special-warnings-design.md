# 모니터링 지상 모드 기상청 폭염·한파 특보 설계

**상태:** 승인됨 · 실행 계획 대기  
**작성일:** 2026-08-03

## 목표

`/monitoring?mode=ground`의 기존 공항경보 배너에 기상청 특보 중 **폭염과 한파만** 함께 표시한다. 공항경보가 온도 관련 특보를 제공하지 않는 공백을 보완한다.

## 화면 동작

- 지상 모드에서만 적용한다. 운항 모드의 공항경보 표시는 바꾸지 않는다.
- 현재 공항의 공항경보와 활성 기상청 폭염·한파 특보를 하나의 기존 순환 목록에 합친다.
- 여러 항목은 기존 배너의 페이지 묶음과 전환 주기를 그대로 사용한다. 새 회전기나 우선순위 규칙은 만들지 않는다.
- 지상 모드 배너 제목은 `기상경보·특보`로 쓴다.
- 기상청 항목은 `기상청 특보 · 폭염주의보`, `기상청 특보 · 한파경보`처럼 출처·현상·단계를 텍스트로 함께 표시하고 발효 시각을 보인다.
- 공항경보와 기상청 특보가 모두 없으면 기존 지상 `일기개황` 표시를 유지한다.
- 공항에 검증된 특보구역 매핑이 없거나 기상청 특보 자료가 일시적으로 없으면, 기상청 항목만 제외하고 기존 공항경보/일기개황 동작을 유지한다.

## 데이터 경계

```text
KMA API Hub 특보현황 조회
→ 입력 파서(KST 원문 시각 해석)
→ 정규화된 기상청 특보 스냅샷
→ /api/kma-special-warning
→ monitoring 데이터 수명주기
→ WarningList의 지상 모드 통합 목록
```

- 수집 대상은 API Hub `wrn_now_data_new.php`의 현재 특보현황이다.
- API의 `WRN`이 코드(`H`/`C`) 또는 한국어 값(`폭염`/`한파`)으로 내려오는 경우를 함께 정규화하고, 이 두 현상만 보존한다. 다른 기상특보는 이 기능에서 제외한다.
- 특보 수준과 명령 상태를 정규화해 **현재 발효 중인 주의보·경보·중대경보만** 화면에 보낸다.
- API 원문 KST 시각은 파서에서 UTC/epoch로 변환해 저장하고, 화면은 현재 선택된 표시 시간대 규칙으로 형식화한다.
- 공항 ICAO와 특보구역의 관계는 검증한 정적 매핑으로 둔다. 받은 `특보구역코드.csv`는 매핑 검증의 원본이며 런타임에 읽지 않는다.
- 수집 실패는 마지막 정상 스냅샷을 덮어쓰지 않는다. 기존 스토어·스케줄러의 타입별 잠금과 캐시 갱신 규칙을 따른다.

## 제외 범위

- 폭염·한파 이외의 기상청 특보
- 공항경보의 변경·삭제 또는 운항 모드 배너 변경
- 특보 알림 팝업·소리·설정 추가
- 영향예보 안전수칙 슬라이드 구현
- 런타임 지오코딩 또는 특보구역 코드 API의 매 요청 호출

## 수용 기준

1. 지상 모드에서 선택 공항에 폭염 또는 한파 특보가 발효 중이면 공항경보와 같은 배너 순환에 나타난다.
2. 공항경보와 기상청 특보가 동시에 여러 개면 기존 회전 규칙으로 모두 순환한다.
3. 운항 모드에는 기상청 특보 항목이 나타나지 않는다.
4. 기상청 특보만 없으면 기존 공항경보 또는 일기개황 동작이 바뀌지 않는다.
5. 기상청 API 실패 때 마지막 정상 특보 스냅샷은 유지되고, 실패 응답이 정상 스냅샷을 비우지 않는다.
6. 폭염·한파 항목은 출처, 현상, 단계, 발효 시각을 색만 쓰지 않고 읽을 수 있다.

## 검증

- 파서: H/C 필터, 주의보·경보 상태, KST→UTC 변환, 실패 시 마지막 정상값 보존, 공항-특보구역 매핑을 단위 테스트한다.
- UI: 지상 모드 통합 목록의 순환, 운항 모드 제외, 빈 상태 폴백을 단위 테스트한다.
- 브라우저: `/monitoring?mode=ground`에서 공항경보와 폭염/한파 특보가 같은 배너 순환에 표시되는 것을 Playwright로 확인한다.
