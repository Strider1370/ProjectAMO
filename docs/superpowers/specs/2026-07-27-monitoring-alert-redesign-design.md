# 모니터링 알람 표시 개편 (벽걸이 상황실 기준)

- 작성일: 2026-07-27
- 대상 화면: `/monitoring` (운항 모드)
- 상태: 설계 확정, 구현 전

## 1. 배경

`/monitoring`은 상황실 벽에 걸어 멀리서 보는 화면이다. 지금의 알람 표시는 앉아서 쓰는 화면을 전제로 만들어져 있어 다음이 어긋난다.

| 현상 | 원인 |
|---|---|
| 하단 자막 바가 사실상 안 읽힘 | 속도 계산이 글자당 5초여서 한 바퀴 약 170초. 그런데 바는 30초 뒤 자동으로 숨는다. 글자가 화면에 다 들어오기 전에 사라진다 |
| 글자가 작음 | 자막 17px. 4m 거리 55인치 기준 권장은 약 50px (Extron 비디오월 가이드: 시청 거리 3m당 글자 높이 1인치) |
| 같은 정보가 두 번 나옴 | 팝업 패널 최상단 카드와 자막 바가 같은 문구를 동시에 표시 |
| 공항경보 알람이 중복 | 공항경보 패널(`warning-banner--danger`)이 이미 주황색으로 꽉 차고 아이콘이 깜빡이며 경보명·유효시간까지 보여준다 |
| 조작이 필요함 | 자동으로 사라진 알람을 다시 보려면 클릭해야 한다. 벽걸이 화면 앞에는 사람이 없다 |

### 근거로 삼은 표준·관행

- **ANSI/ISA-18.2, EEMUA 191** — 알람 홍수 기준(10분에 10건), 개요 화면 동시 표시 10건 이내, 정상은 무채색·이상만 색
- **ASM Consortium HMI 지침** — 알람 배너는 화면 최상단 또는 최하단, 모든 화면에서 보이게
- **알람 목록의 시각 골격** — Zabbix Problems, PagerDuty Alerts, ABB 800xA 알람배너, 항공기 EICAS/ECAM. 공통적으로 고정 컬럼 · 왼쪽 정렬 · 심각도순. 가운데 정렬 사례는 없음
- **WCAG 2.3.1** — 깜빡임 초당 3회 이하
- **프로젝트 디자인 헌법** (`docs/policies/design/design-language.md`) — 한 색에 두 의미 금지, 색은 아껴 쓰기, 시맨틱 레벨색 사용

가운데 정렬은 Material 3 스낵바처럼 "짧은 한 건이 잠깐 뜨는" 경우의 관습이며, 여러 건이 지속되는 알람 목록에는 쓰이지 않는다. 따라서 채택하지 않는다.

## 2. 목표

1. 내용물을 최대한 덜 가리면서 알람을 표시한다
2. "방금 터졌다"와 "지금 걸려 있다"를 구분한다
3. 아무도 조작하지 않아도 알람이 정리된다
4. 멀리서 읽힌다

## 3. 범위

### 삭제

| 대상 | 사유 |
|---|---|
| `warning_issued` 트리거 | 공항경보 패널과 중복 |
| `warning_cleared` 트리거 | 위와 동일. 더불어 해제 판정 구조상 항상 "해제됨"으로 표시되는 결함이 있었다 |
| `AlertMarquee.jsx` 및 관련 CSS | 하단 알람 목록이 같은 자리에서 대체 |
| 자막 설정 키 4개 (`marquee.enabled`, `min_severity`, `speed`, `show_duration_seconds`) | 자막 삭제에 수반 |

### 남는 알람 6종

`low_visibility` · `high_wind` · `weather_phenomenon` · `low_ceiling` (METAR)
`taf_adverse_weather` (TAF) · `lightning_detected` (낙뢰)

판정 조건과 임계값은 **변경하지 않는다.** 이번 개편은 표시 방식만 다룬다.

소리(`AlertSound`)도 **변경하지 않는다.** 새 알람 발생 시 1회 재생하는 현재 동작을 그대로 유지한다.

### 범위 밖

- 알람 이력 보기 (해소된 알람 되짚기)
- 알람 확인(acknowledge)
- 모바일(<=719px) — 모니터링 모바일은 별도 task UI이며 벽걸이와 무관. **모바일 레이아웃에서는 하단 알람 표를 렌더링하지 않는다.** 요소 반짝임과 소리는 그대로 둔다

## 4. 구조

세 조각으로 나뉘고 역할이 겹치지 않는다.

```
새 기상 데이터
      ↓
  알람 판정 ── 발동 결과에 "강조 대상"을 함께 실어 반환
      ↓
  MonitoringPage 가 갈라 전달
      ↓
  ┌──────────┬───────────┬────────────┬─────────┐
  ↓          ↓           ↓            ↓         ↓
하단 알람 표  METAR 카드  TAF 타임라인  지도    소리
(전체 목록)  (강조 칸)   (강조 시간칸) (강조 원)
```

| 조각 | 답하는 질문 | 지속 |
|---|---|---|
| 요소 반짝임 | **어디가** 문제인가 / 방금 터졌나 | 처음 60초만 |
| 하단 알람 표 | **무엇이 언제**부터 걸려 있나 | 조건이 살아있는 동안 |
| 소리 | 지금 봐야 한다 | 발생 시 1회 |

`MonitoringPage`가 네 컴포넌트를 모두 직접 렌더링하므로 prop 한 단계로 전달한다. 전역 상태나 컨텍스트를 새로 만들지 않는다.

## 5. 강조 대상 전달 방식

각 트리거의 `evaluate()` 결과에 대상 정보를 포함한다. 판정 로직이 이미 "무엇이 문제인지" 알고 있으므로, 대응표를 별도로 두지 않고 트리거 정의 옆에 둔다. 낙뢰처럼 상황에 따라 대상이 바뀌는 경우도 자연히 처리된다.

```
저시정      → { panel: 'metar', field: 'visibility' }
저운고      → { panel: 'metar', field: 'ceiling' }
강풍        → { panel: 'metar', field: 'wind' }
특이기상    → { panel: 'metar', field: 'weather' }
TAF 악기상  → { panel: 'taf', fields: ['visibility'|'weather'], times: [...] }
낙뢰        → { panel: 'map', zone: 'alert'|'danger'|'caution' }
```

낙뢰 구역은 지도의 `RANGE_RING` 레이어 반지름과 일치한다 — 경보 8km(빨강) · 위험 16km(주황) · 주의 32km(노랑). 링은 feature마다 `radiusKm` 속성을 가지므로 paint 표현식으로 특정 링만 굵게·깜빡이게 할 수 있다.

## 6. 요소 반짝임

### 시각 표현

칸 **바깥에 외곽선(outline)** 을 그려 깜빡인다. 테두리(border)나 배경을 쓰지 않는다.

- METAR 시정 칸 등은 이미 비행조건(VFR/IFR/LIFR)을 배경색과 왼쪽 띠로 표현한다. 외곽선을 쓰면 두 색이 각자의 의미를 유지한다 (디자인 헌법 §3 "한 색에 두 의미" 금지)
- `outline`은 레이아웃을 차지하지 않으므로 칸이 밀리지 않는다
- 색은 알람 심각도의 시맨틱 레벨색 (red `#c0291f` / amber `#92400e` / gray `#475569`)
- 지도 원은 외곽선 대신 `line-width` 증가 + 깜빡임

### 깜빡임 규격

- 주기 **0.8초** — 기존 `LIGHTNING_BLINK_INTERVAL_MS`와 동일 값을 재사용. 초당 1.25회로 WCAG 2.3.1(초당 3회 이하) 충족
- `prefers-reduced-motion: reduce`이면 깜빡이지 않고 **고정 외곽선**만 표시

### 지속

- **발동 시 60초.** 이후 조용히 사라지고 요소는 평소 모습으로 복귀
- **조건이 계속 나쁜 동안에는 재개하지 않는다.** 지속되는 나쁨은 칸 자체의 색이 이미 표현하고 있다. 조건이 이어지는 한 재알림 간격(기본 5분)이 재발동을 막으므로 자연히 한 번만 반짝인다
- **조건이 한 번 해소되었다가 다시 나빠지면 새 알람이므로 다시 반짝인다.** 이는 재개가 아니라 새 발동이다
- 이 60초는 하단 목록의 "새 알람" 강조와 **동일한 창**이며, 설정값 하나가 둘을 함께 조종한다

### 대상을 표시할 수 없을 때

지도를 다른 지역으로 이동, 낙뢰 레이어 꺼짐, TAF가 타임라인이 아닌 카드/표 모드인 경우 등에는 **강조를 생략한다. 오류로 취급하지 않는다.** 하단 목록과 소리가 정보의 본줄기이며 반짝임은 보조 신호다.

## 7. 하단 알람 표

### 위치

화면 최하단 전폭. 실측 결과 현재 이 영역(화면 높이의 약 22%)은 비어 있어 **콘텐츠를 가리지 않는다.** 아래에 고정되어 위로 자란다.

### 골격

```
┃ 색띠 │ 등급 │ 내용                          시각 × ┃
```

Zabbix Problems · PagerDuty Alerts · ABB 800xA의 공통 골격이다. 컬럼이 세로로 정렬되어 시선이 아래로 훑인다.

### 규칙

| 항목 | 값 |
|---|---|
| 정렬 | 심각도순 → 같으면 최신순 |
| 최대 표시 | **6건** (ISA-101 권고 10건 이내). 초과 시 오래된 것부터 제거 |
| 알람 없을 때 | 아무것도 표시하지 않음 |
| 자동 제거 | 조건이 해소되면(재평가에서 유효하지 않으면) 스스로 빠짐 |
| 수동 제거 | `×` 버튼 유지. 필수가 아닌 보조 수단 |
| 자동 숨김 | **없음.** 조건이 살아있는 한 계속 표시 |

### 두 가지 줄 상태

| | 새 알람 | 가라앉은 알람 |
|---|---|---|
| 배경 | 심각도 색으로 채움 | 종이색 + 왼쪽 색 띠 |
| 제목 | 약 46px | 약 32px |
| 상세 문구 | 표시 | 숨김 |
| 지속 | 60초 | 조건 해소까지 |

px는 55인치 1920px 화면 기준 환산값이다. 실제 구현은 컨테이너 비율 단위를 쓰며, 4m 거리에서 읽히는 크기를 목표로 한다.

**색으로 채우는 줄은 새 알람 중 가장 최근 1건으로 제한한다.** 60초 동안 여러 알람이 발동해도 채운 줄은 하나뿐이며, 나머지 새 알람은 보통 줄로 들어오되 요소 반짝임은 각자 유지한다. 색을 아껴 써야 무엇이 급한지가 남는다.

정렬이 심각도 우선이므로, 가장 최근 알람이 낮은 심각도이면 **채운 줄이 목록 맨 위가 아닐 수 있다.** 의도된 동작이다. 위쪽에 더 심각한 알람이 있다는 사실 자체가 색 띠로 이미 드러나며, 채운 줄은 "무엇이 방금 터졌는가"만 표시한다.

기존 공항경보 배너가 이미 같은 문법을 쓴다 — 정상은 연한 배경 + 테두리(`--ok`), 위험은 색으로 채움(`--danger`).

### 레이아웃 안정성

목록이 하단에 고정되어 있으므로, 새 알람 줄이 60초 뒤 작아져도 **아래 줄들은 움직이지 않는다.** 목록의 위쪽 끝만 내려온다.

## 8. 지상 모드

지상 모드에서는 **알람 판정 자체를 정지한다.** 목록·반짝임·소리 모두 없다. 공항경보 패널만 평소대로 동작한다.

## 9. 평가 기준 리셋 (공통)

알람 평가가 중단되었다가 재개될 때, "그동안 무엇이 바뀌었나"가 아니라 **"지금 무엇이 나쁜가"** 로 판정한다. 이전 데이터를 비운 채 한 번 평가하여 현재 조건이 나쁜 항목만 올린다.

하나의 처리로 세 상황을 해결한다.

| 상황 | 현재 동작 | 변경 후 |
|---|---|---|
| 지상 → 운항 복귀 | (신규) | 지금 나쁜 것만 발동 |
| 방해금지 시간 종료 | 중단 중 이전 데이터가 갱신되지 않아, 해제 시 그동안의 변화가 한꺼번에 발동 | 지금 나쁜 것만 발동 |
| 공항 전환 | 알람 이력이 공항 구분 없이 전역이라, 다른 공항을 보는 동안 이전 공항 이력이 삭제되어 재알림 간격이 무시됨 | 공항별로 이력 분리 |

재개 시 발동한 알람은 **새 알람으로 취급**하여 반짝인다. 돌아온 사람에게는 실제로 새 정보다. 모드를 반복 전환해도 기존 재알림 간격(기본 5분)이 중복 발동을 막는다.

## 12. 검증

### 브라우저 계약 (`frontend/verification/contracts/monitoring.spec.mjs`)

- 알람이 심각도순으로 정렬되는가
- 색으로 채운 줄이 항상 1건인가
- 강조 시간이 지나면 가라앉되 목록에서 사라지지 않는가
- 조건이 해소되면 자동으로 제거되는가
- 저시정 알람 발동 시 METAR 시정 칸에 강조가 붙는가
- 지상 모드에서 알람이 표시되지 않는가

### 단위 테스트

각 트리거가 올바른 강조 대상을 반환하는가. 낙뢰는 최근접 거리에 따라 `alert`/`danger`/`caution` 중 맞는 구역을 반환하는가.

### 기존 테스트 수정

`monitoring` 계약에서 자막 바 체크박스를 확인하는 부분을 제거한다.
