# 공항 상세 예보 분석 — 설계 스펙

**작성일:** 2026-09-06  
**갱신:** 2026-09-06 — 모델별 운량·운고 방식과 실자료 검증에 더해, 화면 명칭을 `상세 예보 분석`으로 정했다. 패널 요약은 현재 이후 첫 정시를 사용하고, EC는 실제 실행을 유지한 채 비교할 예보시간 구간을 뒤로 옮겨 미래 시각을 확보한다. 기온과 RH는 `기온·RH` 영역에서 함께 비교한다. 1차 구현은 비교표·그래프·패널 요약이며, 순위·자동 변화 판단·임계값 강조는 후속 과제로 옮겼다.
**상태:** 1차 범위 합의·구현계획 작성 — 2026-09-06 사용자가 표·그래프·패널 요약을 먼저 구현하고 순위·자동 판단은 후속으로 분리하는 방향에 동의했다. 현재 요청은 구현계획 작성까지다.

자료 제공 여부는 실호출과 제공자 문서·코드로 확인한다. 운고 추정 방식은 아래 설계에 따르며, 입력 자료가 반환된다는 확인과 추정 운고의 정확도 검증은 구분한다. 아직 관측과 대조하지 않은 추정식을 검증된 항공 운고로 표현하지 않는다.

## 무엇을 만드는가

국내 공항 하나를 기준으로 실황(METAR), 항공예보(TAF), KIM, ECMWF IFS, GFS, ICON Global의 시간별 예보를 한 표와 그래프에서 비교한다. 화면 정보 구조는 `artifacts/airport-model-comparison-mockup.html`의 중앙 비교 영역을 따른다.

오른쪽 일기도 영역은 이번 범위에서 데이터 연동하지 않는다. 선택 공항·모델 실행시각과 무관한 임시 이미지와 `준비 중` 표지만 두며, 일기도 수집·생성·해석은 별도 작업으로 남긴다.

## 왜 만드는가

공항 운항 판단에서 중요한 바람 변화, 강수 시작, 저층 구름, 습도 변화를 한 모델의 단일 예보가 아니라 관측·TAF·여러 NWP 실행값과 나란히 읽는다. 이후에는 저장한 예보와 실제 METAR를 대조하여, 공항·요소별로 최근 잘 맞았던 모델을 보조 정보로 제시할 수 있다.

## 확정 범위

### 시간과 실행자료

- 비교 단위는 **모델별 `run_at`** 이다. 한 화면에 여러 모델이 서로 다른 실행시각을 쓴다.
- **KIM·GFS·ICON은 실제 실행 기준 F000~F012**, 1시간 간격을 유지한다. **ECMWF는 다른 모델의 실행시각에 맞춰 13개 예보시각의 시작점을 이동**한다. 예를 들어 다른 모델의 최신 실행이 06Z이고 EC가 00Z이면 EC는 F006~F018을 사용한다. 자세한 기준은 아래 「표시 구간」을 따른다.
- KIM의 F012 제한은 서버 용량과 한반도 영역 격자 수집의 API 호출량을 고려한 범위다. 이번 EC 구간 이동 때문에 KIM·GFS·ICON의 수집 범위를 늘리지는 않는다.
- 모든 모델에서 **`valid_at = run_at + forecast_hour`**를 유지한다. EC의 실제 `run_at`을 바꾸거나 실제 F006을 F000으로 다시 이름 붙이지 않는다. 달라지는 것은 선택할 예보시간 구간이다.
- **가로축은 유효시각으로 맞춘다. F-hour는 모델별 값이며 공유 머리글에 쓰지 않는다.** 같은 칸이라도 모델마다 몇 시간 앞 예보인지가 다르다. F-hour는 셀 hover와 그래프 hover에 모델별로 표시한다.
- 모델별 실행시각을 상단 칩에 각각 보인다. 실측 발표 지연은 ECMWF +7시간09분, ICON +4시간03분, GFS +5시간36분, KIM 약 +5시간20분이다. EC가 한 사이클 오래된 실행이면 같은 유효시각의 실제 예보시간도 6시간 더 길다. **그 차이는 그대로 표시하고, EC의 더 긴 예보시간 값을 가져와 미래 시각을 채운다.**
- 표·그래프에는 선택 실행의 유효시각을 공항 사용자의 표준 시간대(KST 기본값)로 표시한다. 저장·비교는 UTC ISO 시각으로 한다.
- 기본 시간축은 과거 3시간과 각 모델의 선택 구간이 덮는 미래 시각을 보인다. 현재부터 12시간 뒤까지를 모든 모델이 보장한다는 뜻은 아니다. 과거 구간은 해당 시각의 관측과 나란히 읽는 용도다. 1차 구현에서는 오차 계산·순위를 표시하지 않는다.
- 수집 성공 시각과 모델 실행시각은 다르다. 모든 모델값은 `run_at`, `available_at`, `collected_at`, `valid_at`, `forecast_hour`를 보존한다.

### 데이터 출처

| 출처 | 받는 방법 | 역할 |
| --- | --- | --- |
| METAR | 기존 수집·정규화 자료 (NOAA) | 실황 행. 강수 표에서는 강수량 대신 **관측된 현재날씨**를 보인다 |
| **AMOS** | 기존 수집 자료 (KMA API Hub `amos.php`) | 강수량 표의 실측 행. 적중도 기준값 활용은 후속 과제 |
| TAF | 기존 수집·정규화 자료 | 항공예보 행. 강수는 예보 현상(`-RA`/`RA`/`NSW`)만. **시간별 기온·RH 쌍이 없으므로 기온·RH 표에서 행 자체를 제외한다** |
| KIM | 기존 KMA API Hub 격자 수집 자료 (`typ01` 격자) | 국내 NWP 행. 공역 오버레이가 격자를 쓰므로 격자 수집을 유지한다 |
| ECMWF IFS | Open-Meteo 실행 고정 API, `models=ecmwf_ifs025` | 해외 NWP 행 |
| GFS Global | **NOAA NOMADS GRIB2 부분추출** | 해외 NWP 행 |
| ICON Global | Open-Meteo 실행 고정 API, `models=icon_global` | 해외 NWP 행 |

#### Open-Meteo (ECMWF · ICON)

주소는 **`https://single-runs-api.open-meteo.com/v1/forecast`** 다. 일반 주소(`api.open-meteo.com`)에 `run`을 붙이면 `Parameter 'run' must not be set`으로 거절한다.

모델 갱신 메타데이터(`https://api.open-meteo.com/data/{디렉터리}/static/meta.json`)에서 `last_run_initialisation_time`과 `last_run_availability_time`을 확인하고, 안정화 10분 뒤 같은 `run`을 요청한다. 디렉터리는 `ecmwf_ifs025`, `dwd_icon`이다.

한 요청에 여러 위경도를 받을 수 있어 **새 실행당 모델별 공항 묶음 요청 1회**를 기본으로 한다. 이때 **`elevation=nan`을 공항 수만큼 반복**해야 한다. 하나만 쓰면 `Parameter 'elevation' must have the same number of elements as coordinates`로 거절한다. 브라우저가 Open-Meteo를 직접 호출하지 않는다.

#### GFS (NOAA 원자료)

NOMADS GRIB 필터가 **변수와 영역을 서버에서 잘라준다**. 한반도 상자(124~132°E, 33~39°N)에 필요한 변수만 요청하면 예보시각 하나당 약 14~18 KB, 한 실행 13시각 전부 받아도 0.2 MB다.

```
https://nomads.ncep.noaa.gov/cgi-bin/filter_gfs_0p25_1hr.pl
  ?file=gfs.tHHz.pgrb2.0p25.fNNN&dir=/gfs.YYYYMMDD/HH/atmos
  &subregion=&leftlon=124&rightlon=132&toplat=39&bottomlat=33
  &lev_surface=on&lev_mean_sea_level=on&lev_10_m_above_ground=on&lev_2_m_above_ground=on&lev_cloud_ceiling=on
  &lev_entire_atmosphere=on&lev_low_cloud_layer=on&lev_middle_cloud_layer=on&lev_high_cloud_layer=on
  &var_UGRD=on&var_VGRD=on&var_GUST=on&var_APCP=on&var_TMP=on&var_DPT=on&var_RH=on
  &var_PRMSL=on&var_TCDC=on&var_LCDC=on&var_MCDC=on&var_HCDC=on&var_HGT=on&var_VIS=on
```

부분추출 결과는 전부 **자료표현 템플릿 5.0(단순압축)** 으로 다시 포장되어 나온다. 따라서 GRIB 라이브러리를 새로 들이지 않고 자체 판독기로 읽는다(검증 완료).

원자료를 쓰는 이유는 셋이다. ① 파일 이름이 곧 실행시각·예보시간이라 실행이 섞일 수 없다. ② Open-Meteo의 GFS는 지상(`ncep_gfs013`)과 상층(`ncep_gfs025`) 창고의 갱신 속도가 달라 두 창고가 공유하는 실행만 쓸 수 있고, 그 결과 항상 한 사이클 뒤처진다. 원자료는 한 파일에 다 있어 최신 실행을 쓴다. ③ 모델 자체 운고와 시정을 얻는다.

#### 검토했으나 채택하지 않은 것

- **ICON 원자료(DWD)**: 전지구 정20면체 격자만 제공하고 영역 추출 창구가 없다. 필요한 변수만 받아도 실행당 약 500 MB, 하루 2 GB다. 실측 전송속도 25~110 KB/s(중간값 약 60)에서 한 실행을 받는 데 2.5~6시간이 걸려 6시간 갱신 주기 안에 끝나지 않는다. Open-Meteo가 주는 값과 지상 12개 항목이 동일하므로 채택하지 않는다.
- **ECMWF 무료 공개 GRIB2 원자료**: 확인한 IFS 0.25° 자료에는 자체 운고 `ceil`, 실제 층별 운량·구름 액체수·얼음 함량이 없다. 원자료 수집으로 전환해도 자체 운고나 응결물 기반 재계산 입력을 얻지 못하므로, 이번에는 Open-Meteo의 습도 기반 층별 추정 운량을 사용한다. 별도 계약·재배포 경로를 통한 EC 자체 운고 확보는 후속 작업이다.
- **JMA GSM(전지구)**: 돌풍 없음, 하층 압력면 없음, 원자료 6시간 간격, 발표 지연 9시간33분. ICON보다 모든 항목에서 나쁘다.
- **JMA MSM(지역 5km)**: 해상도·지형 정확도·갱신 주기가 뛰어나지만 지역모델이라 전지구 4종과 성격이 달라 순위 비교가 성립하지 않는다. 별도 기능으로 남긴다.
- **UKMO 10km**: 김포 격자고도를 96 m로 잡아(실제 18 m) 운고 환산에 약 250 ft 오차가 생기고 발표 지연이 7시간09분이다.

### 공항 좌표와 격자값

- 공항에는 ICAO, 요청 위도·경도, 공항 표고를 둔다.
- KIM은 KMA 격자 좌표와 추출/보간 방식을 저장한다.
- Open-Meteo 요청에는 `cell_selection=nearest`, `elevation=nan`을 사용한다. 응답의 선택 격자 중심 위도·경도와 격자 지형고도도 저장한다.
- 화면은 “공항 좌표에 대응하는 모델 격자값”이라고 밝힌다. 모델 해상도와 격자 중심이 다르므로 서로 완전히 같은 점의 관측값이라고 표현하지 않는다.

## 공통 데이터 계약

각 `airport + model + run_at + valid_at` 레코드는 아래처럼 정규화한다. 사용 불가한 값은 숫자 0으로 대체하지 않고 `null`과 사유를 저장한다.

```text
airport_icao, source, model, run_at, available_at, collected_at,
forecast_hour, valid_at,
window_start_at, window_end_at,
requested_lat, requested_lon, grid_lat, grid_lon, grid_elevation_m,
selection_method, temporal_method,
wind_direction_deg, wind_speed_kt, wind_gust_kt,
precipitation_mm,
temperature_c, relative_humidity_pct, dew_point_c, pressure_msl_hpa,
cloud_total_pct, cloud_low_pct, cloud_mid_pct, cloud_high_pct,
ceiling_agl_ft, ceiling_method, ceiling_status, ceiling_limit_ft, ceiling_source_levels,
visibility_m,
field_provenance, source_payload_revision
```

- `selection_method`: `nearest_grid` 또는 KIM의 실제 추출/보간 방식.
- `window_start_at`·`window_end_at`: 해당 실행에서 이번 비교에 선택한 유효시각 범위. EC는 다른 모델의 최신 실행이 바뀌면 같은 EC 실행에서도 이 범위가 이동할 수 있다. `run_at`·`forecast_hour`는 실제 원자료 기준을 유지한다.
- `ceiling_method`: `model_diagnostic`(GFS) / `cloud_condensate_estimate`(KIM) / `humidity_based_estimate`(ECMWF) / `pressure_level_estimate`(ICON). 화면 배지가 이 값을 따른다. 자료가 누락돼도 모델의 산출 방식은 유지하고 상태를 별도로 기록한다.
- `ceiling_status`: `value`(수치 있음), `not_detected_below_limit`(추정에 쓴 층에서 5,000 ft 이하 조건 미검출), `no_ceiling`(제공자가 명시한 ceiling 없음), `missing_input`(필수 자료 누락), `outside_run`(모델별 선택 예보 구간 밖). 숫자가 없는 상태를 모두 같은 뜻으로 취급하지 않는다.
- `ceiling_source_levels`: 추정에 실제로 쓴 압력면, AGL, 층별 운량과 선택된 층을 기록한다. KIM은 `tqc`·`tqi`도 기록한다. hover 근거로 쓴다.
- `visibility_m`: GFS만 채워진다. 나머지는 `null`.
- `temporal_method`: 원 1시간 자료는 `native_hourly`, 원 3시간 자료를 Open-Meteo가 메운 값은 `interpolated_hourly`.
- `field_provenance`: 모델 원변수인지, Open-Meteo 계산/보간 변수인지 필드별로 남긴다.
- 단위 변환(풍속 m/s·km/h → kt, 온도 K → °C, 고도 m → ft)은 수집 경계에서 한 번만 한다.

### 변수 할당

| 화면 요소 | 정규화 필드 | 모델 입력 |
| --- | --- | --- |
| 지상 바람 표 | 풍향·풍속·돌풍 | 10m wind direction/speed/gust. wind barb는 프런트엔드 렌더링 |
| 풍속·돌풍 그래프 | 풍속, 돌풍 | 풍속은 실선·점 표식, 돌풍은 점선·점 표식 |
| 강수량 표 | 시간당 강수량 | `precipitation_mm`; KIM 시간당 값은 `pr`×3600. 비교 누적선은 모든 모델에서 같은 표시 구간의 시간당 값을 합산하며 결측 구간을 연결하지 않는다. KIM `prec_acc`는 실행 시작 기준 누적이므로 비교 구간 누적과 혼용하지 않는다 |
| 강수 관측 행 | 시간당 강수량 | AMOS `RN`(일누적)의 시간차 |
| 강수 현상 행 | 현재날씨 / 예보 현상 | METAR는 관측된 현재날씨, TAF는 예보 현상. 둘 다 mm가 아니므로 정량 비교·누적선에 넣지 않는다 |
| 운량 표 | 전·저·중·상층 운량 | `cloud_*_pct`; NWP는 %를 기본값으로 유지한다. 표식은 모델 운량의 시각화이며 METAR의 FEW/SCT/BKN/OVC 관측 보고로 변환하지 않는다 |
| 기온·RH 표·그래프 | `temperature_c`, `relative_humidity_pct` | NWP는 2m 기온·RH를 함께 표시. METAR는 보고된 기온과 기온·이슬점으로 계산한 RH. **TAF 행 없음** |
| 이슬점·기압 | `dew_point_c`, `pressure_msl_hpa` | 접을 수 있는 보조 행 또는 상세 hover 값 |
| 운고 표·그래프 | `ceiling_agl_ft` | 모델마다 근거가 다르다. 아래 「운고」 절 참조 |

### 모델별 변수와 수집 근거

#### KIM (KIMG/NE57) — 추가로 받을 변수

`docs/operations/kim-nwp-variables.md` 3.1·3.2절 기준. 아래 단일면 변수는 `data=U`, `level=0`에서 정상 응답을 확인했다. 운고 입력은 `data=P`의 기존 등압면 수집 자료를 재사용한다.

| 화면 항목 | 변수 | 단위 | 비고 |
| --- | --- | --- | --- |
| 풍향·풍속 | `u10m` `v10m` | m/s | 기존 수집 |
| 돌풍 | `gust` | m/s | **추가** |
| 시간당 강수 | `pr` × 3600 | kg/m²/s → mm | **추가**. 1시간 평균 강수율이라 곱하면 시간당 mm |
| 누적 강수 | `prec_acc` | kg/m² | **추가**. 실행 시작부터의 누적 |
| 전운량 | `tcld` | 0~1 | **추가** |
| 저·중·상층 운량 | `lcld` `mcld` `hcld` | 0~1 | **추가** |
| 기온·이슬점·습도 | `t2m` `td2m` `rh2m` | K, K, % | `t2m` 기존 수집 |
| 해면기압 | `psl` | Pa | **추가** |
| 모델 지형고도 | `topo` | m | **추가**. AGL 환산 기준 (김포 37 m) |
| 운고 추정 | `cld` + `tqc` + `tqi` + `hgt` (등압면), `topo` (단일면) | 0~1, kg/kg, kg/kg, m, m | 등압면 변수는 기존 수집 설정에 포함. `tqc`·`tqi`·`cld`는 착빙용 1000~300 hPa 자료를 재사용 |

`prec_acc`가 누적, `precl + precc`와 `pr × 3600`이 시간당 값임을 비 오는 격자점의 시계열로 대조해 확인했다.

**KIM 전구에는 시정이 없다.** 시정(`VIS`)과 안개비율(`FOGFRAC`)은 지역/국지 모델(`KIMR`/`KIML`)에만 있다. 이번 범위 밖이다.

#### ECMWF — Open-Meteo 운량과 임시 습도 기반 운고

`models=ecmwf_ifs025`를 유지한다. 전운량 `cloud_cover`는 원자료의 `tcc`에 대응하며, 저·중·상층 `cloud_cover_low/mid/high`와 기압면별 `cloud_cover_*hPa`는 **습도 기반 파생값**이다. 특히 층별 운량은 Open-Meteo가 상대습도와 기압으로 Sundqvist 방식에 따라 계산한다. `field_provenance`에 원변수와 파생값을 구분한다.

운고는 `cloud_cover_*hPa`와 같은 층의 `geopotential_height_*hPa`, 응답의 모델 `elevation`으로 **임시 추정**한다. `cloud_base`·`cloud_ceiling`을 요청해 EC 자체 운고를 받는 방식이 아니다. 응결물 자료를 추가로 받지 않으며, GRIB2 직접 수집도 추가하지 않는다.

**실행 고정 API 검증(2026-09-06):** 인천 좌표 `37.46,126.44`, `run=2026-09-05T00:00`, `models=ecmwf_ifs025`, `elevation=nan`, `cell_selection=nearest`로 1000/925/850/700/600/500/400/300/250/200/150/100/50 hPa의 `cloud_cover`·`geopotential_height`를 요청했다. 각 변수에 유효한 값이 반환됐고, 선택 격자 `37.5,126.5`와 지형고도 10 m도 확인했다. 이 확인은 자료 접근 검증이며 운고 정확도 검증은 아니다. EC에는 아래 예보시간 구간 이동 규칙을 적용한다.

#### GFS — 원자료에서 전부 나온다

`UGRD`/`VGRD`/`GUST`/`APCP`/`TMP`/`DPT`/`RH`/`PRMSL`/`TCDC`/`LCDC`/`MCDC`/`HCDC` 전부 존재를 확인했다. 더해 **`HGT:cloud ceiling`(모델 자체 운고)** 과 **`VIS:surface`(시정)** 를 얻는다. 시정을 화면에 넣을지는 별도로 정한다.

운량은 `TCDC:entire atmosphere`, `LCDC:low cloud layer`, `MCDC:middle cloud layer`, `HCDC:high cloud layer`의 **해당 유효시각 순간값**을 사용한다. 같은 이름의 시간평균 레코드가 있어도 혼용하지 않으며, GRIB 필터에 각 층을 포함한다. 운고는 NOAA 진단값을 사용하므로 운량·응결물로 다시 계산하지 않는다.

**실자료 검증에서 확인한 요청·시간 구간:** `PRMSL`을 받으려면 `lev_mean_sea_level=on`도 필요하다. `APCP`는 같은 F-hour에 서로 다른 누적 구간이 함께 있으므로 GRIB의 `stepType`·`startStep`·`endStep`을 읽는다. F009의 시간당 강수는 같은 실행의 0~9시간 누적에서 0~8시간 누적을 빼서 구한다. F009의 6~9시간 누적이나 0~9시간 누적을 그대로 시간당 값으로 쓰지 않는다. F001~F012에도 같은 원칙을 적용하며, 필요한 직전 누적이 없으면 결측으로 둔다.

#### ICON Global — Open-Meteo 운량과 압력면 기반 운고

`models=icon_global`의 `cloud_cover`, `cloud_cover_low/mid/high`를 전·저·중·상층 운량으로 사용한다. 운고 입력은 `cloud_cover_*hPa`와 `geopotential_height_*hPa`, 모델 `elevation`이다. 이번 방식에서는 응결물 조건을 추가하지 않고 층별 운량 50% 초과 조건으로 추정한다. EC의 습도 기반 파생 운량과 산출 근거를 구분하며, 아래 기존 6개 하층 확보 절차를 유지한다.

#### F000의 구조적 빈칸

시간당 강수와 돌풍은 직전 1시간을 대상으로 하는 값이므로 **F000에는 정의가 없다.** 세 모델 모두 빈값으로 온다. 0으로 채우지 않고 `자료 없음`으로 둔다.

이 규칙은 **실제 F000**에만 적용한다. EC 선택 구간의 첫 칸이 실제 F006이면 그 칸의 강수·돌풍은 반환된 값을 사용하며, 첫 칸이라는 이유로 비우지 않는다.

## 운량·운고 — 모델별 비교 방법

### 비교 대상

운량은 구름이 덮는 비율, 운고는 **5옥타 이상(BKN/OVC)에 해당하는 가장 낮은 구름층의 밑면 높이(ceiling, 지상 기준)**를 비교한다. 단순히 가장 낮은 구름의 높이나 전운량을 운고로 사용하지 않는다. METAR/TAF의 층별 운량·높이는 원자료의 의미를 유지한다.

NWP의 연속적인 층별 운량에는 **50% 초과**를 ceiling 탐색의 대응 조건으로 사용한다. `5/8=62.5%`로 기계적으로 바꾸지 않는다. 이는 모델 진단 조건이며, 격자 운량 %가 관측 옥타와 정확히 같다는 뜻은 아니다.

### 모델별 확정 방식

| 모델 | 운량 출처 | 운고 산출 | 운고 배지 |
| --- | --- | --- | --- |
| **KIM** | KMA `tcld`·`lcld`·`mcld`·`hcld`, 0~1을 %로 변환 | 기존 층별 `cld`·`tqc`·`tqi`·`hgt`와 `topo`로 추정 | `운량·응결물 기반 추정` |
| **GFS** | NOAA GRIB2 `TCDC`·`LCDC`·`MCDC`·`HCDC`의 순간값, % | `HGT:cloud ceiling`의 제공자 진단값 사용 | `모델 자체 운고` |
| **ECMWF** | Open-Meteo 전운량, 습도 기반 저·중·상층 추정 운량, % | 습도 기반 층별 추정 운량과 높이로 임시 추정 | `습도 기반 추정` |
| **ICON** | Open-Meteo 전·저·중·상층 운량, % | 층별 운량과 높이로 추정, 응결물 조건 없음 | `압력면 기반 추정` |

### 압력면 추정 절차 (KIM·ECMWF·ICON)

1. 같은 실행·유효시각·격자의 층별 운량과 높이를 맞춘다. KIM은 `cld`와 `hgt`에 더해 `tqc`(구름 액체수)·`tqi`(구름 얼음)를 쓴다. EC·ICON은 `cloud_cover_*hPa`와 `geopotential_height_*hPa`를 쓴다.
2. `지위고도 − 격자 지형고도`로 각 층을 AGL로 변환한다. KIM은 `topo`, EC·ICON은 `elevation=nan`으로 요청한 응답의 `elevation`을 쓴다. 지면 아래 층은 제외하고, 기존 설계대로 지상 30 m 미만도 탐색에서 제외한다. 이 제외만으로 안개를 완전히 식별한다고 보지 않는다.
3. 낮은 AGL부터 위로 탐색한다. **KIM은 `cld > 0.5`와 `tqc + tqi > 1e-6 kg/kg`를 함께 만족하는 첫 층**을 선택한다. `q`(수증기)나 `tqr`·`tqs`(비·눈)를 구름 응결물에 더하지 않는다. 이 임계값은 EC의 진단 원리를 참고해 채택하는 잠정 추정 조건이며, KIM의 공식 ceiling 진단은 아니다.
4. **EC·ICON은 층별 운량 >50%인 첫 층**을 선택한다. EC의 운량은 습도에서 추정한 값이며 응결물 조건은 평가하지 않는다. ICON도 이번 입력에서는 응결물 조건을 평가하지 않는다.
5. 선택한 층의 AGL을 ft로 바꿔 `ceiling_agl_ft`에 저장한다. 초기 버전에서는 층 사이의 구름 밑면 위치를 추가 보간하지 않고, 가용 층에 기반한 추정값으로 표시한다.
6. 탐색 범위는 기존 **5,000 ft AGL 이하**로 한다. 필요한 입력이 모두 있는데 조건에 맞는 층이 없으면 `ceiling_agl_ft = null`, `ceiling_status = not_detected_below_limit`로 두고 `5,000 ft 이하 조건 미검출`로 표시한다. 얇은 구름층을 놓쳤거나 범위 위에 ceiling이 있을 가능성을 부정하지 않는다. `NSC`나 `맑음`으로 바꾸지 않는다.
7. 필수 변수·대상 층의 결측은 `missing_input`, 모델별 선택 예보 구간 밖은 `outside_run`으로 둔다. 결측을 0으로 만들거나, 판정할 수 없는 낮은 층을 건너뛰고 높은 층의 값을 확정하지 않는다.

KIM 실응답의 `tqc`에는 0 부근의 작은 음수(이번 표본 약 `-5.82e-11 kg/kg`)가 있었다. 원값은 보존하고 응결물 합을 평가할 때 `max(0, tqc) + max(0, tqi)`를 사용한다. 결측 코드는 이 보정 전에 판별하며 음수 결측을 정상 0으로 바꾸지 않는다.

KIM API는 24개 압력면, 기존 수집은 21개 압력면이며 응결물·층별 운량 수집 범위는 1000~300 hPa다. 이번에 필요한 하층은 기존 자료로 충당한다. EC의 주요 하층은 1000/925/850 hPa, ICON은 아래 6개 층을 사용한다. **층 간격은 현행 자료의 제약으로 받아들이며, 더 촘촘한 자료 확보를 이번 구현의 조건으로 삼지 않는다.**

### GFS 제공자 진단값

`HGT:cloud ceiling`을 선택하고, 제공자의 높이 기준과 ceiling 없음 표현을 확인해 `ceiling_agl_ft`·`ceiling_status`로 정규화한다. AGL 값에서 지형고도를 두 번 빼지 않는다. 제공자의 ceiling 없음·결측 특수값을 거대한 숫자 운고로 그리지 않는다. 압력면 추정의 5,000 ft 탐색 상한을 GFS의 실제 진단값에 적용하지 않으며, 공통 저층 요약에서 5,000 ft 이하 여부를 비교한다.

이번 인천 표본의 원값은 `19999.937622070312` gpm으로, NOAA UPP 문서의 ceiling 없음 표식 20,000 m 부근이었다. GRIB 양자화 간격(이 표본 0.4)을 고려해 표식을 식별하며 `raw === 20000` 같은 정확 일치 비교를 쓰지 않는다. 결측과 ceiling 없음은 별도 상태다. [NOAA ceiling 정의와 없음 표식](https://noaa-emc.github.io/UPP/upp_v11.0.0/AVIATION_8f.html)

### 격자 지형고도 경고

모델 격자가 지형을 표현하는 정도는 공항마다 다르다. 기존 실측에서 제주(실제 36 m)의 격자고도는 ICON 365 m, ECMWF 224 m, GFS 0 m였다. 압력면 높이는 해당 격자의 지형고도로 AGL을 계산하고 공항 표고로 임의 대체하지 않는다. 지형고도 차이는 공항 대표성의 한계이며, 그 차이가 그대로 운고 예측 오차라고 단정하지 않는다. 공항별 격자 지형고도와 실제 표고의 차이를 저장하고 기존 hover에서 보여 준다.

- EC 습도 기반 층별 운량: [Open-Meteo ECMWF 문서](https://open-meteo.com/en/docs/ecmwf-api), [공개 변환 코드](https://github.com/open-meteo/open-meteo/blob/main/Sources/App/Ecmwf/EcmwfReader.swift). 위 실행 고정 API 실호출에서도 입력을 확인했다.
- GFS 운량·운고 레코드: [NOAA GFS 0.25° 변수 목록](https://www.nco.ncep.noaa.gov/pmb/products/gfs/gfs.t00z.pgrb2.0p25.f003.shtml).
- 초기 구현에서는 위 방식과 배지를 적용한다. 관측 대비 오차와 EC 습도 기반 추정의 유용성은 후속 검증 대상으로 남기며, 더 촘촘한 층 확보나 유료 EC 자료 계약을 선행 조건으로 추가하지 않는다.

**비교표 실자료 검증(2026-09-06):** 인천·울산의 `2026-09-06T09:00Z` 자료를 실제 수집했다. KIM·EC·GFS는 00Z 실행 F009, ICON은 06Z 실행 F003으로 같은 유효시각을 맞췄다. KIM은 공항 최근접 1개 격자의 46개 입력을 확인했고, GFS는 NOMADS GRIB2를 ecCodes로 판독했다. ICON의 975/950/900 hPa는 일반 API로 보완했으며, 각 공항에서 겹치는 232개 값이 실행 고정 API와 일치하고 실행 메타데이터가 유지됨을 확인했다. 운량·운고·바람·돌풍·강수·기온·이슬점·습도·해면기압을 HTML 비교표로 만들고 Playwright에서 표시를 확인했다.

울산 운고는 EC 약 4,524 ft, GFS 약 3,680 ft로 나왔다. KIM·ICON은 저층 운량이 각각 97%·74%여도 탐색 압력면에서 5,000 ft 이하 조건이 미검출됐다. 저층 집계 운량을 특정 높이의 운고로 바꾸거나 미검출을 구름 없음으로 표시하면 안 된다는 실제 사례다. 이번 검증은 두 공항 한 유효시각의 자료 접근·변환·표 표시 검증이며, F000~F012 전체 자동 수집이나 관측 대비 운고 정확도 검증은 아니다. 원응답·계산 근거·비교표는 `artifacts/nwp-live-validation-20260906/`와 그 하위 `RKPU/`에 보관한다.

## 진입점

이 화면은 **공항 패널에서 단추를 눌러 여는 전체화면**이다. 패널 안에 비교표를 그리지 않는다.

### 공항 패널의 단추

공항 패널(`frontend/src/features/airport-panel/AirportPanel.jsx`)은 구획 배열(`sections`)을 세로로 쌓고, 상단 칩이 각 구획으로 스크롤하는 구조다. 여기에 **`상세 예보 분석`** 구획을 **AMOS 다음 자리**에 추가한다.

```
공항경보 · METAR · TAF · AMOS · 상세 예보 분석 · NOTAM · 기상정보 · 달빛
```

기존 관측·항공예보 구획 뒤에서 여러 모델의 예보를 더 자세히 분석하는 흐름으로 연결한다.

구획에는 **같은 유효시각의 예보 요약과 `분석 화면 열기 ↗` 단추**를 둔다. 전체화면 제목은 **`{공항명} 상세 예보 분석`**으로 표시한다.

패널 요약은 바람(모델별 풍속·돌풍 범위), 강수(모델별 시간당 강수 차이), 운고(모델명과 수치 또는 미검출 상태) 3개 항목을 짧게 보여준다. 운고 숫자가 있는 모델만 묶어서 전체 모델의 합의 범위처럼 표시하지 않는다. 요약값은 전체화면의 정규화된 레코드를 재사용한다.

**요약 시각은 현재 시각 이후 첫 정시**로 한다. 14:20이면 15:00, 정확히 15:00이면 15:00, 15:01이면 16:00이다. 프로젝트의 유효 현재시각을 사용하며 저장·계산은 UTC, 표시는 사용자 시간대(KST 기본값)를 따른다. 제목 옆에 `15:00 KST 예보 · 3/4개 모델`처럼 시각과 해당 시각의 수집 성공 모델 수를 표시한다. 개별 항목의 결측은 별도로 유지한다.

해당 시각이 모델의 선택 구간 밖이면 `예보 범위 밖`으로 표시한다. 모든 모델을 채우려고 과거 시각으로 이동하거나 모델별로 다른 유효시각을 섞지 않는다. 단추를 누르면 `/airport/{ICAO}/models`로 이동하며 요약의 유효시각을 초기 `selected_valid_at`으로 유지한다. 전체화면에서 사용자가 다른 시간을 선택할 수 있다.

### 왜 패널 안에 표를 그리지 않는가

비교표의 자연 폭은 **1,146 px**이다(칸 11개, 칸당 최소 102 px, 줄바꿈 없음). 공항 패널 폭은 `clamp(560px, 50vw, 960px)`라 1440 px 노트북에서 720 px, 1920 px 모니터에서도 960 px다. 어느 경우에도 표가 들어가지 않는다.

패널 폭을 이 구획에서만 넓히는 방법도 검토했으나, 표 하나 때문에 패널 레이아웃 규칙을 예외 처리하는 것보다 전체화면이 낫다. 전체화면에서는 오른쪽 연직자료 열(440 px)도 같이 놓을 수 있다.

### 전체화면

`/monitoring`과 같은 방식으로 독립 경로를 쓴다(`app/App.jsx`가 `window.location.pathname`으로 분기하는 기존 패턴).

```
/airport/{ICAO}/models
```

경로에 공항이 들어가므로 새로고침해도 유지되고, 두 번째 모니터나 벽걸이에 띄워둘 수 있다. 전체화면에서 나가면 원래 공항 패널로 돌아온다.

### 노출 범위

AMOS 구획과 같은 `FULL_FEATURE_AIRPORTS` 8곳에만 단추를 보인다.

```
RKSI 인천 · RKSS 김포 · RKPC 제주 · RKPU 울산
RKJY 여수 · RKJB 무안 · RKNY 양양 · RKPK 김해
```

기존 AMOS 구획과 같은 지원 목록을 유지한다. 다만 **김해(RKPK)는 `amos_stn`이 없다.** 김해도 모델 비교를 제공하되 AMOS 강수 실측은 `자료 없음`으로 표시한다.

### 사이드바에는 넣지 않는다

사이드바 항목은 공항이 정해지지 않은 상태에서 눌리므로 "어느 공항?"부터 물어야 하고, 그것은 지도에서 공항을 고르는 동선을 두 번 만드는 일이다. 필요해지면 홈 공항이나 최근 본 공항으로 바로 여는 항목을 나중에 추가한다.

## 화면

### 상단

- 선택 공항명·ICAO, 표시 시간대, 선택 실행시각을 보인다.
- METAR 시각, TAF 발표시각, KIM/ECMWF/GFS/ICON의 `run_at`과 자료 이용 가능 시각을 **모델별로 분리한** 칩으로 보인다. 실행시각이 서로 다르다는 사실이 화면에서 바로 읽혀야 한다.
- 상단 요약은 선택 유효시각의 바람·강수·운고를 패널과 같은 뷰모델로 표시한다. 최초 진입은 패널에서 넘긴 시각, 직접 진입은 현재 이상 첫 정시를 쓴다. 시각 선택 시 요약도 함께 바뀐다. 자동으로 다음 변화나 운고 하회 시점을 찾아내는 카드는 후속 과제다.

### 비교 영역

- 시간축은 모든 표와 그래프가 같은 열·같은 **유효시각**을 공유한다. F-hour는 열 머리글이 아니라 셀·그래프 hover에 모델별로 보인다.
- 행 순서: METAR, TAF, KIM, ECMWF, GFS, ICON.
- 바람 표는 풍향 wind barb와 풍속을 한 줄, 돌풍을 별도 줄로 표시해 겹치지 않게 한다.
- 풍속·돌풍, 누적 강수, 추정 ceiling, 기온·RH는 각각 전폭 그래프 영역으로 놓고 값마다 점을 찍는다.
- **기온·RH 표는 같은 모델·유효시각의 두 값을 한 셀에 병기**한다. 기온(°C)을 먼저, RH(%)를 다음에 표시한다(예: `23.0°C / 74%`). 둘 중 하나가 없으면 해당 값만 `자료 없음`으로 표시하고 다른 값은 유지한다. 기온을 hover에만 숨기지 않는다.
- 기온·RH 그래프는 한 영역 안에 기온(°C)과 RH(%) 그래프를 위아래로 두고 같은 시간축과 모델 색상을 공유한다. 단위별 세로축을 분리하며 hover에는 해당 시각의 기온·RH를 함께 보인다.
- 그래프 hover는 같은 유효시각의 모든 모델값, 실행시각, 단위, 원/보간 여부를 보여 준다.
- 1차 화면에서는 모델별 색상·산출 방식·자료 상태만 구분한다. 위험 임계값 강조, 최근 3시간 추종도, 순위·1등 배지와 순위에 따른 행 재정렬은 표시하지 않는다.
- 운고 행의 배지는 KIM `운량·응결물 기반 추정`, GFS `모델 자체 운고`, ECMWF `습도 기반 추정`, ICON `압력면 기반 추정`이다. 표·그래프·hover에서 같은 산출 방식과 값을 사용한다.
- 운량은 네 모델 모두 전·저·중·상층 %를 비교한다. EC의 저·중·상층 운량에는 파생값 근거를 표시한다. 전운량과 저·중·상층 운량은 중첩 방식이 다르므로 합산해서 맞추지 않는다.
- 강수 표에는 **AMOS 실측 행**을 둔다. 정량 비교의 관측 기준값은 AMOS다.
- 강수 표의 METAR 행은 강수량 대신 **관측된 현재날씨**를 보인다. 0으로 두면 모델의 0.0 mm와 같은 값으로 읽히고, `자료 없음`으로만 두면 METAR가 실제로 아는 정보를 버리게 된다. TAF 행도 같은 방식으로 예보 현상을 보인다.
- **기온·RH 표에는 TAF 행을 두지 않는다.** TAF에는 비교할 시간별 기온·RH 쌍이 없으며, 최고·최저기온을 시간별 기온으로 채우지 않는다.

### 전체 보기와 요소별 탭 — 사용자 표시 모드

한 화면에 바람·강수·운고·운량·기온·RH의 **표와 전폭 그래프를 모두** 놓으면, 한 번에 전체 경향을 대조할 수 있다. 반면 특정 요소를 자세히 읽을 때는 세로 이동이 길어진다. 두 방식 중 하나를 고정하지 않고 사용자가 표시 모드를 바꾼다.

- 비교 구간 위에 `전체 보기 | 요소별 보기` 전환을 둔다. 기본값은 전체 보기다.
- **전체 보기:** 바람 → 강수 → 운고·운량 → 기온·RH 순으로 모든 표와 그래프를 세로로 보인다.
- **요소별 보기:** `바람 | 강수 | 운고·운량 | 기온·RH` 탭 중 하나만 보인다. 각 탭에는 해당 요소의 시간별 표와 같은 시간축의 전폭 그래프를 함께 둔다.
- 두 모드는 같은 선택 공항·실행시각·시간축·모델 정렬·hover 상태를 공유한다. 보기 모드를 바꿔도 새로 수집하거나 서로 다른 데이터가 보이지 않는다.
- 상단 요약은 두 모드 모두에서 선택 시각의 바람·강수·운고를 보인다. **ECMWF도 해당 시각의 유효한 값이 있으면 포함**한다. 요약·표·그래프는 동일한 정규화 값과 상태를 사용하며, 별도 하드코딩한 운고·운량이나 결측을 0으로 바꾼 값으로 요약하지 않는다.

### 관측과 모델의 행 순서

METAR·TAF 다음에 KIM → ECMWF → GFS → ICON 순서를 고정한다. 강수량의 AMOS 행은 METAR·TAF 현상 행 다음, NWP 행 앞에 둔다. 기온·RH에서는 TAF 행을 제외한다. 과거 관측이 부족해도 다른 시각의 값으로 채우지 않는다.

### 일기도 자리

오른쪽 열은 높이를 유지한 임시 이미지 카드 두 개(연직시계열·단열선도)만 둔다. 이미지에는 `임시 예시 — 현재 공항·실행자료와 연결되지 않음`을 명시한다. 이 카드가 NWP 비교 데이터 수집을 유발하지 않는다.

### 연직시계열과 단열선도의 미래 조작 모델

이번 범위에서는 두 카드 모두 임시 이미지이지만, 실제 연직 자료를 연결할 때의 조작 원칙을 미리 고정한다.

- 연직시계열은 한 장의 시간-고도 단면이므로 선택 실행의 전체 시간 범위를 한 카드에 보인다.
- 단열선도는 `valid_at` 하나당 한 장이다. 따라서 독립된 그림 여러 장을 세로로 나열하지 않는다.
- 화면 전체에 `선택 유효시각(selected_valid_at)` 상태를 하나만 둔다. 표의 시간 열, 그래프의 점 클릭/hover 고정, 단열선도는 모두 이 시각을 따른다.
- 단열선도 카드 아래에는 비교 시간축의 유효시각을 1시간 단위로 이동하는 슬라이더와 이전/다음 단추를 둔다. 키보드 좌우 화살표도 같은 단위로 이동한다. EC를 포함한 실제 F-hour는 모델별로 따로 표시한다.
- 연직시계열의 시간축을 클릭해도 같은 `selected_valid_at`이 바뀐다. 별도의 두 번째 시간 상태나 서로 어긋나는 슬라이더를 만들지 않는다.
- 선택 시각의 모델 실행·유효시각·공항·격자 좌표를 단열선도 제목에 표시한다.

실제 연직 자료 연결은 이번 데이터 수집 범위 밖이다. 위 조작 모델은 나중에 KIM 또는 해외 모델의 연직 자료를 붙일 때 UI를 다시 설계하지 않기 위한 계약이다.

## 수집·저장·실패 처리

1. 모델별 갱신 메타데이터를 확인한다.
2. 새 `run_at`이 확인되고 `available_at + 10분`이 지난 뒤 공항 묶음 JSON을 수집한다. EC는 다른 모델의 최신 완전 실행이 바뀌어 목표 구간이 이동한 경우에도, 같은 EC 실행에서 새로 필요한 시각을 확보한다. 새 EC 실행이 나올 때까지 기다리지 않는다.
3. 응답의 모델·실행시각·시간축이 요청과 일치하는지 검증한다.
4. **모델별 목표 구간의 13개 레코드**가 모두 검증된 공항만 해당 실행·구간을 완전으로 발행한다. KIM·GFS·ICON은 F000~F012, EC는 계산된 이동 구간이다. 실제 F000의 구조적 결측이나 운고 조건 미검출은 허용 상태로 검증한다. 일부 공항 실패는 기존 마지막 완전 실행·구간을 유지하고, 실패 공항·원인·재시도 시각을 기록한다.
5. 수집 원문은 필요한 보존 기간 동안 압축 보관하고, 화면은 정규화된 공항별 레코드만 읽는다.
6. 관리자 콘솔(`/admin`)에는 모델별 마지막 성공 실행, 이용 가능/수집 시각, 대상 공항 수, 성공/실패 수, 마지막 실패 원인, 다음 예정 확인 시각을 보인다. 자세한 편입 규약은 아래 「운영 편입」 절을 따른다.

KIM은 현재 `config.js`의 `kim_nwp.forecast_hours`가 `[5…16]`이다. **F000~F012로 바꾼다.** F000부터 F016까지 전부 정상 응답함을 실호출로 확인했다(각 445 KB). `docs/operations/kim-nwp-variables.md` 4절의 예보시간 기술도 함께 고친다.

### 표시 구간 — EC의 예보시간 구간 이동

**KIM·GFS·ICON은 F000~F012를 유지하고, EC만 같은 미래 시각을 채우도록 선택 구간을 이동한다.** 기준은 명목상 발표 지연 시간이 아니라 현재 화면에서 선택한 실제 실행시각이다.

1. `comparison_anchor_at`은 현재 선택 가능한 KIM·GFS·ICON의 최신 완전 실행들 중 가장 최근 `run_at`으로 정한다. 세 모델이 모두 없으면 EC의 `run_at`을 사용한다.
2. `ec_offset_hours = max(0, (comparison_anchor_at − ec_run_at) / 1시간)`으로 계산한다. 현재 6시간 실행 체계에서는 통상 0 또는 6이며, 고정 6으로 가정하지 않는다.
3. EC의 목표 실제 예보시간은 **`ec_offset_hours`부터 `ec_offset_hours + 12`까지 13개 시각**이다. `window_start_at`·`window_end_at`은 그 실제 유효시각으로 저장한다.
4. EC의 `run_at`·실제 `forecast_hour`를 보존한다. 표 머리글은 공통 유효시각이며, hover에는 실제 F-hour를 표시한다. EC 예보의 시간축이나 값 자체를 평행 이동하지 않는다.

예시(모두 같은 날짜, UTC):

| 모델 | 실제 실행 | 선택할 실제 F-hour | 표에 제공할 유효시각 |
| --- | --- | --- | --- |
| KIM·GFS·ICON | 06Z | F000~F012 | 06Z~18Z |
| EC — 한 실행 늦음 | 00Z | **F006~F018** | **06Z~18Z** |
| EC — 06Z 실행 확보 후 | 06Z | F000~F012 | 06Z~18Z |

실행 고정 Open-Meteo 요청에서 이동 구간 끝까지 포함하는 응답을 확보한다. `forecast_hours=13` 등으로 실제 F000~F012만 받아놓고 첫 시각을 바꾸는 구현은 하지 않는다. 응답에서 실제 유효시각으로 13개 목표 레코드를 선택한다. 같은 EC 실행의 원응답·정규화 자료에 새 목표 시각이 이미 있으면 재사용하고, 없으면 해당 실행을 다시 요청한다. **다른 모델의 기준 실행이 갱신될 때도 EC 목표 구간을 재평가**한다. 구간과 실행을 함께 추적해 미완성 자료가 기존 성공 자료를 덮지 않게 한다.

이미 수집한 `2026-09-06T00:00Z` EC 실행의 인천·울산 원응답에서 F006~F018의 13개 시각 × 20개 필드(지상 변수와 층별 추정 운량·높이)가 두 공항 모두 결측 없이 반환됐음을 확인했다. EC 구간 이동을 위한 새 자료 제공자나 GRIB 수집은 필요 없다. 이 확인은 저장된 원응답의 구간 검증이며 자동 갱신 동작 검증은 아니다.

화면 규칙은 다음과 같다.

- 시간축은 과거 3시간과 모델별 선택 구간이 덮는 미래 유효시각의 합집합으로 한다. 현재부터 12시간의 미래 예보를 항상 보장하지는 않는다.
- 해당 모델의 선택 구간 밖은 **`예보 범위 밖`**으로 표시한다. EC의 실제 F013~F018도 목표 구간에 포함되면 정상 값으로 표시한다. 실제 포함 범위는 hover에서 확인할 수 있다.
- 필수 입력 결측의 `자료 없음`, 추정 운고의 `5,000 ft 이하 조건 미검출`과 구분한다. 범위 밖을 `미예상`으로 표현하지 않는다.
- 같은 행의 다른 실행이나 다른 모델 값으로 빈칸을 메우지 않는다. EC도 선택한 한 실행의 더 긴 예보시간을 사용하는 것이다.
- 패널 요약은 현재 이후 첫 정시를 유지한다. 전체화면의 선택 시각 요약도 각 모델의 실제 커버리지 안에서만 계산한다.

## 운영 편입 — 기존 자료와 똑같이 관리한다

해외 수치모델은 새 데이터 종류다. [data and time](../../policies/engineering/data-and-time.md)의 데이터 수명주기 규약을 그대로 따른다.

> API 클라이언트 → 파서 → 프로세서 → 종류별로 보호된 스케줄러 등록 → 스냅샷 저장소 소유권 → 캐시된 API 경로 → 필요할 때만 프런트 클라이언트

아래 여덟 관문을 모두 채우기 전에는 구현이 끝난 것이 아니다.

### 1. API operation 등록 — 빠뜨리면 호출 자체가 실패한다

모든 외부 호출은 `backend/src/lib/request-observability.js`의 `requestObservedApi()`를 거치고, 등록되지 않은 주소는 거절된다.

```js
if (!resolvedOperation?.requestPolicy) throw requestError('invalid_api_operation')
```

`backend/src/api-operation-registry.js`에 아래 여섯 항목을 추가한다. 형식은 이미 등록된 `open_meteo_air_quality`(Open-Meteo 대기질)를 그대로 따른다.

| id | label | provider | collectorType |
| --- | --- | --- | --- |
| `open_meteo_ecmwf_meta` | EC 갱신 메타 | Open-Meteo | `nwp_ecmwf` |
| `open_meteo_icon_meta` | ICON 갱신 메타 | Open-Meteo | `nwp_icon` |
| `open_meteo_ecmwf_single_runs` | EC 실행 고정 예보 | Open-Meteo | `nwp_ecmwf` |
| `open_meteo_icon_single_runs` | ICON 실행 고정 예보 | Open-Meteo | `nwp_icon` |
| `open_meteo_icon_pressure_window` | ICON 압력면 시간창 | Open-Meteo | `nwp_icon` |
| `nomads_gfs_filter` | GFS GRIB2 부분추출 | NOAA NOMADS | `nwp_gfs` |

각 항목에 `dataHealthKeys`, `callContract: { kind: 'collector' }`, `canonicalUrl`, `requestPolicy`, `match(url)`를 채운다. 메타는 모델별 경로, 실행 고정 API는 `models` query 값으로 구분해 요청 URL이 정확히 한 operation에만 매칭되게 한다. `overseas_nwp`는 설정 묶음이며 실제 수집기 ID로 쓰지 않는다.

**`apiHub: false`, `credentialCategory: null`이다.** Open-Meteo와 NOAA는 기상청 API Hub 인증키 한도를 쓰지 않는다. 레이더·위성 키 한도 조사와 무관하다.

### 2. 수집기 등록

`backend/src/collector-registry.js`의 `COLLECTOR_REGISTRY`에 모델별로 등록한다. **하나로 묶지 않는다** — 발표 지연이 모델마다 달라 하나의 일정으로 감쌀 수 없다.

```js
collector('nwp_ecmwf', utc('nwp_ecmwf_interval', 6*HOUR, 90*MINUTE), (c) => c.overseas_nwp?.enabled !== false, [])
collector('nwp_icon',  utc('nwp_icon_interval',  6*HOUR, 60*MINUTE), (c) => c.overseas_nwp?.enabled !== false, [])
collector('nwp_gfs',   utc('nwp_gfs_interval',   6*HOUR, 75*MINUTE), (c) => c.overseas_nwp?.enabled !== false, [])
```

- 네 번째 인자(`apiHubCategories`)는 **빈 배열**이다.
- `graceMs`는 발표 지연의 흔들림을 흡수할 만큼 넉넉히 준다. 실측 지연은 ECMWF 7시간09분, GFS 5시간36분, ICON 4시간03분이다.
- `enabled`는 `config.overseas_nwp.enabled`로 끌 수 있게 한다. 기존 `kim_nwp.enabled`와 같은 방식이다.

KIM은 이미 `kim_surface_wind` 수집기가 있다. 변수만 추가되므로 새 수집기를 만들지 않는다.

### 3. cron 일정

`backend/src/config.js`의 `schedule`에 모델별 표현식을 추가한다. 기존 수치예보 수집기들이 발표시각에 맞춘 시각 목록을 쓰는 방식을 따른다(`kim_surface_wind_interval`, `ktg_interval` 참고).

발표 지연이 실측 기준이므로 **실제 자료 요청은 실행 후 지연시간+30분쯤부터 시작**한다. 모델별 UTC 10분 점검에서 새 실행·실패 구간·EC 기준 실행 변경이 있을 때만 수집을 실행한다. 완료된 같은 실행·구간이면 점검만 하고 외부 요청을 보내지 않는다. 부분 실패도 실패 상태로 기록하고 다음 10분 점검에서 재시도한다.

### 4. 저장소

`store.js`의 `TYPES`가 아니라 **KIM 방식의 실행별 저장소**를 쓴다. 실행·선택 구간 재현과 마지막 성공 자료 보존이 필요하기 때문이다.

`backend/src/processors/kim-nwp-store.js`의 구조를 따른다 — 실행별 디렉터리 + `manifest` / `index` / `latest`.

부분 실패 처리는 스토어 규약 그대로다. **일부 공항 실패가 마지막 완전 실행을 덮어쓰지 않는다.**

### 5. 보존과 정리

`cleanupKimNwpRuns()`에 해당하는 정리 규칙을 반드시 둔다. 없으면 디스크가 무한히 찬다.

- `config.overseas_nwp.max_runs`를 둔다. 기본값은 **4실행**이며, 최근 실행의 재현과 실패 시 마지막 성공 자료 보존에 쓴다.
- 공항별 정규화 레코드만 남기고 원문은 보존 기간을 짧게 둔다.

### 6. 캐시된 API 경로

브라우저가 Open-Meteo·NOAA를 직접 부르지 않으므로 백엔드 경로가 필요하다.

```
GET /api/airport/{ICAO}/model-comparison
```

캐시 정책은 정책 문서의 기준을 따른다 — 실행이 바뀌는 운영 자료이므로 **명시적 신선도와 낡은 자료 처리 동작**을 정한다.

### 7. 관리자 콘솔 — /admin

관리자 페이지가 자료 34종의 수집 상태를 보고 있다. 해외 수치모델도 **같은 목록에 들어가야 한다.**

#### 7-1. `data-health-catalog.js`의 `SOURCES`에 출처 추가

기존 출처는 `kma_aviation` / `kma_radar` / `kma_nwp` / `noaa` / `kac` / `external`이다. Open-Meteo를 추가한다. NOAA NOMADS는 기존 `noaa`를 쓴다.

```js
open_meteo: { label: 'Open-Meteo', apiHubCategory: null },
```

#### 7-2. `CATALOG`에 자료 3종 추가

`character`는 기존 `nwp`(수치예보)를 쓴다. KIM·KTG·WISSDOM·QPF와 같은 묶음에 들어간다.

| key | label | source | normalMs | lateMs | stoppedMs |
| --- | --- | --- | --- | --- | --- |
| `nwp_ecmwf` | ECMWF IFS | `open_meteo` | 6시간 | 10시간 | 20시간 |
| `nwp_icon` | ICON Global | `open_meteo` | 6시간 | 9시간 | 18시간 |
| `nwp_gfs` | GFS Global | `noaa` | 6시간 | 9시간 | 18시간 |

**ECMWF의 `lateMs`를 다른 둘보다 길게 잡는다.** 발표가 7시간09분 걸려 다른 모델과 같은 기준을 쓰면 정상인데도 `지연`으로 뜬다.

`disabledWhen`은 `(c) => c.overseas_nwp?.enabled === false`로 둔다. 꺼둔 자료를 멈춘 것으로 판정하지 않는 기존 규칙(`OFF.kimNwp`)과 같다.

#### 7-3. API 사용량 화면

`/api/admin/api-hub-usage`와 `ApiUsageScreen`은 API Hub 인증키 한도를 보는 화면이다. Open-Meteo·NOAA는 `apiHub: false`라 **한도 집계에는 잡히지 않지만**, 호출 성공·실패·소요시간은 `requestObservedApi`를 거치므로 수집 실행 문제 목록에는 정상적으로 뜬다.

#### 7-4. 데이터 수집 화면에서 보여야 할 것

`DataCollectionScreen`이 읽는 값이 그대로 채워져야 한다.

- 모델별 마지막 성공 실행과 그 시각
- 모델별 `run_at` / `available_at` / `collected_at`
- 대상 공항 수, 성공·실패 수, 마지막 실패 원인
- 다음 예정 확인 시각 (cron에서 계산됨)

### 8. 데모 모드 스냅샷

`backend/data/snapshots/demo/`에 데모용 자료가 종류별로 있다. 새 자료도 스냅샷 저장·불러오기(`/api/admin/snapshot/*`)에 포함되어야 데모 모드가 깨지지 않는다. 모델별 하위 경로에 latest 포인터를 두는 비교 저장소는 캡처 대상 탐색과 전체 디렉터리 복사 양쪽에 등록한다. 과거 비교에 쓰는 METAR·AMOS 이력도 함께 캡처하며, 구형 스냅샷에 새 자료가 없으면 실황으로 보충하지 않는다.

## 후속 과제 — 1차 구현의 완료 조건에서 제외

| 과제 | 착수 전에 정할 기준·확인할 근거 |
| --- | --- |
| 최근 3시간 추종도·순위 | 요소별 오차 계산법, 최소 관측 수, 같은 비교 시각, `차이 미미` 기준, 결측 처리. 기온·RH는 서로 다른 단위이므로 순위를 각각 낼지부터 결정한다. 순위에 따른 행 재정렬도 이때 검토한다 |
| 관측을 순위 기준으로 사용 | AMOS `WD10`·`WS10`·`WS10_MAX`·`TA`·`TD`·`HM`과 METAR의 시간 정렬, `RN` 차분, AMOS `CH_MIN`이 비교하려는 항공 ceiling과 같은 의미인지 확인. 김해는 AMOS가 없으므로 대체 기준과 강수 순위 제외를 정한다 |
| 자동 변화 요약·임계값 강조 | 바람·강수 변화와 운고 하회 판단 조건, 모델 간 의견 차이·부분 결측 처리, 운영 기준에 따른 임계값·색상. 확정 전에는 자동 판단 문구와 위험 색상을 넣지 않는다 |
| 운고 추정 정확도 | 공항·기상 사례별 관측 대조, KIM 층별 운량·응결물 조건과 EC 습도 기반 추정의 오차·미검출 확인. 더 촘촘한 층이나 EC 자체 운고 확보는 결과를 보고 판단한다 |
| 예보시간 확대 | KIM 한반도 격자 수집량·API 한도·저장 용량을 확인하고 확대. 이번 EC 이동 구간과 별개다 |
| 장기 통계·실제 일기도 | 과거 실행 백필과 장기 적중도, 연직시계열·단열선도 실제 생성은 별도 설계한다 |

전체 시간대 자동 수집, 실행 갱신, 부분 실패 보존, 재시도, 데모 전환은 **1차 구현 중 검증할 항목**이다. 후속 과제로 미뤄 완료 검증에서 빼지 않는다.

## 하지 않는 것

- ECMWF·ICON 원 GRIB2 직접 수집·파싱과 전체 모델층 응결물 기반 ceiling 재계산. **GFS NOMADS GRIB2 부분추출·파싱과 KIM 기존 등압면 응결물 활용은 이번 범위에 포함한다.**
- 운항 의사결정을 자동으로 승인/차단하는 기능.
- 모델 간 값을 평균내거나 하나의 단일 예보로 합성하는 기능.
- METAR/TAF의 운고를 NWP 운고로 대체하는 기능.
- 실제 일기도·연직시계열·단열선도 생성 또는 선택 공항 동기화.
- 장기 적중도 통계와 과거 실행분 백필. 실행별 보존은 하되 이번 범위에서 통계를 내지 않는다.
- ECMWF 자체 `ceil` 확보를 위한 별도 계약·유료 자료 연동. 이번에는 Open-Meteo 습도 기반 운고 추정을 사용한다.
- KIM 지역/국지 모델(`KIMR`/`KIML`)의 시정·안개비율.
- JMA MSM 등 지역모델 행 추가.

## 수용 기준

0. 지도에서 지원 공항을 누르면 공항 패널의 `상세 예보 분석` 구획에 요약과 `분석 화면 열기 ↗` 단추가 보이고, 단추를 누르면 `/airport/{ICAO}/models`가 열린다. 전체화면 제목은 `{공항명} 상세 예보 분석`이다. 미지원 공항에서는 구획 자체가 보이지 않는다.
0-1. 패널 요약은 현재 시각 이상인 첫 정시를 기준으로 바람·강수·운고 세 줄과 대상 시각·참여 모델 수를 표시한다. 정확히 정시면 그 시각을 쓴다. 전체화면을 열 때 같은 `selected_valid_at`을 유지하며, 모델 수를 채우려고 과거 시각으로 돌아가지 않는다.
1. 지원 공항 하나를 선택하면 KIM·ECMWF·GFS·ICON의 시간별 값과 METAR·TAF·AMOS를 하나의 유효시각 축에 표시한다.
2. 모델별 `run_at`이 상단 칩에 각각 표시되고, 표의 각 칸에서 그 모델의 F-hour를 hover로 확인할 수 있다.
2-1. 다른 모델이 06Z 실행이고 EC가 00Z 실행이면 EC의 실제 F006~F018을 사용해 같은 06Z~18Z를 표시한다. EC의 `run_at`과 실제 F-hour를 보존하며, 다른 모델의 기준 실행이 갱신되면 EC의 목표 구간도 재평가한다.
3. 모든 모델값은 실행·이용 가능·수집·유효시각과 격자 좌표를 추적할 수 있다.
3-1. 강수 표에서 METAR는 현재날씨, TAF는 예보 현상을 보이고 둘 다 누적선에 포함되지 않는다. 기온·RH 표에는 TAF 행이 없다.
4. 바람, 돌풍, 시간당/누적 강수, 운량, 운고, 기온, RH는 이를 표시하는 요약·표·그래프·hover에서 동일한 유효시각의 값과 상태로 일치한다.
4-1. 모델별 선택 예보 구간 밖의 칸은 `예보 범위 밖`으로 표시되며, 입력 결측의 `자료 없음`·추정 조건의 `5,000 ft 이하 조건 미검출`과 구분된다. 다른 실행이나 다른 모델의 값으로 채우지 않는다.
4-2. `기온·RH` 표의 같은 셀에 기온(°C)과 RH(%)가 함께 보이고, 그래프는 같은 시간축에서 단위별 세로축을 분리한다. 한 값의 결측이 다른 값을 가리지 않으며, 전체 보기와 요소별 보기에서 같은 값을 사용한다.
5. 운고 행의 배지가 KIM `운량·응결물 기반 추정`, GFS `모델 자체 운고`, ECMWF `습도 기반 추정`, ICON `압력면 기반 추정`으로 구분된다. 추정에 사용한 압력면·AGL·운량을 hover로 확인할 수 있다.
5-1. KIM은 층별 운량 >50%와 `tqc + tqi > 1e-6 kg/kg`를 함께 적용한다. GFS는 제공자 운고를 재계산 없이 정규화한다. EC·ICON은 각 출처의 층별 운량 >50%로 추정하고 응결물 조건을 적용한 것처럼 표시하지 않는다.
5-2. EC는 `ecmwf_ifs025` 실행 고정 API의 층별 추정 운량·높이로 계산하며, 값이 있으면 운고 표·그래프·요약에 포함된다. EC 원자료 수집은 추가하지 않는다.
5-3. 네 모델의 전·저·중·상층 운량은 %로 비교하고, EC 습도 기반 파생값의 출처를 표시한다. 전운량만으로 운고를 산출하거나 NWP 운량을 관측 BKN/OVC 보고로 바꾸지 않는다.
6. 실제 F000의 구조적으로 제공되지 않는 강수·돌풍은 `자료 없음`으로 표시하며 0으로 채우지 않는다. EC 구간의 첫 칸이 실제 F006이면 반환된 강수·돌풍을 표시한다. METAR의 강수는 현재날씨를 표시하며 강수량 0으로 취급하지 않는다.
7. 모델 행은 KIM → ECMWF → GFS → ICON 순서로 고정한다. 순위·1등 배지·자동 변화 판단·위험 임계값 강조를 표시하지 않는다. 전체화면 요약은 선택 시각의 바람·강수·운고를 표시한다.
8. 수집 실패가 마지막 완전 실행을 덮어쓰지 않으며, 관리자 콘솔에서 실패 원인과 성공 기준을 확인할 수 있다.
8-1. `/admin`의 데이터 수집 화면에 ECMWF·ICON·GFS가 기존 자료와 같은 목록에 나타나고, 각각 정상/지연/멈춤이 판정된다. ECMWF는 발표 지연 7시간09분을 반영한 기준으로 판정되어 정상 동작 중에 `지연`으로 뜨지 않는다.
8-2. 세 모델의 모든 외부 호출이 `api-operation-registry.js`에 등록되어 있고, 등록되지 않은 주소로의 호출이 없다.
8-3. `overseas_nwp.enabled = false`로 끄면 수집기가 등록되지 않고 관리자 콘솔이 이를 멈춤이 아니라 꺼둔 상태로 판정한다.
8-4. 보존 실행 수 상한이 설정되어 있고, 상한을 넘긴 오래된 실행이 정리된다.
9. 일기도 카드는 임시 이미지임을 명시하고 실제 데이터처럼 보이지 않는다.
