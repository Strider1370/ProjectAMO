# 국내 기상 래스터 전환·레이더 정리 설계

## 목적

타임라인을 이동하거나 재생할 때 국내 기상 이미지 레이어가 사라졌다가 다시 나타나는 현상을 없앤다. 사용자가 선택할 국내 레이더는 기상청 합성 HSR 이미지로 단일화하고, 원시 BIN 기반 ProjectAMO 레이더 수집은 일시 중단한다.

## 범위

대상은 국내 시간 프레임을 가진 이미지/벡터 레이어다.

- 기상청 합성 레이더 HSR (`radarHsr`, 화면명 `레이더`)
- 강수 형태 HCI (`radarHci`)
- WISSDOM
- MAPLE QPF
- 적외·가시 위성
- 낙뢰

RainViewer 해외 레이더는 이 변경의 전환 대상에서 제외한다. 타임라인과 직접 관련 없는 레이어도 제외한다.

## 레이어 정책

### 국내 레이더 단일화

- 기존 BIN 기반 `radar`는 MET 패널과 검색/공유 레이어 진입점에서 숨긴다.
- `radar_echo`의 시작 수집과 cron 수집을 중단한다. 기존 저장 프레임은 삭제하지 않는다.
- `radarHsr`의 표시명은 `레이더`로 변경한다.
- `레이더`가 켜지면 같은 선택 시각의 HSR 이미지와 WISSDOM을 자동으로 함께 표시한다. 기존 별도 WISSDOM 켜기/끄기 제어는 제거한다.
- `강수 형태`는 HCI 이미지로 유지한다.

### 범례

- HSR과 HCI가 켜지고 현재 표시 프레임이 있을 때 각각 가로 범례를 표시한다.
- KMA가 프레임에 제공하는 세로 범례 이미지는 색/구간의 기준으로만 사용하며 화면에 그대로 표시하지 않는다.
- HSR은 `mm/h` 색 막대와 수치 구간을, HCI는 강수 분류별 가로 색 칩을 ProjectAMO UI로 렌더한다.
- `레이더`의 WISSDOM도 자동 표시되는 가로 `m/s` 범례를 HSR 범례 영역에 포함한다.
- 범례의 값과 색은 확인한 KMA 원본 범례와 일치해야 하며, 추정값을 만들지 않는다.

### 공통 경계선

- HSR 또는 HCI가 켜지면 기존 공통 GeoJSON 경계선을 표시한다.
- 적외 또는 가시 위성이 켜지면 같은 경계선을 노랑으로 표시한다. 위성이 꺼진 상태에서 HSR/HCI만 켜진 경우에는 기존 어두운 색을 사용한다.
- 다른 베이스맵과 함께 켜진 경우에도 경계선 가시성/색상 결정은 단일 정책 함수가 맡는다.
- 스타일 또는 베이스맵 변경 뒤에도 경계선, 선택 프레임, 토글 상태를 현재 상태로 복구한다.

## 프레임 전환

### 이미지 레이어

공통 이미지 오버레이 어댑터가 프레임별로 다음 상태를 관리한다.

1. 현재 정상 프레임은 계속 표시한다.
2. 새 프레임 이미지를 먼저 preload한다.
3. preload가 성공하면 이전/새 프레임을 Mapbox 소스·레이어 두 벌로 잠시 겹친다.
4. 새 레이어는 0에서 목표 불투명도로, 이전 레이어는 목표 불투명도에서 0으로 약 200ms 전환한다.
5. 전환이 끝나면 이전 소스·레이어를 정리하고 새 프레임을 현재 프레임으로 확정한다.

대상은 HSR, HCI, WISSDOM, QPF, 적외영상, 가시영상이다. 해외 레이더 타일은 이 어댑터를 사용하지 않는다.

### 빠른 타임라인 이동과 실패

- 선택 시각이 다시 바뀌면 아직 완료되지 않은 preload/전환은 취소한다.
- 늦게 끝난 이전 요청은 현재 선택을 덮어쓸 수 없다.
- 새 이미지 preload 또는 투영/소스 설치가 실패하면 현재 정상 프레임을 유지한다.
- 재생 시 인접 프레임을 선로딩할 수 있으나, 선로딩 실패는 화면 상태를 바꾸지 않는다.

낙뢰는 이미지 프레임이 아니므로 현재 GeoJSON을 새 데이터로 교체하기 전에 다음 데이터 준비를 보장하고, 동일한 최신 선택/취소 가드로 빈 상태와 stale 반영을 막는다. 별도 DOM 또는 지도 밖 애니메이션은 만들지 않는다.

## 타임라인 자료 있음 표시

- 자료 가능 여부는 현재 켜진 시간 레이어들의 실제 프레임 집합에서 계산한다.
- 관측 과거 프레임과 QPF/NWP 미래 유효 프레임을 모두 포함한다.
- 같은 시각에 켜진 레이어 중 하나 이상이 표시 가능한 프레임을 가지면 `hasData`가 참이다.
- 타임라인의 기존 눈금 띠 **안**에서만 `hasData`를 단색의 짧은 세로 표시로 표현한다.
- 표시를 위해 타임라인 위·아래에 새 행, 점, 레이블, 패딩, 높이를 추가하지 않는다.
- 레이어 종류·개수별 색 구분은 하지 않는다. 토글 변경과 프레임 메타 변경에 즉시 다시 계산한다.
- 재생 헤드와 기존 시간 눈금/라벨은 현재 레이아웃과 동작을 유지한다.

## 소유권과 변경 경계

- `weather-overlays/lib/`가 프레임 선택, 전환 어댑터, 범례 파생, 자료 가능 여부를 소유한다.
- `TimelineRail`과 순수 timeline model은 표시용 `hasData` 입력을 받아 기존 눈금 내부에 렌더한다.
- `MapView`는 현재 모델을 조합하고 style revision마다 각 소유 어댑터를 재동기화할 뿐 새 레이어 상태를 직접 소유하지 않는다.
- 백엔드는 원시 `radar_echo` 스케줄만 중단한다. HSR/HCI/WISSDOM/QPF/위성 수집은 유지한다.

## 검증

- 순수 테스트: 프레임 가능 시각 합집합, 레이어 토글 반영, 미래 QPF 포함, 취소/늦은 완료 무시, preload 실패 시 직전 프레임 유지.
- 어댑터 테스트: 두 버퍼의 불투명도 전환, 전환 완료 정리, 스타일 재설치 뒤 현재 프레임 복구.
- 정책 테스트: BIN 레이더 숨김/스케줄 중단, HSR 이름 변경과 WISSDOM 자동 연동, 경계선 가시성·위성 노랑 규칙, 가로 HSR/HCI 범례 조건.
- 브라우저 계약: 레이더/강수형태/위성 토글, 타임라인 빠른 이동, 관측→예측 전환, 두 번의 베이스맵 변경, 레이아웃 높이 변화 없음.
- 전체 검증: `npm test`, `npm run build`, 관련 Playwright 계약, `graphify update .`.

## 비범위

- RainViewer 해외 레이더의 이중 타일 소스 전환
- 기존 저장 BIN 프레임 삭제
- KMA 원본 세로 범례 이미지 표시
- 새로운 강수 분석 또는 KIM 일기도 기능
