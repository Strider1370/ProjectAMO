# Spec: 레이더 원자료 기반 재산출 Echo Top

**Status:** Draft
**Created:** 2026-07-24

## Problem / Goal

조종사가 지도에서 강한 대류 셀의 위치, 반사도 강도, 대략적인 수직 발달을 함께 판독할 수 있도록 한다. 기상청이 API로 공식 ETOP 합성 산출물을 제공하지 않는 상황에서, 사이트별 QCD UF 원자료의 고도각 sweep을 이용해 Echo Top을 재산출할 수 있는지 검증하고, 충분히 검증된 경우에만 독립 레이더 레이어로 제공한다.

이 기능은 현재 구현하지 않는다. 향후 구현 판단과 계획 수립을 위한 보류 스펙이다.

## Confirmed Source Facts

- KMA API Hub의 UF 파일 다운로드는 사이트·시각·QCD당 하나의 UF 파일을 반환한다.
- 2026-07-24에 KWK QCD 2010-08-02 09:20 KST 표본을 확인했다. 압축 파일 하나를 해제한 결과 18,897,840 bytes UF가 나왔고, UF 정보에는 volume 1과 volume 3 각각에 sweep 0부터 12까지, 총 13개 고도각이 기록돼 있었다.
- 같은 표본의 고도각은 0.0도부터 15.7812도까지였다. 따라서 sweep별 다운로드가 아니라 사이트당 UF 파일 하나를 내려 받아 내부 sweep을 해석할 수 있다.
- 공식 UF자료-sweep API는 volume과 sweep을 지정해 하나의 sweep을 조회하는 별도 API다. 재산출 처리의 정상 수집 경로로 사용하지 않는다.
- 현재 레이더 시간축은 5분 주기다. 사이트 12~13개를 쓴다면 UF 다운로드는 하루 3,456~3,744회, 18개 전체 사이트라면 5,184회다. 이 수치는 다운로드 호출만 포함하며 목록·정보 API는 정상 수집 때 매번 호출하지 않는다.

## Requirements

- FR-001: 시스템은 사이트별 QCD UF 파일에서 보정 반사도 변수와 모든 사용 가능한 고도각 sweep을 읽어야 한다. [NEEDS CLARIFICATION: 사용할 volume과 반사도 변수 CZ 또는 DZ의 최종 선택]
- FR-002: 시스템은 레이더 위치·해발고도·거리·고도각을 사용해 빔 중심 고도를 계산하고, 명시된 반사도 임계값 이상 에코의 최고 고도를 산출해야 한다. [NEEDS CLARIFICATION: 반사도 임계값과 보간 규칙]
- FR-003: 전국 레이어는 동일한 관측시각에 유효한 사이트 산출물만 합성해야 하며, 사이트별 실제 관측시각을 검사해야 한다. 직전 시각 UF를 새 시각 자료처럼 표시해서는 안 된다.
- FR-004: 지도는 이 결과를 KMA 공식 ETOP으로 표기해서는 안 된다. 사용자 표기는 반사도 기준과 함께 재산출 Echo Top임을 명확히 밝혀야 한다.
- FR-005: 레이더 합성 최대반사도, 최대반사도 고도, 위성 운정고도, 대류운 발생탐지는 서로 다른 관측·산출물로 독립 표기해야 한다.
- FR-006: UF 다운로드 또는 한 사이트 처리 실패는 다른 정상 사이트의 최신 정상 산출물을 무효화하지 않아야 한다. 결측·지연 사이트는 표시와 데이터 계약에서 식별 가능해야 한다.
- FR-007: 원시 UF를 브라우저로 전송해서는 안 된다. 다운로드·압축 해제·파싱·Echo Top 계산·전국 합성은 백엔드가 소유한다.

## User-visible State and Failure Matrix

| Situation | Required user-visible behaviour |
|---|---|
| Initial/default state | Echo Top 레이어는 기본 OFF다. |
| Loading | 새 관측시각 계산 중에는 마지막 정상 프레임을 유지하고, 새 시각으로 오인시키지 않는다. |
| Data available | 지도와 기존 레이더 시간축에 기준 반사도와 관측시각을 함께 표시한다. |
| No matching data | 해당 시간 레이어를 숨기고 자료 없음으로 처리한다. |
| Partial data | 정상 사이트만 합성하되, 부분 커버리지임을 식별 가능하게 한다. |
| Request failure | 마지막 정상 프레임을 보존하고 실패 자료를 새 프레임으로 발행하지 않는다. |
| Stale or late response | 실제 관측시각이 선택 시각과 맞지 않으면 해당 프레임을 표시하지 않는다. |
| User changes time/filter/selection | 기존 레이더 시간축의 실제 선택 시각에 정확히 일치하는 Echo Top 프레임만 표시한다. |
| Feature disabled and re-enabled | OFF에서는 지도 source와 layer가 보이지 않으며, ON에서는 현재 선택 시각의 정상 프레임만 복원한다. |
| Recovery after failure | 다음 정상 UF 수집·발행 시 새 프레임으로 갱신한다. |

## Non-Goals (out of scope)

- 현재 단계에서 Echo Top 구현, 수집 스케줄 등록, API·UI 변경
- 2차원 CMX, CMX EBH, 또는 위성 운정고도만으로 Echo Top을 재구성
- 재산출 결과를 KMA 공식 ETOP, 항공 위험등급, 자동 회피 권고, Go/No-go 판단으로 표기
- sweep별 UF API를 전국 운영 수집 방식으로 사용

## Success Criteria

- SC-001: 사이트 UF 파일 하나에 포함된 모든 필요 sweep을 파싱해, 명시된 반사도 기준의 사이트별 Echo Top 격자를 재현 가능하게 산출한다.
- SC-002: 지도는 실제 선택된 5분 레이더 시각과 정확히 일치하는 정상 Echo Top 프레임만 표시한다.
- SC-003: 사용자에게 재산출 기준과 KMA 공식 ETOP이 아니라는 사실이 항상 명확히 전달된다.
- SC-004: 사이트별 다운로드 1회/시각이라는 수집 계약을 지키며, 실패·결측 사이트가 전체 정상 프레임을 폐기하지 않는다.

## Implementation Freedoms

- 서버 내부의 UF 파서 라이브러리와 저장 표현은, 전체 UF를 브라우저로 보내지 않고 위 요구사항을 만족하는 범위에서 구현 계획이 선택한다.
- 전국 합성의 공간 인덱스와 이미지·격자 출력 형식은 기존 레이더 레이어 계약과 호환되는 범위에서 구현 계획이 선택한다.

## Alternatives Considered

| Option | Trade-off | Why not chosen |
|---|---|---|
| 공식 ETOP API 제공 여부를 기다림 | 가장 권위 있는 산출물 | 제공 여부가 확인되지 않았고, 현재 API Hub 공개 cmp 목록에 ETOP이 없다. |
| 2차원 최대반사도와 EBH만 사용 | 구현과 호출이 단순 | Echo Top을 재구성할 수 없으며 수직 에코 범위를 제공하지 못한다. |
| sweep별 UF자료 API 호출 | 개별 sweep 해석이 단순 | 사이트당 다수 호출이 필요하다. UF 파일 하나에 전체 sweep이 포함됨을 표본으로 확인했다. |

## Open Questions

- 재산출 기준 반사도는 18, 30, 40 dBZ 중 무엇으로 할지, 또는 다중 기준을 제공할지 결정이 필요하다.
- 보정 반사도 volume과 변수 CZ 또는 DZ의 선택을 실제 최신 QCD UF 표본으로 확정해야 한다.
- 전국 합성 시 중첩 사이트 선택, 지형 차폐, 이상전파, 빔 과대확산, 시간 허용오차의 운영 기준이 필요하다.
- 적용 사이트 수는 운영 가능한 최신 사이트·자료 가용성을 기준으로 확정해야 한다.
- 원시·중간 산출물 보존 기간, 계산 자원 한계, 5분 내 완료 목표를 측정해야 한다.
