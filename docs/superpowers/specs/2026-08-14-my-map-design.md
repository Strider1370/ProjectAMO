# 내 지도 (이용자 KML/KMZ 표출) — 설계 스펙

**작성일:** 2026-08-14
**근거 조사:** [KML 표출 스파이크 실측 기록](../status/2026-08-12-kml-viewer-spike-findings.md), [스파이크 설계](2026-08-12-kml-viewer-spike-design.md)
**이 스펙의 범위:** 아래 "판 나누기"의 **1판만**.

## 무엇을 만드나

조종사가 구글어스에서 직접 만든 지도 파일(`.kml` / `.kmz`)을 우리 지도 위에 겹쳐 보는 기능. 사이드바에 **내 지도** 항목을 더하고, 그 패널에서 파일을 올리고 폴더 단위로 켜고 끈다.

## 왜 만드나

조종사들은 이미 구글어스에 훈련공역·절차·즐겨찾는 지점을 직접 그려 쓰고 있다. 그 자료를 우리 지도로 가져오면, **본인이 늘 보던 지도 위에 우리 기상과 지형 위험이 겹친다.** 스파이크에서 확인한 조합 중 가장 값어치 있는 것이 이것이었다.

## 판 나누기

한 번에 다 만들지 않는다. 각 판은 그 자체로 쓸 수 있고, 실제로 돌려본 뒤 다음으로 넘어간다.

| 판 | 무엇 | 상태 |
| --- | --- | --- |
| **1판** | 파일을 올리고 폴더를 켜고 끄고 보관한다 | **이 스펙** |
| 2판 | 지점 아이콘, 설명 풍선 | 다음 |
| 3판 | 3D (공역 기둥·뜬 경로·고도 과장·카메라 거리 규칙) | 그다음 |

1판이 없으면 2·3판은 얹을 자리가 없다. 3판은 가장 독립적이다 — 기둥·과장·카메라 규칙은 KML 없이 지형 근접에도 쓸 수 있어 사실상 별개 기능에 가깝다.

## 요구사항

1. 사이드바에 **내 지도** 항목을 더한다. 누르면 지도 위에 패널이 열린다.
2. 패널 맨 위에 **무엇에 쓰는 기능인지** 설명한다.
3. `.kml`과 `.kmz`를 올릴 수 있다. **파일 여러 개를 보관하고 동시에 여러 개를 켤 수 있다.**
4. 파일 안의 폴더 구조를 그대로 보여주고, 폴더 단위로 켜고 끈다. 상위를 끄면 하위도 꺼진다.
5. 폴더 목록은 **접을 수 있고 이름으로 찾을 수 있다.** 찾기 상자는 목록 위에 고정한다.
6. 폴더마다 **여기로** — 그 폴더 도형 전체가 화면에 들어오게 이동한다.
7. 올린 파일은 브라우저에 보관한다. 다시 열면 **목록은 남고 체크는 꺼진 상태**로 시작한다. 목록에서 파일을 지우면 보관에서도 사라진다.
8. 스타일은 파일이 정한 값을 쓴다. 값이 없을 때만 기본값을 쓴다.
9. **비행 전 브리핑의 경로 불러오기는 지도 파일을 거부**하고 내 지도로 안내한다.
10. 기존 화면(`/`, `/monitoring`, `/test`)이 깨지지 않는다.

## 설계

### 코드를 어디에 두나

`MapView.jsx`는 이미 2,200줄이다. 여기에 더 넣으면 2,600줄이 되고 3판까지 얹으면 3,000줄을 넘는다. **필요한 것 전부를 새 폴더에 담고 `MapView.jsx`는 몇 줄만 건드린다.**

| 파일 | 하는 일 |
| --- | --- |
| `features/my-map/lib/kmzUnzip.js` | 압축 바이트 → 지도 내용 문자열. 스파이크에서 이동(시험 5개 포함) |
| `features/my-map/lib/kmlFolderTree.js` | 폴더 트리 → 평평한 목록, 상위/하위 표시 판정. 스파이크에서 이동(시험 7개) |
| `features/my-map/lib/kmlPaint.js` | 파일 속성을 읽는 색칠 표현식. 스파이크에서 이동(시험 10개) |
| `features/my-map/lib/folderView.js` | **신규** 접기·찾기 걸러내기 (순수) |
| `features/my-map/lib/mapFileGuard.js` | **신규** "이건 경로가 아니라 지도다" 판정 (순수) |
| `features/my-map/lib/myMapStore.js` | **신규** 파일 보관·목록 (IndexedDB + localStorage) |
| `features/my-map/useMyMap.js` | **신규** 파일 상태와 지도 배선을 묶는 훅 |
| `features/my-map/MyMapPanel.jsx` + `.css` | **신규** 패널 화면 |
| `app/layout/Sidebar.jsx` | 수정 — 항목 한 줄, `PANEL_MAP` 한 줄 |
| `features/map/MapView.jsx` | 수정 — 훅 호출 1줄, 패널 표시 4줄 |
| `features/route-briefing/lib/routeImport.js` | 수정 — 지도 파일 거부 |

순수 모듈을 분리하는 이유: 압축 해제·트리 변환·색 대응·걸러내기는 **눈으로 봐서는 맞는지 알 수 없다.** 순수 함수로 빼면 단위 시험으로 굳히고, 화면에서는 배선만 확인하면 된다.

### 지도 레이어 구조

**파일을 몇 개 켜든 지도 레이어는 항상 4개**(면 → 선 → 점 → 이름표)로 고정한다. 도형마다 `__file`(어느 파일)과 `__folder`(어느 폴더)를 심어두고 필터로 걸러 켜고 끈다.

파일마다 레이어를 만들면 파일 3개에 레이어 12개, 폴더까지 나누면 수백 개가 된다. 그러면 측정값이 파일의 성질이 아니라 배선 방식을 재게 된다. 스파이크에서 이 방식으로 좌표 22만 개를 2.9초에 그려낸 것을 확인했다.

그리기 순서는 전역으로 면 → 선 → 점 → 이름표를 지킨다. 그래야 점이 면에 가리지 않는다. 이름표는 점에만 붙인다 — 도형 묶음을 하위 도형마다 쪼개면서 속성이 복제되므로, 필터가 없으면 지점 하나가 이름표 수백 개가 된다.

### 화면

```
내 지도
──────────────────────────────
구글어스에서 직접 만든 지도를 불러와
우리 지도 위에 겹쳐 봅니다.
훈련공역, 절차, 즐겨찾는 지점 같은
직접 그린 요소를 그대로 볼 수 있습니다.
※ 비행경로를 불러오려면 '비행 전 브리핑'을 쓰세요.

[ 파일 올리기 ]   .kml .kmz

내 파일
 ☑ 맥케이 비행지도 ver.230729   1.8MB
 ☑ 개인 랜드마크                12KB
 ☐ 훈련구역 2026               0.3MB

─────── 폴더 ───────
[ 찾기.................. ]
▾ 맥케이 비행지도
   ☑ RKTA TAEAN        (23)  [여기로]
   ☑ CROSS COUNTRY    (450)  [여기로]
   ▸ ☑ RESTRICTED/MOA (122)  [여기로]
```

- **파일 체크** — 켜면 그 파일 도형이 뜬다. 동시에 여러 개 가능. 끄면 지도에서만 사라지고 보관은 유지된다.
- **처음 켰을 때** — 그 파일의 폴더는 **전부 켜진 상태**로 시작하고, 화면을 그 파일 전체가 들어오게 이동한다. 올렸는데 아무것도 안 보이면 실패한 줄 안다. 전국이 도형으로 뒤덮여 지저분하면 조종사가 폴더를 꺼서 줄인다.
- **폴더 체크** — 파일 안에서 골라 켠다. 상위를 끄면 하위도 꺼지고, 목록에서도 꺼진 것으로 보인다.
- **접기** — 처음엔 최상위만 펼친다.
- **찾기** — **폴더 이름만** 찾는다(도형 이름은 찾지 않는다). 맞는 폴더만 남고, 하위가 맞으면 상위는 자동으로 펼친다. 찾기는 켜고 끈 상태를 바꾸지 않는다 — 보이는 것만 줄인다. **찾기 상자는 목록 위에 고정한다** — 스크롤해도 사라지지 않아야 한다.
- **여기로** — 그 폴더 도형 전체가 화면에 들어오게 이동한다. **꺼져 있던 폴더면 켜면서 이동한다** — 옮겨갔는데 아무것도 없으면 뜻이 없다. 도형이 하나도 없는 폴더는 이 버튼을 두지 않는다.
- **파일 지우기** — 목록에서 지우면 보관에서도 사라진다.

패널이 지도 위에 뜨는 서랍이라 높이가 제한된다. 폴더 목록은 그 안에서 스크롤한다.

#### 실제 파일에서 목록이 어떻게 되는가

맥케이 파일을 올리면 **접힌 상태에서 101줄**이 뜬다(전체 폴더 176개 중). 이 숫자를 알고 설계해야 한다.

| 사실 | 값 |
| --- | --- |
| 최상위 폴더 | 101개 |
| 그중 **하위 폴더가 있는 것** | **4개**뿐 (`RKTA TAEAN`, `RKPD JEONGSEOK LOCAL`, `지역정보 모음`, `PROHIBITED/DANGER AREA`) |
| 접기가 감추는 줄 | 75줄 — 그중 절반이 `RKTA TAEAN` 하나에서 나온다 |
| 도형이 1개뿐인 폴더 | 44개 (`SEL`, `CJU`, `KAE` 같은 공항 부호 28개 + TMA 15개) |
| 가장 큰 폴더 | `RKTA TAEAN` 1,134개 (그 안 `CROSS COUNTRY`가 985개) |

**접기만으로는 101줄 문제가 풀리지 않는다.** 97개 폴더는 애초에 접을 하위가 없다. 그래서 **찾기가 곁다리가 아니라 주된 도구**다 — 조종사가 "김포 근처"를 볼 때 101줄을 훑는 대신 이름을 친다. 이 판단이 찾기 상자를 목록 위에 고정하는 이유다.

### 브리핑과의 구별

`비행 전 브리핑`의 경로 불러오기는 지금 `.geojson, .json, .gpx, .kml, .fpl`을 받는다. **선 하나를 비행경로로 삼는** 기능이다. 여기에 지도 파일을 올리면 도형 수천 개를 경로로 해석하려다 이상해진다.

**거부 기준** (`mapFileGuard.js`, 순수 함수):
- 폴더가 있다, 또는
- 선이 아닌 도형(면·점)이 섞여 있다, 또는
- 선이 여러 개다

맥케이 파일은 셋 다 해당한다. 거부할 때 이렇게 알린다:

> 이 파일은 비행경로가 아니라 지도로 보입니다 (폴더 175개, 도형 2,135개).
> 왼쪽 **내 지도**에서 열어보세요.

선 하나짜리 `.kml`은 지금처럼 그대로 통과한다. **기존 동작을 좁히는 것이 아니라, 지금 이상하게 동작하는 경우만 막는다.**

### 보관

**올린 파일의 원본 바이트를 그대로 보관한다.** 변환 결과가 아니다.

크기 때문이다. 원본 1.8MB, 풀면 15.8MB, 지도용으로 변환하면 더 커진다. 원본만 두고 켤 때마다 다시 푸는 편이 낫다 — 그 비용이 0.8초뿐이다.

| 무엇 | 어디에 | 왜 |
| --- | --- | --- |
| 파일 원본 | IndexedDB | 큰 파일을 담을 수 있는 유일한 자리 |
| 파일 목록 (이름·크기·올린 날짜·id) | localStorage | 패널 열 때 목록만 바로 읽으면 됨 |

이 구조는 이 저장소에 이미 있다 — `features/monitoring/lib/monitoringSlideshow.js`가 이용자 이미지를 같은 방식으로 보관한다. 새로 발명하지 않고 그 패턴을 따른다.

**다시 열었을 때 자동으로 그리지 않는다.** 목록은 남고 체크는 모두 꺼진 상태로 시작한다. 파일 하나가 3초·200MB를 쓰므로, 기상만 보려고 연 사람이 매번 기다리게 하지 않는다.

보관 공간이 꽉 차면 "자리가 부족합니다. 안 쓰는 파일을 지워주세요"라고 알리되, **이번에 연 파일은 그대로 볼 수 있게 한다.** 보관 실패가 표시 실패가 되면 안 된다.

### 오류 처리

단계마다 어디서 왜 실패했는지 남긴다. 단계는 다섯이다: 파일 읽기 → 압축 해제 → 지도 내용 해석 → 도형 변환 → 지도에 올리기.

```
압축 해제 단계에서 실패: 압축 파일을 열 수 없습니다.
                        KMZ 또는 KML 파일인지 확인하세요.
```

**반드시 검사할 것 하나:** 깨진 파일을 해석해도 예외가 나지 않는다. 조용히 오류 표시만 심어두므로, 검사하지 않으면 "폴더 0개"만 뜨고 실패인 줄 모른다. 해석 결과에 오류 표시가 섞였는지 직접 확인한다.

파일 크기 제한은 두지 않는다. 대신 해석 중에는 지금 무슨 단계인지 글로 보여준다 — 큰 파일은 해석 중 화면이 잠깐 굳는다(맥케이 파일 기준 0.7초).

### 검증

**계산 부분 — `node --test`**

- 스파이크에서 옮겨오는 22개(압축 해제 5, 폴더 트리 7, 색칠 10)를 그대로 유지한다
- `folderView.js` — 접기 상태, 찾기 걸러내기, 하위가 맞으면 상위가 펼쳐지는지
- `mapFileGuard.js` — 선 하나는 통과, 폴더/여러 선/섞인 도형은 거부
- `myMapStore.js` — 목록 저장·읽기·지우기 (보관소 없는 환경에서 조용히 실패하는지 포함)

**화면 동작 — Playwright 계약**

[계약 등록부](../../policies/verification/contracts.md)에 새 항목을 등록한다.

1. 파일을 올리면 도형이 지도에 뜨고, 폴더 목록이 뜨고, 화면이 그 파일 전체에 맞춰진다
2. 폴더를 끄면 그 도형이 사라진다. 상위를 끄면 하위도 사라진다
3. 찾기에 이름을 치면 맞는 폴더만 남고, 켜고 끈 상태는 안 바뀐다
4. 다시 열면 파일 목록이 남아 있다 (체크는 꺼진 채로)
5. 브리핑에 지도 파일을 올리면 거부하고 내 지도로 안내한다
6. 기존 화면 `/`, `/monitoring`, `/test`가 그대로 동작한다

6번을 넣는 이유: 사이드바와 `MapView.jsx`를 건드린다. 스파이크에서 라우트 한 줄을 더했을 때도 기존 경로 셋을 확인했다.

### 아예 하지 않는 것

| 무엇 | 왜 |
| --- | --- |
| **KMZ 안에 든 아이콘** | 맥케이 KMZ 안에는 `doc.kml` 하나뿐이다. `files/dme1.bmp`를 네 번 가리키지만 그 그림이 압축에 없다(깨진 참조). **시험할 표본이 없어 만들어도 맞는지 확인할 수 없다.** 실제로 그런 파일을 만나면 그때 붙인다 |
| **저장된 시점(LookAt) 읽기** | 부산물이다. 지점을 만들 때의 카메라가 자동 기록될 뿐이라, 저장된 화면이 그 지점을 정중앙에 두는 경우가 **4.5%**뿐이다. 45%는 1km 넘게, 14%는 10km 넘게 어긋난다. 쓰면 엉뚱한 빈 땅으로 데려간다 |
| **강조 스타일(StyleMap)** | 543개 중 220개는 평상시와 완전히 같고, 나머지도 **아이콘 크기 1.2→1.4**가 전부다. 구글어스 기본값이지 작성자가 표시한 정보가 아니다 |
| **지점 하나씩 데려가기** | 목록이 2,135줄이 된다. 폴더 단위 "여기로"로 대신하고, 지점을 이름으로 찾는 것은 나중에 찾기 상자로 푼다 |
| **고도 표현(평면에 눌러 그림)** | 3판에서 다룬다. 이 파일의 비행 경로에는 애초에 고도가 실려 있지 않다 |
