# 터미널 사이니지 3안 — 시간별 + 주간 병렬 화면

- 작성일: 2026-08-04
- 상태: 승인 대기
- 대상: `/terminal` 승객 사이니지
- 짝 문서: [2안 — 날씨 중심 화면](2026-08-04-terminal-weather-first-design.md)

## 왜 만드는가

3안은 **2안의 변형**이다. 위쪽 절반(도시명 · 현재날씨 · 기온차 · 항공편 목록)은 2안과 같고, 아래쪽 예보 영역만 다르다.

2안은 아래를 예보 띠 하나가 통째로 쓴다. 3안은 아래를 **좌우로 쪼개** 왼쪽에 하루치 시간별, 오른쪽에 주간을 세로로 놓는다.

두 가지를 얻는다.

- **배치가 조여진다.** 시간별을 가로 전체로 늘이면 칸 사이가 휑해진다. 오른쪽을 주간이 차지하면 왼쪽이 적당한 폭으로 좁혀지고 화면에 빈 곳이 없어진다.
- **"오늘 하루"와 "이번 주"가 나뉘어 읽힌다.** 성격이 다른 두 정보가 좌우로 갈라져 승객이 필요한 쪽만 보면 된다.

기존 3안(레일 화면)은 **버린다.**

## 범위

- 이번 작업은 3안 화면과 그에 필요한 주간예보 데이터만 만든다.
- **기존 레일 화면(`RailScreen` · `RailRow` · `RailStats` · `ForecastTimeline`과 그 CSS·테스트)을 지운다.**
- 2안과 1안은 건드리지 않는다.
- 전환 스위치는 `1안 / 2안 / 3안` 세 개를 유지한다.

## 2안과 같은 것

아래 항목은 **2안 사양서를 그대로 따른다.** 여기서 다시 정의하지 않는다.

- 머리띠 (도시명 + 도시 순환 표시)
- 현재날씨 블록과 출발지 대비 기온차 (관측 기준, 2도 미만 숨김, 자리 유지)
- 항공편 목록 (5줄 고정, `편명 · 시각 · 탑승구 · 상태배지`, 공동운항은 한 줄에 편명만 쌓기)
- 도시 선정·순서·순환 규칙 (시간창, 시간순 정렬, 편 많으면 목록만 넘김)
- 프레임당 30초, 도시 순서는 한 바퀴 유지하되 편 상태는 즉시 갱신
- 전환 애니메이션과 자리 고정 규칙
- 편이 없을 때 `운항 종료` 화면

## 화면 구성

```
┌─────────────────────────────────────────────┐
│  제주 CJU            제주 ─ 오사카 ─ 울산   │  12%
├──────────────────────────┬──────────────────┤
│   현재날씨               │   항공편         │  40%
│   (기온차 포함)          │                  │
├───────────────────────┬──┴──────────────────┤
│  시간별               │  주간               │  48%
│  15시 18시 21시 0시 … │  수 8/5  ☔25° ☁29° │
│  아이콘·꺾은선·기온    │  목 8/6  ☁26° ☀30° │
│  강수확률             │  …                  │
└───────────────────────┴─────────────────────┘
         약 62%                 약 38%
```

좌우 비율은 시간별 8칸과 주간 5줄이 각각 읽히는 크기가 나오도록 구현 단계에서 확정한다. 초안은 62 : 38.

### 좌측 — 시간별 (앞으로 24시간)

2안의 예보 띠와 재료는 같지만 **묶는 방식이 다르다.**

- 2안: `오늘 / 내일 / 모레` 세 구간으로 나누고 내일·모레는 대표값
- 3안: **구간을 나누지 않고 3시간 간격 8칸을 쭉 잇는다.** `15시 18시 21시 0시 3시 6시 9시 12시` — 자정을 그냥 넘어간다

각 칸에 위에서부터 네 층. 2안과 동일하다.

1. 날씨 아이콘
2. 기온 꺾은선
3. 기온 숫자
4. 강수확률 `%` (해외 목적지는 강수량 `mm`)

강수 가능성이 높은 칸(확률 60% 이상 / 강수량 있음)만 주황 알약으로 칠하는 것도 2안과 같다.

**날짜 구분선을 두지 않는 이유**는 기온 꺾은선이 하루의 오르내림을 온전히 보여주기 위해서다. 낮에 높고 새벽에 낮은 곡선(34 → 25 → 31)이 끊기지 않고 그려진다. 2안은 대표값만 찍어 이 곡선이 나오지 않는다.

칸 수가 항상 8개로 고정이라 도시가 바뀌어도 폭이 변하지 않는다. 전환 중 겹칠 위험이 없다.

### 우측 — 주간 (5일)

내일부터 5일을 **세로로** 쌓는다. 오늘은 왼쪽 시간별에 이미 들어 있으므로 넣지 않는다.

한 줄 구성:

```
        오전        오후
 수 8/5   ☔ 25°     ☁ 29°
 목 8/6   ☁ 26°     ☀ 30°
 금 8/7   ☀ 27°     ☀ 33°
 토 8/8   ☀ 28°     ☀ 34°
 일 8/9   ☁ 27°     ☁ 31°
```

- 왼쪽부터 `요일 · 날짜 · [오전 아이콘 + 최저기온] · [오후 아이콘 + 최고기온]`
- **아이콘과 기온을 짝지어 붙인다.** 떨어뜨려 놓으면 어느 아이콘이 어느 기온인지 승객이 눈으로 이어야 한다. 붙이면 그 일이 없어진다
- 최저기온은 파랑, 최고기온은 빨강
- `오전 / 오후` 제목은 첫 줄 위에만 둔다
- 줄 수는 **항상 5줄 고정**. 자료가 모자라면 빈 줄을 투명하게 남긴다 (자리 고정 규칙)

최저를 오전 쪽에, 최고를 오후 쪽에 붙이는 것은 실제 하루 기온 흐름과 맞는다. 최저는 이른 시간, 최고는 오후에 나온다.

## 데이터

### 국내 — 이미 있다

`ground-forecast-processor.js`가 주간예보를 **이미 받아 정리하고 있다.**

- 하루마다 `date · dayOfWeek · am · pm · tempMin · tempMax`
- `am` / `pm` 각각에 `weather · icon · rainProb`
- 단기예보로 앞쪽 며칠, 중기예보로 뒤쪽(4~6일) 며칠을 채워 **7일치**가 나온다
- 자료가 빠진 날은 직전 회차 값으로 메우는 처리도 이미 있다

**화면에 꺼내 쓰기만 하면 된다. 백엔드 변경 없음.**

### 해외 — 새로 만든다

MET Norway는 하루 단위 최저·최고를 주지 않는다. 시간별만 길게(약 9일) 준다.

`overseas-forecast-processor.js`에 **`daily` 배열을 새로 만든다.** 국내 `days`와 같은 모양으로 맞춰, 화면 코드가 출처를 구분할 필요가 없게 한다.

만드는 규칙:

- **시간 묶기** — `오전 = 06~12시`, `오후 = 12~18시`
- **대표 기상은 "가장 나쁜 것"** 으로 정한다
  1. 그 구간에 비나 눈이 **한 칸이라도 있으면 그것으로** (여러 종류면 강한 쪽: 눈·천둥 > 비 > 소나기)
  2. 강수가 전혀 없으면 **구름이 가장 많은 칸으로** (흐림 > 구름많음 > 맑음)
- **최저·최고기온** — 그 날짜 시간별 칸 전체의 최솟값·최댓값
- **7일치**를 저장한다 (화면은 5일을 쓰고 여유를 둔다)

평균이나 최빈값이 아니라 최악을 고르는 이유: 주간예보를 보는 승객은 "그날 우산이 필요한가"를 묻는다. 6시간 중 2시간만 비여도 그날은 비 오는 날이다. 최빈값으로 하면 그 비가 사라져 비 예보를 보고도 우산을 안 챙기는 일이 생긴다. 사이니지에서는 이쪽 실수가 더 비싸다.

시간별 저장 칸 수는 2안이 정한 **72칸(3일)** 그대로 둔다. 주간은 `daily`로 따로 담으므로 시간별을 7일치로 부풀릴 필요가 없다.

### 해외 주간의 시간대 — 주의할 점

지금 해외 시간별 예보는 **한국 시각 기준으로 저장**되어 있다. 도착 시각이 한국 시각이라 그렇게 맞춰둔 것이다.

그런데 주간예보의 `오전 / 오후`는 **그 도시 현지 기준**이어야 맞다. 승객이 보는 것은 "거기 가서 맞을 오전"이다. 오사카는 시차가 없어 상관없지만 베이징은 1시간, 방콕은 2시간 어긋난다.

**`daily`를 만들 때만 현지 시각으로 되돌려 묶는다.**

> **위험**: 백엔드 해외공항 자료에 시차 정보가 없을 수 있다. 구현 첫 단계에서 확인한다. 없으면 목적지별 시차를 자료에 채우고, 그것이 이번 작업 범위를 넘으면 **한국 시각 기준으로 묶되 그 사실을 코드 주석에 남긴다.** 시차가 큰 목적지가 생기면 그때 고친다.

## 코드 구조

3안도 **별도 파일로 뺀다.** 2안과 같은 이유다 — 최종적으로 한 안만 남길 때 파일 하나를 지우고 스위치 버튼 하나를 빼면 끝나야 한다.

### 새 파일

| 파일 | 하는 일 |
|---|---|
| `frontend/src/features/terminal/WeeklyWeatherScreen.jsx` | 3안 화면 전체 |
| `frontend/src/features/terminal/terminalWeeklyForecast.js` | 주간 5줄 만들기 (국내는 그대로 통과, 해외는 `daily`에서 변환) |
| `frontend/src/features/terminal/terminalWeeklyForecast.test.js` | 위 함수 테스트 |

### 고칠 파일

| 파일 | 무엇을 |
|---|---|
| `terminalForecastStrip.js` (2안이 만든 것) | 24시간 8칸을 뽑는 방식을 추가한다. 2안의 3일 방식과 같은 파일에 둔다 — 둘 다 "시간별 칸에서 화면용 칸 고르기"라는 한 가지 일이다 |
| `DestinationWeatherPage.jsx` | 3안 버튼이 `WeeklyWeatherScreen`을 부르게 바꾼다. **레일 화면 코드를 지운다** |
| `terminalLiveData.js` | 주간예보(국내 `days` / 해외 `daily`)를 받아 목적지에 붙인다 |
| `terminal.css` | 3안 구역 추가, **레일 구역 삭제** |
| `overseas-forecast-processor.js` | `daily` 7일치 생성 |

### 지울 것

- `DestinationWeatherPage.jsx`의 `RailScreen` · `RailRow` · `RailStats` · `ForecastTimeline` · `railMotionModes`
- `terminal.css`의 `.exact-rail` · `.rail-*` · `.rail-motion-*` 규칙
- 레일만 검사하는 기존 테스트

이 삭제로 `DestinationWeatherPage.jsx`가 작아진다. 2안·3안이 각자 파일로 빠지고 나면 이 파일은 **화면 고르기와 공통 껍데기만** 남는다.

## 검증

- `terminalWeeklyForecast.js` 단위 테스트
  - 국내 자료가 그대로 5줄로 나오는지
  - 해외 시간별에서 오전·오후 대표를 뽑을 때 **비가 한 칸만 있어도 비로 표시되는지**
  - 자료가 5일치가 안 될 때 빈 줄이 남는지
- `terminalForecastStrip.js`의 24시간 8칸 뽑기 — 자정을 넘어가는 경우
- `overseas-forecast-processor.js`의 `daily` 생성 테스트
- 1안 기존 테스트(`DestinationWeatherPage.board-layout.test.js`)가 그대로 통과
- 레일 삭제 후 남은 참조가 없는지 — `npx knip`, `npx depcruise .`
- **Playwright 1920×1080 실제 화면 촬영** — [browser verification](../../policies/verification/browser-verification.md) 절차
  - 김포 (목적지 여러 곳)
  - 해외 목적지 (주간이 계산값으로 채워지는지)
  - 야간 (시간별이 자정을 넘어가는 경우)
  - 주간 자료가 모자란 목적지 (빈 줄 처리)
  - 전환 도중 화면 (겹침 없는지)

## 결정하지 않은 것

- 좌우 비율 62 : 38 — 실제 화면에서 조정한다
- 주간을 5일로 둘지 6일로 늘릴지 — 세로 여유를 보고 정한다. 자료는 7일치가 있다
