# Spec: 경로비교·고도비교 위험기상 표시 개편

**Status:** Approved
**Created:** 2026-07-21

## Problem / Goal

경로비교(`RouteAlternativesStep.jsx`)와 고도 비교(`AltitudeWeatherComparison.jsx`) 탭은 위험기상 정보를 굵기·색 구분 없는 평문 목록으로 나열한다. 착빙·난류 강도(0~3)가 일반 텍스트와 같은 `kind: 'info'`로 취급되어 안 보이고, 경로비교 카드는 위험기상을 2건까지만 보여주고 나머지를 안내 없이 버리며(`slice(0, 2)`), 비교 델타(`exposure.key`)에 내부 코드가 그대로 노출된다. 두 탭이 같은 위험기상을 서로 다른 정보량(거리만 vs 출처·고도·시간)으로 보여줘 일관성이 없다.

이 작업의 목표는 조종사가 여러 경로·고도 후보를 훑어보고 비교할 수 있도록 측정된 사실(강도, 노출거리, 조우 여부)을 항상 같은 위치·형식으로 보여주는 것이다. **시스템은 판단하지 않는다** — "위험/안전/추천" 같은 결론은 산출하지 않고, 결정에 필요한 재료만 제공한다.

## Requirements

- FR-001: 착빙·난류 강도는 항공 표준 등급(LGT/MOD/SVR, 백엔드 grade 0~3 매핑)을 배지로 표시해야 한다. 배지는 색만이 아니라 영문 약어 텍스트도 함께 포함해 색약·저시력 사용자도 구분 가능해야 한다.
- FR-002: SIGMET/AIRMET 등 강도 코드가 없는 위험기상(`TS`, `MTW`, `GR` 등 14개 현상)은 강도를 표시하지 않는다. 출처(SIGMET/AIRMET)·현상명·교차거리만 표시한다. 강도 데이터가 없는 현상에 강도를 부여해서는 안 된다.
- FR-003: 경로비교 카드의 위험기상 목록은 `slice(0, 2)` 제한을 제거하고, 대신 노출거리 내림차순으로 정렬한 뒤 일정 개수 초과분은 "N건 더 보기"로 펼칠 수 있게 한다. 숨겨진 항목이 있다는 사실은 항상 표시되어야 한다.
- FR-004: 고도 비교 카드는 착빙·바람·난류·위험기상 열이 모든 행에서 동일한 가로 위치에 오도록 격자로 정렬한다. 값이 없는 항목("보고 없음")은 한 줄로 접어 값이 있는 항목이 상대적으로 눈에 띄게 한다.
- FR-005: 위험기상이 고도·시간 모두와 실제로 겹치는지(`encounter: 'on'`)와 경로만 지나고 고도/시간이 어긋나는지(`'nearby'`)를 시각적으로 구분해 표시한다.
- FR-006: 고도 비교 각 행에 해당 고도의 위험기상 노출거리 합계(NM)를 표시한다. 백엔드 `matchHazards()`가 이미 계산하는 `horizontalExposure`를 반환값에 포함시켜야 한다(신규 계산 없음).
- FR-007: 경로비교 각 카드에 위험기상 노출거리 합계와 건수를 표시하고, 기준 경로 대비 변화량을 방향(증가/감소)만으로 표시한다. 변화량에 "좋다/나쁘다"를 뜻하는 색(녹색/빨강)을 쓰지 않는다.
- FR-008: `exposure.key`(예: `sigmet:TS`) 같은 내부 식별자를 화면에 노출하지 않는다. 사람이 읽을 수 있는 현상명으로 매핑해 표시한다.
- FR-009: 배지·아이콘은 설치된 `lucide-react`만 사용한다. 새 아이콘 라이브러리를 추가하지 않는다.
- FR-010: 판단·추천 문구(`위험`/`주의`/`양호`/`가장 안전` 등 시스템이 내리는 결론)를 표시하지 않는다. 측정값과 사실만 표시한다.

## Non-Goals (out of scope)

- SIGMET/AIRMET 등 강도 코드가 없는 현상에 강도 등급을 신규로 산정하는 기상학적 작업은 하지 않는다(데이터 부재).
- 위험기상 판정 로직(`evaluateHorizontalExposure`, `evaluateAltitudeExposure`, `evaluateTimeStatus`)의 계산 방식을 바꾸지 않는다.
- 연직단면도(`VerticalProfileWindow`/`VerticalProfileChart`)의 SIGMET/AIRMET 레이어 표시 방식은 이번 범위에 포함하지 않는다.
- 지도 상단 위험기상 요약 배지(`AdvisoryBadges.jsx`)는 이미 별도로 잘 동작하고 있어 범위에서 제외한다.
- 새 색상 토큰, 새 CSS 변수 체계를 만들지 않는다 — `tokens.css`의 기존 `--level-*` 토큰만 사용한다.
- 응답 스키마, API URL, 사용자 설정의 의미는 바꾸지 않는다(FR-006의 반환값 추가 제외).

## Success Criteria

- SC-001: 고도 비교 카드에서 착빙·난류 강도가 LGT/MOD/SVR 중 하나로 항상 같은 열 위치에 표시되고, 값이 없으면 "보고 없음"으로 접힌다.
- SC-002: 경로비교 카드가 위험기상 3건 이상을 가진 경로에서 전부(또는 "N건 더 보기" 안내와 함께) 표시되며, 안내 없이 사라지는 항목이 없다.
- SC-003: 화면 어디에도 `sigmet:`, `airmet:` 같은 내부 키 문자열이 그대로 노출되지 않는다.
- SC-004: 화면 어디에도 `위험`/`주의`/`양호`/`추천`/`가장 안전` 등 시스템 판단 문구가 없다.
- SC-005: 고도 비교 각 행과 경로비교 각 카드에 노출거리 합계(NM)가 표시되고, 값은 백엔드가 반환하는 `horizontalExposure` 기반으로 계산된다(프런트 재계산이 아님).
- SC-006: 기존 백엔드/프런트 테스트가 전부 통과하고, 응답 스키마의 기존 필드는 값이 그대로 유지된다(FR-006 추가 필드 제외).

## Alternatives Considered

| Option | Trade-off | Why not chosen |
|---|---|---|
| 위험기상 전체에 자체 심각도 스코어링 도입(거리·현상 조합으로 점수 산정) | 강도 데이터가 없는 현상도 일관된 배지를 줄 수 있음 | 시스템이 판단을 만들어내는 것이라 FR-010과 정면 충돌. 사용자가 명시적으로 "조종사가 판단한다"고 지시함 |
| 새 아이콘 세트(basmilius 날씨 아이콘) 재사용 | 이미 프로젝트에 있어 추가 설치 불필요 | 풀컬러 일러스트라 강도 색과 충돌하고 소형 배지에서 뭉개짐 — lucide 단색 아이콘이 이미 15개 파일에서 쓰이는 기존 패턴과 일치 |
