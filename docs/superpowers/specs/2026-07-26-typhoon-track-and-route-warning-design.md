# 태풍 경로 표시 및 경로/공항 노출 판정

- 상태: 승인 대기
- 작성일: 2026-07-26
- 원천: KMA API Hub 태풍정보

## 1. 배경과 목적

지도에 태풍의 예상 경로와 영향권을 표시하고, 비행계획의 경로·공항이 그 영향권과 겹치는지 알린다.

여객기는 태풍을 통과하지 않고 우회·지연·회항한다. 따라서 이 기능의 목적은 정밀한 3차원 충돌 판정이 아니라 **계획 단계의 조기 인지**다. "이 노선, 이 시간대에 태풍이 걸린다"를 빨리 알아채게 하는 것까지가 범위이며, 우회 여부의 판단은 사용자가 한다.

## 2. 확인된 사실 (실호출 검증)

기존 `KMA_AVIATION_AUTH_KEY`로 태풍 API가 열린다. 신규 키·환경변수 불필요.

| 엔드포인트 | 반환 | 쓰는 곳 |
| --- | --- | --- |
| `typ01/url/typ_now.php?tm=&mode=1` | **그 시각 활성 태풍 전부**의 과거 분석 경로 + 최신 예보 | 경로·예보 |
| `typ01/url/typ_lst.php?disp=1` | 그 해 태풍 목록 — 번호, **이름**, 진행여부(`NOW`), 한반도영향(`EFF`) | 이름 |
| `typ01/url/typ_data.php?YY=&typ=&mode=1` | 특정 태풍 하나의 경로 + 예보 | 과거 태풍 픽스처 생성 |

응답은 EUC-KR이다. `backend/src/api-client.js:17`이 이미 디코딩한다.

`typ_now`와 `typ_data`는 같은 21개 컬럼을 반환한다. 차이는 대상 범위뿐이다 — `typ_now`는 시각 기준 활성 태풍 전부, `typ_data`는 지정한 태풍 하나.

### 활성 태풍 판별 — `typ_lst.php`의 `NOW`

`typ_lst.php`는 `disp=1`을 주면 **쉼표로 구분**되어 온다. 고정폭 오프셋에 기대지 않아도 된다.

```
2026,12,1,4,202607231800,210012310000,노을,NOUL,제12호 태풍 노을(NOUL)은 …,=
 YY  SEQ NOW EFF   TM_ST        TM_ED     TYP_NAME TYP_EN  REM
```

- `NOW` : 1(진행중), 2(종료) → **활성 태풍 판별은 `NOW=1`로 한다.**
- `EFF` : 1(상륙), 2(직접영향), 3(간접영향), 4(없음) — 한반도 영향도
- 진행 중인 태풍의 `TM_ED`는 `210012310000` 센티널이다.
- `YY`를 생략하면 올해 목록이 온다.
- **`tm` 인자는 무시된다.** 문서에는 "이 시각 기준 과거 12시간 내 발표된 태풍"이라고 되어 있으나, `tm=202209050000`과 `tm=201808220000` 모두 2026년 목록을 반환했다. 과거 시점 조회에 쓸 수 없다.

### `typ_now.php`에는 `tm`이 반드시 필요하다

`tm`을 주지 않으면 **활동 중인 태풍이 있어도 빈 응답이 온다.** 2026-07-26 실측:

| 호출 | 결과 |
| --- | --- |
| `typ_now.php?disp=0` (tm 없음) | 0줄 |
| `typ_now.php?tm=202607251800&mode=1` | 11줄 — 12호 태풍 노을 |

빈 응답을 "활동 중인 태풍 없음"으로 읽으면 태풍이 와도 영구히 0개를 보고하게 된다. `tm`은 현재 UTC 정시로 넣는다.

### `mode`는 1이다

`typ_now`와 `typ_data` 모두 `mode`를 받는다. `mode=2`는 최신 분석 **1개**와 예보만 반환해 지나온 경로가 없다. 지도에 과거 경로선을 그릴 수 없다.

2026년 12호 실측(두 엔드포인트 동일):

| mode | 분석(과거 경로) | 예보 |
| --- | --- | --- |
| 0 | 8 | 0 |
| **1** | **8** | **3** |
| 2 | 1 | 3 |
| 3 | 8 | 36 (과거 발표분 전부) |

`seq`를 생략하면 최신 발표가 온다. `typ_now`의 `mode=3`은 빈 응답을 반환하므로 쓰지 않는다.

### 예보 간격은 태풍마다 다르다

| 태풍 | `TMD` |
| --- | --- |
| 2022년 11호 힌남노 | 0 6 12 18 24 30 36 42 |
| 2026년 12호 노을 | 0 12 24 36 |

6시간으로 고정할 수 없다. 유효구간은 **인접 예보 시점의 실제 간격에서 계산한다**(§10).

### 현재 활동 중인 태풍이 있다

2026-07-26 기준 **12호 태풍 노을(NOUL)** 이 진행 중이다(홍콩 동쪽 약 200 km, 965 hPa, 37 m/s). 과거 픽스처뿐 아니라 실제 자료로도 검증할 수 있다.

### 발표 주기 (실측)

| 태풍 | 발표 횟수 | 간격 |
| --- | --- | --- |
| 2022년 11호 힌남노 | 39 | 6h ×29, 3h ×9 |
| 2020년 9호 마이삭 | 30 | 6h ×17, 3h ×12 |

멀리 있을 때 6시간, 접근하면 3시간으로 전환 후 유지. 최단 간격은 3시간이다.

**측정하지 못한 것**: 분석시각과 실제 게시시각의 지연. 현재 활동 태풍이 없어 실시간 관찰이 불가능하다. 실제 태풍 발생 시 수집 로그로 측정하여 주기를 재조정한다.

### 비대칭 반경

강풍/폭풍 반경은 원이 아니다. `RAD15`(전방위 반경)와 별도로 `ED15`(축소 방향), `ER15`(그 방향의 반경)가 주어진다. 폭풍은 `RAD25`/`ED25`/`ER25`.

예) 힌남노 `RAD15=430, ED15=SW, ER15=340` → 대체로 430 km, 남서쪽만 340 km.

축소 방향은 통상 진행방향 왼쪽(안전반원)이지만 **항상은 아니다**.

| 태풍 | 축소방향이 진행방향 왼쪽인가 |
| --- | --- |
| 2022년 11호 | 7/7 |
| 2019년 8호 | 7/7 |
| 2018년 19호 | 3/6 — 나머지는 오른쪽 |

표본 3개 태풍의 결과다. 전수 검증은 아니다.

**결론: 진행방향에서 안전반원을 유도하지 않는다.** 기상청이 매 시점 제공하는 `ED`/`ER` 값을 그대로 사용한다.

## 3. 결정사항

| 항목 | 결정 | 근거 |
| --- | --- | --- |
| 판정 기준 반경 | `RAD15` + `RAD` (강풍반경 + 중심 오차반경) | 예보 위치가 빗나가도 강풍을 만날 수 있는 전체 범위. 보수적 |
| 반경 모양 | 비대칭 그대로 | 원 근사는 실제보다 넓게 잡아 과잉 경고. 폴리곤 생성 비용은 동일 |
| 시간 표현 | 경로선·부채꼴은 42시간 통째 고정 표시, 강풍/폭풍 영역은 현재 시점만 | 슬라이더 조작 없이 전체 파악 가능 |
| 고도 판정 | **하지 않음** | 반경은 지상풍 기준이라 순항고도에 적용하면 오류. 우회 결정에 고도 정밀도는 불필요 |
| 공항 | 출발·도착·교체공항도 판정 | 경로가 깨끗해도 도착지가 닫히면 못 감 |
| 항목 단위 | 예보 시점별로 판정, 태풍번호로 묶어 보고 | 시간 정확도와 가독성 동시 확보 |
| 수집 주기 | 30분 고정 (`*/30 * * * *`) | 최단 발표 간격 3시간 대비 충분. 단순함 우선 |

### 판정 기준의 의미

`RAD`는 위험 범위가 아니라 **중심 위치의 불확실성**이다(70% 확률). `RAD15`/`RAD25`가 실제 바람 영향권이다. 판정에는 두 성격을 합쳐 "예보가 빗나가는 경우까지 포함한 강풍 가능 범위"를 쓴다.

### 등급 없음

브리핑은 노출 사실과 자료 상태만 보고한다. 안전점수·경로선택·고도선택·권고를 생성하지 않는다. [route briefing source contract](../../policies/engineering/route-briefing-source-contract.md)의 안전 경계를 따른다.

## 6. 수집 흐름

```
30분마다
  ① typ_now.php?tm=<현재 UTC 정시>&mode=1&disp=0
       → 활성 태풍 전부의 과거 분석 경로 + 최신 예보 (한 번에)
       → 비었으면 활성 태풍 없음 상태 저장, 종료
       → TYP(태풍번호)로 그룹핑
  ② typ_lst.php?disp=1
       → 올해 목록에서 이름(TYP_NAME/TYP_EN)과 EFF를 태풍번호로 이어 붙인다
  저장 (base_path/typhoon)
```

**호출 수는 활성 태풍이 몇 개든 2회다.** `mode=1`이 태풍별 경로를 한 응답에 담아 준다. 2018-08-22 실측: 19호(분석 25 + 예보 6), 20호(분석 15 + 예보 4)가 한 번에 왔다.

`tm`은 반드시 넣는다. 없으면 태풍이 있어도 빈 응답이 온다(§2).

발표번호 비교로 중복 조회를 거르는 최적화는 두지 않는다. 30분마다 2회 호출이고 응답이 수 KB라 아낄 것이 없다.

### 활성 판별의 기준

**`typ_now`(①)에 행이 있는 태풍번호가 활성이다.** `typ_lst`의 `NOW`는 이름·`EFF`를 붙이기 위한 보조 자료로만 쓴다. 둘이 어긋나면 ①을 따른다 — 실제 경로 자료가 있는 쪽이 화면에 그릴 수 있는 것이다.

`typ_lst`에 없는 태풍번호가 ①에 나오면 이름 없이 번호만으로 표시한다. 이름이 없다고 태풍을 빠뜨리지 않는다.

## 7. 파싱 계약

**컬럼 순서**: `FT YY TYP SEQ TMD TYP_TM FT_TM LAT LON DIR SP PS WS RAD15 RAD25 RAD ED15 ER15 LOC ED25 ER25`

**단순 공백 분리 금지.** `LOC`(위치설명)에 공백이 포함된다 — 예: `서귀포 남남서쪽 약 410 km 부근 해상`. 필드를 세면 밀린다.

공백으로 나눈 뒤 위치로 되짚는다. 공백을 포함하는 필드는 `LOC` 하나뿐이고 그 앞뒤 필드 수가 고정이므로 다음이 성립한다.

```
토큰 = 줄을 공백으로 분리
앞 18개  = FT … ER15
마지막 1개 = "ED25,ER25," 형식      ← /^[A-Z-]+,-?\d+,?$/ 로 검사
가운데 나머지 = LOC (공백으로 다시 이어붙임)
```

마지막 토큰이 위 형식이 아니면 `ED25`/`ER25`가 없는 행으로 보고, 그 토큰까지 `LOC`에 포함한다. 고정폭 오프셋에 의존하지 않으므로 `LOC` 길이가 바뀌어도 깨지지 않는다.

**`-999`는 결측이다.** 숫자가 아니다. 해당 필드가 `-999`이면 그 값에 의존하는 도형을 생성하지 않는다. `ED`가 `-`인 경우도 동일.

**필드 의미**

| 필드 | 의미 |
| --- | --- |
| `FT` | 0=분석, 1=예보 |
| `TMD` | 분석시각으로부터 경과 시간(h). 0, 6, 12 … 42 |
| `TYP_TM` / `FT_TM` | 분석시각 / 예측시각 (UTC) |
| `RAD15` / `RAD25` | 15 m/s / 25 m/s 반경 (km) |
| `RAD` | 70% 확률 중심 오차반경 (km) |
| `ED15` / `ER15` | 강풍 축소 방향(16방위) / 그 방향 반경 (km) |
| `ED25` / `ER25` | 폭풍 축소 방향 / 반경 |

**태풍 이름은 경로 응답(`typ_now`/`typ_data`)에 없다.** 21개 필드에 이름 칸이 없다. 이름은 `typ_lst.php`에서 받아 태풍번호로 잇는다.

### `typ_lst.php` 파싱

`disp=1`을 쓴다. 쉼표로 구분되어 오므로 컬럼이 밀 여지가 없다.

```
2026,12,1,4,202607231800,210012310000,노을,NOUL,제12호 태풍 노을(NOUL)은 …,=
 YY  SEQ NOW EFF   TM_ST        TM_ED     TYP_NAME TYP_EN  REM
```

| 위치 | 필드 | 쓰임 |
| --- | --- | --- |
| 1 | `YY` | 연도 |
| 2 | `SEQ` | **태풍번호** — 경로 응답의 `TYP`와 잇는 열쇠 |
| 3 | `NOW` | 1(진행중), 2(종료) |
| 4 | `EFF` | 1(상륙), 2(직접영향), 3(간접영향), 4(없음) |
| 7 | `TYP_NAME` | 한글 이름 |
| 8 | `TYP_EN` | 영문 이름 |

`REM`(9번째)은 쓰지 않는다. 설명문에 쉼표가 들어갈 수 있으므로 **앞 8개만 취하고 나머지는 버린다.**

`typ_lst`의 `SEQ`는 경로 응답의 `SEQ`(발표번호)와 이름이 같지만 의미가 다르다 — 목록에서는 **태풍번호**다. 혼동하지 않는다.

| 도형 | 반경 | 용도 |
| --- | --- | --- |
| 강풍 영역 | `RAD15`, `ED15` 방향은 `ER15` | 지도 표시 |
| 폭풍 영역 | `RAD25`, `ED25` 방향은 `ER25` | 지도 표시 |
| 판정 영역 | `RAD15 + RAD`, `ED15` 방향은 `ER15 + RAD` | 경로·공항 판정 |

비대칭 구현: 방위각 θ에 대한 반경 함수를 쓴다. `ED` 방위와의 각차를 Δ라 할 때

```
Δ >= 90°  →  r(θ) = RAD
Δ <  90°  →  r(θ) = RAD - (RAD - ER) * cos(Δ)
```

`ED` 방위에서 정확히 `ER`, 90° 이상 벗어나면 `RAD`, 그 사이는 코사인 보간이다. 원 폴리곤 생성이 이미 다점 근사이므로 방위별 반경 함수를 쓰는 데 추가 비용이 없다. 정점 간격은 기존 오버레이 관례를 따른다.

**오차 부채꼴**: 각 예보 시점의 `RAD` 원을 합집합(`@turf/union`)하여 하나의 영역으로 만든다.

## 9. 지도 표시

**항상 표시**

- 분석 구간 경로: 실선 + 지점 마커
- 예보 구간 경로: 점선 + 지점 마커
- 오차 부채꼴

**현재 시점만 표시**

- 강풍 영역(옅게), 폭풍 영역(진하게)
- 라벨: 태풍번호, 중심기압

위험반원/안전반원을 **진행방향으로부터 유도하여 별도 음영으로 칠하지 않는다.** §2에서 확인했듯 그 규칙은 표본에서 항상 성립하지 않았다. 비대칭 폴리곤 자체가 어느 쪽 영향권이 좁은지를 이미 나타내므로, 유도된 반원 음영을 덧그리면 데이터가 뒷받침하지 않는 구분을 추가하게 된다.

복수 태풍은 태풍번호별로 색을 달리한다(§9.1). 경로선 옆에 태풍번호를 글자로 붙인다 — 색만으로 구분하지 않는다.

태풍 타일 하나가 지도 요소와 목록 패널을 함께 제어한다. 타일을 끄면 둘 다 사라진다(정책: 마스터 토글이 모든 표시 요소를 제어할 것).

레이어 설치·런타임 이미지는 스타일 교체 후 재생성한다.

## 9.1 색 배정

색은 **태풍번호로 결정한다**. 목록 순서로 배정하면 태풍 하나가 소멸했을 때 남은 태풍의 색이 바뀐다. 번호 기준이면 갱신·소멸과 무관하게 같은 태풍이 같은 색을 유지한다.

```
색 = 팔레트[태풍번호 mod 팔레트길이]
같은 색이 이미 활성 태풍에 배정되어 있으면 다음 빈 색으로 밀어낸다
```

팔레트는 [design language](../../policies/design/design-language.md)의 색을 쓴다. 목록 패널의 색 표식과 지도의 경로·영역 색은 같은 함수에서 나온다.

**색은 유일한 구분 수단이 아니다.** 지도의 경로 라벨과 패널의 태풍번호가 항상 함께 표시된다. 색각 이상 사용자와 색 충돌 상황 모두를 위한 것이다.

## 9.2 태풍 목록 패널

기상 레이어 패널 오른쪽에 나란히 배치한다. 레이어 드로어는 화면 왼쪽 위에 `--panel-overlay-sm` 고정 폭으로 붙어 있으므로 그 폭만큼 오른쪽으로 민다. `layer-drawer` 셸을 재사용한다(`NotamPanel`의 선례와 동일).

**태풍 타일**은 기존 `layer-tile` 격자에 추가하고, 활성 태풍 수를 `layer-tile-badge`로 표시한다. 패널을 열지 않아도 활성 개수가 보인다.

**목록 항목**

| 요소 | 값 |
| --- | --- |
| 색 표식 | §9.1의 배정 색 |
| 제목 | 태풍번호 + 이름 (예: `12호 태풍 노을`). 이름을 못 받았으면 번호만 |
| 강도 | 중심기압(`PS`) · 최대풍속(`WS`) |
| 위치 | `LOC` 원문 (기상청 한글 위치설명) |
| 시각 | 분석시각(`TYP_TM`) |
| 바로가기 | 지도를 해당 태풍 현재 위치로 이동시키는 버튼 |

**바로가기 버튼**은 지도 카메라만 움직인다. 레이어 가시성이나 선택 상태를 바꾸지 않는다.

**활성 태풍이 없으면** "현재 활동 중인 태풍 없음"을 표시한다. 빈 패널을 두지 않는다. 수집 실패로 자료가 없는 경우는 §11에 따라 "자료 없음"으로 구분해 표시한다 — 태풍이 없는 것과 모르는 것은 다르다.

## 10. 브리핑 판정

### 경로

`evaluateHorizontalExposure`를 재사용한다. 항로 좌우 30 NM 회랑(`HAZARD_CORRIDOR_NM`), `enRouteRange` 적용은 기존과 동일. 판정 대상 geometry는 §8의 판정 영역.

고도는 판정하지 않는다. `verticalKnown: false`, 고도 항목은 "자료 없음"으로 표시한다. 임의의 밴드를 부여하지 않는다.

### 공항

출발·도착·교체공항 좌표가 판정 영역에 포함되는지 검사한다. `hazard-section.js`의 기존 `airportWarnings` 경로(경로 지오 없음)에 얹는다.

### 시간

예보 시점마다 유효구간을 부여하고 `evaluateTimeStatus`로 ETD~ETA와 겹칠 때만 채택한다.

**간격을 고정하지 않는다.** 예보 간격은 태풍마다 다르다(§2 — 힌남노 6시간, 노을 12시간). 각 시점의 반폭은 **그 태풍의 인접 예보 시점 간격의 절반**으로 계산한다.

```
step = 그 태풍 예보 행들의 TMD 차이 중 최솟값 (없으면 6시간)
유효구간 = FT_TM ± step/2
```

6시간으로 고정하면 12시간 간격 태풍에서 시점 사이에 6시간짜리 구멍이 생겨, 그 시간대에 지나가는 항공기가 걸리지 않는다.

### 그룹핑

시점별로 판정한 뒤 `TYP`(태풍번호)로 묶어 태풍당 한 항목으로 보고한다. 겹친 시점들의 구간과 시각을 합쳐 요약한다.

**보고 형태**

```
11호 태풍 힌남노  935 hPa
  경로   120~380 NM 구간 해당
  시간   09:00~14:00Z
  공항   RKPC(도착) 영향권
  고도   판정 안 함 (지상풍 기준 자료)
```

### 프로버넌스

태풍번호, 발표번호(`SEQ`), 분석시각(`TYP_TM`), 예측시각(`FT_TM`)을 응답에 보존한다.

## 11. 실패·결측 처리

| 상황 | 처리 |
| --- | --- |
| 활성 태풍 없음 | 정상 상태. 빈 목록. 지도에 표시 없음 |
| API 실패 | 직전 저장분 유지. 노후 시 "자료 없음" 상태 노출 |
| `-999` 결측 | 해당 반경 도형 미생성 |
| 예보 노후 | 분석시각 표시. 최신으로 위장하지 않음 |

**금지**: 결측·미해결·실패·만료를 `clear`나 `matched`로 변환하는 것. 해당 상태와 사유를 그대로 반환한다.

## 12. 검증

### 단위

- **파서**: 힌남노 실제 응답을 고정 픽스처로 저장. 공백 포함 `LOC`로 컬럼이 밀리지 않을 것, 한글 디코딩, `-999`/`-` 결측 처리를 확인한다.
- **도형**: 축소 방향의 반경이 반대 방위보다 작을 것. `-999`일 때 도형이 생성되지 않을 것.
- **브리핑**: 겹침 / 시간 불일치로 제외 / 자료 없음 3가지 상태에 대해 공유 픽스처 케이스를 추가한다. 태풍번호·발표번호·분석시각이 합성된 응답까지 살아남는지 확인한다.

### 브라우저

Playwright 계약으로 지도 렌더를 검증한다. 계약은 재현 가능해야 하므로 **픽스처를 주입해** 확인한다. 복수 태풍은 2018-08-22(19·20호) 픽스처를 쓴다.

픽스처와 별개로, **현재 12호 태풍 노을이 진행 중이므로 실제 자료로도 한 번 확인한다**(§13).

- 경로선(실선/점선), 부채꼴, 강풍/폭풍 영역이 렌더될 것
- 태풍 타일이 지도 요소와 목록 패널을 함께 켜고 끌 것
- 타일 배지의 숫자가 활성 태풍 수와 일치할 것
- 베이스맵 2회 전환 후에도 유지될 것
- 복수 태풍(2018년 19호·20호 픽스처)이 구분되어 표시될 것. 패널의 색 표식과 지도 경로 색이 태풍별로 일치할 것
- 바로가기 버튼이 지도를 해당 태풍 위치로 이동시킬 것
- 활성 태풍 없음 픽스처에서 "현재 활동 중인 태풍 없음"이 표시될 것

계약은 [contract registry](../../policies/verification/contracts.md)에 등록한다.

## 13. 실제 태풍으로 확인할 것

2026-07-26 현재 **12호 태풍 노을**이 진행 중이다. 구현 후 실제 자료로 다음을 확인한다.

- 지도에 경로·부채꼴·강풍 영역이 실제로 그려지는지
- 목록 패널에 `12호 태풍 노을`이 이름까지 나오는지
- 소멸 시점에 `typ_now`에서 사라지고 화면이 "활동 중인 태풍 없음"으로 바뀌는지

### 아직 측정하지 못한 것

- **발표 게시 지연**: 분석시각 대비 실제 게시까지 걸리는 시간. 수집 로그로 측정해 30분 주기가 적절한지 재확인한다.
- **`EFF`(한반도영향)의 갱신 시점**: 진행 중인 태풍에도 값이 채워지는지, 사후에만 확정되는지 확인하지 못했다. 현재 12호는 `EFF=4`(없음)다. **판정 로직에 쓰지 않는다** — 확인되기 전까지는 표시용으로도 쓰지 않는다.
- **비대칭 방향 규칙**: 표본 3개로는 안전반원 규칙이 일반화되지 않았다(§2). 사례가 쌓이면 재확인한다.

## 14. 이 스펙에 포함되지 않은 변경

`taf_interval`을 30분에서 10분으로 변경했다(`backend/src/config.js`). TAF는 AMD가 예고 없이 발행되어 정시 발표 주기와 무관하게 정정 반영 지연이 갱신 주기를 결정한다. 태풍 작업과 독립적인 변경이다.
