## 후보별 근거·위험·검증

### W07-01 — 관측 풍속 단위/누락이 kt 숫자로 소비됨

**사실.** `parse-utils.js:32–35`는 knot 표기만 KT로 정리하고 기타 단위 문자열은 유지한다. `parseWind:192–205`는 수치 변환 없이 반올림하며 누락/비수치 speed와 direction을 0으로 바꾼다. `formatWindRaw:158–165`는 단위와 무관하게 KT 접미사를 만든다. 국내 `metar-parser.js:270`은 wind가 없을 때 `{}`를 넘기므로 이 0 경로에 도달한다.

이 값은 `metar-processor.js:21–26,49`→`/api/metar`→`metarViewModel.js:72–91,103–105`→`MetarTab.jsx:102`의 kt 표시 및 풍속 배지/측풍 계산까지 전달된다. 비교 경로도 `service.js:32–39`가 단위를 검사하지 않고 `wind.speed`를 `wind_speed_kt`로 명명하고 `modelComparisonViewModel.js:128`→Table/Chart가 kt로 소비한다. TAF parser도 같은 parseWind를 쓰며, panel의 `tafViewModel.js:39`는 원래 unit 문자열을 표시하지만 비교 `:148`는 kt 고정이다. 따라서 비-KT 유효 수치 입력에서는 두 화면의 단위 해석이 달라지고, 풍속 누락은 비교 그래프에 유효한 0으로 남을 수 있다.

**효과/위험/선행.** P1 후보(관측 경계). 지원 unit 변환/거부와 missing 상태 보존을 parser/normalized schema에서 명시하면 모든 소비자의 반복 보정과 잘못된 임계값 계산을 줄인다. calm/VRB, 구 snapshot, TAC 재구성, 지도·브리핑·알림 소비자와의 호환이 선행이다. UI에서 unit마다 제각각 변환하거나 NOAA 원문 풍속을 다시 변환하면 이중 변환 위험이 있다.

### W07-04 — 유효시간은 충족하나 검증 실패한 Open-Meteo raw가 재시도를 막을 수 있음

**사실.** `open-meteo.js:244–271`은 응답을 좌표로 공항 대응한 뒤 persistent raw cache에 먼저 쓴다. hourly 단위/TZ/range·13record validation은 이후 `:278`에 실행된다. `readPersistentRaw:197–203`는 envelope와 collected_at만 확인하고, 다음 수집의 `cacheCovers:213–219`는 expected time 존재만 확인한다. 값 검증 실패 catch `:281–283`는 raw를 무효화하지 않는다.

**효과/위험/선행/검증.** P2 회복성 후보. 공항/window의 검증 실패에 맞춘 cache 유효성·eviction 또는 validation-before-cache 정책을 정의하면 같은 run 수정 응답으로 회복 가능해진다. 성공 공항 cache와 EC expanded-window 재사용은 유지해야 한다; 무조건 전체 cache 폐기는 요청량 증가 위험이 있다. 기존 `airport-model-comparison-open-meteo.test.js:129`는 sibling 실패의 첫 게시, `:156`은 정상 cache 재슬라이스·재시작만 보호한다. 주 담당이 동일 run 두 회차(첫 단위 오류→둘째 정상)에서 제공자 call count/failed/pointer revision을 확인하고, 성공 sibling 보존 및 EC peer-window 이동도 검증해야 한다. 이번 재현 미실행.

### W07-07 — TAF 중복 규칙은 의도된 차이와 공통화 후보를 분리

**확인된 현재 동작.** 국내 parser timeline은 BECMG 시작 시각부터 변경을 적용(`taf-parser.js:348–351`); NOAA timeline도 시작 gate를 쓰되 validity 시작과 같은 BECMG는 끝에서 적용한다(`noaa-taf-parser.js:242–246`). 패널은 이 timeline을 그대로 소비한다. 비교는 base/change_groups에서 재구성하여 BECMG **끝**, FM **시작**, TEMPO/PROB **구간 안**의 단일 값으로 표시한다(`modelComparisonViewModel.js:144–151`). 동일 국내 TAF의 BECMG 전이 구간에서 패널과 비교 값이 달라질 수 있는 사실은 확인했다.

그러나 비교의 단일값/조건부 disclosure 제거는 `modelComparisonViewModel.test.js:138–151`과 browser `airport-model-comparison.spec.mjs:67–91`의 명시 계약이다. “조건부 표시가 없으므로 버그”로 판정하거나 다시 TEMPO 상세를 추가할 권한은 없다. Architecture `:55`의 조건부 TAF 설명은 현재 계약을 충분히 설명하지 않는다.

**실제 공통화 후보.** immutable base, null=미변경, touched=false=inherit, 빈 배열=명시 해소, FM/BECMG gate를 입력으로 받는 작은 순수 resolver는 중복 변경 비용을 줄일 수 있다. 다만 일반 parser의 `partialMerge`는 CAVOK/NSC/NSW flag 전이를 다루고 비교의 얕은 merge는 표시 필드 중심이며, parser timeline에는 저시정시 BR 보완(`taf-parser.js:244`, NOAA `:146`)도 있다. 출력 목적이 달라 전체 resolver를 기계적으로 통일할 근거는 없다.

**판정/선행/위험/검증.** 우선순위 미정, 계약 정리 후보. BECMG gate 차이를 유지할지 사용자 흐름의 기준을 먼저 결정하고 현재 테스트 oracle을 보존해야 한다. 구조 공통화와 관측/예보 표시 의미 변경을 같은 카드에 섞지 않는다. 검증 matrix는 BECMG start/end, 겹친 TEMPO/PROB, FM, touched false/null/empty, CAVOK 해제, 발행/날짜 경계의 parser timeline와 비교 row 값이다. 이번 통합 재현 미수행.

### W07-08 — 전달된 모델비교 브라우저 6실패는 초기 탭 기대 불일치

**실행 증거의 소유자.** 주 담당이 전달한 `artifacts/refactoring/S004/browser-main-failures.json`에 모델비교 두 테스트가 desktop/ipad-landscape/mobile에서 각각 실패했다. 전체 214pass/58fail/85skip은 주 담당 알림의 main 357사례 결과이며 본 작업이 실행한 결과가 아니다.

**첫 실패.** `airport-model-comparison.spec.mjs:288`은 초기 “연직시계열 크게 보기” 버튼을 기대한다. 실제 `AtmosphericReference.jsx:26`은 `kind='sounding'`으로 시작하고 `:34–43,64`는 단열선도 버튼/이미지를 표시한다. desktop error-context `:1493–1503`은 단열선도 탭 selected, 단열선도 크게 보기 및 인천 샘플 F018을 명시한다.

**둘째 실패.** 같은 spec `:564`는 초기 무안 연직시계열 이미지를 기대하고, `:565`에서야 단열선도 tab을 클릭한다. component 기본 상태와 순서가 반대다. 두 테스트 모두 같은 mismatch로 3viewport에서 실패할 수 있다. reference는 `/briefing-charts/…png` 고정 샘플이고 “현재 공항 실행자료와 연결되지 않았습니다”를 명시(`AtmosphericReference.jsx:66`)하므로 모델비교 API run 선택/새 수집 필요성의 증거가 아니다.

**제안/위험/검증.** P2 검증 계약 정리. 현재 기본 탭이 의도된 제품 동작인지 주 담당이 확인한 뒤, 테스트가 원하는 탭을 먼저 선택하고 이미지·13샘플·확대·키보드·TZ assertions에 도달하도록 정리한다. 단순히 실패 assertion을 삭제하거나 API fixture를 바꾸는 것은 검증 목적을 잃는다. 현재 실패 지점 이후의 이미지 load, dialog, arrow order 성공은 미검증이다. 탭 배열도 sounding/profile 순서라 초기 assertion만 바꾼 뒤 뒤쪽 keyboard 기대까지 다시 확인해야 한다. 이 작업에서 테스트/컴포넌트 수정 및 재실행 없음.

## 유지할 구조와 제안 순서

1. root shared 공항 식별자, provider별 adapter, 저장-only GET, UTC valid_at 비교, model run/F-hour/결측 provenance는 유지한다.
2. 관측 parser의 정규화/결측과 AMOS 운고 원단위를 먼저 확정한다(W07-01/02/03). downstream별 증상만 고치면 같은 입력이 다른 화면에서 다시 틀릴 수 있다. unit 변경은 기존 저장자료와 타 영역 소비자 검수가 선행이다.
3. 공항별 immutable 게시·마지막 정상값 보존을 유지하면서 raw cache 검증 실패 회복과 HTTP200 partial 상태 표시를 별도 카드로 검토한다(W07-04/05).
4. W04/A11 공통 시계와 A05 표시의 교차 근거를 합치고, TAF gate/TAC/원문/계획 날짜의 의도 차이를 기록한다(W07-06/07). 특정 date library 도입을 전제로 하지 않는다.
5. 브라우저 초기 탭 drift는 작고 독립적인 검증 후보(W07-08). API 실자료 정확도 검증과 분리하며 실패 뒤 미도달 assertions를 통과로 계산하지 않는다.

강수 공통 누적시작·중간 결측 뒤 누적 중단(`ViewModel:18–25,179–192`), 회전풍향 범위(`:28–44`), NSC/결측 선 분리(`chartPath`), 운고 상한 넘는 표식, 같은 UTC 축의 표/그래프를 유지한다. summary가 같은 full view model을 계산한다는 사실은 있으나 비용 측정 없이 성능 결함으로 판정하지 않는다. WarningCarousel의 측정·타이머 cleanup, model tooltip의 outside/Escape/scroll/resize cleanup, Moon 월력의 열린 때만 계산하는 경계도 유지한다.

## 남은 범위·체크포인트·좁은 후속 질문

**체크포인트:** A05 34개 파일의 소유/소비 경로, 비교 backend 7파일의 모델 선택·저장·조회, 공항 runtime 표시면, 관련 관측/NWP parser와 핵심 표시모델을 정적으로 조사했다. 후보 W07-01~08 및 source/기존 검사 근거를 기록했고, 자체 실행 검증은 0이다. CSS full cascade/천문 수식/아이콘 규칙/외부 제공자 정확도·장시간·성능은 부분 확인으로 남긴다. 이 보고서 반환은 진단 요청의 산출물 완료이며 A05의 모든 runtime 조합을 실행 검증했다는 뜻이 아니다.

2. **W07-01/03 관측 경계:** 실제 국내 XML에서 비-KT/단위 누락/풍속 누락·VV·cloud nil 사례가 있는가? 없다면 synthetic boundary 계약부터 정하고, 과거 정상 snapshot과의 호환을 어떻게 유지할 것인가?
