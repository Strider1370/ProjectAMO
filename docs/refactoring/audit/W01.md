## W01-01 — root test/check의 발견 경계

**확인된 사실.** `package.json:22-23`의 `&&` 때문에 backend 실패 시 frontend, test 실패 시 build는 생략된다. frontend `package.json:16`은 fonts:check 실패 시 node test도 생략한다. `.nvmrc` 기준과 일치하는 로컬 Node v22.23.1 내장 runner를 읽어 cwd 하위 glob과 node_modules 제외를 확인했다. `file:..` 의존성으로 root package가 하위 node_modules에 존재해도 자동 탐색 복구 경로가 아니다. 추적 backend/frontend 소스에는 root test 파일을 import하는 구문이나 Python/deploy 테스트를 실행하는 호출을 찾지 못했다.

root shared는 사용 중이다. `frontend/src/features/route-briefing/useRouteBriefing.js:18`의 `buildCommonRouteModel`, `lib/verticalProfileRequest.js:155`, `lib/routeSaveGeometry.js:7`이 route 모델을 소비한다. `backend/src/briefing/enroute-cross-section.js:19`와 frontend `lib/nwpTimeSelection.js:1`이 NWP 시간 선택을 소비한다. `backend/src/organizations/geometry.js:2`는 annotation 투영, `briefing/hazard-exposure.js:1-6`, `typhoon-briefing.js:8`은 briefing status를 소비한다. 각 소비자 테스트가 있더라도 shared의 독립 case 14개가 자동 실행된다는 뜻은 아니다.

Python ENR tests는 파서 함수에 인라인 표 입력을 넘겨 결과를 단언한다(`test_aip_enr31_poc.py:1-6,68-69`, `test_aip_enr33_poc.py:1-6,50-51`). 반면 변경 후보/개정 조사 tests는 `main()` 내부에서 changes와 affected_sections/pdf_titles/amendment_for를 호출하고 `if __name__ == '__main__'`에서만 실행한다(`test_build_aip_change_candidates.py:8-15`, `test_inspect_airac_amendment.py:4-13`). 따라서 unittest discover 하나로 네 파일이 보호되는 것으로 보고하면 안 된다.

배포 lock test는 실제 `/tmp/projectamo-deploy.lock`을 잡고 git/npm/pm2/sudo/curl/sleep을 임시 stub으로 바꾼 다음 두 배포 스크립트가 비영(非0) 종료하며 command marker를 남기지 않는지 확인한다(`deploy/test-deploy-lock.sh:16-41`). nginx rate-limit은 설정 문자열만 검사한다(`deploy/test-nginx-rate-limit.mjs:5-9`). `backend/test/deployment.test.js:3-17`은 admin deploymentInfo/certificateExpiry 호출이므로 배포 lock 동작을 보호하지 않는다.

추적 2,248개 경로 중 `.github`, `.gitlab`, CircleCI/Buildkite/Jenkins/주요 hook CI 정의는 없었다. **repo 외 CI 부재는 가설이며 확인하지 않았다.** prototype은 독립 package이고 `sites-worker.test.mjs:64-67`이 dist/client, dist/server, dist/.openai 산출물을 검사하므로 무조건 root test에 추가하면 미빌드 상태 실패를 만들 수 있다.

**유지/효과/위험/선행.** 빠른 Node 검사와 서버·실자료 검증의 분리는 유지한다. root shared와 offline Python/deploy 검사 그룹을 명시적 명령/기준선 목록에 연결하면 빠진 독립 계약을 식별할 수 있다. 단일 거대 명령으로 통합할 경우 prototype build·global deploy lock·실자료 검증 부작용을 섞을 위험이 있으므로 W02의 명령 소유권 조사와 주 담당의 실행 결과를 먼저 합친다. 추천은 빠진 가벼운 그룹부터 명시하고 browser/live 그룹은 별도 실행 상태를 기록하는 방식이다.
