# 연직단면도 개선 검토 화면

`/concepts/vertical-profile`은 개발 전용이다. 기존 메인 지도 위에 이동·크기 조절 가능한 창을 표시한다. 기본 미리보기는 예시 경로(RKSI–예시 경유점–RKPC)로 운영 `/api/vertical-profile`, `/api/briefing/cross-section`을 호출한다. 경로는 승인·권장 항로가 아니며, 로컬 저장자료의 유효시각을 화면에 표시한다. 오래된 저장자료를 현재 예보로 표시하지 않는다.

## 운영 자료와 기능 연결

- `OperationalProfileWindow`는 운영 `VerticalProfileChart`를 재사용한다. 합성 기상장 확대, 고정 FL420 결측, 고정 47,000 ft 상한을 사용하지 않는다. 원자료의 기압층·coverage·권계면·제트·난류 자료와 기존 결측 처리를 따른다.
- 고도 표기는 모두 ft다. QNH/기압고도 변환을 추가한 것이 아니며, 모델 고도와 계획고도의 기존 좌표 기준을 유지한다.
- 동일 개발 경로에서 메인 지도의 운영 단면을 열어도 새 창을 사용한다. 기존 프로파일·비교 고도·예보시간·NWP 지점별 시간 변경 콜백·자료 상태를 전달한다. 일반 앱 경로도 공통 `VerticalProfileViewer` 창을 사용한다. 브리핑·조직 발표는 같은 뷰어를 패널에 삽입하고, 보관 결과는 편집 콜백을 전달하지 않는다.
- 예시 미리보기는 조회 취소와 마지막 성공 스냅샷을 관리한다. 갱신 실패 시 요청한 새 시간·고도로 이전 자료를 재표기하지 않고, 기존 자료와 오류를 표시한다. 사용 가능한 예보시간만 선택한다.
- 지점 이름을 고유 식별자로 사용하지 않는다. 실제 폰트 폭을 측정해 한 줄에 배치하고 선택 지점을 우선한다. 생략된 지점은 확대하거나 지점 이름에 초점을 둔 뒤 좌우 화살표/Home/End로 접근한다. 하단 지점 선택 목록은 두지 않는다.
- 지도 위 창의 휠은 포인터 위치를 기준으로 확대·축소한다. 삽입된 패널은 페이지 스크롤을 유지하며 확대 버튼을 사용한다. 드래그는 브라우저 스크롤로 이동하고, 차트는 memo로 분리한다. 주요 기상 도형 계산도 자료·크기 변경 시에만 재계산한다. 고도 축은 고정한다.
- 아래 전체 항로 바에서 구간을 옮기고 `전체`로 복귀한다. 고도 비교 후보선과 NWP 시간선은 운영 기능을 유지한다.
- 낮은 화면에서는 창을 화면 크기에 맞추고 설정·범례를 접는다. 차트 높이를 확보하며, 필요하면 창 내부에서 세로로 스크롤할 수 있다.

## 검증

서버가 실행 중일 때:

```bash
node frontend/scripts/verify-operational-profile.mjs
node frontend/scripts/verify-shared-profile.mjs
```

운영 API 연결, 시간·고도 선택, NWP 콜백, 실패 시 이전 자료 보존, 휠/드래그/고정 축, 작은 화면, 접근성 및 별도 601개 표본·401개 지점 계약 자료를 검증한다. 계약 자료는 긴/중복 이름과 결측을 포함한다. 이 테스트는 전체 운영자료의 성능 벤치마크나 실제 iPad 검증을 대신하지 않는다. 결과 및 화면은 `artifacts/vertical-profile-concept/operational-*`에 저장한다.

## 이전 합성 시안

`?demo=1`은 이전 6,000 NM·401개 지점 합성 시안을 보존한다. `?demo=1&route=short`는 312 NM 예시다. 합성 자료를 운영 자료로 사용하지 않는다. 이 경로는 과거 창·탐색 조작 검증용이며 기본 검토 화면은 위 운영 API 버전이다.

```bash
node frontend/scripts/verify-vertical-profile-concept.mjs
node frontend/scripts/verify-profile-long-route.mjs
```
